# 加密博文

加密文章沿用博客的标题、日期和导航。访客输入密码后，浏览器解密正文；点击“重新锁定”或刷新页面，会回到密码输入界面。密码与解密后的正文不会写入浏览器存储。

标题、日期、URL、分类和标签是公开信息。正文在发布前加密，仓库和网站保存密文。密码需要足够长且独立使用；访问者可以下载密文并在本地尝试密码，静态网站无法限制这种尝试次数。

## 写作与加密

将 HTML 正文保存在仓库之外，例如与仓库并列的 `private-blog/` 目录。源文件是正文片段，可以包含段落、标题、公式、内联 SVG、样式和作者自己的脚本。

```html
<p>这里开始写正文。</p>
<h2>一个小标题</h2>
<p>公式可以使用 \(E=mc^2\)。</p>
```

在仓库根目录运行：

```sh
node scripts/encrypt-post.mjs \
  --source ../private-blog/notes.html \
  --slug private-notes \
  --title "一些笔记" \
  --date 2026-11-06 \
  --math
```

命令会隐藏输入并要求确认密码，然后生成 `posts/private-notes/index.html`。使用 Node.js 20 或更新版本，不需要安装 npm 依赖。源文件不能位于仓库内部，符号链接也会检查真实路径。

`--math` 将本站固定版本的 KaTeX、符号提示脚本和字体一起封装进加密正文。图例需要共享分步控制时，增加 `--steps`。符号提示继续使用文章中的 `#math-definitions` JSON；这些定义随正文一起加密。

正文中的私有图片使用内嵌 `data:` URL，SVG 可以直接写进正文。解密文档的资源来自自身，外链图片、脚本和样式不加载。独立放在文章目录中的图片、PDF、实验文件仍是公开文件；需要保密的内容应放进加密正文或通过另一个受保护的渠道分享。

内联脚本用于作者自己的交互图。不要将未审查的第三方 HTML 或脚本直接放进正文。解密文档在独立的 sandbox iframe 中显示，密码不会传给该 iframe。

下载文件也可以把字节嵌入加密正文，在读者点击按钮后由受信任的内联脚本生成 Blob 下载。文件与正文一起加密，浏览器本地生成下载内容；解锁本身不触发下载。

更新同一篇加密文章时，修改仓库外的源文件，再运行相同命令并增加 `--replace`。每次加密会生成新的随机 salt 和 IV。更换密码后，持有旧密文和旧密码的人仍能解密旧版本。

## 加入博客列表

在 `assets/posts.js` 中添加公开条目：

```js
{
  slug: "private-notes",
  title: "一些笔记",
  date: "2026-11-06",
  kind: "encrypted",
  cat: "basics",
  tags: [],
  desc: "这是一篇加密文章，输入密码后阅读。"
}
```

RSS 使用同一公开标题和中性摘要。系列登记也只使用公开标题。不要把正文摘录、私有链接或图片地址写进这些索引。

运行 `python3 scripts/post-links.py` 更新公共资源版本，然后在 `http://localhost:8000/` 预览。提交前检查暂存区，确认文章目录只有生成的密文页面。主页继续只保留个人信息，不添加文章推广区块。

之前已经公开提交过的文章，即使现在加密，旧正文仍然存在于 Git 历史或已有副本中。新的私密文章应从第一次提交起就只包含密文。

## 格式与验证

加密使用 AES-256-GCM，密码通过 PBKDF2-SHA256、600,000 次迭代和随机 16 字节 salt 派生密钥；每次使用随机 12 字节 IV 与 128 位认证 tag。Node 发布工具与浏览器 Web Crypto 使用相同的版本化格式。阅读端需要 HTTPS 或 localhost 的安全上下文。

运行完整检查：

```sh
python3 scripts/check-encrypted-post.py
```

检查会在临时目录中生成合成文章，验证密码、篡改检测、重新锁定、公式字体、手机布局和明文不会进入生成页面。测试用的 `--password-stdin` 通过标准输入传递合成密码；日常写作使用默认的隐藏交互输入。
