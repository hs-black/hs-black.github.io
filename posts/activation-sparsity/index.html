激活稀疏：当前 token 需要哪些神经元

交互2026-10-22

一个 FFN 可能有上万个神经元，而某个 token 只需要其中一部分。激活稀疏把这个事实变成一次输入相关的计算选择：先判断当前向量里哪些分量值得保留，再跳过对应的权重读取或乘法。真正的难点是让选择足够准确、足够便宜，并且符合 GPU 的执行方式。

这条路线串起了几类看似不同的论文：ReLU Strikes Back 研究怎样训练出更多自然零值；Deja Vu 提前预测当前输入需要的神经元和注意力头；TEAL 直接截断低幅值激活；2:4 激活稀疏进一步把零值排进 Tensor Core 可用的格式。理解它们，可以从同一个矩阵乘法开始。

1. 一个零激活省掉什么

先看普通两层 FFN。输入 \(x\in\mathbb R^d\)，上投影 \(W_{\rm up}\in\mathbb R^{m\times d}\)，下投影 \(\htmlData{symbol=downweight}{W_{\rm down}}\in\mathbb R^{d\times m}\)，中间宽度为 m。计算为

\[ \htmlData{symbol=activation}{h}=\phi(W_{\rm up}x),\qquad y=W_{\rm down}h=\sum_{j=1}^{m}h_j\,W_{{\rm down},:,j}. \]

h 是 m 维中间激活。若 \(h_j=0\)，这一项对输出没有贡献，下投影的第 j 列就可以跳过。权重本身可以完全稠密；不同 token 的 h 不同，跳过的列也随之改变。这与固定删除某些连接的权重剪枝对应着不同的执行方式。

ReLU 定义为 \(\max(z,0)\)，负输入会精确变成零。SiLU 定义为 \(z/(1+e^{-z})\)，通常保留较小的负值。ReLU Strikes Back 比较了激活函数，并研究对已有模型更换激活函数后继续训练以恢复质量。它的工程启发是：模型的非线性选择会影响将来可用的稀疏 kernel，因此预训练目标可以同时考虑质量与执行成本。

Squared ReLU 使用 \(\max(z,0)^2\)。它与 ReLU 具有相同的零值位置，同时改变正值的相对尺度：0.1 变成 0.01，2 变成 4。模型需要适应新的幅值和梯度；正值平方后的大小变化，也会影响后续截断与量化。

SwiGLU 则计算 \(h=\operatorname{SiLU}(W_{\rm gate}x)\odot(W_{\rm up}x)\)。其中每一项由门控分量和上投影分量共同决定。只观察 gate 的大小，可能漏掉另一个乘数的放大作用。选择在哪个张量上建立稀疏，是算法的一部分。

2. 从幅值阈值推到输出误差

已经训练好的模型往往使用平滑激活函数。TEAL 对矩阵乘法的输入向量做幅值截断，把小分量设为零。给定阈值 \(\htmlData{symbol=threshold}{\tau}\)，定义

\[ \widehat h_j=h_j\,\mathbf1\{|h_j|\ge\tau\},\qquad \htmlData{symbol=activationerror}{e}=y-\widehat y=W_{\rm down}(h-\widehat h). \]

\(\mathbf1\) 是条件成立时取 1 的指示函数；e 是 d 维输出误差。令 \(\htmlData{symbol=droppedactivation}{\delta}=h-\widehat h\) 为被删掉的激活向量，就有

\[ \|e\|_2\le \|W_{\rm down}\|_2\,\|\delta\|_2. \]

这里向量的 2 范数是长度，矩阵的 2 范数是最大奇异值，刻画该层对输入扰动最大的放大倍数。它给出一个确定性的误差上界；实际误差还取决于被删分量朝向权重矩阵的哪个方向。

进一步展开，平方误差为 \(\delta^\top W_{\rm down}^\top W_{\rm down}\delta\)。相应权重列的长度和列之间的夹角，都会改变删除代价。只删第 j 项时，误差长度恰好是 \(|h_j|\|W_{{\rm down},:,j}\|_2\)。一个小激活乘到很长的权重列上，仍可能贡献较大输出。

图中阈值为 0.1 时，会删除 0.08、−0.03、0.02、−0.01。它们对两个输出的总贡献分别为 0.09 和 −0.22，所以误差长度是 \(\sqrt{0.09^2+0.22^2}\approx0.238\)。继续增大阈值时，实际误差可能因向量相消而局部下降；验证时应直接测量输出，而不是把非零比例当成误差的替代量。

TEAL 用通用文本离线估计激活绝对值的分布，把目标稀疏率转换成阈值。它还在 Transformer block 内，按输出重建误差和矩阵存储成本分配不同层的预算：相同的 block 目标，可以对应不同的矩阵稀疏率。它的输入截断覆盖模型中的多类投影，包括注意力投影；上面的 FFN 只是方便推导的一个位置。

阈值来自校准分布，线上代码、数学或多语言请求的分布可能不同。可以同时记录每层实际保留比例、误差分位数和最终任务指标，判断是激活整体变大导致速度收益下降，还是少数关键通道被频繁误删。对于分布变化明显的场景，按场景重新校准预算比直接沿用一个全局阈值更容易解释。

3. 先算出来，还是提前预测

从 h 里发现零值时，上投影已经算完，直接收益主要落在下投影。若能在计算 \(W_{\rm up}x\) 之前预测将要活跃的神经元，就有机会同时跳过上投影的对应行和下投影的对应列。

Deja Vu 训练轻量预测器，依据输入预测当前语境需要的 MLP 神经元和注意力头，并利用相邻层表示的相似性进行提前预测。其异步设计让预测与已有计算重叠，降低串行等待。预测器的输出决定哪些权重进入后续计算。

预测错误有不同后果。把一个低贡献神经元预测为活跃，会多做一些工作；把高贡献神经元预测为不活跃，会引入输出误差。因此，比起只报告分类准确率，更有解释力的是：活跃集合大小、按输出贡献加权的漏选量，以及预测和索引操作暴露在关键路径上的时间。

设稠密路径耗时为 \(T_d\)，稀疏乘法耗时为 \(T_s\)，索引与聚合耗时为 \(T_i\)，重叠后仍然暴露的预测耗时为 \(T_p\)。实际有收益的条件是 \(T_s+T_i+T_p<T_d\)。例如原本 100 μs，稀疏乘法 55 μs，索引 15 μs，预测暴露 20 μs，总计 90 μs。继续减少乘法之前，先压低索引或预测开销，可能更有效。

TEAL 的路径更直接：输入向量已经存在，只需按预先校准的阈值判断要读哪些列；Deja Vu 额外学习一个能在较早位置工作的预测器。前者主要依赖幅值与校准误差，后者还依赖预测召回、提前量与异步调度。两者都需要让权重布局顺着选中的行或列读取，才能减少实际内存流量。

4. batch 为什么会吃掉带宽收益

单 token 解码常常要为一次向量乘法读取大量权重。若只用 10% 的神经元，跳过其余列可能节省很多带宽。但把多个 token 放到一起后，它们可能需要不同的列。

令 \(\htmlData{symbol=density}{\rho}\) 为一个神经元对单 token 的活跃概率，\(\htmlData{symbol=batch}{B}\) 为同时处理的 token 数。假设各 token 的活跃事件独立，则这个神经元至少被一个 token 使用的概率为

\[ \htmlData{symbol=uniondensity}{q_B}=1-(1-\rho)^B. \]

推导只需要先算“所有 token 都不用它”的概率 \((1-\rho)^B\)，再取补集。若 \(\rho=0.1\)，B=1 时并集密度为 10%；B=8 时约 56.95%；B=32 时约 96.57%。每个 token 依然只使用约十分之一，但整个 batch 已经几乎访问了所有权重列。

这个并集公式刻画的是“该 batch 一共会访问多少不同权重列”。逐 token 的乘法数量仍可保持稀疏，而 GPU 若按共享列组织整个 batch，读取范围就更接近并集。支持集合之间的相关性会改变结果：若所有 token 总是用同一批神经元，并集密度就保持 \(\rho\)。因此，应从真实请求采样掩码重合度。

TEAL 的主要加速评估针对单 batch 解码；其较大 batch 的扩展考虑了按 batch 平均激活幅值建立共享选择。共享选择能改善执行规则性，同时改变每个 token 的误差与可达稀疏率。对于服务系统，可以按 batch 大小切换 kernel，或者把激活稀疏主要用在低并发延迟路径。

PowerInfer 则把激活频率与 CPU/GPU 权重放置联系起来：高频神经元放在 GPU，低频部分交给 CPU 路径。这把“当前是否需要”扩展成“通常多常需要、数据应该常驻哪里”。是否合算，取决于 CPU 内存带宽、PCIe、并发度和活跃集合稳定性；应与目标机器上的完整 dense 路径比较。

5. 从全局零值到局部 2:4

通用 GPU 的稀疏 Tensor Core 需要规则模式。即使一个激活矩阵总体 90% 为零，某个连续四元素组里仍可能有三个或四个非零数。使用 2:4 kernel 时，必须在每组内再保留幅值最大的两个，并统计这一步新增的误差。

把激活按 token 排成 \(A\in\mathbb R^{N\times m}\)：一行是一个 token，一列是一个特征。这一节把下投影存成 \(W\in\mathbb R^{m\times d}\)，输出为 \(Y=AW\)，输出梯度为 \(G=\partial L/\partial Y\in\mathbb R^{N\times d}\)。前向 \(A W\) 沿特征方向归约，需要每行的四特征组满足模式。权重梯度包含 \(A^\top G\)，沿 token 方向归约，需求转成每列的四 token 组。两个方向可以有完全不同的局部密度。

Accelerating Transformer Inference and Training with 2:4 Activation Sparsity 采用 Squared ReLU，并研究两个实际障碍。一些特征经常激活，逐列做 2:4 会删掉很多信息；相邻 token 的激活还会成段出现，使原本全局很稀疏的特征在局部四元组里挤满。

图中原顺序会删掉一半非零值；交错以后，每个四 token 组在每列恰好有两个非零值，额外删除降为零。论文使用固定 token 置换来打散局部相关性，并在 FFN 后恢复原顺序。

这样做成立的原因是 FFN 逐 token 独立作用。设 P 为 token 行的置换矩阵，对同一逐行函数 F，有 \(F(PX)=PF(X)\)。所以先置换、计算 FFN、再逆置换，可以恢复原来的 token 对应。把置换融合到已有的逐元素操作里，有助于控制额外访存。

对少量高密度特征，该工作另外保留 dense 路径，其余走 sparse 路径，最后合并梯度。论文中的一种配置约把 5% 特征放入 dense 分支；这一比例由实际激活分布决定。这样，少数高密度列就不必迫使所有列都使用相同的激进剪法。

前向已经删掉的值，在构造后向稀疏激活时应继续保持为零；后向选择是在前向有效激活上进一步截断。否则，权重梯度会使用前向从未出现的值。这里还要区分输入梯度的激活导数与权重梯度使用的激活矩阵，两条反向路径各有自己的数值约束。

该论文报告了训练质量实验和 FFN kernel 基准，其中训练质量实验模拟了稀疏模式。把某个 FFN kernel 的加速转成完整训练收益，还需要纳入置换、打包、dense 分支、量化和其他算子。有关三个训练 GEMM 的完整账本，可见稀疏预训练。

6. 把质量、访存和执行放在一起测

第一步固定权重和输入，比较三份输出：完整 dense、dense 实现的掩码参考、真正 sparse kernel。前两份之差衡量算法近似，后两份之差检查索引、布局、量化和累加。若后两份有明显偏差，应先修正执行路径再调稀疏预算。

第二步测各层分布：保留比例、被删激活的能量、输出误差、权重列范数，以及 batch 的活跃并集。对 2:4 再记录每个四元组中非零数量的直方图，区分原有零值与为满足模式新增的删除。整体稀疏率相同的两层，可能有完全不同的局部适配成本。

第三步把实际字节数和时间拆开。假设 dense FFN 下投影原本要读 200 MB，单 token 活跃集合覆盖 20%，理想列读取是 40 MB。真实访问还受 cache line、连续性、索引表和重复读取影响。用 profiler 的内存流量与 kernel 时间检查这一预测，再查看是否把节省的时间花在了筛选和 gather 上。

最后在长文本、代码、数学和多语言上做端到端质量验证。阈值提高后，平均 loss 可能缓慢变化，某些任务却更敏感。按层误差和按任务结果一起保留，才能判断应该降低哪个位置的预算。低位权重还会改变权重读取和量化误差；可以把“dense 精度、只量化、只稀疏、两者组合”作为四个对照，逐项量出叠加成本。

7. 计算与诊断练习

练习 1：小激活是否可以放心删除

输出 \(y=[1,100]h\)，激活 h=[0.1,0.01]，阈值 τ=0.05。求完整输出、截断输出、误差和矩阵范数上界。

展开完整解答

完整输出为 \(0.1+100\times0.01=1.1\)，截断输出为 0.1，绝对误差为 1。被删向量长度为 0.01；单行矩阵的谱范数为 \(\sqrt{1^2+100^2}=\sqrt{10001}\)，上界约为 1.00005。小激活对应很大的权重列，因此贡献仍大。可用列范数加权贡献或直接输出重建评估这一位置。

练习 2：90% 稀疏为何还会读几乎所有列

每个神经元对各 token 独立地以 0.1 概率活跃。求 B=8 与 B=32 的权重列并集比例。如果 token 共享完全相同的活跃集合，结果如何？

展开完整解答

独立时，B=8 得到 \(1-0.9^8=0.56953279\)，约 56.95%；B=32 得到 \(1-0.9^{32}\approx0.96566316\)，约 96.57%。完全共享时，并集期望密度保持 10%。前者预测被整个 batch 触及的列范围；每个 token 自身的非零比例仍为 10%。测实际掩码重合度，可以判断请求更接近哪种情况。

练习 3：预测器需要多快

dense 路径为 120 μs，稀疏乘法 62 μs，索引与聚合 18 μs。预测器原本需 50 μs，其中 30 μs 可以与已有计算重叠。求加速比，以及失去重叠后的结果。

展开完整解答

暴露预测时间为 50−30=20 μs，总时间 \(62+18+20=100\) μs，加速 1.2 倍。失去重叠后总时间 130 μs，加速比约 0.923，延迟增加。收支平衡要求暴露预测耗时低于 \(120-62-18=40\) μs。测试应关注关键路径的暴露时间，并同步检查预测漏掉的输出贡献。

练习 4：两种方向为什么需要不同处理

八行激活的前四行均为 [1,2,0,0]，后四行均为 [0,0,3,4]。按每列连续四个 token 保留两个非零值，求原顺序被删的平方能量；再用 token 顺序 [1,5,2,6,3,7,4,8] 计算。

展开完整解答

原总能量是 \(4(1^2+2^2)+4(3^2+4^2)=120\)。每个活跃列的四元组只能留两个，因此删除一半，即 60。交错后，每个四 token 组的每列恰好有两个非零数，删除能量为 0。FFN 逐行作用，逆置换可以恢复输出顺序；后向还需在前向实际保留的激活上构建列方向掩码。

8. 运行实验

下载 lab.py，在安装 NumPy 的环境中执行：

python3 lab.py

正常运行会逐项打印 PASS，随后给出当前数值实验的结果。

脚本用直接逐列求和验证截断后的输出，检查谱范数误差上界；枚举小概率模型验证 batch 并集公式，再用固定种子展示采样偏差。随后逐组检查 token 置换前后的 2:4 删除能量，并验证逐 token FFN 与置换的交换关系。

把权重的一列放大十倍，比较同一阈值下的输出误差；把 token 从独立采样改成共享掩码，比较并集；改变一部分高密度特征的幅值，观察“删除个数”和“删除能量”是否仍然同步。每个改动都对应一种实际诊断：通道敏感性、batch 复用，以及局部格式的代价。
