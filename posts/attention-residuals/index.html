Attention Residuals：沿深度选择信息

交互2026-10-22

读到一个代词时，浅层可能已经抓出了候选实体，中层在搭句法骨架，深层才拍板它指代谁。标准 Transformer 把每个子层的输出一股脑加进同一条残差流里，等传到深层，早期信息虽然还在，却早和后面几十层的输出搅成了一团，深层只能自己再费劲扒出来。Attention Residuals（AttnRes）换了个思路：把沿途的表示留下来，让当前子层按内容自己挑——这一步要多少 embedding、多少浅层特征、多少刚算出来的结果，由深度方向的 attention 说了算。

它和 Hyper-Connections（HC）、mHC 盯着的是同一个问题：信息怎么穿过几十上百层网络。区别在于做法不同——HC 把残差流加宽成多条并行通道，mHC 给通道混合套上流形约束，AttnRes 则直接把注意力拉到深度轴上，去翻历史层的账。下面我们从公式一路算到显存和跨卡通信，看看这笔账到底怎么算。

把残差展开，看到深度轴

先盯住单个 token，隐藏维度记作 \(d\)。用 \(l\) 给 attention 和 MLP 子层统一编号（一个常见 decoder block 算两个子层），把子层里的 normalization 一并包进 \(F_l\)，标准 PreNorm 残差就是：

$$x_{l+1}=x_l+F_l(x_l),\qquad x_1=e.$$

这里 \(e\in\mathbb R^d\) 是 embedding。把子层 \(i\) 的分支输出记作 \(v_i=F_i(x_i)\)，再令 \(v_0=e\)，反复展开就能看到残差流的真面目：\(x_l=\sum_{i=0}^{l-1}v_i\)。不管哪一层算出来的东西，送进残差流的系数全都是 1。网络当然可以靠 \(F_i\) 自己去缩放甚至抵消旧特征，但残差连接本身只会一路做加法。

一路无脑加法有个很现实的麻烦：粗略估算，只要各层输出之间不算强相关、量级也相近，累加和的方差就会随深度线性增长，RMS 大约按 \(\sqrt{l}\) 往上飘。等进入下一个子层，PreNorm 一把把它缩回固定尺度，刚算出来的新增量在总和里占的份额就越来越小——到了深层，新分支很容易被前面几十层的历史「淹掉」。真实模型里各层存在相关性，增长不会严格贴着 \(\sqrt{l}\) 走，但逐层看残差 RMS 和分支输出 RMS 的比值，深层分支相对变弱是很常见的现象。

Full AttnRes 做的改动非常直接：不再把历史硬加在一起，而是把第 \(l\) 个子层的输入换成历史输出的加权和。算上 embedding 和前面 \(l-1\) 个子层的输出，此时共有 \(l\) 个可选来源：

$$\htmlData{symbol=h}{h_l}=\sum_{i=0}^{l-1}\htmlData{symbol=alpha}{\alpha_{i\to l}}\,\htmlData{symbol=v}{v_i},\qquad v_l=F_l(h_l),\qquad \sum_{i=0}^{l-1}\alpha_{i\to l}=1.$$

每个历史来源各自存着，当前子层先按权重聚合成 \(h_l\)，再算自己的输出 \(v_l\)；跑完所有层后，最终输出层也可以用同样的方式再聚合一次。至于因果性不用担心：这里重读的始终是同一个 token 在前面几层的表示，并不跨时间步，只要每个 \(F_l\) 里的序列注意力遵守 causal mask，沿深度聚合就不会泄露未来信息。

一次深度 attention 怎样算

还是看单个 token，把它的 \(l\) 个历史来源摞成矩阵 \(V_l\in\mathbb R^{l\times d}\)。每个子层 \(l\) 配一个可学习的查询向量 \(q_l\in\mathbb R^d\)，同一层的全部 token 共用这个参数。把每个来源过一遍 RMSNorm 当 key，和 \(q_l\) 做点积打分，再沿来源深度做 softmax：

$$\begin{aligned} \htmlData{symbol=k}{k_{i,l}}&=\gamma_l\odot\frac{v_i}{\sqrt{\frac1d\sum_{r=1}^{d}v_{i,r}^{\,2}+\varepsilon}},\\ s_{i,l}&=\htmlData{symbol=q}{q_l}^{\mathsf T}k_{i,l},\\ \alpha_{i\to l}&=\frac{\exp(s_{i,l}-m_l)}{\sum_{j=0}^{l-1}\exp(s_{j,l}-m_l)},\qquad m_l=\max_j s_{j,l},\\ h_l&=\sum_i\alpha_{i\to l}v_i. \end{aligned}$$

其中 \(\gamma_l\in\mathbb R^d\) 是这层 RMSNorm 的缩放参数，\(\varepsilon\) 防除零，\(m_l\) 用于 softmax 的数值平移。注意打分直接写 \(q_l^{\mathsf T}k_{i,l}\)，没有额外的 \(1/\sqrt{d}\)——\(q_l\) 自己会学出合适的模长。这里有个刻意的不对称设计：只对 key 做 RMSNorm，value 用原始的 \(v_i\)。前者管「挑谁」，后者管「取回什么」。这样一来，就算某个来源的幅值很大，也不会单靠音量把打分压过去；可一旦被选中，它原本的幅值依然完整保留下来。

放回批量计算里，来源张量的形状是 \([S,B,T,d]\)（\(S\) 是当前来源数，\(B\) 是 batch 大小，\(T\) 是 token 数）。跟 \(q_l\) 点积得到 \([S,B,T]\) 的分数，沿着第 0 维做 softmax，再沿第 0 维加权求和，正好回到 \([B,T,d]\)。虽然整层共用一个参数向量 \(q_l\)，但不同 token 的历史表示不一样，算出来的 key 也各不相同，所以每个 token 分到的深度权重依然是动态、因输入而异的——\(q_l\) 决定这层想找什么，各 token 的 key 决定手里有什么。

如果把所有查询初始化为 0，起步时每个来源分到的权重都是 \(1/S\)，也就是直接取平均。注意这跟标准残差直接相加差了一个 \(1/S\) 的系数——从零训练没问题，但要是把训好的标准 Transformer 直接改成 AttnRes 继续训，起步输出会突然缩水，接不住原权重，得额外做过渡。

顺带一提，把 \(q_l\) 设成全 0 并不会让梯度卡死在 0。先把历史来源看成常数，对 \(q_l\) 求雅可比矩阵：

$$\frac{\partial h_l}{\partial q_l}=\sum_i\alpha_{i\to l}(v_i-h_l)k_{i,l}^{\mathsf T}\in\mathbb R^{d\times d}.$$

接上标量损失 \(\mathcal L\)，把上游梯度记作 \(g=\partial\mathcal L/\partial h_l\)，\(q_l\) 的梯度就是：

$$\frac{\partial\mathcal L}{\partial q_l}=\sum_i\alpha_{i\to l}\big[g^{\mathsf T}(v_i-h_l)\big]k_{i,l}.$$

只要各来源的 value 不全相同，偏差 \(v_i-h_l\) 就不为零，\(q_l\) 一开始就能拿到非零梯度：哪一路来源更能帮当前步降 loss，\(q_l\) 就立刻往它的 key 方向偏（文末的 lab.py 里可以直接拿有限差分验算这个式子）。

Block AttnRes 怎样管理历史

Full AttnRes 把选择权给到了每一层，账单也很直接：\(L\) 个子层一路留下来，每个 token 要存 \(O(Ld)\) 的历史表示，逐层聚合的计算量按 \(O(L^2d)\) 涨。这点算力跟子层内部的矩阵乘比起来不算大头，真正卡脖子的是显存和通信——历史得一路留着，activation checkpointing 没法随便丢，流水线并行还得跨卡往后传。

Block AttnRes 的解法很工程：把连续 \(K\) 个子层打包成一块，总共分成 \(N=\lceil L/K\rceil\) 块（最后一块可以不够 \(K\) 个）。块内恢复老办法，把原始分支输出直接相加，攒成这一块的汇总：

$$\htmlData{symbol=block}{b_n}=\sum_{j\in\mathcal B_n}F_j(h_j),\qquad b_0=e.$$

其中 \(\mathcal B_n\) 是第 \(n\) 块里的子层编号。正在跑的这一块另维护一个部分和 \(p\)，存着块里已经算完的分支输出。轮到块里第一个子层时，\(p\) 还是空的，它只读 embedding 和前面已经封口的块；从第二个子层起，当前的 \(p\) 也加入候选来源。每算完一个子层就把新输出加进 \(p\)，整块跑完就把 \(p\) 封成只读的 \(b_n\)，下一块再从空开始：

completed = [embedding]
partial = None
for l in range(L):
    sources = completed + ([] if partial is None else [partial])
    h = depth_attention(q[l], sources)
    v = F[l](h)
    partial = v if partial is None else partial + v
    if (l + 1) % K == 0 or l + 1 == L:
        completed.append(partial)
        partial = None
output = depth_attention(q_out, completed)

注意代码里用 None 而不是全零向量来占位。要是硬塞一个零向量进去，它虽然 value 是 0，却会多占一个 softmax 分母位置——比如前两个来源分数都是 0，多出一个零向量就会把两者的权重硬生生从 \(1/2\) 压成 \(1/3\)，平白把输出缩了一截。

分块的代价也很明确：选择粒度从「逐层」粗化成了「逐块」。如果同一块里有两个分支正好互相抵消，加完之后信息就没了，后面的层再也分不开它们。缩小 \(K\) 能保住更细的粒度，来源数也会跟着涨；两个极端一目了然——\(K=1\) 时每块就一层，完全回到 Full AttnRes；\(K=L\) 时整个网络只有一块，每一层就只在 embedding 和当前累计和之间学一个动态配比。

分块之后，聚合计算量降到 \(O(LNd)\)，要存的历史状态降到 \(O(Nd)\)。算一笔具体显存账：对一个形状为 \(B\times T\) 的 prefill chunk、每个元素占 \(u\) 字节，跑完全部块时，光来源库（embedding 加 \(N\) 个完成块）本身就要占：

$$\htmlData{symbol=memory}{M_{\mathrm{sources}}}=(N+1)\,B\,T\,d\,u.$$

代一组常见规模感受一下：\(L=96\) 个子层按 \(K=12\) 切成 8 块，取 \(B=1,\ T=8192,\ d=4096\)，BF16 下 \(u=2\)。单个来源是 64 MiB，9 个来源一共 576 MiB；要是换成 Full AttnRes，97 个来源直接飙到 6208 MiB（约 6.06 GiB），光历史缓存就差了十倍——而且这还没算分支激活和反向图。

让历史只读一次

照着上面的伪代码逐层硬写能跑通，但上 GPU 效率很差：每个子层都要把历史来源重新 stack 一遍、算 RMSNorm、算 softmax，冒出一堆零碎小 kernel 和临时张量。这些操作 FLOPs 极小，几乎全是显存带宽瓶颈——同一批完成块，一块里有 \(K\) 个子层，就得从 HBM 重复读 \(K\) 遍。

转机藏在 AttnRes 的一个结构特点里：查询向量 \(q_l\) 是静态的层参数，不依赖当前块的激活。刚走进一块时，前面所有完成块已经定死，本块 \(K\) 个子层的查询也全在手边。干脆把这 \(K\) 个查询拼成 \(Q\in\mathbb R^{K\times d}\)，一次性把所有完成块从显存读进来，批量算完这 \(K\) 层对已完成块的聚合结果；至于还没算出来的当前块部分和 \(p\)，等后面逐层算到时再补进去。这就是两阶段计算。

问题是，怎么把晚到的部分和无缝并进已经算完的 softmax？办法和 FlashAttention 一样——第一阶段先不急着除分母，对每个子层存下三个统计量：

$$m=\max_i s_i,\qquad z=\sum_i e^{s_i-m},\qquad u=\sum_i e^{s_i-m}v_i.$$

这里 \(m\) 是当前最大分数，\(z\) 是平移后的分母，\(u\in\mathbb R^d\) 是还没除分母的加权分子。等后面拿到当前部分和 \(p\in\mathbb R^d\)，只需单独算它在这层查询下的分数 \(a=q^{\mathsf T}\operatorname{RMSNorm}(p)\)，取新的共同最大值 \(m'=\max(m,a)\)，把旧统计量和新部分和一起对齐到 \(m'\)：

$$\begin{aligned}z'&=e^{m-m'}z+e^{a-m'},\\u'&=e^{m-m'}u+e^{a-m'}p,\\h&=u'/z'.\end{aligned}$$

因为新旧两边的指数基准都对齐到了 \(m'\)，算出来的 \(h\) 跟把所有来源凑齐一次做 softmax 在数学上完全等价。前面讲的「分块」改了模型结构，而这里的 online softmax 纯粹是执行顺序的等价改写，不改变模型函数。

第一阶段批量算出 \([K,B,T,d]\) 的中间结果，把重复读历史块的显存带宽摊薄了 \(K\) 倍。不过还有个小坎：每个子层都有自己的 RMSNorm 缩放参数 \(\gamma_l\)，难道每个子层还得各做一遍归一化？不用，把点积改写一下就行：

$$q_l^{\mathsf T}(\gamma_l\odot\widehat v)=(q_l\odot\gamma_l)^{\mathsf T}\widehat v.$$

把 \(\gamma_l\) 吸收到查询侧，所有子层就能共用同一份去掉增益的单位 RMS 向量 \(\widehat v\)，历史块真正只用归一化一次、读一次。当然，每个子层的 \(m,z,u\) 统计量还是得各自存着，毕竟查询不同、权重也不同。

第二阶段每层只合并一个部分和 \(p\)，访存极轻，正好和部分和更新、下一层的 normalization 融成同一个 kernel。精度上要留心两处：点积、平方和以及 softmax 的 \(m,z,u\) 统一用 FP32 累加，最后再转回计算精度；来源库虽然通常用 BF16 省显存，但如果一块里子层很多，BF16 只有 7 位尾数，连加下来容易把小增量吃掉，块内部分和的累加精度值得单独核一下。

梯度、重算与跨卡状态

放到训练里，一个历史来源会被后面很多子层反复读取，反向时它的梯度自然是所有读取路径之和。哪怕只看单次读取，传回 \(v_i\) 的梯度也有两条路：一是作为 value 的直达项 \(\alpha_i g\)，二是 \(v_i\) 经 RMSNorm 变成 key、反过来影响权重的那条路由项。Full AttnRes 里每个子层输出各走各的路；Block AttnRes 里，完成块 \(b_n=\sum_{j\in\mathcal B_n}v_j\) 收到的块级梯度会原样分发给块内每个 \(v_j\)，再加上各 \(v_j\) 在本块内被后续部分和读取时攒下的梯度。

这就引出一个写训练代码时极易踩的坑：历史 buffer 和部分和不能随便原地修改（in-place）。推理时复写旧 buffer 没问题，训练时只要后面还有子层引用过这个张量，原地改动就会把反向传播要用的版本冲掉。做完融合或省显存优化后，最稳妥的校验是固定随机种子，拿最朴素的 out-of-place 版本当对照，把 loss、查询梯度和每个来源的梯度全比一遍——光看前向输出对得上，很容易放过偷偷 detach 掉的计算图或写坏的缓存。

Activation checkpointing 的常规套路是前向丢激活、反向再重算，但 AttnRes 的历史状态有前向存活期：后面的层还在等着用它，前向没跑完根本丢不掉。因此能重算的主要是子层内部激活，以及聚合时的 scores、weights 等中间量；来源库本身（Full 是每层输出，Block 是各个完成块）必须常驻。如果改完重算发现显存峰值几乎没降，把显存拆开看一眼，大头多半就趴在长期存活的来源库上。

跨卡训练时，流水线并行（PP）的麻烦更直观：上一个 stage 传给下一个 stage 的不再只是一条残差流，还得把后面要读的历史块一并带过去。如果每次过边界都重传整份历史，越往深处通信量越爆炸。在交错流水线（interleaved PP）里，同一张物理卡会先后跑同一个 micro-batch 的多个虚拟 stage，所以可以把已经收到的旧块留在本地缓存，下次轮到这张卡时只补传新增的块就行。代价是用显存换带宽：缓存要按 micro-batch 和块号分别管住，等该 micro-batch 跑完反向、把对应的历史梯度合并完才能释放。

到了长 prefill，来源库还可以沿 token 轴切开。因为深度 attention 对每个 token 互相独立，\(P\) 张 TP 卡各管 \(T/P\) 个 token 就能各算各的深度聚合，配合层输出的 reduce-scatter 和进入子层前的 all-gather，单卡的来源库容量直接缩成 \((N+1)BTdu/P\)。前面那笔 576 MiB 的账，8 卡均分后每卡只剩 72 MiB（再给通信缓冲和两阶段中间统计量留出余量即可）；做 chunked prefill 时，也可以直接拿这个公式反推能塞下多长的 chunk。

回头看开头的对比，三种残差设计的工程账单就很清楚了：HC 和 mHC 的额外状态跟并行残差路数成正比，每一层都在横向混合；AttnRes 的状态则跟着历史块数 \(N\) 走，压力集中在长期存活的来源库、交错流水线缓存和两阶段 kernel 上。要不要分块、\(N\) 取多大，本质上是在更细的深度选择粒度和这笔系统开销之间做权衡。

顺着深度轴继续往下看，还有两个相邻问题：如果想知道这些跨层路径到底有多少在真正干活，可以结合有效深度实验去测删层和提前退出的代价；而共享深度模型则走另一条路——把同一组层参数反复展开成多轮计算，对应要单独追踪每一轮的隐藏状态与 KV。

实验与练习

下载配套的 NumPy 脚本，直接跑 python lab.py 就能在 CPU 上把文里的几件事全验一遍：用双精度有限差分核对查询梯度和来源梯度（含经由 RMSNorm 的路由项），比对分组 online softmax 与直接计算的误差，核查块边界和空部分和反例，顺带把一个全零初始化的二维查询训到能从三个来源里挑出目标，最后复算练习里的显存数字。

脚本里也顺手塞了几个边界自检：全零查询依然能正常学动；把所有来源设成相同向量时，查询梯度立刻归零；把 logits 整体加减 1000，稳定 softmax 和在线合并的结果纹丝不动。你也可以自己改改 block_size 或目标向量，看看权重和块边界怎么跟着变。

练习 1：从方向算到输出

三个二维来源为 \((1,0),(0,2),(-1,0)\)，RMSNorm 增益为 1，取 \(\varepsilon=0\)，查询为 \(q=(1,0)\)。求 keys、权重和输出。把第二个来源放大成 \((0,20)\)，哪些量会变？

展开解答

三个 keys 是 \((\sqrt2,0),(0,\sqrt2),(-\sqrt2,0)\)，分数为 \(\sqrt2,0,-\sqrt2\)。softmax 权重约为 \((0.7679,0.1867,0.0454)\)，输出约为 \((0.7225,0.3734)\)。把第二个来源放大 10 倍后，key 和权重纹丝不动，输出的第二维变成约 3.734，第一维仍是约 0.7225——归一化把打分尺度锁住了，取回的 value 依然保留原本的幅值。

练习 2：零查询有没有梯度？

只取 \(v_0=(1,0),v_1=(0,1)\)，令 \(q=0\)，增益为 1、\(\varepsilon=0\)。损失取输出的第一维 \(\mathcal L=h_1\)。求 \(\partial\mathcal L/\partial q\)，并判断一步梯度下降后查询会偏向哪一个来源。

展开解答

初始权重都是 \(1/2\)，所以 \(h=(1/2,1/2)\)，上游梯度 \(g=(1,0)\)。两个 value 在第一维上的偏差分别是 \(1/2\) 和 \(-1/2\)，keys 是 \((\sqrt2,0)\) 和 \((0,\sqrt2)\)，代入梯度公式得：

$$\frac{\partial\mathcal L}{\partial q}=\frac{\sqrt2}{4}(1,-1).$$

梯度下降往反方向走，让查询第一维变负、第二维变正，于是更偏向 \(v_1\)，把输出第一维压下去。要是把两个 values 都改成 \((1,0)\)，每一项 \(v_i-h\) 都是 0，查询梯度也就归零了。

练习 3：来源库能否装下？

96 个子层每 12 个一块，\(B=2,T=16384,d=4096\)，来源用 BF16 存。算上 embedding，最终来源库有多大？均匀分到 8 张卡后每卡多少？如果每卡只给来源库 128 MiB、batch 保持 2，均匀分片时 chunk 最长能取多少 token？

展开解答

一共 9 个来源，总字节数是 \(9\times2\times16384\times4096\times2\)，即 2304 MiB（2.25 GiB），8 卡均分后每卡 288 MiB。设 chunk 长为 \(T_c\)：

$$\frac{9\times2\times T_c\times4096\times2}{8}\le128\times2^{20},\qquad T_c\le7281.77\ldots$$

整数上界是 7281 token。工程上通常会选对齐友好的 7168 或 6144，顺便给工作区留余量；如果算子要求 chunk 被 8 整除，最大可取 7280。

练习 4：一次错误合并怎样改变结果？

已完成来源的分数为 \((0,1)\)，values 为 \((2,-1)\)，新部分和的分数为 2、value 为 3。算出正确合并结果；如果直接把「旧 attention 输出」和 3 取平均，会得到多少？再写一个能抓出这个 bug 的测试思路。

展开解答

旧最大值 \(m=1\)，分母 \(z=e^{-1}+1\)，分子 \(u=2e^{-1}-1\)。新最大值变成 2，对齐后得：

$$h=\frac{e^{-1}(2e^{-1}-1)+3}{e^{-1}(e^{-1}+1)+1}=\frac{2-e+3e^2}{1+e+e^2}\approx1.9311.$$

旧输出约为 −0.1932，直接跟 3 取平均会算出约 1.4034——这相当于硬把旧来源组和新部分和各分一半权重，完全丢了相对分数信息。写单测时，把分组在线合并和一次全量 softmax 对着比，覆盖不同切分方式、极端分数和整体平移 1000，训练代码再把对应的反向梯度也比一遍，这种错一测就露馅。
