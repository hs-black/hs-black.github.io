Attention Residuals：沿深度选择信息

交互2026-10-22

读到一个代词时，浅层可能已经提取出候选实体，中层在组织句法关系，深层要决定它指向谁。标准 Transformer 把每个子层的新结果累加到同一条残差流里；到了深层，早期的信息仍在累加结果中，但读取它需要从混合表示里重新提取。Attention Residuals（AttnRes）保留沿途的表示，让当前子层按内容选择：这次需要多少 embedding、多少早期结果、多少刚算出的特征？

这条路线与 Hyper-Connections、mHC 关注同一个问题——信息怎样穿过深度。HC 扩展同时运行的残差流，mHC 约束流之间的混合，AttnRes 选择历史深度上的来源。它们给出不同的状态组织方式，也带来不同的显存与通信需求。

把残差展开，看到深度轴

以一个 token 的表示为观察对象，宽度为 \(d\)。用 \(l\) 编号 attention 或 MLP 子层，一个常见 decoder block 包含两个这样的子层。把子层内部的 normalization 也包含在函数 \(F_l\) 里，标准 PreNorm 残差写成：

$$x_{l+1}=x_l+F_l(x_l),\qquad x_1=e.$$

这里 \(e\in\mathbb R^d\) 是 embedding。设子层 \(i\) 的新输出为 \(v_i=F_i(x_i)\)，再令 \(v_0=e\)，反复展开便得到 \(x_l=\sum_{i=0}^{l-1}v_i\)。每个来源到当前残差流的直接系数都是 1。网络当然可以在 \(F_i\) 中学会缩放或抵消；从这条直达路径看，聚合规则始终是加法。

当来源近似不相关、方差相近时，累加的方差随来源数增长，RMS 约按来源数的平方根增长。后续 RMSNorm 再把整个向量缩回固定尺度，一个新子层的增量在总和中的相对份额就会变小。真实模型的相关性和尺度会改变这个增长规律；诊断时可以逐层记录残差 RMS、分支输出 RMS，以及两者的比值。深层分支相对份额持续下降，是值得检查的信号。

Full AttnRes 把输入改成历史输出的加权和。对子层 \(l\)，共有 \(l\) 个来源：embedding 和前面 \(l-1\) 个子层的输出。

$$\htmlData{symbol=h}{h_l}=\sum_{i=0}^{l-1}\htmlData{symbol=alpha}{\alpha_{i\to l}}\,\htmlData{symbol=v}{v_i},\qquad v_l=F_l(h_l),\qquad \sum_{i=0}^{l-1}\alpha_{i\to l}=1.$$

各来源保存独立表示；当前子层先选择，再计算自己的新输出。最后的输出聚合也可以用一个查询读取全部来源。沿深度重读同一 token 的表示保持了已有的因果关系：只要每个 \(F_l\) 的序列 attention 遵守 causal mask，聚合已有表示就继续遵守它。

一次深度 attention 怎样算

选取一个 batch、一个 token，历史来源排成 \(V_l\in\mathbb R^{l\times d}\)。子层 \(l\) 有自己的可学习查询 \(q_l\in\mathbb R^d\)，同一子层的所有 token 共享这个参数。对每个来源做 RMSNorm 得到 key，点积形成分数，softmax 的归一化轴是来源深度：

$$\begin{aligned} \htmlData{symbol=k}{k_{i,l}}&=\gamma_l\odot\frac{v_i}{\sqrt{\frac1d\sum_{r=1}^{d}v_{i,r}^{\,2}+\varepsilon}},\\ s_{i,l}&=\htmlData{symbol=q}{q_l}^{\mathsf T}k_{i,l},\\ \alpha_{i\to l}&=\frac{\exp(s_{i,l}-m_l)}{\sum_{j=0}^{l-1}\exp(s_{j,l}-m_l)},\qquad m_l=\max_j s_{j,l},\\ h_l&=\sum_i\alpha_{i\to l}v_i. \end{aligned}$$

\(\gamma_l\in\mathbb R^d\) 是这一聚合器的 RMSNorm 增益，\(\varepsilon\) 是小正数；\(m_l\) 是数值稳定用的最大分数。这里采用原始 AttnRes 的打分形式 \(q_l^{\mathsf T}k_{i,l}\)，查询自身学习合适尺度。keys 经过归一化，values 使用原来的 \(v_i\)：前者决定选谁，后者决定取回什么。放大一个来源时，它的归一化方向近似保持，而被取回的数值仍随之放大。

扩展到批量计算，来源张量是 \([S,B,T,d]\)，其中 \(S\) 是当前来源数，\(B\) 是 batch 大小，\(T\) 是本次处理的 token 数。点积产生 \([S,B,T]\) 分数，对轴 0 做 softmax，最后沿轴 0 加权求和得到 \([B,T,d]\)。因此，同一个 \(q_l\) 遇到不同 token 的 keys，会产生不同权重。可以把查询理解为这一子层长期学习的“需求方向”，把每个 token 的 key 理解为本次输入携带的内容。

把全部查询初始化为 0，会得到均匀权重 \(1/S\)，模型从来源的平均值开始训练。这改变了初始聚合尺度：三个来源得到的是三分之一的和。若把已有残差模型直接换成 AttnRes，需要把这种函数变化纳入转换与继续训练的评估。

零初始化仍然能学习。暂时把来源当作固定输入，对查询求导：

$$\frac{\partial h_l}{\partial q_l}=\sum_i\alpha_{i\to l}(v_i-h_l)k_{i,l}^{\mathsf T}\in\mathbb R^{d\times d}.$$

右侧是 value 偏差与 key 的加权关联。只要不同来源提供不同内容，查询就可能得到非零梯度。对标量损失 \(\mathcal L\)，设上游梯度 \(g=\partial\mathcal L/\partial h_l\)，则 \(\partial\mathcal L/\partial q_l=\sum_i\alpha_{i\to l}[g^{\mathsf T}(v_i-h_l)]k_{i,l}\)。这给出了一个可直接做有限差分检查的公式。

Block AttnRes 怎样管理历史

Full AttnRes 给每个子层输出独立的选择权。代价是历史必须一直可读：对于 \(L\) 个子层，每个 token 的来源存储量按 \(Ld\) 增长，直接逐层聚合的运算量按 \(L^2d\) 增长。层函数内部通常更昂贵，但保留历史会改变重算和流水线通信的设计。

Block AttnRes 把连续 \(K\) 个子层划为一块，共 \(N=\lceil L/K\rceil\) 块，末块可以较短。第 \(n\) 块保存原始分支输出的和：

$$\htmlData{symbol=block}{b_n}=\sum_{j\in\mathcal B_n}F_j(h_j),\qquad b_0=e.$$

\(\mathcal B_n\) 表示第 \(n\) 块中的子层索引。正在计算的块还有一个部分和 \(p\)：它只包含这块已经完成的分支输出。块内第一个子层读取 embedding 与之前完成的块；之后的子层再把当前 \(p\) 当作一个来源。每算完一个子层，就把新输出加进 \(p\)；块结束时，将它转成不可变的 \(b_n\)，下一块从空的部分和开始。

completed = [embedding]
partial = None
for l in range(L):
    sources = completed + ([] if partial is None else [partial])
    h = depth_attention(q[l], sources)
    v = F[l](h)
    partial = v if partial is None else partial + v
    if (l + 1) % K == 0 or l + 1 == L:
        completed.append(partial)
        partial = None
output = depth_attention(q_out, completed)

这里的 None 表示当前块还没有输出。若把它换成一个额外的零向量，零向量也会参与 softmax 分母；例如两个来源的分数均为 0 时，加入第三个零来源就会把已有内容各自的系数从 \(1/2\) 改为 \(1/3\)。块边界的表示与来源数量，都是模型函数的一部分。

分块把选择粒度从“每个子层”变成“每个完成块”。块中两个分支若正好互相抵消，它们的和已经丢掉了区分两者的能力；后续 attention 只能选择这个和。缩小块可以保留更细的信息，同时增加来源数。\(K=1\) 时，每个块只含一个输出，便恢复 Full 的来源集合。\(K=L\) 时，整个网络只形成一块，块内持续在 embedding 与当前部分和之间学习归一化权重。

对于固定深度 \(L\)，直接实现需要约 \(O(LNd)\) 聚合运算；保存的历史按 \(O(Nd)\) 增长。假设一个 prefill chunk 有 \(B\) 条、每条 \(T\) 个 token，每个元素占 \(u\) 字节，最终来源库包含 embedding 和全部块，则：

$$\htmlData{symbol=memory}{M_{\mathrm{sources}}}=(N+1)\,B\,T\,d\,u.$$

这个计数只统计来源库；实际峰值还包括当前分支、聚合工作区以及训练的反向激活。例如 \(L=96\)、\(K=12\) 得到 8 块；\(B=1,T=8192,d=4096\)，BF16 的 \(u=2\)。每个来源是 64 MiB，9 个来源为 576 MiB。Full 的 97 个来源则是 6208 MiB，约 6.06 GiB。块数减少带来的容量差异在长 prefill 中尤其明显。

让历史只读一次

逐层调用上面的伪代码很直接，但每层都重新 stack 来源、RMSNorm、计算 softmax，会生成多个小 kernel 和中间张量。模型变慢时，先用 profiler 观察这些 kernel 的时间、来源库读取字节量和分配次数，再决定融合范围。算子 FLOPs 小而时间随 token 数和块数明显增长，通常意味着数据搬运值得优先检查。

AttnRes 的查询是层参数，这个设计给了调度机会。进入一块时，之前的块都已经完成，这一块中 \(K\) 个子层的查询也全部已知。可以把它们排成 \(Q\in\mathbb R^{K\times d}\)，一次读取来源，算好各查询对完成块的结果。当前块的部分和依赖前一个子层，随后逐层补入。这就是两阶段计算。

怎样把后来产生的部分和补进一次已经算过的 softmax？对某个子层的已完成来源，保存三个统计量：

$$m=\max_i s_i,\qquad z=\sum_i e^{s_i-m},\qquad u=\sum_i e^{s_i-m}v_i.$$

这里 \(m,z\) 是标量，\(u\in\mathbb R^d\) 是尚未除以分母的加权和。新部分和为 \(p\in\mathbb R^d\)，它在同一查询下的分数为 \(a=q^{\mathsf T}\operatorname{RMSNorm}(p)\)。令 \(m'=\max(m,a)\)，把两组权重移到共同尺度：

$$\begin{aligned}z'&=e^{m-m'}z+e^{a-m'},\\u'&=e^{m-m'}u+e^{a-m'}p,\\h&=u'/z'.\end{aligned}$$

新旧两部分乘回相同的指数基准，所得结果与一次对所有来源做 softmax 相同。这个 online softmax 合并保留了模型函数；分块本身则改变了可选择的信息粒度。两种操作分别作用于执行顺序和网络结构。

对于 \([K,B,T,d]\) 这一组查询结果，两阶段实现用批量操作摊薄重复读取。每个子层仍需要自己的统计量：查询不同，权重就不同。训练后 RMSNorm 的增益也可能因子层而异，可以利用 \(q_l^{\mathsf T}(\gamma_l\odot\widehat v)=(q_l\odot\gamma_l)^{\mathsf T}\widehat v\)，把增益吸收到查询，复用来源的单位 RMS 表示。

第二阶段只处理一个部分和及对应统计量，适合与部分和更新、后续 normalization 融合。实现时让点积、平方和与 softmax 统计量使用 FP32 累加，再按计算精度写回输出。BF16 能减小来源库，但长加法链仍可能吞掉较小增量；可用同一批输入比较 FP32 和 BF16 部分和的误差，并记录每层的权重熵与最大分数。精度策略要覆盖 keys 的归一化与 raw values 的累加。

梯度、重算与跨卡状态

同一个历史来源会被很多后续子层读取，它的梯度要累加所有读取路径的贡献。单次读取就有两部分：\(v_i\) 作为 value 的直达梯度 \(\alpha_i g\)，以及它经过 RMSNorm 改变 key、进而改变权重的梯度。Full 的每个子层输出拥有独立路径；Block 内，\(b_n=\sum_{j\in\mathcal B_n}v_j\) 的块级梯度通过加法传给每个 \(v_j\)，每个输出还可能收到本块后续部分和读取产生的梯度。

因此训练代码中的历史 buffer 必须保持 autograd 关系。推理可以复用已不再读取的工作区；训练时原地修改一个仍被后续计算引用的部分和，会改变反向传播需要的值。一个小而有用的检查是：固定随机种子，让简单 out-of-place 版本与优化实现分别计算损失、查询梯度和各来源梯度，再逐项比较。只比最终输出会漏掉错误的 detach 或缓存复用。

Activation checkpointing 通常通过丢弃中间值、反向时重算来节省显存。AttnRes 的历史有额外的前向存活期：后续层仍要读它。Full 保存每个来源，Block 保存块汇总；聚合的 scores、weights 和局部中间值可以重算。若一次优化只减少了 softmax 中间张量，而峰值几乎不变，可以把显存分解成来源库、层内激活和工作区，检查主要部分是否正是长期存活的来源。重算的粒度必须尊重这三种对象的用途。

流水线并行中，下一 stage 除了当前部分和，还要拥有可读取的旧块。若每次都发送整个历史，越深的边界传得越多。交错流水线会让同一物理 rank 再次处理同一个 micro-batch 的后续虚拟 stage；把已经收到的块缓存在这个 rank 上，后面就只发送新增块。缓存键要区分 micro-batch 和块编号，反向完成后再释放该 micro-batch 的状态，反向也要合并对应的梯度贡献。这里节省的是重复传输，代价是延长本地缓存的存活期。

长 prefill 还可以沿 token 轴分片来源库。深度 attention 对每个 token 独立，\(P\) 张 TP 卡各持有 \(T/P\) 个 token，就能独立计算自己的深度聚合。结合层输出的 reduce-scatter、局部聚合和 all-gather，来源存储按每卡 \((N+1)BTdu/P\) 缩小。前面的 576 MiB 算例在 8 卡均匀分片下是每卡 72 MiB；还需单独核算通信缓冲和两阶段中间结果。选择 chunked prefill 时，同一个公式也能估计 chunk 长度对额外显存的影响。

比较这些残差设计时，质量与系统预算要放在一起。HC/mHC 的核心状态按多路残差宽度增长，AttnRes 按历史来源数增长；它们对 kernel 融合、重算和流水线的压力各不相同。训练实验可以同时记录验证 loss、逐层 RMS、梯度范数、聚合权重的熵、step 时间及显存峰值。改变块数时保持参数量、训练 token 数和数据顺序可比，再报告真实墙钟成本，才能判断信息选择带来的收益是否值得其状态开销。

深度权重描述了模型在当前位置怎样读取历史。要判断这些路径对任务的贡献，还可以做有效深度实验：同时记录表示变化和删层后的损失，再检查提前退出的质量与时延。共享深度模型则把同一组参数展开成多轮计算，需要为各轮分别追踪隐藏状态和 KV。

实验与练习

下载 NumPy 实验，运行 python lab.py。实验用双精度验证查询梯度，比较 online softmax 与直接计算，追踪块边界，并优化一个二维查询，让它从三个来源中选择目标信息。最后输出固定配置的来源库容量。训练对象是这个小型聚合器，输出可用于检查公式与状态语义。

把实验里的查询初值改为零，可以观察查询仍然移动；把来源设置成三个完全相同的向量，查询梯度则变为零。再把 logits 整体增加 1000，稳定 softmax 与在线合并结果应保持一致。这些修改分别检验可学习性、不可区分来源和数值平移不变性。

练习 1：从方向算到输出

三个二维来源为 \((1,0),(0,2),(-1,0)\)，RMSNorm 增益为 1，取 \(\varepsilon=0\)，查询为 \(q=(1,0)\)。求 keys、权重和输出。把第二个来源变为 \((0,20)\)，哪些量改变？

展开解答

三个 keys 是 \((\sqrt2,0),(0,\sqrt2),(-\sqrt2,0)\)，分数为 \(\sqrt2,0,-\sqrt2\)。归一化后权重约为 \((0.7679,0.1867,0.0454)\)，输出约为 \((0.7225,0.3734)\)。放大第二个来源后 key 和权重保持相同，输出第二维变成约 3.734；第一维保持约 0.7225。归一化控制打分尺度，value 保留内容幅度。

练习 2：零查询有没有梯度？

只取 \(v_0=(1,0),v_1=(0,1)\)，令 \(q=0\)，增益为 1、\(\varepsilon=0\)。损失为输出的第一维 \(\mathcal L=h_1\)。求 \(\partial\mathcal L/\partial q\)，并写出梯度下降后查询偏向哪一个来源。

展开解答

初始权重均为 \(1/2\)，\(h=(1/2,1/2)\)，上游梯度为 \(g=(1,0)\)。两个 value 的第一维偏差分别为 \(1/2,-1/2\)，keys 为 \((\sqrt2,0),(0,\sqrt2)\)。

$$\frac{\partial\mathcal L}{\partial q}=\frac{\sqrt2}{4}(1,-1).$$

梯度下降使查询第一维变负、第二维变正，更多选择 \(v_1\)，从而减小输出第一维。把两个 values 都改为 \((1,0)\) 时，每项 \(v_i-h\) 为零，查询梯度也为零。

练习 3：来源库能否装下？

96 个子层每 12 个一块，\(B=2,T=16384,d=4096\)，来源采用 BF16。包含 embedding 的最终来源库多大？均匀分到 8 张卡后每卡多少？若每卡只给来源库 128 MiB，batch 保持 2，每卡均匀分片时 chunk 最长多少 token？

展开解答

共有 9 个来源，字节数为 \(9\times2\times16384\times4096\times2\)，得到 2304 MiB，即 2.25 GiB。8 卡均分后为每卡 288 MiB。设 chunk 长为 \(T_c\)：

$$\frac{9\times2\times T_c\times4096\times2}{8}\le128\times2^{20},\qquad T_c\le7281.77\ldots$$

整数上界为 7281 token，实际可以选对齐友好的 7168 或 6144，再给工作区留出预算。若另有算子要求 chunk 被 8 整除，则这个约束下最大可取 7280。

练习 4：一次错误合并怎样改变结果？

已完成来源的分数为 \((0,1)\)，values 为 \((2,-1)\)，新部分和的分数为 2、value 为 3。计算正确合并结果。工程师直接平均“旧 attention 输出”和 3，会得到什么？设计一个能发现该错误的测试。

展开解答

旧最大值 \(m=1\)，分母 \(z=e^{-1}+1\)，分子 \(u=2e^{-1}-1\)。新最大值为 2，所以：

$$h=\frac{e^{-1}(2e^{-1}-1)+3}{e^{-1}(e^{-1}+1)+1}=\frac{2-e+3e^2}{1+e+e^2}\approx1.9311.$$

旧输出约为 −0.1932，直接与 3 平均得到约 1.4034；这相当于强行把旧来源组和新来源各分一半权重。测试时应比较完整 softmax 与分组后合并，覆盖不同分组、极端分数以及整体平移 1000 的情况，并在训练实现中比较对应梯度。
