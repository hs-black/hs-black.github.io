从 token 到概念：句向量生成与动态分段

交互2026-10-22

“明天上午十点，林医生会带三位同事来开会。”标准语言模型只能把这句话拆成一个个 token 往外蹦。要跳出逐 token 生成，常见有两条路：要么彻底换掉预测单位，先生成整句话的语义向量，再把向量展开成文字；要么外部仍旧逐 token 输入输出，只在内部把相邻 token 压成几个短片段，让最贵的 Transformer 主干在短序列上算。

Meta 的 Large Concept Model（LCM）走的是第一条路：用 SONAR 把每句话编成向量，在句向量序列上预测下一句。Dynamic Large Concept Model（DLCM）走的是第二条路：把 token 隐藏状态动态聚成变长片段，送进更宽的主干，最后再还原回 token 预测。两者说的「概念」落到代码里都很实在——前者是一个可解码的句向量，后者是一段 token 表示的汇总。要看清这两套设计的得失，不妨从一个最朴素的问题开始：如果下一句话有两种截然不同、但都说得通的走向，直接预测它们的平均向量会怎样？

1. 一句话怎样成为一个预测单位

先把整篇文档切成句子 \(s_1,\ldots,s_N\)，过一遍冻结的 SONAR encoder，每句话就变成一个 1024 维向量：

$$\htmlData{symbol=embedding}{z_i}=E(s_i)\in\mathbb R^{1024},\qquad p_\theta(z_{i+1}\mid z_1,\ldots,z_i).$$

LCM 的主干就在这条句向量序列上做自回归。等它吐出下一句向量 \(\hat z_{i+1}\) 后，再交给 SONAR decoder，按指定的目标语言 \(\ell\) 逐 token 展开成文字：

$$p_D(s\mid\hat z,\ell)=\prod_{t=1}^{|s|}p_D(w_t\mid w_{\lt t},\hat z,\ell).$$

整套生成于是嵌套了两层自回归：外层一句一句预测向量，内层把每个向量展开成词序列。语种覆盖完全由 SONAR 编解码器兜底，主干模型本身并不关心输入输出是中文还是英文，眼里只有 1024 维向量。

训练主干时，SONAR 的表示空间保持冻结。原始句向量各维度的数值尺度不均匀，直接喂给 Transformer 并不好训，所以进主干前要先逐维做一次稳健归一化（robust normalization），再线性投影到隐藏宽度；出来后再逆变换回 SONAR 空间：

$$u_{i,j}=\frac{z_{i,j}-\mu_j}{s_j},\qquad z_{i,j}=s_j u_{i,j}+\mu_j.$$

这里的中心 \(\mu_j\) 取中位数，尺度 \(s_j\) 按分位数估计（官方默认的 gaussian_robust 还会按高斯分布做一次校准）。这套统计量在混合训练语料上抽样算完就固定存盘，训练和推理加载同一份 normalizer，保证进出主干的坐标系严丝合缝。

这样一来，分句、多语种适配和文字展开全被外包给了句子编解码器。为了避免每个 epoch 都重跑 SONAR，官方流水线会先用 SaT 分句，再把句向量预编码落盘。代价是存储账单立马上来：一亿个 1024 维 BF16 向量，光裸数据就有 204.8 GB；而且分句切法、SONAR 权重和 normalizer 统计量是绑死的，换掉其中任何一个，预编码的数据就得重算。

2. 预测均值与生成分布

最直觉的做法（Base-LCM）是拿均方误差直接回归下一句向量：给定前文 \(c=(z_1,\ldots,z_i)\)，让模型输出 \(a=f_\theta(c)\)，最小化 \(\mathbb E[\|Z-a\|_2^2\mid c]\)。把下一句向量的条件均值记作 \(\mu=\mathbb E[Z\mid c]\)，把平方项按 \(\mu\) 拆开：

$$\mathbb E[\|Z-a\|_2^2\mid c]=\mathbb E[\|Z-\mu\|_2^2\mid c]+\|a-\mu\|_2^2.$$

前一项只由真实数据分布决定，模型动不了；后一项在 \(a=\mu\) 时取到零。也就是说，理想的 MSE 回归器只会输出条件均值。问题在于，如果前文后面既可能接「同意方案」，也可能接「拒绝方案」，两类续写在向量空间里各占一团，MSE 会把预测拉向两团之间的重心——那里往往既不像同意，也不像拒绝，送进 decoder 很容易吐出模棱两可的废话，甚至解码跑偏。

拿一个一维玩具分布就能算明白：假设下一句向量只取 \(-2\) 或 \(+2\)，取 \(+2\) 的概率是 \(\pi\)。此时条件均值是 \(4\pi-2\)，最小 MSE 是 \(16\pi(1-\pi)\)。当 \(\pi=1/2\) 时，老老实实猜一个真实答案 \(+2\)，MSE 高达 8；改猜根本不可能出现的中间值 0，MSE 反倒砍半降到 4。平方误差天然偏爱「和稀泥」的中间位置，哪怕真实样本全在两端。

要摆脱均值坍缩，就得学完整的条件分布，这正是 Diffusion LCM 的思路。训练时先给真实下一句向量 \(z\) 加噪，构造 \(y_\tau=\alpha_\tau z+\sigma_\tau\varepsilon\)（其中 \(\varepsilon\sim\mathcal N(0,I)\)，方差保持设定下满足 \(\alpha_\tau^2+\sigma_\tau^2=1\)），再让 denoiser 根据前文 \(c\)、带噪向量 \(y_\tau\) 和噪声步 \(\tau\) 去预测干净向量：

$$\mathcal L=\mathbb E\!\left[w(\tau)\left\|z-g_\theta(y_\tau,\tau,c)\right\|_2^2\right].$$

表面上看这还是平方误差，但条件多了一个带噪观测 \(y_\tau\)，最优解也从 \(\mathbb E[Z\mid c]\) 变成了 \(\mathbb E[Z\mid y_\tau,\tau,c]\)。只要 \(y_\tau\) 稍微偏正或偏负，后验就会迅速倒向某一端。回到刚才的一维例子，取 \(\alpha=\sigma=\sqrt{0.5}\) 时，由贝叶斯公式就能算出正端点的后验概率：

$$P(Z=2\mid y,c)=\operatorname{sigmoid}\!\left(\log\frac\pi{1-\pi}+\frac{4\alpha y}{\sigma^2}\right).$$

随着噪声一步步退去，带噪状态会自然分化进某一个具体的续写分支，不再卡在中间。推理时从随机高斯噪声出发，按采样器多步迭代去噪；初始噪声和采样随机性顺带保住了生成的多样性。

落到具体架构，还有两个常见变体。Two-Tower LCM 把编码前文的 contextualizer 和去噪的 denoiser 拆成两座塔：前文只跑一次因果编码，denoiser 在多步去噪里反复 cross-attend 这份缓存好的上下文，省掉大量重复计算。另一条路是用残差向量量化（RVQ）把连续句向量拆成一串离散码本索引，像传统语言模型一样逐个采样再把码向量加回来——它换回了熟悉的离散交叉熵和温度采样，代价是多出量化误差，而且每句话都要串行跑好几步码本预测。

3. 句向量的误差，怎样落到数字和实体上

把「三位同事」解成「四位同事」，在语义空间里几乎没差多远，但任务已经失败了。LCM 论文里的 SONAR 脆弱性（fragility）分析点破了这个痛点：向量空间里一点不起眼的扰动，落在解码文本上就可能把数字、专名、ID、超链接或技术术语翻车。欧氏距离只能告诉你向量偏了多远，关键信息有没有丢，必须解码回文字才能见真章。

真要排查失真出在哪一环，最直接的办法是拆成三层对照：

  1. 直接编解码：把原句送进 SONAR 再解出来，先摸清 1024 维瓶颈本身的无损上限；
  2. 加噪解码：在归一化向量上叠不同强度的随机噪声，逆归一化后再解码，测出 decoder 对扰动的容忍度；
  3. 真实生成解码：换成 LCM 实际预测出来的向量，看模型自身的偏移到底坏在哪。

每一层都按句长和内容类型分桶，把向量距离、语义相似度以及人名、数值、单位的 exact match 并排看，就能把误差准确归因到分句、压缩瓶颈、主干偏移还是解码敏感度上。为了堵住最后一环，LCM 论文还专门拿加噪后的句向量微调了 SONAR decoder，拉高它面对不完美输入时的恢复能力。

为什么极小的向量误差也能把数字翻掉？看一个极简的线性边界就明白了。假设 decoder 靠打分 \(a^{\mathsf T}z+b\) 的正负在两个数字表述间二选一。当句向量发生扰动 \(\Delta z\)，打分变化是 \(a^{\mathsf T}\Delta z\)，幅度最大可达 \(\|a\|_2\|\Delta z\|_2\)。只要原句离决策边界的余量（margin）本来就窄，哪怕 \(\|\Delta z\|_2\) 很小，只要刚好撞在敏感方向 \(a\) 上，输出就会直接翻面。所以决定解码稳不稳的，不只是误差有多大，更在于它沿敏感方向偏了多少。

4. 从固定句子到动态片段

按自然句子硬切有个显而易见的短板：一句「好的。」和一条塞满符号的长公式，在 LCM 里占的都是同一个 1024 维槽位。DLCM 的想法是让压缩粒度随内容动态伸缩，同时把输出层留给熟悉的 token 级交叉熵。

具体做法分三步。首先，因果 token encoder 逐位置算出隐藏状态 \(h_t=E(x_{\le t})\in\mathbb R^{d_{\rm tok}}\)，再把相邻位置各自投影成 \(q_{t-1}=W_qh_{t-1}\) 和 \(k_t=W_kh_t\)，用方向差异打出一个边界分数：

$$\htmlData{symbol=boundary}{p_t}=\frac{1-\cos(q_{t-1},k_t)}2,\qquad p_1=1.$$

相邻两个 token 方向一致时分数趋近 0，方向相反时趋近 1。推理时直接卡阈值 \(b_t=\mathbf1[p_t\ge0.5]\)，\(b_t=1\) 就表示从位置 \(t\) 另起一段；训练时则可以对分数加温度后再采样边界。因为硬切分本身不可微，DLCM 把离散分段决策和语言建模损失解耦：encoder 表示照常沿着后续池化路径反传梯度，硬边界则按规则切出，整体切分频率交给专门的辅助损失来控。

接着，对第 \(k\) 段包含的所有位置 \(S_k\) 做均值池化，再升维投影到概念主干的宽度 \(d_{\rm con}\)：

$$\htmlData{symbol=concept}{c_k}=W_{\rm up}\frac1{|S_k|}\sum_{t\in S_k}h_t,\qquad W_{\rm up}\in\mathbb R^{d_{\rm con}\times d_{\rm tok}}.$$

真正的重活交给更宽的因果概念主干，只在短得多的序列 \(c_1,\ldots,c_M\) 上算；最后 token decoder 用自己的状态当 query，去 cross-attend 概念侧的 key/value，再预测下一个 token。换句话说，压缩只发生在内部计算流里，对外依然是标准的逐 token 语言模型。

如果一段文本有 \(T\) 个 token、切出了 \(M\) 段，实际压缩比就是 \(\htmlData{symbol=effective-ratio}{R_{\rm eff}}=T/M\)。为了防止模型偷懒把所有词全切开或者全并成一段，DLCM 在大 batch 上约束平均压缩比——让代码、公式切得细，普通叙述拉得长。记 batch 里的平均边界概率为 \(G\)、实际切出的边界比例为 \(F\)、目标压缩比为 \(\htmlData{symbol=target-ratio}{R_*}\)（对应目标边界率 \(1/R_*\)），辅助损失写成：

$$\mathcal L_{\rm aux}=\frac{R_*}{R_*-1}\bigl[(R_*-1)FG+(1-F)(1-G)\bigr]-1,\qquad R_*\gt1.$$

求导时把离散统计量 \(F\) 当常量看，对平均概率 \(G\) 的梯度非常干净：

$$\frac{\partial\mathcal L_{\rm aux}}{\partial G}=\frac{R_*}{R_*-1}(R_*F-1).$$

只要实际切得太碎（\(F \gt 1/R_*\)），梯度为正，梯度下降就把边界概率往低压；切得太粗（\(F \lt 1/R_*\)），梯度反号，把边界概率往上推。全局统计量负责卡住总预算，具体哪段长、哪段短，则全交给局部边界分数按内容难度自己分配。

5. 压缩后的信息，什么时候可以读取

均值池化把一整段 token 揉进了一个向量，因果性就立刻变得微妙起来——你必须给每个概念标清最早可用时间。假设第一段包含位置 1、2、3，除了必须等读完位置 3 才能算出均值，还有一个更容易漏掉的条件：如果这段的结束是由位置 4 触发的新边界确认的，那在读到位置 3 时，模型其实还不知道这一段已经收尾，必须等到位置 4 真正出现，才能宣布旧段闭合。追踪因果性，要同时盯紧两件事：向量里混进了哪些 token，以及「段结束了」这个决策何时可知。

为了把这个规则落成可执行的 mask，这里采用一条直观的流式约定：只有新边界出现时才闭合上一段，decoder 只读已闭合的段；最后一段由文档结束标记闭合。记第 \(k\) 段的可用时间为 \(a_k\)，读到位置 \(t\)、准备预测 \(x_{t+1}\) 时，cross-attention 的可见性 mask 就是：

$$M_{t,k}=\begin{cases}0,&a_k\le t,\\-\infty,&a_k\gt t.\end{cases}$$

至于还没闭合的当前段，信息并不会断流：decoder 自己本来就留着一条因果 token 路径，当前段里已经读过的 token 直接沿着这条路径影响预测。如果主干还做了相邻概念的平滑（smoothing），平滑后的可用时间就必须取所有被混合概念里最晚的那个，否则照样会把未来信息漏进来。

训练时整条序列一次喂进去，离线池化一不小心就会把整段均值提前露给段内靠前的 token。要查整套实现到底有没有偷看未来，最狠也最省事的回归测试是做未来扰动不变性检查：固定前缀 \(x_{\le t}\)，把后面的未来 token 全部换成随机数，看位置 \(t\) 输出的 logits 变不变。这个黑盒测试一口气穿过 encoder、边界判定、池化、平滑、cross-attention 和缓存，专治那种单看三角 mask 觉得天衣无缝、一跑起来却悄悄泄漏的 bug。

6. 复制 KV 怎样改变 softmax

落到 GPU 上，DLCM 会撞上一个很实际的硬件问题：decoder 里的 token query 长度是 \(T\)，概念侧的 K/V 长度却是 \(M\)，而且每个 token 能看到的概念范围还跟着动态段长变。不规则的交叉注意力不好喂给高效 attention kernel，一个省事的做法是用 repeat_interleave 把每个概念的 K/V 按段长复制展开，凑回长度 \(T\)，重新变成规则布局。可这么一复制，softmax 的权重其实已经悄悄变了。

固定一个 query 来算最清楚。假设它能看到两个概念，缩放后的打分是 \(s_1, s_2\)，value 是 \(v_1, v_2\)。每个概念只出现一次时，权重就是标准的 \(e^{s_j}/\sum_k e^{s_k}\)。但如果概念 \(j\) 在展开后有 \(m_j\) 个可见且完全相同的副本，把这些副本的权重加起来，概念 \(j\) 实际拿到的总权重会变成：

$$\tilde A_j=\frac{\htmlData{symbol=multiplicity}{m_j}e^{s_j}}{\sum_km_ke^{s_k}}=\operatorname{softmax}_j(s_j+\log m_j).$$

副本数直接变成了一个 \(+\log m_j\) 的加性偏置——段越长、副本越多的概念，在 softmax 里天然占便宜。如果原本想算的是「每个概念占一条」的注意力，就得给每个副本的打分减去 \(\log m_j\)，把多出来的权重抵消掉。这里有两个细节容易踩坑：第一，\(m_j\) 必须是当前 query 实际可见的副本数，而不是原始段长——一旦因果 mask 切掉了一部分副本，不同 query 对应的 \(m_j\) 会不一样；第二，同一概念的所有副本必须拿到完全相同的打分，如果位置编码或 bias 按展开后的 token 位置来加，这个等式就不成立了。

说到底，按「唯一概念」归一化还是按「展开位置」归一化，本质上是两个不同的算子，最怕的是当成等价优化写进去、不知不觉改了数学定义。DLCM 原文同时讨论了概念复制和 FlashAttention VarLen 两条实现路径；不管走哪条，验收时拿不同段长、不同 query 位置和截断 mask 跑一遍前向输出与反向梯度对拍，就能立刻看出权重有没有算歪。

7. 把编码、主干和解码一起计费

序列缩短之后，主干里两类计算下降的速度并不一样。设原序列长为 \(T\)，实际压缩比为 \(R_{\rm eff}=T/M\)，概念数约为 \(T/R_{\rm eff}\)，概念主干宽度为 \(d_{\rm con}\)。在层数和宽度不变的前提下，稠密投影与 MLP 的算术量只随长度线性降到 \(O(Td_{\rm con}^2/R_{\rm eff})\)，而概念 self-attention 的 \(QK^{\mathsf T}\) 与 \(AV\) 则按平方掉到 \(O(T^2d_{\rm con}/R_{\rm eff}^2)\)。正因主干序列变短了，模型才腾得出预算去拉宽 \(d_{\rm con}\)，把省下来的算力换成容量。

但账不能只算主干——完整的 DLCM 计算账本是三段加总：

$$C_{\rm DLCM}=C_{\rm enc}(T)+C_{\rm backbone}(T/R_{\rm eff})+C_{\rm dec}(T,T/R_{\rm eff}).$$

Encoder 和 token decoder 仍旧要老老实实跑满全部 \(T\) 个位置。至于 decoder 里的 cross-attention，按唯一概念看逻辑规模是 \(T\times(T/R_{\rm eff})\)；如果为了走规则 kernel 把 K/V 复制展开到了长度 \(T\)，那这部分计算和显存就得按展开后的实际布局记账。

拿一组具体数字算笔快账：假设 token 侧（encoder 加 decoder）有 \(P_t=1\text{B}\) 参数，概念主干有 \(P_c=3\text{B}\)，实际压缩比 \(R_{\rm eff}=4\)。先只看参数主导的矩阵乘加（前向每参数约 2 FLOPs，暂不算 attention 的长度项），摊到每个原始 token 上的计算量是：

$$2\left(P_t+\frac{P_c}{R_{\rm eff}}\right)=2\left(1+\frac{3}{4}\right)=3.5\ \text{GFLOPs}.$$

同样 4B 参数如果全部逐 token 执行，需要 \(8\ \text{GFLOPs/token}\)。压缩比虽然有 4 倍，总算力只省到原来的 \(1/2.29\)——卡住提速上限的，正是 token 侧那 1B 逃不掉的固定开销。

换到 LCM，账本上要算四笔：

$$C_{\rm LCM}=C_{\rm SONAR\ enc}+C_{\rm context}+K\,C_{\rm denoise}+C_{\rm SONAR\ dec}.$$

每生成一句新向量，denoiser 要串行跑 \(K\) 步，最后还得靠 SONAR decoder 逐 token 展开成文字。句子切得越长，外层序列越短，但单句塞进的信息一多，第 3 节的实体保真问题就会冒头；采样步数 \(K\) 提上去能改善分布质量，却直接按倍数拉长单句延迟。

除了算清总 FLOPs，异构宽度还会牵动训练超参：token 侧和概念侧的隐藏维度不同，学习率与初始化缩放需要按各自宽度分别处理，见 μP 与超参数迁移。压缩比到底选多大、算力该多给主干还是多给编解码器，归根结底也是 训练预算分配 的问题——压缩不会凭空变出算力，只是把同一笔预算在容量、长度与重建精度之间重新切分。

8. 推导与工程练习

练习 1：均值为何优于任选一个答案

下一句的一维表示以 0.75 概率取 +2、0.25 概率取 −2。求最佳 MSE 预测与最小 MSE，再求始终预测 +2 的 MSE。若带噪观测模型为 \(y=\alpha Z+\sigma\varepsilon\)（\(\varepsilon\sim\mathcal N(0,1)\)，\(\alpha=\sigma=\sqrt{0.5}\)），观察到 \(y=0\) 后，后验均值是多少？

展开完整解答

条件均值为 \(0.75\times2+0.25\times(-2)=1\)，对应最小 MSE 为 \(0.75(2-1)^2+0.25(-2-1)^2=3\)。如果始终猜真实样本 \(+2\)，MSE 是 \(0.75\times0+0.25\times16=4\)，反倒更高。当观测到 \(y=0\) 时，\(-2\) 和 \(+2\) 两个端点生成 \(y=0\) 的高斯似然完全相等，所以后验退回先验，后验均值依然是 1。

练习 2：段结束与可用时间

标量表示为 [2, 4, 6, 8, 10, 12]，边界落在位置 1、4、6。采用「看到新边界才闭合上一段」的约定：预测位置 4 的 token 时，哪些完整概念可见？读到位置 6、预测下一 token 时呢？

展开完整解答

预测位置 4 的 token 时只读到了位置 3，还没见到位置 4 的边界，因此第一段尚未闭合，概念侧暂时为空，模型只能靠因果 token 路径和初始状态预测。读到位置 4 后，第一段 [1, 2, 3] 闭合，均值为 4；读到位置 6 后，第二段 [4, 5] 闭合，均值为 \((8+10)/2=9\)，此时可见概念为 [4, 9]。位置 6 自己刚开启新段，要等下一个边界或结束标记才能闭合；在此之前，无论后面位置的值怎么改，这两份已闭合概念都不会变。

练习 3：推导副本补偿

两个概念的打分均为 0，value 分别为 1 和 7。概念 1 有 2 个可见副本，概念 2 有 4 个。分别计算唯一概念 attention、展开 attention，以及按可见副本数补偿后的输出。

展开完整解答

按唯一概念算，权重各占 1/2，输出为 4。展开后 6 份副本打分相同、每份权重 1/6，两组总权重变成 1/3 和 2/3，输出被拉到 \(1/3+14/3=5\)。给第一组每份减 \(\log2\)、第二组每份减 \(\log4\)，两组未归一化总质量分别变为 \(2e^{-\log2}=1\) 和 \(4e^{-\log4}=1\)，等权与输出 4 一起恢复。如果因果 mask 截掉了第二组的 3 份、只剩 1 份可见，那第二组的补偿就必须改成 \(\log1=0\)，否则反而会矫枉过正。

练习 4：压缩预算往哪个方向调

目标压缩比 \(R_*=4\)，实际边界率 \(F=0.4\)。把 \(F\) 视为常量，求辅助损失对平均概率 \(G\) 的导数，并判断梯度下降的方向。另设 token 侧 1B、概念侧 3B 参数，如果实际压缩比掉到了 2，按稠密参数模型算每个原始 token 要花多少 FLOPs？

展开完整解答

导数为 \(\frac4{3}(4\times0.4-1)=0.8\gt 0\)。当前边界率 0.4 高于目标 0.25，梯度下降会压低 \(G\)，也就是减少边界、拉长平均段长。实际压缩比掉到 \(R_{\rm eff}=2\) 时，稠密算力涨到 \(2(1+3/2)=5\ \text{GFLOPs/token}\)，比达标（\(R_{\rm eff}=4\)）时的 \(3.5\ \text{GFLOPs/token}\) 足足多出 42.9%——盯紧真实压缩比，比盯着目标超参 \(R_*\) 实在得多。
