DeepSeek-V4-Pro 架构：一个 token 的旅程

交互2026-10-20更新于 2026-10-22

一个 token 走进 DeepSeek-V4-Pro 时，携带的是一个 7168 维向量。经过 61 层处理，它要完成两件事：从过去的上下文里取出相关信息，再用少量专家把当前表示向前推进。它的 1.6T 总参数提供大量可选择的专家，每个 token 激活约 49B。理解它的成本，需要同时追踪更宽的表示、更多的层，以及每一层真正读取的历史条目和专家权重。

这两件事对应 attention 和 MoE。围在它们外面的 mHC 维护四路残差，让每个子层能够选择从哪些信息流读取、向哪些信息流写回。主干处理完成后，四路信息合并，输出头为 129,280 个词表项产生 logits，采样器再选出下一枚 token。

1. 先把一个 Block 的张量画清楚

设 \(\htmlData{symbol=batch}{B}\) 是请求数，\(\htmlData{symbol=query}{S}\) 是每条请求本次处理的 token 数，\(\htmlData{symbol=width}{d}=7168\) 是隐藏宽度。Embedding 把输入映射成 \([B,S,d]\)，进入主干时扩展为 \([B,S,4,d]\)。每个 attention、MoE 子层先通过 mHC 将四路汇成一份 \([B,S,d]\)，完成计算后，再把输出写回四路。

位置逻辑形状每个输入 token 的元素数
残差流[B, S, 4, 7168]28672
Attention / MoE 输入[B, S, 7168]7168
全部 query 头[B, S, 128, 512]65536
shared KV[B, S, 512]512
一个专家中间态[路由到该专家的 token 数, 3072]3072

Decode 时通常 \(S=1\)，prefill 时一条请求会提供多行输入。线性投影实际处理 \(BS\) 行，因此 batch、prompt 长度和专家分组共同决定矩阵乘能否形成足够大的工作块。四路残差增加的是每层持续传递的激活；attention 头数增加的是 query 及其输出的计算量。它们在内存账本中应分别计数。

Pro 的前两层已经采用 HCA 加局部窗口，主干共有 30 个 CSA 层与 31 个 HCA 层。 从第 3 层起，CSA 与 HCA 交替，最后一层为 CSA。各层都保留最近 128 个 token 的局部窗口；CSA 再选读较细的压缩记忆，HCA 则读取较粗的全部压缩记忆。

2. 四路残差怎样混合

把四路旧残差记为 \(x_0,x_1,x_2,x_3\)，每一路都是 \(d\) 维。mHC 先生成 4 个 pre 系数，将它们加权成子层输入 \(z\)。子层 \(F\) 产生一份新结果，再由 4 个 post 系数分发。与此同时，一个 \(4\times4\) 矩阵把旧残差混入新残差：

$$z=\sum_{i=0}^{3}p_i x_i,\qquad y_j=q_jF(z)+\sum_{i=0}^{3}\htmlData{symbol=mix}{C_{ij}}x_i.$$

这里 \(p_i\) 是 pre 系数，\(q_j\) 是 post 系数；\(C_{ij}\) 的行表示旧流 \(i\)，列表示新流 \(j\)。将每条流放在矩阵的一行时，残差混合项就是 \(C^\top X\)。动态系数来自展开后的 \(4d\) 维输入：每个子层用 \([24,4d]\) 权重生成 4+4+16 个数。矩阵 \(C\) 经过 20 轮 Sinkhorn 行列归一化，行和与列和接近 1；pre 和 post 分别使用自己的门控约束。

这个坐标的汇合输入为 \(0.2+0.8+1.8+3.2=6\)。当 \(C=I\) 时，输出是 [5, 10, 15, 20]；循环移位时，旧值先变成 [8, 2, 4, 6]，再加上 [3, 6, 9, 12]，得到 [11, 8, 13, 18]。这个例子也提供了一个很有用的移植测试：用非对称混合矩阵验证转置方向。单位矩阵和对称矩阵会让两个方向得到相同结果，从而掩盖轴顺序错误。

3. 共享 KV、分组投影与 attention sink

128 个 query 头分别提出问题，每个头有 512 个分量；同一个位置保存一份 512 维 shared KV，同时供 key 匹配和 value 汇总使用。它的前 448 维承载内容，末尾 64 维施加 RoPE。这样增加 query 头数主要扩大 query 侧，历史缓存仍按一份 shared KV 增长。

Query 先经过 1536 维低秩中间态。将 \(BS\) 个输入展开为矩阵，形状变化为

$$[BS,7168]\longrightarrow[BS,1536]\longrightarrow[BS,128\times512].$$

两次投影之间有 RMSNorm；投影后还要按头做归一化，并对最后 64 维施加 RoPE。这两块投影权重共 \(7168\times1536+1536\times128\times512=106.5\text{ Mi}\) 个参数，而直接投影需要 448 Mi。Mi 表示 \(2^{20}\)。低秩减少权重，也引入中间张量和额外算子；实际耗时取决于形状与 kernel 融合。

一个 query 的候选集合由局部位置与可见压缩条目组成。设 \(a_j=q^\top k_j/\sqrt{512}\) 是候选 \(j\) 的分数，\(s\) 是该 query 头的 learned sink 分数，输出为

$$o=\frac{\sum_j e^{a_j}v_j}{e^s+\sum_j e^{a_j}}.$$

Sink 提供一个 value 为零的额外选项，因此贡献分母。两个候选分数为 \(\ln2,0\)，value 为 4、10，sink 分数为 0 时，输出是 \((2\times4+10)/(2+1+1)=4.5\)。局部与压缩候选共享这一个分母。实现时可以先减去所有分数的最大值，再累计指数和，获得数值稳定的同一结果。

Attention 输出先对 RoPE 部分做逆旋转，再按 16 组整理；每组 8 个头，即 4096 维。每组从 4096 映射到 1024，拼接后映射回 7168 维。于是输出投影的形状是 \([128,512]\to[16,4096]\to[16,1024]\to[7168]\)，共 176 Mi 参数。分组的 reshape、inverse RoPE 和矩阵转置都属于需要逐项复现的计算。

4. 压缩记忆的内容与可见时间

压缩器需要回答两个不同的问题：怎样汇总一组 token，以及从哪个 query 开始允许读取这份汇总。先看内容。对组内 token \(t\)，投影生成 value \(v_t\) 与 gate \(g_t\)，gate 还带有组内位置偏置。对每个通道 \(j\) 单独归一化：

$$c_j=\sum_{t\in\mathcal G}\frac{e^{g_{tj}}}{\sum_{u\in\mathcal G}e^{g_{uj}}}\,v_{tj}.$$

\(\mathcal G\) 是参与池化的位置集合，\(j\) 是向量通道。同一组的不同通道可以强调不同 token。例如一条通道的 values 为 [2,4,8,10]，归一化权重为 [0.1,0.2,0.3,0.4]，池化结果就是 7.4；随后整个向量再做 RMSNorm 和 RoPE。

CSA 的步长 \(\htmlData{symbol=ratio}{r}=4\)，每个 token 投影出两份 512 维内容。一次池化取上一组的前半投影与当前组的后半投影，形成最多 8 个 token 的重叠窗口。首组的缺失位置用 \(-\infty\) gate 得到零权重。HCA 的步长为 128，一组使用自己的 128 个位置；压缩条目的 RoPE 位置取当前组起点。

位置从 0 编号。处理完位置 \(t\) 后，完成组数为 \(\lfloor(t+1)/r\rfloor\)，可见的压缩索引满足

$$0\le j\lt\left\lfloor\frac{t+1}{r}\right\rfloor.$$

CSA 在 \(t=3\) 产生第 0 条、\(t=7\) 产生第 1 条；HCA 在 \(t=127\) 产生第 0 条。未完成组保存在 value/gate 状态里，等待后续输入。Prefill 虽然能并行计算整段压缩结果，每个 query 仍使用自己的完成组数作为因果边界。

这个状态机决定了 chunked prefill 的交接内容。新 chunk 除了接收已经完成的压缩 KV，还要接收未完成组的 value、gate 和组内偏移。对 CSA 还需携带上一组，用于下一次重叠池化。只传压缩结果会丢掉这些继续计算所需的状态。

5. CSA 与 HCA 的计算账本

CSA 先用一个较小的 Indexer 给所有可见压缩条目打分，再让主 attention 读取分数最高的 1024 条。Indexer 有 64 个 128 维 query 头，共享一份 128 维压缩索引缓存；分数为 \(s_j=\sum_h w_h\operatorname{ReLU}(q_h^\top k_j)\)。权重 \(w_h\) 由输入线性投影和缩放得到，可以为正或负。多卡按头分工时，先合并各头的分数，再执行 top-k。

设历史长度 \(\htmlData{symbol=context}{N}\) 足够填满 128 token 局部窗口。CSA 主 attention 访问 \(128+\min(1024,\lfloor N/4\rfloor)\) 个条目，HCA 访问 \(128+\lfloor N/128\rfloor\) 个条目。每个 query 的两次矩阵乘分别计算 QK 与加权 value，粗略 FLOPs 为 \(4HC\times512\)，这里 \(\htmlData{symbol=heads}{H}=128\)，\(C\) 是访问条目数。

固定 top-k 让 CSA 主 attention 的读数达到上限，Indexer 仍会扫描 \(N/4\) 个候选。HCA 压缩得更粗，随着历史增长继续读取更多摘要。在 N=131,072 时，HCA 有 1024 个压缩条目，恰好达到 Pro 的 CSA 上限。Flash 的 CSA 上限为 512，因此两种尺寸在相同历史长度下也会选择不同的计算预算。 在做性能预测时，把压缩器、Indexer、主 attention 分别计时，才能解释同样的主 attention 读数为什么会有不同延迟。

6. 专家选择与专家内部计算

每层有 \(\htmlData{symbol=experts}{E}=384\) 个路由专家，每个 token 选择 6 个，再加一个总会执行的共享专家。前 3 层通过 token ID 查固定专家映射；后续层用 \(\sqrt{\operatorname{softplus}(xW_g^\top)}\) 得到路由分数。负载均衡 bias 参与选择，选中专家的组合权重由原始分数归一化，再乘 2.5：

scores = sqrt(softplus(x @ Wgate.T))
ids = tid2eid[token_id] if layer_id < 3 else topk(scores + bias, 6)
weights = scores[ids] / scores[ids].sum() * 2.5
y = sum(weights[j] * expert[ids[j]](x) for j in range(6))
y += shared_expert(x)

这使 6 个路由权重之和为 2.5。共享专家独立贡献结果。用四个候选的简化算例检查实现：原始分数 [1,2,3,4]，bias=[4,0,0,0]，选择两个专家时选中第 0、3 个，权重是 [0.5, 2.0]。这样可以分别核对专家 ID 与加权结果。

一个专家含三块矩阵，gate/up 从 \(d\) 映射到中间宽度 \(\htmlData{symbol=intermediate}{m}=3072\)，down 再映射回 \(d\)。对齐这份模型的计算顺序是先投影、做 FP32 中间运算，将 up 限在 [−10,10]、gate 上限设为 10，然后计算 SwiGLU：

$$E(x)=W_2\left[\operatorname{SiLU}(\min(W_1x,10))\odot\operatorname{clip}(W_3x,-10,10)\right].$$

路由权重可以乘在 down 投影之前。共享专家也使用相同的激活裁剪配置。单个专家有 \(3dm=63\) Mi 参数，主干全部路由专家合计 1547.396 B；每个 token 经过的 6+1 个专家合计约 28.208 B 参数。完整模型的 1.6T 参数还包含 attention、embedding、路由与其他模块，整体每 token 激活约 49B。

Pro 的专家数量让调度粒度尤其重要：128 个 token 一共产生 768 次路由分配，平均每个专家仅 2 行；Flash 在相同 batch 下平均为 3 行。Pro 每个专家矩阵更宽，但行数偏小仍会限制 GPU 利用率。应同时测每专家 token 数、不同专家数与最慢 rank 耗时，再决定增大 batch、使用 grouped GEMM 或复制热点专家。 最后一层残差经合并和 RMSNorm 进入词表头。深度为 1 的 MTP 分支额外预测后续 token，可用作投机草稿；草稿的接受率与验证成本决定它对服务延迟的贡献。

7. 把架构落实为一致性检查

移植实现时，先固定输入 token、模型权重、dtype 和并行配置，按层保存中间检查点：mHC 汇合值、压缩 KV、Indexer 分数与 top-k IDs、attention 输出、专家输出。找到首次显著分歧后，只比较这一段算子。对于经过量化或改变归约顺序的实现，同时记录最大绝对误差、相对误差与最终 logits 排序。

具体症状关键证据下一步
短输入正确，4 / 8 token 附近开始偏离完成组数、写入槽位、pooling 前的 token 范围核对严格小于边界、跨组 remainder、CSA 两半投影
mHC 输入一致，混合后立即不同非对称 C 与四路旧残差逐坐标检查旧流轴上的求和和 C 的转置
路由 ID 一致，MoE 输出不同原始 scores、权重、共享专家 gate/up核对 route scale、bias 的使用位置及激活裁剪
改变合批请求后才出现差异首次分歧的 logit、top-k 次序与归约结果固定 backend 与 batch，分别测试压缩状态和归约路径

这些检查能捕捉 shape 正确而语义错误的实现。mHC 的转置错误就属于这一类：矩阵仍是 4×4，运行时无法靠形状发现它。共享专家的裁剪顺序也需要与当前 checkpoint 的推理路径对应。将它们写成小张量回归测试，比只比较最终生成文本更容易定位问题。

8. 练习与实验

练习 1：把形状换成字节

令 B=2、S=16，残差、全部 Q 和 shared KV 都按 BF16 存储。分别计算元素数与 KiB。

展开解答

残差为 2×16×4×7168=917504 个元素，占 1792 KiB；Q 为 2×16×128×512=2097152 个元素，占 4096 KiB；shared KV 为 16,384 个元素，占 32 KiB。BF16 每元素 2 字节，1 KiB=1024 字节。

练习 2：选择分数与组合权重

scores=[1,2,3,4]，bias=[4,0,0,0]，选两个专家，route scale=2.5。求 ID、权重及权重之和。

展开解答

选择分数 [5,2,3,4] 得到 ID [0,3]。取原始分数 [1,4]，除以 5，再乘 2.5，得到 [0.5, 2.0]，和为 2.5。将选择分数直接归一化会改变这次输出。

练习 3：一个因果边界错误

程序放行 j≤⌊(t+1)/4⌋ 的压缩条目。t=6、7 时分别多放行哪个条目？怎样改正？

展开解答

t=6 时完成 1 组，合法索引是 0，错误规则多放行 1；t=7 时完成 2 组，合法索引为 0、1，错误规则多放行 2。条件改为 j<⌊(t+1)/4⌋。Prefill 中多出的条目可能含未来输入，decode 中则可能读取尚未写入的缓存。

练习 4：用非对称矩阵检查 mHC

将上图 C 改成“旧流 i 送到新流 i+1，末流回到第 0 流”。旧值为 [2,4,6,8]，F(z)=12，post=[0.25,0.5,0.75,1]。求新四路坐标。

展开解答

残差项 Cᵀx=[8,2,4,6]，新计算贡献为 [3,6,9,12]，合计 [11,8,13,18]。若误算 Cx，会得到 [4,6,8,2]+[3,6,9,12]=[7,12,17,14]。两个结果可以直接作为转置方向的测试用例。
