01 · 并行草拟的困难

每个位置都像正确答案，放在一起却不对

如果两个位置独立抽样，第一个可能选 “of”，第二个选 “problem”。后一个位置需要知道前一个到底抽中了什么，而不是只知道它可能是什么。

短语仅作机制示意；实际模型按 token 工作。

02 · 两段生成

backbone 一次算完，轻量 head 顺着往后走

target 的上下文特征和 anchor 进入 draft。backbone 并行产生各位置的隐藏向量与基础 logits；Markov head 再根据刚采样的 token 修正下一个位置。

工程 · 算清楚，再实现

先画清楚一个 block 的输入与输出

张量 教学形状 内容
context features [B,L,d] target 已确认前缀的隐藏特征
draft input [B,γ] anchor + γ−1 个 mask 位置
H、U [B,γ,d]；[B,γ,V] 并行 backbone 隐藏状态、基础 logits
qₖ、cₖ [B,V]；[B] Markov 修正后的分布、条件接受率

k=1 的前一个 token 是 anchor。k>1 才读取刚抽出的候选 xₖ₋₁。并行 backbone 不需要逐个等待这些候选。

工程 · 算清楚，再实现

并行算特征，串行决定实际选哪个词

qₖ(v | prefix) = softmax(Uₖ + W₁[xₖ₋₁] W₂)ᵥ
q(x₁…xγ) = ∏ₖ qₖ(xₖ | x₀,x₁…xₖ₋₁)

条件中包含 anchor x₀ 与本 block 已采样的 x₁…xₖ₋₁。每一行都有自己的归一化常数。

重计算保留并行

上下文 attention、FFN 和基础 logits 在整段上一起算。Uₖ 已带有长上下文信息。

便宜的依赖保持串行

查出前一个 token 的低维向量，投影成词表 bias，然后 softmax 和采样。

不能把整段联合打分后一次全局归一化，冒充这些逐位置 q；接受检验需要实际采样的条件分布。

工程 · 算清楚，再实现

“轻量”也要计算参数量与访存量

教学设定 V=128,000、r=256、FP16；W₁∈ℝⱽˣʳ，W₂∈ℝʳˣⱽ。

实现 参数 / 计算 代价
完整 V×V 转移矩阵 V²=16.384B 参数 FP16 约 30.52 GiB
低秩 W₁W₂ 2Vr=65.536M 参数 FP16 125 MiB
每位置查表 + 投影 约 2rV=65.536M FLOP 仍有词表投影与 softmax
γ=8 的串行 head 约 524.288M FLOP backbone 之外的成本

这些是形状推算，不是模型实测。batch、数据驻留与融合 kernel 会改变延迟；r、γ 都应进入性能扫描。

03 · Markov head

“of” 不重跑 backbone，只给下一位置加一份偏置

查表得到前一个 token 的低维向量，再投影到词表：qₖ = softmax(Uₖ + W₁[xₖ₋₁] W₂)。重的上下文计算已经完成，串行部分只补局部转移。

柱长与 logits 为示意；Markov head 只显式看前一个 token，更长上下文由 backbone 特征提供。

工程 · 算清楚，再实现

两种续写模式，怎样用一个 rank-1 head 分开

前词 A 时，logits 差为 ln3，因此概率比 exp(ln3)=3:1，q₂=(0.75,0.25)；前词 B 时正好反过来。

教学词表只有 A、B。若首词均匀抽样，AB 或 BA 的总概率是 0.5×0.25+0.5×0.25=0.25。

工程 · 算清楚，再实现

把真正用于采样的 q 保存下来

H, U = backbone(context, anchor_and_masks)
previous = anchor
for k in range(gamma):
    bias = W1[previous] @ W2
    q[k] = softmax(U[k] + bias)
    c[k] = sigmoid(confidence(H[k], W1[previous]))
    candidate[k] = sample(q[k])
    previous = candidate[k]

cₖ 在 xₖ 抽样之前就能得到。target 验证时用这里的 q[k]；只用 softmax(U[k]) 会遗漏 Markov 改变的抽样概率。

04 · 置信度

第 4 个 token 要留下，前 3 个也得留下

confidence head 预测“前面全接受时，这一个也接受”的概率 cₖ。调度时用的是整个前缀存活概率 aₖ = c₁ × … × cₖ，后面的收益会逐步变小。

示意概率；实际模型通过校准，让预测的前缀存活率贴近观测接受率。

工程 · 算清楚，再实现

confidence 预测“通过的概率”，不是词的概率

cₖ* = Σᵥ min(pₖ(v),qₖ(v))
= 1 − ½‖pₖ−qₖ‖₁

训练目标

在相同前缀上取得 pₖ、qₖ，计算软标签 cₖ*。用二元交叉熵等损失，让 sigmoid 输出接近这个条件接受率。

两种事件要分清

“第 4 个位置本身能过”和“前 4 个位置全过”不同。前面拒绝导致后缀未被使用，不等于后缀的条件接受率为零。

最大词概率 qₖ(xₖ)、模型熵、p/q 比值都不能直接替代 cₖ。它们回答的是不同的问题。

工程 · 算清楚，再实现

每一格只高估 0.1，长前缀就会高估很多

假设四格同率 单格条件率 前四格存活 E[输出]
原始预测 0.9 0.9⁴=0.6561 4.0951
真实行为 0.8 0.8⁴=0.4096 3.3616
高估量 0.1 0.2465 约 21.82%

调度器要用绝对概率来估算 token/s；只有排序正确还不够。

温度校准：c′ = sigmoid(logit(c) / T)

教学例子 T=ln9/ln4≈1.585 时，0.9 映到 0.8。真实 STS 逐位置搜索温度，校准累计存活概率，固定前面已选的温度。

工程 · 算清楚，再实现

校准集要回答：预测 80% 的前缀真活了多少？

预测 a₃ 分桶 样本数 实际存活 校准差
[0.7,0.8)，桶均值 0.75 200 120/200=0.60 0.15
[0.8,0.9)，桶均值 0.85 300 240/300=0.80 0.05
加权 ECE 500 0.4×0.15+0.6×0.05 0.09

示例只展示两桶。按位置、代码/聊天、上下文长度分别看可靠性曲线；训练数据、校准数据和最终评估数据分开。

小样本桶会抖动。保留样本量与时间窗口，观察请求分布变化后“预测输出数”和“实际输出数”是否持续偏离。

05 · 按收益分配

同一份验证预算，先给更可能用上的前缀

把各请求的 aₖ 放在一起看，优先考虑高存活概率的位置。因为同一请求的 aₖ 不增，选中后面的 token 时，前面的也会先被选中。

图中为玩具概率和固定的 5 个草稿位置预算；一个请求还需要 anchor / bonus 对应的基础位置。

工程 · 算清楚，再实现

每个请求先占一格 anchor，再竞争草稿预算

aᵣⱼ = ∏ᵢ₌₁ʲ cᵣᵢ
B = R + Σᵣ ℓᵣ
E[输出] = R + Σᵣ Σⱼ₌₁ˡʳ aᵣⱼ

R 个请求各有一个 anchor 输入；每个请求本轮最终输出一个纠正或 bonus token，再加通过验证的候选。

预测吞吐 = E[输出] × SPS(B) = E[输出] / Tstep(B)

SPS 的单位是 step/s，B 统计 target token 位置数，不是请求数。实际 profile 应覆盖 draft、同步与服务调度的端到端成本。

工程 · 算清楚，再实现

固定预算时，先买收益最高的下一格

两个请求先各有一格 anchor。增加 3 个名额时选 A₁、A₂、B₁：B=5，长度为 (2,1)，期望输出 2+0.9+0.72+0.6=4.22。

存活率沿前缀不增，所以高分位置前面的格也会入选；相等时必须让同一请求的前一格优先。这里的数值在候选采样前已固定。

工程 · 算清楚，再实现

预算增长是否值得，看新增收益与新增耗时

(E+a)/(T+ΔT) > E/T
⇔ a > E·ΔT/T

当前 E=4.22 token，T=5.4 ms。下一个位置的 a=0.36；增加它后 T=6.4 ms。

门槛 = 4.22 × 1/5.4 ≈ 0.7815 > 0.36

这一步不划算。若新增位置只多花 0.1 ms，门槛就变成 0.07815，此时应该加入。

这是局部比较。真实 SPS(B) 可能跨过 kernel 或并行配置边界，产生不平滑变化；搜索策略还要遵守采样因果关系。

工程 · 算清楚，再实现

历史信号定容量，当前信号分配容量

为什么需要异步

GPU 启动下一轮前，host 需要提前知道 batch 形状；等当前采样和调度完成再做决定，会在流水线上留下空隙。

两条信息通路

用两步前的历史预测选择本轮容量 K；用当前累计置信度安排验证前缀。历史容量搜索可以跨过不平滑的性能曲线。

关键约束：某候选是否入选，不能借助这个候选的取值或更远的候选来反选它。过去的容量选择为当前采样建立因果隔离。

实现时把容量 K、置信度版本、请求 ID 与轮次一起记录；防止跨轮复用错位或让当前候选悄悄进入容量搜索。

07 · 调度和采样

先决定候选有没有资格送验，再看它抽到了什么

送验事件要只依赖采样 xₖ 之前的信息，才不会偏爱某种抽样结果。随后使用实际的 qₖ（包含 Markov bias）做 p/q 接受与残差重采样，保留 target 的分布。

这是算法的因果依赖顺序。调度实现还要避免后续候选通过回溯搜索影响当前候选的入选。

工程 · 算清楚，再实现

即使 p=q，按候选内容选择也能采错

两词表 A/B，p=q=(0.5,0.5)。坏规则：抽到 A 就采用草稿；抽到 B 就跳过草稿，重新从 p 抽一次。

P(最终 A)=P(草稿 A)+P(草稿 B)·P(重采 A)
=0.5+0.5×0.5=0.75

正常应是 0.5。p/q 检验在这里永远接受，但它无法消除“是否送验”已经制造的选择偏差。

用未来 cₖ₊₁ 反过来决定 xₖ 是否进入前缀，也可能发生相同问题：cₖ₊₁ 已经读过 xₖ。

工程 · 算清楚，再实现

把“决定”和“抽样”的依赖顺序写进代码

# 示意：单请求的因果门控，预算由历史状态给出
capacity = choose_from_history(history)
previous_token, prefix_survival = anchor, 1.0
for k in range(gamma):
    qk, ck = head(H[k], previous_token)
    admit = gate(ck, prefix_survival, capacity)
    if not admit: break  # 不看 x[k] 或更晚的候选
    x[k] = sample(qk)
    previous_token = x[k]
    prefix_survival *= ck
    capacity -= 1

批量调度要把同样的依赖约束扩展到多个请求。若全局回溯搜索用到未来候选，必须另外证明入选事件没有被这些候选影响。

08 · 闭合一轮

confidence 高，也仍然要经过 target

先裁掉没送验的 H；target 接受 E、F，拒绝 G，就输出纠正的 G*。置信度是预估收益，接受检验才是最终决定，下一轮从新前缀继续。

09 · 训练与部署

让草稿接近 target，让置信度接近实际

训练三个小部件

backbone 学内容；Markov head 学转移；confidence head 学条件接受率。

前面位置权重更大：早一点出错，会让后面整段失效。

接入真实推理引擎

练习 1 · 计算与分析

算出 Markov head 真正使用的 q

基础 logits U=(0,0)。上一词对应 W₁ 的行是 [2]，W₂=[ln2/2, −ln2/2]。求 bias、q 与目标 p=(0.5,0.5) 下的总接受率。
展开参考解答

bias=(ln2,−ln2)，两词概率比为 exp(2ln2)=4:1，故 q=(0.8,0.2)。总接受率 Σmin(p,q)=0.5+0.2=0.7。若误用基础 softmax(U)=(0.5,0.5) 作为 q，采样与接受检验不再一致。

练习 3 · 计算与分析

后缀很有把握，可以回头保留首词吗？

调度器先采样 x₁，再计算依赖 x₁ 的 c₂。如果 c₂>0.9 就验证两个候选，否则连 x₁ 也不验证。只要最后仍做 p/q 检验，是否保持 target 分布？
展开参考解答

不能据此保证。x₁ 的入选事件已经依赖 x₁ 的取值；p/q 校正的是从 q 产生的无偏候选。可先按不依赖 x₁ 的信息决定首词是否入选，再决定后续；或用历史信息确定容量，并审计当前前缀分配的因果依赖。
