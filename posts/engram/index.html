Engram：条件记忆怎样与 MoE 分工

交互2026-10-22

“Diana, Princess of Wales”是一个可以反复遇到的局部组合。普通 Transformer 会逐层把这些 token 组合成实体表示，再用上下文决定它在当前句子中的作用。把常见组合存进一张可训练表，可以提前提供一份局部表示；隐藏状态继续负责判断，这份表示在此刻该发挥多大作用。

Engram 把这条路径做成条件记忆模块：由输入 token 确定性寻址，用当前层隐藏状态门控，再把结果写回残差流。它同时提出一个资源分配问题：同样的总参数与激活计算预算，多少参数用于 MoE 专家的动态变换，多少参数用于可直接读取的局部模式？

先确定地址，再解释内容

常见 tokenizer 为大小写、空格形式等分配不同 ID。Engram 先对 token 的文本形式做规范化，将部分形式映射到同一个 canonical ID。记这张映射表为 \(\mathcal P\)，当前位置的原始 ID 为 \(x_t\)，压缩 ID 为 \(x'_t=\mathcal P(x_t)\)。它为查表提高模式复用率；基础 token 序列仍用于原有主干与输出预测。

接着构造以当前位置结尾的 n-gram：\(g_{t,n}=(x'_{t-n+1},\ldots,x'_t)\)。每阶使用多个哈希头，每个头有自己的表大小与寻址函数：

$$r_{t,n,k}=\varphi_{n,k}(g_{t,n}),\qquad e_{t,n,k}=E_{n,k}[r_{t,n,k}],\qquad \htmlData{symbol=memory}{e_t}=\operatorname{concat}_{n=2\ldots N,\,k=1\ldots K}e_{t,n,k}.$$

\(N\) 是最大 n-gram 阶数，\(K\) 是每阶头数；\(E_{n,k}\) 是一张可训练表，\(e_t\) 是当前 token 读出的记忆向量。若每行宽度为 \(q\)，拼接后宽度为 \(d_{mem}=(N-1)Kq\)。例如 bigram 和 trigram 各 4 个头，每行 128 维，得到 1024 维记忆。

表通过语言模型训练更新，推理时提供固定参数。不同上下文可能共享哈希行，规范化也可能合并不同形式。多头提供不同的组合地址，后面的门控进一步判断内容与当前上下文是否相容。关于哈希容量、碰撞梯度和按行分片的推导，可接着看Over-Encoding。

这里有一个重要的调度性质：输入 token 一旦确定，所有 Engram 层的查表地址就能提前计算。MoE 的 expert 路由依赖当前层隐藏状态，而 Engram 的表地址依赖已知的离散序列。两个条件分支因此有不同的可预取时机。

上下文怎样决定记忆的作用

局部组合在不同句子中可以承担不同含义。主干隐藏状态 \(h_t\in\mathbb R^d\) 已经聚合前面若干层的上下文，适合决定当前读出的内容是否有用。Engram 将记忆投影为 key 与 value：

$$k_t=W_Ke_t,\qquad v_t=W_Ve_t,\qquad W_K,W_V\in\mathbb R^{d\times d_{mem}}.$$

Key 负责与上下文比较，value 负责提供写入内容。令 \(R(h)\) 表示 RMSNorm，论文中的标量门为：

$$s_t=\frac{R(h_t)^\top R(k_t)}{\sqrt d},\qquad \htmlData{symbol=gate}{a_t}=\sigma(s_t),\qquad \tilde v_t=a_t v_t.$$

\(\sigma(s)=1/(1+e^{-s})\)，门值位于 0 与 1 之间。它控制当前 token 的整条 value 向量；RMSNorm 先调整 query 与 key 的尺度，再计算匹配分数。加入记忆并不要求先在全部表行之间做 softmax，因为被读取的行已经由哈希确定。

一个二维算例能看清这一步。取 \(h=[\cos\theta,\sin\theta]\)、\(k=[1,0]\)、\(v=[1,2]\)，RMSNorm 的 gain 为 1、epsilon 为 0。两个单位向量经过 RMSNorm 后长度都是 \(\sqrt2\)，所以 \(s=\sqrt2\cos\theta\)。同向时门约为 0.804，正交时为 0.5，反向时约为 0.196；对应写入向量为这三个系数乘以 [1,2]。

门控的数值变换属于实现配置。官方演示代码在归一化点积后使用 \(\operatorname{sign}(s)\sqrt{\max(|s|,10^{-6})}\)，再送入 sigmoid；这会放大小幅 logit、压缩大幅 logit。固定 query、key、value，逐项比较 RMS、点积、变换后 logit 和门值，可以检验移植前后的行为。归一化归约精度、epsilon 和 gain 也应一致。

多路残差结构还可以让同一记忆服务不同分支。Engram 在各分支间共享 embedding 与 value 投影，为每条分支使用独立 key 投影与门。这样同一份检索内容有不同的上下文解释。将共享 value 和各分支 key 投影合并为一次矩阵运算，可提高小投影的计算利用率；与 mHC 的读写映射结合时，还要保留分支维度和归一化轴。

短卷积与流式状态

门控后，Engram 用短的 depthwise causal convolution 进一步组合临近位置。每个通道单独卷积，形式为：

$$z_{t,c}=\sum_{j=0}^{w-1}A_{j,c}\,R(\tilde v_{t-j\delta})_c, \qquad y_t=\tilde v_t+\operatorname{SiLU}(z_t),\qquad h_t\leftarrow h_t+y_t.$$

\(w\) 是 kernel 长度，\(\delta\) 是 dilation，\(c\) 为通道索引；上式把 \(j=0\) 定义为当前位置的系数，序列开始前输入为零。原配置使用 \(w=4\)，dilation 等于最大 n-gram 阶数。取 \(N=3\)，当前卷积读取位置 \(t,t-3,t-6,t-9\)，单 token 推理需要保存最近 9 个位置的卷积输入。

流式推理因此至少有两类局部状态：哈希器保留最近 \(N-1\) 个 canonical IDs，卷积保留最近 \((w-1)\delta\) 个归一化门控 value。Chunked prefill 到 decode 的切换必须续接这些状态。若每个 chunk 都从零 padding 开始，chunk 开头的 n-gram 和卷积结果会同时改变。

可以固定一段输入，分别整段计算、逐 token 计算、按不等长 chunks 计算，然后比较每个位置的行号、门和输出。再让两个请求交错执行，检查各自状态独立，结束请求后清空局部缓存。这个实验能发现请求边界、切块边界与因果卷积方向造成的差异。

条件计算与条件记忆怎样分预算

MoE 把参数放进多个专家，每个 token 选择少数专家执行矩阵变换；Engram 把参数放进许多表行，每个 token 选择少数行读出。二者都允许总参数远大于当前激活参数，但激活后执行的工作不同：专家提供上下文相关的非线性计算，表提供可复用的局部表示。

用 \(P_{tot}\) 表示除基础词表 embedding 与输出头之外的总参数，\(P_{act}\) 表示每 token 激活参数的统计量，记 \(P_{sparse}=P_{tot}-P_{act}\)。Engram 的容量实验用分配比例 \(\rho\) 划分这部分预算：

$$P_{\mathrm{MoE,inactive}}=\rho P_{sparse},\qquad P_{\mathrm{memory}}=(1-\rho)P_{sparse}.$$

\(\rho=1\) 对应把这部分容量全给 MoE；降低 \(\rho\) 时减少专家总数并增加表行。比较时保持激活计算和训练流程接近，才容易判断结果来自容量用途。以 \(P_{tot}=10\)B、\(P_{act}=1\)B 的示例预算，\(\rho=0.8\) 分给未激活专家 7.2B、记忆 1.8B 参数。这个简化账本还需细化投影、路由和查表通信成本。

原研究在约 5.7B 与 9.9B 的总参数配置、各自固定 FLOPs 预算下扫描比例，观察到验证损失随分配出现 U 形，较优区域把约 20%–25% 的稀疏预算给记忆。这个结果支持同时扩展两类容量；最佳比例仍与主干、数据和训练长度相关。工程预算还需把表字节和激活流量单列。

局部记忆也有不同来源。OE 直接学习 token 组合表并在输入端融合；SCONE 用单独的模型学习 frequent n-gram 表示，训练后预计算并存到加速器之外；Engram 直接学习多头表，在中间层由上下文门控。比较三条路线时，应把额外编码器训练、离线生成表、参数容量和在线计算分别计入预算，才能看清资源从何处转移到何处。

为什么插入位置会影响有效深度

较早注入记忆，可以让后续层更早获得局部模式；但早层隐藏状态聚合的上下文较少，门控判断也较粗。较晚注入拥有更成熟的上下文，却让前面许多层已经做过局部组合。插入层的选择需要在这两种作用之间实验比较。

有效深度可以用可观察量描述。第一种方法是把中间隐藏状态送入最终 LM head，比较该层预测分布与最后一层分布的 KL 距离，观察“预测准备程度”沿深度怎样变化。第二种方法比较不同模型、不同层的表示相似性：对齐同一组样本，计算 CKA，再观察 Engram 某层最接近基线哪些层。

原研究在实体末 token 的表示上观察到层间对齐偏移，例如 Engram 第 5 层接近基线约第 12 层；这为“更早形成实体表示”提供了机制证据。评估能力时还应做局部模式、长程组合和任务结果的对照：固定插入参数量，扫描层位置，再观察表示变化是否伴随验证与推理任务改善。

这条问题线还可以延伸到沿深度读取信息：连接方式改变中间表示怎样被后层使用，条件记忆改变部分表示从哪里得到。二者能够互补，实验则需要分别控制连接结构与新增记忆。

预取窗口怎样变成吞吐

一张 100B 参数的 BF16 表有 200 GB 权重，但每个 token 只读固定数量的行。假设 bigram、trigram 各 4 个头，每行 128 个 BF16 元素，那么每 token 读取 \(8\times128\times2=2048\) B。512 个新 token 的原始读出量是 1 MiB，与表总行数分开变化。

把表放在主机内存，GPU 只接收本次激活的行，可以缓解 HBM 容量压力。其时间模型是：

$$t_{fetch}=t_0+\frac{B_{fetch}}{\beta},\qquad \htmlData{symbol=stall}{t_{stall}}=\max(0,t_{fetch}-t_{before}).$$

\(t_0\) 汇总调度、查表与传输启动延迟，\(B_{fetch}\) 是本次取回字节，\(\beta\) 是有效传输带宽，\(t_{before}\) 是 Engram 前面的 GPU 计算窗口。请求顺序已知后，CPU 可以先计算哈希与准备向量；GPU 同时执行前置层，等到使用记忆时只支付未被覆盖的部分。

默认 512 个 token、插入第 4 个 block，传输约需 \(8+1,048,576/(25\times10^9)\times10^6=49.94\) μs，前置窗口为 45 μs，剩余等待约 4.94 μs。移到第 5 个 block 后，60 μs 的窗口可覆盖这份取数；增加 batch 后，应重新测量字节量与前置层耗时。

现实中 batch 同时影响传输与计算，热点缓存也会减少主机读出量。每次预取可以记录地址准备、主机 gather、DMA、GPU 等待和模块计算的时间线，检查重叠发生在哪一段。预取太晚会暴露延迟，过早取回大量层的向量则会增加临时缓冲。根据实际插层位置限制在途请求，可以同时控制容量与等待。

Engram 的主机卸载实验使用 H800、512 条序列、100–1024 tokens 的均匀长度分布，在 4B 与 8B dense backbone 的第二个 block 插入一张完全位于 host DRAM 的 100B 参数表。该配置中报告的最大吞吐损失约 2.8%。部署评估可沿 batch、上下文长度、PCIe 带宽和插入位置扫描，用相同请求比较吞吐与 token 延迟，找到本机能够隐藏取数的区域。

从模块正确到系统有效

训练时的大表通常按行分片，通过 all-to-all 取回激活行并送回梯度。推理时表冻结，可以按访问频次设计 HBM 与 host DRAM 的缓存。对长尾模式，更大的表扩充容量；对高频模式，缓存减少重复传输。命中率应按实际读出字节统计，并与行热点、batch 和请求来源一起观察。

先做模块级检查：规范化映射固定，哈希和边界一致，门控公式与精度一致，整段与流式输出一致。再做受控质量比较：相同主干与训练预算，分别改变表长、阶数、门控、卷积和插入层。最后将选定结构接到服务负载，记录吞吐、延迟和峰值内存。每一步都有可独立观察的数值，方便定位质量收益和工程收益来自哪里。

计算与诊断

1. 算出门与写入量

二维 h=[0,1]、k=[1,0]、v=[1,2]，RMSNorm gain=1、epsilon=0。求论文公式的门 a 与短卷积前的残差输出 h+av。再把 h 换为 [1,0]。

展开解答

正交时归一化点积为 0，门为 0.5，写入 [0.5,1]，输出 [0.5,2]。同向时 \(s=\sqrt2\)，\(a\approx0.80443\)，写入约 [0.80443,1.60886]，输出约 [1.80443,1.60886]。

2. 表容量与每步流量

一张合计 100B 参数的 BF16 记忆，最大阶数 3、每阶 4 个头、每行宽 128。总容量多少 GB？512 个 token 要读取多少 MiB？忽略缓存与重复请求合并。

展开解答

总容量 \(100\times10^9\times2=200\) GB。每 token 读 8 行，共 2048 B；512 个 token 为 1,048,576 B，即 1 MiB。总容量决定表的安放位置，激活流量决定每步需要搬多少数据。

3. 最早能隐藏传输的插入层

读取 2 MiB，带宽 25 GB/s，固定开销 8 μs，每 block 为 15 μs。假定输入确定时立刻取数，最早在第几个 block 插入才能隐藏取数？

展开解答

取数时间约 \(8+2,097,152/(25\times10^9)\times10^6=91.89\) μs。需要至少 \(\lceil91.89/15\rceil=7\) 个前置 block，因此最早在第 8 个 block。建模收益若偏好更早位置，可考虑减少读出字节、提高缓存命中或传输带宽，并重新测量门控与系统效果。

4. 切块后头几个输出发生变化

最大 n-gram 阶数为 3，卷积 w=4、dilation=3。整段计算正确，分成两个 chunk 后第二块开头不一致。应该保留哪些状态，怎样区分哈希与卷积问题？

展开解答

保留上块最后 2 个 canonical IDs，以及最后 9 个归一化门控 value。先比较第二块开头的每个哈希行号；行号不同就检查 ID 缓存与 padding。行号、key、value、门都一致后，再比较卷积输入及 t−3、t−6、t−9 的读取。用恒等门控和固定卷积核分别隔离两条路径，并检查每个请求独立维护状态。

核对门控、流式更新和预取

下载 NumPy 实验并运行 python3 lab.py --seed 7。实验用有限差分检查归一化门控的梯度，比较论文门与官方演示的 logit 变换，核对两种切块方式下的 suffix 哈希与 dilated causal convolution，并验证预取与容量算例。

默认输出应显示同向门约 0.80443、官方演示门约 0.76660；分块与整段卷积最大差接近 0，默认预取等待约 4.94 μs。将 --chunk 7 改为 1 或 4，流式结果应保持一致；把最近 ID 或卷积历史清零，可以主动复现边界误差。实验在 CPU 上验证数值与状态；H800 吞吐来自参考论文的指定配置。
