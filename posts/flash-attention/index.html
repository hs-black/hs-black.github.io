FlashAttention 1、2、3

交互2026-10-20更新于 2026-10-22

Attention 的计算量随序列长度平方增长，但显存里最昂贵的对象往往是那张同样按平方增长的分数矩阵。FlashAttention 把计算拆成能放进片上存储的小块，一边读取 Q/K/V，一边更新输出，从而减少大中间结果在 HBM 与计算单元之间的往返。

三代实现沿着同一条数学基础继续优化：第一代解决中间结果的 IO，第二代改善 GPU 工作划分，第三代进一步利用 Hopper 的异步搬运、矩阵乘和低精度硬件。理解这些层次，就能判断某个形状为什么受益，以及哪种瓶颈仍留在整层模型里。

大矩阵搬运怎样成为开销

对一个头，设 \(Q,K\in\mathbb R^{N\times d}\)、\(V\in\mathbb R^{N\times d_v}\)。标准 attention 为：

$$S=\frac{QK^\top}{\sqrt d},\qquad P=\operatorname{softmax}(S),\qquad O=PV.$$

\(N\) 是序列长度，\(d\) 是 query/key 每头维度，\(d_v\) 是 value 每头维度。朴素分阶段实现先写出分数 S，softmax 读取 S 并写出 P，矩阵乘再读取 P。若 \(N=16384\)、中间矩阵使用 2 B 元素，一张矩阵占 512 MiB；这两次写和两次读合计约 2 GiB/头。

最终需要的是 \(N\times d_v\) 的输出。把 Q 保留一小块，依次扫描 K/V 块，只保留当前输出的部分和，就能缩短这些大中间结果的生命周期。关键问题变成：尚未看到所有分数时，怎样正确进行 softmax？

在线 softmax 保存三个量

先看一个 query 对应的一行分数 \(s_j\)。已经扫描的部分用三个量概括：最大值 \(m\)，指数和 \(\ell=\sum_j e^{s_j-m}\)，加权分子 \(u=\sum_j e^{s_j-m}v_j\)。输出是 \(u/\ell\)。其中 \(u\) 是 \(d_v\) 维向量，\(m,\ell\) 是标量。

读取新块后，新最大值为 \(m'=\max(m,\max s_{new})\)。旧指数需要统一换到新尺度，乘上 \(\alpha=e^{m-m'}\)，然后加入新块：

$$\ell'=e^{m-m'}\ell+\sum_{j\in new}e^{s_j-m'},\qquad u'=e^{m-m'}u+\sum_{j\in new}e^{s_j-m'}v_j.$$

分子和分母一起重新定标，保持最终加权平均一致。所有块处理完后只除一次；整个过程中始终保留有限大小的状态。

块 A 的状态是 \((\ln2,1.5,5)\)，块 B 是 \((\ln4,1.75,12.5)\)。合并时，块 A 换到最大值 \(\ln4\) 的尺度，两项都乘以 \(e^{\ln2-\ln4}=1/2\)。最终 \(\ell=0.75+1.75=2.5\)，\(u=2.5+12.5=15\)，所以输出为 6。

若先把两个块分别归一化，再直接平均局部输出，会丢失每块的指数质量。正确的合并必须携带最大值与未归一化的分子、分母。PagedAttention跨物理页读取时也可以利用同一个恒等式。

Mask 怎样进入分块计算

Mask 在取块最大值之前作用于分数。因果模型的条件是 key 的逻辑位置不超过 query 的逻辑位置；最后一个不满块还要检查实际长度。整块都无效时直接跳过更新，避免计算无意义的 \(-\infty-(-\infty)\)。整行无有效位置时，调用方和 kernel 需要约定返回值。

非方形 attention 特别值得测试：已有 3 个历史位置，本次新增 2 个 query，总 key 长度为 5，正确可见行分别是 [1,1,1,1,0] 和 [1,1,1,1,1]。FlashAttention 2.1 起，非方形 causal mask 采用右下对齐；调用其他接口时应按它的具体对齐约定构造逻辑位置 mask。

# Q: [B, H, 2, d]；K/V 含 3 个历史位置和 2 个新增位置
q_pos = torch.arange(3, 5, device=q.device)
k_pos = torch.arange(5, device=q.device)
allowed = k_pos[None, :] <= q_pos[:, None]
out = torch.nn.functional.scaled_dot_product_attention(
    q, k, v, attn_mask=allowed, dropout_p=0.0, is_causal=False
)

这里布尔 mask 的 True 表示允许参与计算。这个小张量适合先与手写 dense 参考对照；生产中的规则可以交给支持对应语义的 fused backend。更多缓存坐标检查见 KV cache 的位置与 mask。

反向传播怎样重建需要的概率

前向保留输出 O 和每行 log-sum-exp：\(\mathrm{LSE}_i=m_i+\log\ell_i\)。反向需要某个概率 tile 时，重新计算分数，然后恢复 \(P_{ij}=e^{S_{ij}-\mathrm{LSE}_i}\)。这样用重算换掉整张 P 的存储。

设输出梯度为 \(G=\partial\mathcal L/\partial O\)。首先 \(dV=P^\top G\)，而 \(dP=GV^\top\)。Softmax 的每行梯度为：

$$dS_{ij}=P_{ij}\left(dP_{ij}-D_i\right),\qquad D_i=\sum_jP_{ij}dP_{ij}=\sum_c O_{ic}G_{ic}.$$

最后一个等式让公共项 D 直接由输出与输出梯度计算。随后 \(dQ=dSK/\sqrt d\)，\(dK=dS^\top Q/\sqrt d\)。Mask 对应的概率为 0，相关梯度贡献也为 0。检查时可以验证每行 dS 的和接近 0，再用有限差分独立核对 dQ、dK、dV。

Tile 大小受哪些资源约束

更大的 tile 能复用更多数据，也会占用更多片上资源。以 \(B_q=B_k=64,d=d_v=128\) 为例，BF16 的 Q、K、V 三块共 48 KiB；FP32 输出累加器含 \(64\times128\) 个元素，占 32 KiB。Score tile、softmax 状态和双缓冲还会增加资源需求。实际实现把这些对象分布到寄存器与 shared memory，生命周期也可以重叠。

把 \(B_q\) 加倍，输出累加器与 Q 块随之加倍，可能降低每个 SM 同时驻留的 block 数。若寄存器不足产生 spill，部分中间值会重新进入显存路径。选 tile 时应同时看运行时间、寄存器数量、shared memory 用量与活跃 block 数。

GQA 会进一步影响 tile 组织。多个 query 头共享一个 KV 头，若同一份 K/V 被加载后服务整组 query，就能提高每字节完成的计算量。若实现把 K/V 显式复制成 query 头数再执行，额外的写入与读取会改变带宽账本。可以从缓存实际 shape、临时张量与 profiler 的内存流量检查这一步，并分别测试不同的 query/KV 头比例。

很长历史的 decode 还可能把 key 维拆成多个独立任务，各自计算部分最大值、指数和与输出分子，再进行一次稳定合并。这增加了并行度，也增加部分结果写回和合并开销。历史较短时，单个任务可能已经足够；历史变长后，split-KV 才更容易覆盖 GPU 的计算资源。选择阈值应同时考虑 batch、头数和每行历史长度。

从 FA1 到 FA2、FA3

FA1 的核心收益是分块融合与在线归一化。FA2 继续减少非矩阵乘开销，并沿 query 序列划分更多独立任务。例如 batch=1、8 个头、长度 4096、query tile=128，可以形成 \(1\times8\times32=256\) 个 query 任务。更多任务有助于覆盖多个 SM，warp 之间按 Q 行分工还能减少共享输出的归约。

FA3 面向 Hopper 的异步执行能力。TMA 把 K/V 从 HBM 搬进 shared memory，WGMMA 把矩阵乘交给 Tensor Core；softmax 的归约、缩放与指数则使用普通计算单元和特殊函数单元。异步提交后，线程可以继续推进独立工作，因此三类操作有机会重叠。

Producer 先等待某个输入缓冲可以复用，再发起 TMA；consumer 等待数据到齐后提交 WGMMA，并在相关矩阵乘消费完成后释放缓冲。这个“可覆盖 → 数据到齐 → 消费完成”的顺序保护每块 K/V。与此同时，一个 warp group 计算 softmax 时，另一个 warp group 可以执行矩阵乘；同一组内也能把不同 tile 的矩阵乘与 softmax 交错。保留更多未完成的累加器会增加寄存器压力，因此要一起核对 Tensor Core 利用率、同步等待和寄存器用量。

四块串行需要 \(4(4+6)=40\) 个单位；理想重叠需要首块的 \(4+6\)，再加三次 \(\max(4,6)\)，合计 28。这个模型保留启动与排空成本，适合解释短序列为什么难以达到稳态流水效率。

FA3 的 FP8 路径进一步利用硬件吞吐。分块 scale 控制数值范围，异常值分散与较高精度的归一化状态帮助控制误差。FP16/BF16 路径与 FP8 路径应分别评估精度和吞吐，选择时同时确认 GPU 架构、头维度、前反向和 mask 的支持范围。

实际调用怎样测到正确的收益

先确认真正运行的 backend。高层 SDPA 接口会根据 dtype、形状、stride、mask 和设备选择实现。固定同一输入，比较数学参考与候选 fused kernel 的输出；再在 profiler 中记录 kernel 名称。执行路径明确后，先热身处理编译和初始化，再用 CUDA events 包住设备计算，批量重复后读取时间。

小 batch decode 的 query 长度通常为 1，可并行的 query tile 很少，读取长 KV 可能主导时间。Prefill 有大量 query 行，矩阵乘效率更容易成为关键。测试矩阵应同时覆盖这两种场景、尾块长度、GQA 头比例和真实 head dim；把两者混成一个平均加速比，会掩盖部署中的主要负载。

数值比较还要固定 dropout。推理路径显式使用 dropout_p=0.0；训练时保存或恢复一致的随机语义。不同融合与分块顺序带来浮点舍入差异，可以用绝对误差和相对误差容忍度检查；出现大幅漂移时，优先核对 mask、缩放因子、输入轴与累计精度。

最后把 attention 的局部收益放回整层。若 attention 占整层时间 20%，即使它加速 2 倍，整层加速也只有 \(1/(0.8+0.2/2)\approx1.11\) 倍。把投影、MLP、通信和 CPU 调度分别计时，才能决定下一步优化应落在哪一段。

可以把正确性测试做成有明确辨别力的输入。令被 mask 的 V 全部变成很大的数，有效输出应保持不变；令所有 logits 相等，输出应是可见 V 的平均值；把最后一个 key tile 切成不满块，检查尾部是否被意外纳入。再分别改变 block 大小与共同的 logit 偏移，归一化输出应在浮点容忍度内一致。这些测试比仅用一个随机张量更容易定位边界与归一化问题。

训练反向还可以检查每个输入的梯度。用一个很小的注意力层定义标量损失，逐个扰动 Q/K/V 中的元素，比较中心差分与 fused backward。前向一致而 dQ/dK 偏差明显时，检查分数缩放和 mask；dV 偏差时检查概率恢复与块累加。小规模 FP64 参考帮助定位数学与索引，大规模低精度测试再衡量实际误差范围。

计算与实现练习

1. 合并两块 softmax

A 的状态为 (ln2,1.5,5)，B 为 (ln4,1.75,12.5)。合并输出是多少？

展开解答

A 换到 ln4 的尺度，指数和与分子乘 1/2，得到 (ln4,0.75,2.5)。相加后为 (ln4,2.5,15)，输出 6。

2. 从概率计算分数梯度

P=[0.25,0.75]，dP=[2,−1]。求 D 和 dS。

展开解答

D=0.25×2+0.75×(−1)=−0.25。dS=[0.25×2.25,0.75×(−0.75)]=[0.5625,−0.5625]，行和为 0。

3. 整层时间的上限

整层原来 10 ms，其中 attention 2 ms。优化后 attention 为 0.8 ms，其余不变。整层加速多少？

展开解答

新时间为 8+0.8=8.8 ms，加速 10/8.8≈1.136 倍。attention 自身加速 2.5 倍，端到端收益由它原来的占比决定。

前向、反向与差分互相对答案

下载 NumPy 实验并运行 python3 lab.py --length 7 --block 3。实验用完整 softmax 对照在线分块前向，再用损失中心差分核对三份输入梯度，同时覆盖因果与非因果模式。把 block 改为 1、4、8，结果应保持一致；随后分别删掉旧状态 rescale 或梯度中的 \(1/\sqrt d\)，观察哪一组断言最先定位问题。
