Gradient checkpointing

交互2026-10-19更新于 2026-10-22

训练一个 Transformer 时，参数和优化器状态常驻显存，而前向产生的中间值会逐层积累：反向还需要它们计算梯度。一个 batch 能完成前向，却在反向前后触发 OOM，往往就发生在这些保存值与临时工作区叠加的时刻。

Gradient checkpointing 把“保存全部中间值”改成“保存少量入口，反向时重算”。它改变了张量的寿命和计算顺序。理解这项交换，要先写出反向究竟需要哪些值，再选择保存边界，最后验证重算是否还原了同一次前向。

1. 反向为什么需要保存激活

先看一层 \(z=xW\)，\(h=\tanh z\)。其中 x 是一批输入行，W 是该层权重，h 是输出。已知上游梯度 \(g_h=\partial\mathcal L/\partial h\)，反向为

$$g_z=g_h\odot(1-h^2),\qquad g_W=x^\top g_z,\qquad g_x=g_zW^\top.$$

计算这一层的参数梯度需要输入 x，计算 tanh 的导数需要输出 h。前向完成时如果把它们丢掉，反向就必须从更早的某个已保存状态恢复它们。激活重计算正是利用这条依赖关系安排存储。

把 L 层串成 \(h_{i+1}=f_i(h_i;W_i)\)。完整保存的方案保留每层反向所需的激活，前向越往后，存储越多；反向从最后一层往回推进，用完一层便释放它对应的保存值。权重、梯度、优化器状态有各自的生命周期，计算激活收益时要单独列账。

2. 保存入口，反向恢复当前段

将网络按 k 层一段划分。前向只长期保存每段入口，输出交给下一段后释放内部中间值。反向到达某一段时，读取该段入口，再跑一次段内前向，随后立即反向并释放恢复出的中间值。

关键是把重算限制在当前反向所需的区段。若每次反向一层都从整网输入重新跑到这里，早期层会重复执行很多次。分段方案让每段内部通常重算一次，额外工作近似为一轮前向。

3. 为什么最优段长取决于入口大小

令 \(\htmlData{symbol=layers}{L}\) 为层数，\(\htmlData{symbol=entry}{c}\) 为一个段入口占用的字节数，\(\htmlData{symbol=activation}{A}\) 为每层恢复出的内部激活字节数。采用等长段时，一个便于选候选配置的模型是

$$M_{act}(k)\approx\left\lceil\frac{L}{\htmlData{symbol=segment}{k}}\right\rceil c+kA.$$

第一项是长期保存的段入口，第二项是正在重算的一个区段。减小 k 会增加入口数量；增大 k 会增加当前段的瞬时存储。忽略整数边界，对 \(Lc/k+kA\) 求导，得到 \(k^*=\sqrt{Lc/A}\)。当 c=A 时才化为熟悉的 \(\sqrt L\)。

这组参数下，k=2 与 k=3 都是 640 MiB，k=1 为 896 MiB，k=4 为 704 MiB。连续最优点约 2.45，所以从 2、3 开始实测很合理。实际模型中，各层尺寸、最后一段、输出保留和 kernel workspace 都会影响峰值，应把公式用作候选筛选，再测真实执行。

时间也可以列账。若一轮前向为 F，反向约为 2F，普通训练约 3F；完整重算一轮前向后约为 4F，即计算量增加约 33%。选择性重算会少于一整轮，编译、通信和内存压力又会改变实际时延。固定序列长度时，可以按样本/s或等价的tokens/s评价最终收益：checkpoint 让 micro-batch 从 1 增到 2，step 从 80 ms 增到 130 ms 时，吞吐从 12.5 增为 15.38 样本/s。

4. Transformer 的中间值并不等大

对传统保存 attention 分数矩阵的实现，某些激活按 \(BS^2H\) 增长：B 是 batch，S 是序列长度，H 是 query 头数。残差和线性层输入则主要按 \(BSD\) 增长，D 是模型宽度。长序列下，重算一个相对便宜而占空间很大的 attention 中间值，比重算整层矩阵乘法更划算。

在一组采用混合精度、标准 attention 保存策略的 Transformer 账本中，每层激活可以写为 \(BSD(34+5HS/D)\) 字节。这个表达式把线性增长与平方增长分开，具体系数对应那套保存与 dtype 选择。换成 FlashAttention 后，完整 \(S\times S\) 分数不再写回 HBM，应按新 kernel 的保存项重新计算。

选择性 checkpoint 按算子选择保存或重算：昂贵的 GEMM 输出可以保留，便宜的逐元素结果可以恢复；FlashAttention 自身也会在反向恢复局部概率。组合策略时，先确认 kernel 已经重算了什么，再决定外层区段的边界，才能避免把大段高代价计算重复执行。

5. 重算要还原同一次计算

PyTorch 的常用接入方式是显式选择 non-reentrant 路径：

from torch.utils.checkpoint import checkpoint
h = checkpoint(block, h, use_reentrant=False,
               preserve_rng_state=True)

non-reentrant 路径记录 autograd 图，并可在恢复出反向所需张量后提前停止重算；它也支持更灵活的嵌套输入与求导方式。旧式 reentrant 路径在原前向中使用 no_grad，并要求至少一个输入和输出参与梯度。冻结 embedding、只训练区段内部 adapter 时，输入可能没有梯度要求，使用 reentrant 就可能出现所有内部梯度为空的现象。

遇到 None of the inputs have requires_grad=True 或 does not have a grad_fn，先用同一个小 batch 比较关闭 checkpoint 与 non-reentrant 模式，打印首个 checkpoint 输入和内部可训练参数的梯度。区段入口的梯度需求与区段内部参数的梯度需求分别检查：冻结 embedding 让入口张量不带梯度，内部 LoRA 参数仍然需要被计算图记录。验收要逐个核对这些参数，确认重算前后的梯度范数和更新量一致。

随机操作是另一个边界。Dropout 的前向为 \(h=m\odot x/(1-p)\)，反向需要同一个 mask m。若 p=0.5，原 mask=[1,0]、上游梯度=[1,1]，正确输入梯度为 [2,0]；重算时换成 [0,1] 就会得到 [0,2]。checkpoint 保存并恢复受支持设备的 RNG 状态，Python/NumPy 等外部随机源则需要显式管理。

被重算函数还应保持可重复的状态读取。计数器自增、队列出入、缓存写入、BatchNorm 运行统计等副作用应移到清楚的外层生命周期，或提供与重算兼容的设计。non-reentrant 提前停止使“函数恰好执行两遍”的假设失去依据；最可靠的契约是给定相同入口与状态，恢复出相同的反向依赖。

6. 与其他省显存技术配合

FSDP 切分参数、梯度和优化器状态，checkpoint 调整保存激活，两者处理不同项。组合时，重算可能再次触发参数 all-gather。把 checkpoint 边界与 FSDP 单元对齐，检查 profiler 中 gather 次数与位置，可以判断额外时延是否来自通信。

流水线中同时在途的 micro-batch 会各持有一组激活。1F1B 通过尽早执行反向缩短保存期；checkpoint 再降低每组的存储量。前端 stage 通常持有更多在途 micro-batch，因此应逐 stage 测量峰值，按各自的在途数量分配预算。

另一条路线是把保存值 offload 到 CPU，反向前再搬回。传输下界为字节数除以有效带宽，能否隐藏取决于复制和计算重叠。checkpoint 消耗重算算力，offload 消耗主机链路；在相同容量目标下对照两条时间线，选择占用较空闲资源的方案。

7. 测量完整训练 step

先完成若干 warmup，让编译和优化器状态分配稳定，再重置峰值，测量包括 forward、backward 与 optimizer.step 的完整 step。GPU 异步执行需要在计时边界同步：

torch.cuda.synchronize()
torch.cuda.reset_peak_memory_stats()
start = time.perf_counter()
train_step()
torch.cuda.synchronize()
seconds = time.perf_counter() - start
peak = torch.cuda.max_memory_allocated()
reserved = torch.cuda.max_memory_reserved()

allocated 降了而 reserved 没降，通常表示分配器仍保留申请过的显存；结合 memory snapshot 看张量实际寿命。前向峰值下降、反向仍 OOM，重点看重算段长度、GEMM workspace 与 all-gather 的重叠。输出相同而梯度不同，先对照随机掩码、原地写与外部状态，再逐层定位首次差异。

每次比较固定模型、序列长度、精度、数据与训练状态；改变 micro-batch 后也要重新核对有效全局 batch、梯度累积归一化与 optimizer update 次数。显存、吞吐和数值正确性要在同一组条件下成立。

8. 练习与实验

练习 1：最优段长

L=48，c=16 MiB，A=128 MiB。计算 k=1、2、3、4 的容量，并给出首轮实测候选。

展开参考解答

依次为896、640、640、704 MiB。连续解 \(\sqrt{48\times16/128}=\sqrt6\approx2.45\)，首先比较k=2与3，再核对真实workspace和尾段。

练习 2：慢 step 的吞吐收益

micro-batch=1时80 ms，checkpoint后micro-batch=2时130 ms。求样本吞吐变化；若保持全局batch不变，应调整哪项？

展开参考解答

吞吐由12.5变为15.385样本/s，提高约23.1%。将梯度累积步数相应减半，并核对loss按有效样本/token数归一化和学习率调度的更新单位。

练习 3：RNG 与外部状态

dropout p=0.5，原mask=[1,0]，重算mask=[0,1]，上游梯度=[1,1]；函数还执行counter+=1。求错误梯度并修复两处状态问题。

展开参考解答

错误梯度[0,2]，正确值[2,0]。重算复用原RNG状态或显式mask；把外部counter更新移出重算函数，以一次逻辑训练操作管理计数。

python3 -m pip install numpy

python3 lab.py --layers 12 --segment 1

默认重算12层，激活数组峰值由13份变成8份，最终打印 PASS。这里计数的是存活的激活数组，包含保留输出。预测段长1与12分别由哪项主导，再用程序结果验证。
