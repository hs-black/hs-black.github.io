以前的博客停在了 2020 年，那时候还在写 OI 题解。现在的兴趣在大模型上，干脆换一个新的地方重新开始。

为什么不用生成器

Hexo、Hugo 这类工具适合「写 Markdown，统一套模板」。但我想写的东西里，有不少不是纯文字：一个能拖动的参数、一段跟着讲解动起来的图、一套能直接拿去讲的幻灯片。这些东西在 Markdown 里写起来很别扭。

所以这个博客的规则很简单：

  • 每篇文章就是 posts/<名字>/index.html，一个完整的网页，想放什么交互就放什么；
  • 所有页面共用一份样式 assets/site.css，幻灯片再加一个很小的翻页引擎 assets/slides.js；
  • 推到 GitHub 上，GitHub Pages 直接把文件原样发出去，没有构建步骤。

文章和演示主要由 Claude 帮我写，我负责想法和把关。

T 越小，概率越集中在分数最高的「好」上，接近每次都选最可能的那个（贪心解码）；T 越大，分布越平，不太可能的词也会被抽到，输出更有变化，也更容易跑偏。
