Hyper-Connections：从一条残差流到多路信息交换

交互2026-10-22

一个 Transformer 子层刚算出新特征，接下来做什么？最熟悉的答案是直接加回输入：\(x_{l+1}=x_l+F_l(x_l)\)。几十层跑下来，词义、位置信息、推理中间结果全叠进了同一个向量里。下一层拿到的只是这个总和；如果某部分信息想单独留着不被覆盖，只能靠通道维自己切分地盘。

Hyper-Connections（下面简称 HC）换了种做法：给每个 token 多开几条残差流，子层先挑从哪几条读，算完再决定把结果写回哪几条。宽度 4096 的 MLP 输入输出依然是 4096 维，但层间传递的状态可以同时握着四条 4096 维向量。它扩大的不是子层本身的计算宽度，而是跨层暂存和交换信息的草稿纸。这份改动值不值，两件事说了算：多出来的路径到底怎么传信息、传梯度，以及多出来的状态每层在显存里搬进搬出要花多少账。

1. 恒等通路留下了什么

我们把一个 attention 或 MLP 统称为一个子层，用 \(l\) 编号。在 Pre-Norm 结构里，顺手把归一化收进分支函数 \(F_l\)——比如 \(F_l(x)=\operatorname{MLP}_l(\operatorname{RMSNorm}(x))\)——相邻子层的递推就是最标准的残差形式：

$$x_{l+1}=x_l+\htmlData{symbol=branch}{F_l}(x_l),\qquad x_l\in\mathbb R^d.$$

顺着往前展开，从第 \(a\) 层到第 \(b\) 层有

$$x_b=x_a+\sum_{l=a}^{b-1}F_l(x_l).$$

无论隔了多少层，旧状态前面始终挂着系数 1。反过来，反向传播时单层的局部导数是 \(I+J_{F_l}\)（\(J_{F_l}\) 是子层输出对输入的 Jacobian），那个单位矩阵 \(I\) 为梯度留出了一条直达底层的快车道——深层残差网络能训得动，底气就在这儿。

但直接累加也带来一个硬约束：所有历史子层的输出都混在同一条向量里往下传。Pre-Norm 网络做深以后，残差流的范数往往越滚越大，新一层算出的分支相对已有状态占比越来越小，相邻层的表示容易趋同（关于归一化、初始化和残差尺度，可见 深层 Transformer 的稳定训练）。HC 干脆把单条残差拆成多路，不再强迫所有历史输出以相同权重挤在一起，而是让它们在多条流之间各有去处、各有系数。

拿 DenseNet 做个对照，这个想法更好懂。DenseNet 也是为了把历史特征留给后面用，但它靠的是显式拼接，层越深状态越宽；HC 则是维护固定 \(n\) 条流，逐层读写和混合——不管网络堆到多少层，每个 token 的残差状态始终定死在 \(nd\) 个数。

2. 读取、混合与写回

先省掉 batch 和 token 轴，只盯一个 token。把它的多路状态排成矩阵 \(\htmlData{symbol=state}{X_l}\in\mathbb R^{n\times d}\)：一共 \(n\) 行，每行是一条 \(d\) 维残差流。过一个子层时，HC 靠三组连接参数调度信息：读取权重 \(p_l\in\mathbb R^n\)、写入权重 \(q_l\in\mathbb R^n\)（两者都记为列向量）以及残差混合矩阵 \(C_l\in\mathbb R^{n\times n}\)。整个更新拆成两步——先读入子层算分支，再把旧流混合后加上新结果：

$$z_l=\htmlData{symbol=pre}{p_l}^{\mathsf T}X_l\in\mathbb R^{1\times d},\qquad f_l=F_l(z_l)\in\mathbb R^{1\times d},$$ $$X_{l+1}=\htmlData{symbol=mix}{C_l}^{\mathsf T}X_l+\htmlData{symbol=post}{q_l}f_l.$$

第一步（pre）沿流轴做加权求和，把 \(n\) 条流压成一个 \(d\) 维向量喂给子层；第二步里，\(C_l^{\mathsf T}X_l\) 负责保留和交换旧状态，外积 \(q_l f_l\)（post）则把同一个子层输出按不同系数分发回各条流。把第 \(j\) 条新流单独展开看更直观：

$$X_{l+1,j,:}=\sum_{i=1}^n C_{l,ij}X_{l,i,:}+q_{l,j}f_l.$$

看清这里的索引方向：\(C_{ij}\) 的行 \(i\) 是旧流、列 \(j\) 是新流，代表「旧流 \(i\) 往新流 \(j\) 送多少」，所以矩阵乘出来才是 \(C^{\mathsf T}X\)。这和原论文的约定一致；如果你的实现习惯把新流放行上，存下来的矩阵就得转置。\(C\) 是个方阵，转置写反了不会报维度错，只会静悄悄地算歪，写代码时最好把轴名注清楚。

补回前导维度，完整张量的形状通常是 [B, T, n, d]（\(B\) 条序列，每条 \(T\) 个 token）。经过 pre 汇总后变成常规的 [B, T, d]，所以 attention 照旧沿 token 轴交互，MLP 照旧沿通道轴计算。最关键的一点：无论残差开了几条流，子层 \(F_l\) 本身只跑一遍，所有流共享这一次的计算结果。

3. 从普通残差开始学习

引入新结构前，工程上最稳妥的起点是让它在第 0 步就退化成已知好训的基线。把 token 嵌入复制成 \(n\) 份，让所有流在入口处都等于 \(x\)，同时把每层的连接初始化为

$$C_l=I,\qquad q_l=\mathbf 1,\qquad p_l=e_{l\bmod n},$$

其中 \(e_k\) 是第 \(k\) 项为 1、其余为 0 的 one-hot 向量（流索引从 0 算起）。这样每层只挑一条流读入 \(x\)，算完 \(F_l(x)\) 后再原样加回所有流，更新后的每一路都恰好等于 \(x+F_l(x)\)。一路归纳下去，前向激活与标准残差网络完全一致。

之所以按层号轮换读取第 \(l\bmod n\) 条流，而不是所有层都读第 0 条，是为了在反向传播时打破各流的对称性——训练一旦开始，每条流收到的梯度不同，读写权重和混合矩阵自然就会分化。顺带一提，网络最末端的读出方式也算架构定义的一部分：原始 HC 是把各流直接求和再进最终归一化，如果拿一份标准残差权重做严格等价性核对，求和会把状态放大 \(n\) 倍（顺带改变归一化里 \(\varepsilon\) 的相对影响），而用平均读出则可以直接跟单路残差逐位对齐。

上面这套只学固定 \(p,q,C\) 的版本叫静态 HC。如果想让每个 token 根据当下内容动态路由，就得到动态 HC。原始实现先对每条流的 \(d\) 个通道各自做一次 LayerNorm 得到 \(\bar X\)，再算出连接参数的动态偏移：

$$[p\;C]=[p_0\;C_0]+s_\alpha\tanh(\bar XW_\alpha),\qquad q=q_0+s_\beta\tanh(\bar Xw_\beta).$$

这里 \([p\;C]\) 是把列向量 \(p\) 拼在矩阵 \(C\) 左侧，凑成一个 \(n\times(n+1)\) 的大矩阵；对应的投影权重分别是 \(W_\alpha\in\mathbb R^{d\times(n+1)}\) 和 \(w_\beta\in\mathbb R^d\)。虽然同一组投影权重共享给所有流，但每条流归一化后的特征不同，算出来的行系数也就不同。静态基准 \(p_0,C_0,q_0\) 和缩放系数 \(s_\alpha,s_\beta\) 都是可学习参数。

初始化时，静态部分沿用上面的 \((e_{l\bmod n},\, I,\, \mathbf 1)\)，把 \(W_\alpha,w_\beta\) 置零、\(s_\alpha,s_\beta\) 设为 0.01。这样网络起步时就是老老实实的普通残差，之后再慢慢长出依赖内容的动态路由。需要注意，\(\tanh\) 只是把单步的动态偏移压在 \([-s,s]\) 之间，静态矩阵和尺度 \(s\) 自身在训练中仍可自由漂移。而且原始 HC 允许负权重——模型既可以把历史特征叠加起来，也能把它从某条流里减掉。组合更灵活，代价是几十层 \(C_l\) 连乘之后信号可能失控，后面第 5 节会具体算这笔账。

4. 一层怎样选择过去的计算

既然残差从一条变成了 \(n\) 条，一个很自然的问题是：第 \(a\) 层的输出 \(f_a\)，经过若干层流转之后，到底有多少直接进了第 \(b\) 层的输入？顺着更新公式往后推一遍就能写出来：

$$w_{b,a}=p_b^{\mathsf T}C_{b-1}^{\mathsf T}\cdots C_{a+1}^{\mathsf T}q_a,\qquad b\ge a+1.$$

从右往左读这条链子非常清楚：\(q_a\) 把 \(f_a\) 写进各条流，中间一串 \(C^{\mathsf T}\) 按层序不停搬运和混合，最后由第 \(b\) 层的 \(p_b\) 捞出来；两层紧挨着时中间乘积为空，系数直接就是 \(p_{a+1}^{\mathsf T}q_a\)。静态 HC 里这个系数是固定常数，动态 HC 里它只代表这一次前向取到的值——求导时，\(p,q,C\) 自身随输入变化的部分还得另算。

更有意思的地方在于，哪怕只有两条流，HC 就能在「串行」和「并行」两种拓扑之间连续切换。假设第一路原封不动地留着输入 \(h\)，第二路专门用来累加子层输出。第一个子层算出 \(F(h)\) 后只写进第二路，此时状态是 \([h,\;h+F(h)]\)；接着第二个子层按 \([1-\lambda,\lambda]\) 读取，收到的输入就是 \(h+\lambda F(h)\)，算完再写进第二路。最后从第二路读出的结果是

$$h+F(h)+G\bigl(h+\lambda F(h)\bigr).$$

\(\lambda=1\) 时，\(G\) 吃的是 \(F\) 更新完的状态，就是常规的串行堆叠；把 \(\lambda\) 拨到 0，\(F\) 和 \(G\) 都直接看同一个 \(h\)，两层在计算图上就变成并行分支了（当然，这只是数据依赖意义上的并行——如果动态门控本身依赖上一步状态，或者调度器没做并行拆图，运行时依然是顺序执行）。

从更高一层看，HC 是用固定宽度的状态递推，把大量历史输出压缩进可学习的通路里。另一条路子干脆把历史层的候选输出留下来，让当前层直接做跨深度的 attention 来挑（见 Attention Residuals）——前者省显存、每层只读写固定 \(n\) 条流，但远距离历史信息得经过层层矩阵混洗；后者可以直连任意历史层，代价是得把候选存着，跨设备切分时还要多搬历史状态。

5. 梯度沿哪些路径回来

先看静态情况（把 \(p,q,C\) 固定，也先不考虑 attention 带来的跨 token 交叉项）。给当前 token 的输入加一个微小扰动 \(\Delta X_l\)，输出的响应分成两路：

$$\Delta X_{l+1}=C_l^{\mathsf T}\Delta X_l+q_l\,D F_l[z_l]\bigl(p_l^{\mathsf T}\Delta X_l\bigr),$$

其中 \(DF_l[z_l](u)\) 是子层在 \(z_l\) 处沿方向 \(u\) 的方向导数。第一项顺着残差混合直接穿过去，第二项则先按 \(p_l\) 汇总、过一遍子层导数、再按 \(q_l\) 写回各流。如果按通道顺序把每条流拉成一条 \(nd\) 维列向量（即对 \(X\) 按列展平），整个局部 Jacobian 能写得非常干净：

$$J=I_d\otimes C_l^{\mathsf T}+\htmlData{symbol=jacobian}{J_{F_l}}\otimes(q_lp_l^{\mathsf T}).$$

这里 \(\otimes\) 是 Kronecker 积（把左边矩阵的每个标量乘到右边整个小矩阵上）。拿它和普通残差的 \(I+J_{F_l}\) 一对照就明白了：原来那个雷打不动的单位矩阵 \(I\)，现在被换成了 \(C_l^{\mathsf T}\)；而子层的导数 \(J_{F_l}\) 也不再直接加回原处，而是经由秩 1 矩阵 \(q_l p_l^{\mathsf T}\) 分摊到各条流之间。

隐患恰恰出在第一项。普通残差的捷径系数永远是 1，但 HC 里 \(C_l\) 是可学的——暂时把子层置零，跨过 \(L\) 层后状态要连乘 \(C_{L-1}^{\mathsf T}\cdots C_0^{\mathsf T}\)。哪怕每层只是轻微偏离恒等，比如 \(C=1.02I\)，60 层叠下来信号就被放大到 \(1.02^{60}\approx 3.281\) 倍；反过来 \(C=0.98I\)，60 层后只剩 0.298。越深的模型，这个指数放大或衰减越致命。真训出 loss 尖刺或梯度爆炸，光看单层 \(C_l\) 往往看不出端倪，得把跨多层的乘积奇异值和各层状态 RMS 拉出来看。

换到动态 HC，求导还会多出一批走门控的分支。写成方向微分一目了然：

$$\begin{aligned}dX^+={}&C^{\mathsf T}dX+(dC)^{\mathsf T}X+(dq)F(z)\\&+q\,DF[z]\bigl(p^{\mathsf T}dX+(dp)^{\mathsf T}X\bigr).\end{aligned}$$

输入一动，经由动态投影产生的 \(dp,dq,dC\) 全都会跟着动，于是梯度除了走原本的残差直通和子层分支，还会额外穿过三组门控。把 \(C\) 约束在合适的流形上，就能把最危险的那条多层连乘直通路稳住（当然，门控导数和子层本身仍会贡献梯度）——这正是 mHC 要解决的核心问题，顺带还要啃掉多路状态带来的显存带宽开销。

6. 参数很少，为什么仍会变慢

单看参数量和 FLOPs，HC 几乎像白送的：原始动态 HC 的两个投影一共只有 \(d(n+2)\) 个权重，读写和混合的计算量也只按 \(n^2 d\) 走。拿 \(n=4,d=4096\) 算，和动辄 \(d^2\) 级别的稠密投影比简直微不足道。可一旦上 GPU 真跑，模型还是会变慢——卡脖子的不是算力，而是显存带宽和 kernel 启动。残差状态扩成 \(n\) 倍之后，每一层都要反复把这份大张量从 HBM 读出来做归一化、混合、再写回去。

算一笔具体的流量账。取 BF16、\(B=2,T=4096,n=4,d=4096\)，四路状态一共 \(BTnd=134{,}217{,}728\) 个数，占 256 MiB，是单路（64 MiB）的四倍。哪怕只完整读一遍再写回一遍，就要搬运 512 MiB；按大批量 kernel 2 TB/s 的有效带宽估算，光搬数据这一趟下界就得 0.268 ms。而到了短 decode 阶段，token 数少到带宽都喂不饱时，拆散的小 kernel 的 launch latency 又会反过来占大头。

想摸清 HC 在自己硬件上到底慢在哪，最直接的办法是固定 \(B,T,d\)，对比三种实现：普通残差加法、把 pre / mix / post 拆成独立算子、以及把 mix 和 post 融进同一个 kernel。盯着 kernel 数、HBM 读写量和端到端耗时，再把 \(T\) 和 \(n\) 拉大看曲线——大 \(T\) 暴露带宽墙，小 \(T\) 暴露启动开销。mHC 的算子融合正是冲着这笔搬运账去的，它把矩阵混合、分支写回和残差累加塞进一次状态读写，具体做法留到下一篇拆。

除了性能，写 HC 实现还很容易在轴顺序上栽跟头。单元测试里至少要塞两个检查：第一，用非对称的 \(C\) 和各不相同的旧流，拿最朴素的标量循环去对矩阵乘法，防止 \(C\) 的转置写反；第二，测一遍流重编号等变性——任取一个置换矩阵 \(P\)，把状态和连接参数同步换成 \(X'=PX,\;p'=Pp,\;q'=Pq,\;C'=PCP^{\mathsf T}\)，输出必须严格满足 \(X^{+\prime}=PX^+\)。只要 reshape、广播或 matmul 混了轴，这个不变量立刻就会报警。另外，如果为了省事在非 attention 算子里把流轴并进 batch 轴，进入 attention 前一定要先完成 pre 汇总，别把不同流当成不同样本或污染了 token 轴。

最后，评估 HC 划不划算得算两本账：一本定死 token 数和子层配置，看多路残差到底换来了多少 loss 收益；另一本定死总训练时间或算力预算，看扣掉额外 I/O 和通信开销后还值不值。把这两本账摊开比，才不会被「参数几乎没涨」的错觉误导。

7. 计算与设计练习

练习 1：手算一次读写

令 \(X=[2,6]^{\mathsf T},p=[1/4,3/4]^{\mathsf T},q=[1,1/2]^{\mathsf T}\)，\(C=\left[\begin{smallmatrix}0.75&0.25\\0.5&0.5\end{smallmatrix}\right]\)，\(F(z)=2z\)。求输出，以及误用 \(CX\) 得到的结果。

展开完整解答

先算读取 \(z=0.25\times2+0.75\times6=5\)，分支输出 \(F(5)=10\)。按约定用 \(C^{\mathsf T}X=[4.5,3.5]^{\mathsf T}\) 混合旧状态，再加上写入项 \(q f=[10,5]^{\mathsf T}\)，最终输出是 \([14.5,8.5]^{\mathsf T}\)。如果手滑写成 \(CX\)，旧状态会变成 \([3,4]^{\mathsf T}\)，最终算成 \([13,9]^{\mathsf T}\)。正因为 \(C\) 不对称且两条旧流不相等，转置写反才会暴露出来。

练习 2：一份历史输出留下多少

某层用 \(q_a=[1,0]^{\mathsf T}\) 写入。接下来用 \(C=\left[\begin{smallmatrix}0.8&0.2\\0.2&0.8\end{smallmatrix}\right]\) 混合两次，再由 \(p_b=[0,1]^{\mathsf T}\) 读取。这份历史输出的直接贡献系数是多少？

展开完整解答

第一次混合后两路的系数变成 \(C^{\mathsf T}q_a=[0.8,0.2]^{\mathsf T}\)，再混一次变成 \([0.68,0.32]^{\mathsf T}\)，最后 \(p_b\) 读第二路，得到 0.32。按路径拆开更好验证：从第一路出发经过两步走到第二路只有两条路径（\(1\to1\to2\) 和 \(1\to2\to2\)），分别贡献 \(0.8\times0.2\) 和 \(0.2\times0.8\)，加起来正好是 0.32。注意这只是沿残差直达的系数，中间子层还可能经由非线性分支间接把这份信息再传一次。

练习 3：初始化时每条流的梯度

取两路标量，\(C=I,q=[1,1]^{\mathsf T},p=[1,0]^{\mathsf T},F(z)=2z\)。求输出对两路输入的 Jacobian。若上游梯度为 \([1,1]^{\mathsf T}\)，输入梯度是什么？

展开完整解答

直接把两路输出写出来就是 \(y_1=3x_1,\;y_2=x_2+2x_1\)，所以局部 Jacobian 是 \(J=\left[\begin{smallmatrix}3&0\\2&1\end{smallmatrix}\right]\)，回传得到的输入梯度为 \(J^{\mathsf T}[1,1]^{\mathsf T}=[5,1]^{\mathsf T}\)。哪怕前向时两条流长得一模一样，只要只读其中一条，反向梯度也会立刻拉开差距（这就是第 3 节轮换读取能打破对称性的原因）。如果这两路都是从同一个 embedding \(h\) 复制出来的，再往前穿回复制节点时两路梯度相加，得到 \(dL/dh=6\)。

练习 4：比较一次训练的开销

前面 256 MiB 的四路状态跨 pipeline 边界发送，每个 micro-batch 经过该边界一次。链路有效带宽为 50 GB/s，单路基线为 64 MiB。估算额外传输时间，并设计检查是否被计算隐藏的实验。

展开完整解答

四路比单路多传 192 MiB（\(201{,}326{,}592\) 字节），除以 50 GB/s（\(50\times10^9\) B/s），单向传输就多出约 4.03 ms（反向传梯度还有同样一笔）。但这 4.03 ms 会不会真拖慢 step time，得看通信能不能藏进计算里。验证时固定 micro-batch 大小和 stage 切分，打点记录发送开始、接收完成和下游依赖该输入的计算开始三个时间戳，同时扫一遍 micro-batch 数量看 pipeline 气泡变化：如果接收总在下游开工之前结束，开销就被藏住了；一旦下游在干等接收完成，这笔时间就实打实落在了关键路径上。

8. 运行 NumPy 实验

下载 lab.py，在装有 NumPy 的环境里直接跑：

python lab.py

脚本全程用 float64，一口气核对前面推导的几条关键性质：8 层复制流初始化与标准残差的严格等价性、非对称 \(C\) 下显式循环与矩阵乘法的对照、流重编号的置换等变性、练习 2 的两步历史权重，以及静态和动态连接的方向导数。其中导数检验拿解析式去对中心有限差分，动态版本把 LayerNorm 和 pre / post / res 三组门控的导数全包进去了。

跑通后会打印 all checks passed，导数相对误差在 \(10^{-6}\) 以下。想直观感受动态门控导数的分量，可以动手删掉 dynamic 里那项 dc.T @ x 再重跑，看看误差涨了多少，顺手把 scale 从 0.03 往上调，观察漏掉的门控项什么时候开始盖过主项。
