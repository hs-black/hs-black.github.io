IQuest-Q1：Stable SplitNorm、混合注意力与递归 MTP

交互2026-10-23

一个 coding agent 会反复读取代码、运行工具、检查输出，再把新的观察接回上下文。任务越长，模型面对的历史越多；模型越深，每层更新的尺度也越难控制。IQuest-Q1 用 320B 总参数、约 15B 激活参数，把稀疏专家、混合 attention 和稳定训练放在同一套结构里。

有三个数字能抓住这套模型的计算特征：88 层、512K 上下文、每个 token 选择 8 个专家。88 层需要有效地利用深度；512K 需要控制历史状态；8 个专家决定一次前向实际经过哪些权重。沿着一个 token 的计算过程看，这些设计之间的关系会清楚很多。

1. 一个 token 经过哪些张量

主干隐藏维度为 3,072。输入 token 经 embedding 变成一个 3,072 维向量，随后经过 88 层 attention 与 FFN，最后通过独立的 LM head 得到词表上的 logits。

部件 发布模型的配置
主干 88 层，隐藏维度 3,072
Attention 48 个 Query 头，8 个 KV 头，每头 128 维
全局与局部 25 层 full attention，63 层 sliding-window attention
局部窗口 4,096 token
位置编码 每头 32 维使用 RoPE，其余 96 维保留内容表示
FFN 第 1 层 dense SwiGLU；其余 87 层 sparse MoE
MoE 每层 256 个 routed expert，每个 token 选 8 个；专家中间维度 1,536
Dense FFN 中间维度 12,288
词表与上下文 160,000 词表；发布配置最大上下文 524,288

这里有一个容易影响实现的张量形状：Query 投影的输出宽度是 \(48\times128=6,144\)，KV 投影各为 \(8\times128=1,024\)。Attention 汇总出 6,144 维结果后，输出投影再将它压回 3,072 维。隐藏维度和所有 attention head 拼起来的宽度，各自承担不同的接口。

8 个 KV 头由 48 个 Query 头共享，每组 6 个 Query 头。这是 GQA 在头维度上的共享。SWA 则限制某一层能读取哪些历史位置：每个 Query 只访问当前位置及窗口内的历史。两种节省可以同时使用。

2. Stable SplitNorm：让残差更新保持可见

先看普通 Pre-Norm 的一个 attention 子层。设 \(x\) 是输入隐藏向量，\(N\) 是 RMSNorm，\(A\) 是 attention：

$$ h=x+A(N(x)). $$

左边那条残差路径把 \(x\) 原样向后传。随着层数增加，残差流不断累加更新。若将各层更新近似看成尺度相当、相关性较弱的向量，残差范数可能随深度增长，而后面一层加入的更新保持在相近尺度。更新相对于当前状态的比例于是变小。这会表现为后面一些层对输出的改变越来越弱；具体模型可以用删层实验、残差更新比和隐藏表示相似度来测量。

SplitNorm 在 attention 入口处先归一化整条流，再从归一化后的状态建立残差：

$$ z=N_{\rm in}(x),\qquad h=z+A(z),\qquad y=h+F(N_{\rm ffn}(h)). $$

这里 \(F\) 是 FFN。Attention 周围的残差起点是 \(z\)，FFN 周围的残差起点是 \(h\)。把这两个起点标出来，就能看清它怎样处理深度：每个普通 block 开始时重新控制主流尺度，同时让 FFN 的更新通过加法进入下一状态。

Stable SplitNorm 再对 attention 的输出做 RMSNorm。将发布实现中的分支尺度也写出来，一个普通 block 是

$$ \begin{aligned} z&=N_{\rm in}(x),\\ h&=z+s_A N_{\rm attn}(A(z)),\\ y&=h+\htmlData{symbol=ffn-scale}{s_F} F(N_{\rm ffn}(h)). \end{aligned} $$

\(s_A,s_F\) 分别是 attention 与 FFN 的输出尺度，\(N_{\rm attn}\) 的 gain 也是模型参数。发布配置里，普通层的 attn_out_scale 为 1，ffn_out_scale 约为 0.5388。部署时按 checkpoint 的 Norm 参数与这些 scale 执行。

RMSNorm 自身的运算是

$$ N(x)=\gamma\odot\frac{x}{\sqrt{d^{-1}\sum_{i=1}^{d}x_i^2+\epsilon}}, $$

其中 \(d\) 是向量宽度，\(\gamma\) 是逐维可学习 gain，\(\epsilon\) 用于稳定分母。Attention 输出的 RMSNorm 控制的是这一整次更新的尺度；FFN 的输出尺度则直接作用于分支结果。

第 1 层承担从 embedding 进入深层主干的过渡，使用单独的 SandwichNorm：保留原输入残差，并对 attention 和 dense FFN 的输出都归一化。后面 87 层使用上述 Stable SplitNorm。实现 block fusion 时应分别检查首层与普通层的残差起点、Norm 位置和缩放顺序。[1–3]

理解深度贡献可以继续看有效深度；RMSNorm 的归约与数值实现见 RMSNorm 算子。

3. 3 层局部、1 层全局，为什么一共是 25 层全局

模型的前两层和最后两层使用 full attention。中间的 84 层重复 21 组“3 层 SWA + 1 层 full attention”，所以

$$ L_{\rm full}=2+21+2=25,\qquad L_{\rm local}=21\times3=63. $$

局部层让大部分 token 混合集中在最近 4,096 个位置；周期性的全局层负责从完整历史提取信息。经过全局层汇总的信息，可以继续进入后面的局部计算。首尾的额外全局层也参与模型的完整信息流。

长上下文 decode 时，局部层保存最近一个窗口的 K/V，全局层保存完整历史。于是缓存增长速度由 25 层全局 attention 主导。只在 attention mask 上屏蔽旧 token，显存占用仍取决于后端是否真的回收对应的缓存块。

4. Query-aware sink：允许一次 attention 少取一些历史信息

普通 softmax 的权重和为 1，即使当前 Query 与所有历史内容都不太相关，它也会将全部权重分给这些位置。给 attention 增加一个可学习的 sink key，并把它的 Value 设为零，就给了这次查询一个可调节的出口。

固定一个 Query 头，设历史位置 \(j\) 的 attention logit 为 \(a_j=q^\top k_j/\sqrt{d_h}\)，其中 \(d_h=128\)。对应 Value 为 \(v_j\)。Sink 的 logit 是 \(a_\star=q^\top k_\star/\sqrt{d_h}\)，其 Value 为零。输出变成

$$ o=\frac{\sum_j e^{a_j}v_j}{e^{a_\star}+\sum_j e^{a_j}}. $$

Sink 进入了 softmax 的分母。它获得越多权重，历史 Value 的总贡献就越小。因为 \(a_\star\) 随 Query 改变，不同 token、不同 Query 头可以选择不同强度的历史更新。

这个设计还能与普通 attention kernel 组合。令真实历史上的 log-sum-exp 为 \(\ell=\log\sum_j e^{a_j}\)，普通 attention 输出为 \(o_0\)，则

$$ o=\frac{e^\ell}{e^\ell+e^{a_\star}}o_0 =\sigma(\ell-a_\star)o_0. $$

\(\sigma\) 是 sigmoid。也就是说，kernel 返回普通 attention 的输出和 LSE 后，可以计算一个标量门来得到带 sink 的结果。公开实现正是利用这种关系：保留稳定的 softmax 归约，再补上 sink 对归一化分母的贡献。[3][4]

发布实现为每个 KV 头保存一个 128 维 sink key，同组的 6 个 Query 头共享它，各自计算自己的点积。计算使用经过 QKNorm 和 partial RoPE 的 Query。Sink key 属于模型权重，其存储大小随层数和头数确定。

这里的门作用于单个头的 Value 聚合。各头随后拼接、经过输出投影，再进入 Stable SplitNorm 的输出 RMSNorm。不同头的门会改变合成向量的方向；若所有头恰好同时乘上同一个正数，忽略 \(\epsilon\) 时，后续 RMSNorm 会消去这次共同的幅度变化。因此观察完整 block 时，要同时看各头的相对贡献和归一化后的分支方向。

一个实用的核对方法是：先把 sink key 与零 Value 显式拼进小型 attention，作为参考结果；再检查 LSE 缩放版本是否一致。后面的 CPU 实验会完成这项比较，包括极大 logits 与被 mask 的位置。

5. QKNorm、Partial RoPE 和 FP8 要怎样接起来

Query 和 Key 的范数都会影响点积的大小。点积尺度过大时，softmax 很容易集中到极少数位置。QKNorm 在每个头内部归一化 Q/K，再进行位置变换和打分，使注意力尺度更容易控制。

训练中的 QKNorm Clip 进一步约束 Norm 的 affine 参数，上限设为 10。这个约束作用在可学习的归一化参数上。检查训练稳定性时，可以同时记录 gain 的分布、Q/K 范数、attention logit 的范围和梯度峰值，判断放大来自哪一环。

每个头的 128 个维度里，前 32 维应用 RoPE。将向量分成位置部分 \(q_p,k_p\) 与内容部分 \(q_c,k_c\)，第 \(t\) 个 Query 对第 \(j\) 个 Key 的点积可写成

$$ (R_tq_p)^\top(R_jk_p)+q_c^\top k_c. $$

\(R_t,R_j\) 是对应位置的旋转。前一项携带相对位置信息，后一项保留内容匹配。SWA 使用 10,000 的 RoPE base，全局层在最终长上下文配置中使用 1,000,000；两类层分别适配窗口内关系和长距离关系。[1][2]

低精度 kernel 又增加了一层数值约定。例如按 \(q\approx s_q\hat q\) 量化 Query，其中 \(\hat q\) 是 FP8 表示，\(s_q\) 是反量化尺度。Attention kernel 可能已经正确处理了这个 scale，但旁路计算 sink logit 时仍需要使用恢复尺度后的 Query：

$$ a_\star=\frac{(s_q\hat q)^\top k_\star}{\sqrt{d_h}}. $$

若省去 \(s_q\)，sink 获得的概率会变化，最终输出门也随之变化。GQA 下还要核对 scale 究竟按 Query 头还是 KV 组存放。公开 vLLM 插件的测试覆盖了 FP8 scale、GQA 共享和非连续张量布局；这些都是移植自定义 attention 时值得保留的数值实验。[3]

6. 256 选 8：计算稀疏，权重仍要放得下

第 1 层使用 dense FFN，使初始 token 表示先经过一套公共变换。后面的每层含 256 个专家，router 为当前 token 选择 8 个。每个专家都是 SwiGLU：两条输入投影产生 gate 与内容，逐元素相乘后，再通过输出投影回到隐藏维度。

设隐藏宽度为 \(d\)，专家中间宽度为 \(m\)，忽略 bias 时，一个专家有约 \(3dm\) 个参数。代入 \(d=3,072,m=1,536\)，87 层的 routed expert 权重总量为

$$ 87\times256\times3\times3,072\times1,536\approx315.28\text{B}. $$

专家权重占据了模型的绝大部分。每个 token 只经过少量专家，降低了当前前向的计算量；保存与部署时，整个专家集合仍占用存储。320B 参数按 BF16 粗算为 640 GB 权重。正式的设备容量账本还要加入 KV cache、临时张量、通信 buffer 与递归 drafter。

MoE 的另一个瓶颈是每个专家分到多少 token。假设一批有 \(M\) 个 token，每个路由到 8 个专家，并且负载均匀，则每个专家平均收到

$$ n_{\rm expert}=\frac{8M}{256}=\frac{M}{32}\text{ 个 token}. $$

当 \(M=32\) 时，平均只有 1 个；当 \(M=512\) 时，平均为 16 个。小批量容易落到小矩阵乘法和通信启动开销主导的区域。扩大批量可能改善 GEMM 利用率，也会增加排队和缓存占用。实际调优应一起观察专家 token 分布、grouped GEMM 时间、all-to-all 时间和请求延迟。进一步的跨卡账本见 MoE 与专家并行。

7. 512K 上下文究竟需要多少 KV cache

现在把层数、窗口和 GQA 放到同一个式子里。令 \(B\) 为请求数，\(T\) 为每个请求的历史长度，\(h_{kv}=8\) 为 KV 头数，\(d_h=128\) 为头维度，\(b=2\) 为每个 BF16 元素的字节数，\(W=4,096\) 为窗口大小。逻辑 KV 存储量为

$$ M_{\rm KV}=2\htmlData{symbol=batch}{B} \htmlData{symbol=kv-heads}{h_{kv}}\htmlData{symbol=head-dim}{d_h} \htmlData{symbol=bytes}{b} \left[25\htmlData{symbol=context}{T}+63\min(\htmlData{symbol=context}{T},\htmlData{symbol=window}{W})\right]. $$

最前面的 2 对应 K 和 V。每层每个历史 token 占 \(2\times8\times128\times2=4,096\) 字节。令 \(B=1\)，得到下面的稳态容量：

历史长度 25 层全局 KV 63 层局部 KV 合计
32K = 32,768 3.125 GiB 0.984 GiB 4.109 GiB
128K = 131,072 12.500 GiB 0.984 GiB 13.484 GiB
512K = 524,288 50.000 GiB 0.984 GiB 50.984 GiB

若全部 88 层都保存完整历史，512K 会达到 176 GiB。混合 attention 将这个算例缩减约 3.45 倍。全局层贡献了 50 GiB，因此长上下文下继续压缩局部窗口，对总缓存的影响已经较小。

这些数字采用单请求、局部窗口正常回收、无 padding 的逻辑 K/V；部署另列页块碎片、缓存池分组、prefill workspace 和 MTP 状态。TP=8 且 8 个 KV 头均匀分到各卡时，逻辑主干 KV 约为每卡 6.373 GiB。进一步增加 TP 时，还要查看后端是否复制 KV 头。

一个具体的配置差异是：vLLM 0.30.0 的缓存规格实现保留了“关闭 hybrid allocator、SWA 按全历史分配”的路径，窗口 mask 仍然有效。要获得上表的容量收益，需要让 allocator 按层类型管理并回收旧块。[5]

检验缓存实现，可以固定请求数逐步增长 \(T\)，分别记录 full 与 SWA 的有效缓存块：前者应继续增长，后者达到窗口容量后进入稳定区间。预分配的总显存可能一直不变，因此还要看已使用块数和剩余容量。再比较一次完整 prefill 与分块 prefill 的末端 logits，覆盖窗口边界和 chunk 边界。分页管理细节见 PagedAttention。

8. 跨卡 SWA：只传边界，还要正确合并 softmax

长序列训练可以把连续的 token 分片放在不同 GPU 上。一张卡的内部 Query 能在本地找到整个窗口；靠近分片起点的 Query，还需要前一张卡尾部的 K/V，这一段称为 halo。

设每卡有 \(S\) 个 token，一个 Query 最多访问前面的 \(H\) 个位置。当 \(0<H<S\) 时，一张卡只需要前一分片的 \(H\) 个尾部位置。在发送和接收 halo 的同时，本地 attention 可以先运行：内部 Query 得到完整结果，边界 Query 得到本地部分的结果。

边界 Query 的本地输出与远端输出，各自在自己的 Key 集合上做过 softmax。要把它们合起来，必须同时保留各自的归一化分母。

令 \(o_l,o_h\) 分别为本地和 halo 的已归一化输出，\(\ell_l,\ell_h\) 为各自 logits 的 LSE。全局结果是

$$ \ell=\operatorname{logaddexp}(\ell_l,\ell_h),\qquad o=e^{\ell_l-\ell}o_l+e^{\ell_h-\ell}o_h. $$

这两个系数表示各分片在完整 softmax 分母中占多少比例。指数权重大的分片，对最终输出贡献更大。

如果还包含一个零 Value sink，令 \(a_\star\) 为当前 Query 对 sink key 的 logit，可以在合并真实历史时只计入一次它的指数权重：

$$ \ell=\log\left(e^{\ell_l}+e^{\ell_h}+e^{a_\star}\right),\qquad o=e^{\ell_l-\ell}o_l+e^{\ell_h-\ell}o_h. $$

若每张卡的部分分母都已经包含同一个 sink，再直接累加分母，就会重复计算它。Sink 与 context parallel 的组合，适合用同一个小张量同时跑“完整 attention”和“分片后合并”，比较每头输出及 LSE。

训练系统采用了这种通信与局部计算重叠的设计。实际收益由通信耗时、可重叠的本地计算和边界 Query 占比共同决定。部署时还需对应具体后端能力：所核对的公开 vLLM 插件版本关闭了 context parallel 和 cascade attention，使用该版本服务时应按其已经实现的执行路径规划并行。[1][3]

9. 递归 MTP：一套小模块，连续起草多个 token

主干生成一个 token 后，通常要再次穿过 88 层才能生成下一个。MTP 让一个较小模块先连续起草几个候选，再由主干批量验证，争取用一次大模型前向推进多个位置。

训练时使用两个独立的 MTP 层，为更远的未来 token 提供监督。后续将第一层适配为递归 drafter，使用同一套参数连续生成候选；递归阶段的 attention 窗口缩为 512。

设主干已经处理到位置 \(t\)，最后一层状态为 \(h_t\)，并刚刚采样出下一个 token \(y_{t+1}\)。词嵌入记为 \(E\)。第一次起草将 \(h_t\) 与这个新 token 的 embedding 分别归一化、拼接，再投影到 MTP block 的输入：

$$ u= W_{\rm merge}[N_h(h_t);N_e(E(y_{t+1}))],\qquad \hat h_{t+1}=\operatorname{MTP}(u). $$

随后从 \(\hat h_{t+1}\) 预测候选 \(\hat y_{t+2}\)。下一次起草把 \(\hat h_{t+1}\) 和 \(E(\hat y_{t+2})\) 送回同一个模块，继续预测 \(\hat y_{t+3}\)。固定的一套权重因此可以产生更长候选链。[1][6]

发布 drafter 配置包含 7 个 draft slot。候选链对应的验证前向，还会产生末端的下一个 token 分布，因此要分别记录“起草几个候选”和“验证前向覆盖多少位置”。实际服务中的候选长度是可配置参数，最终能提交多少 token 由接受结果决定。

假设起草 \(K\) 个候选，每一步在此前全部接受的条件下，接受概率近似为 \(a\)。考虑遇到拒绝时的修正 token，或全部接受后的额外 token，一轮平均推进量为

$$ \mathbb E[n]=1+a+a^2+\cdots+a^K. $$

例如 \(K=7,a=0.8\)，平均约为 4.16 个 token。吞吐还取决于起草与验证时间。若单 token 主干耗时为 \(t_b\)，整个候选链耗时为 \(t_d\)，批量验证与调度合计为 \(t_v\)，理想化加速比为

$$ \operatorname{speedup}\approx\frac{\mathbb E[n]t_b}{t_d+t_v}. $$

这几个时间都应在目标 batch 和上下文长度下测量。候选越长，接受前缀可能增加，起草和验证也会更贵。

缓存提交必须跟随接受前缀。Full attention 的新增 K/V、SWA 的窗口槽位、drafter 的状态各自记录已确认边界；验证失败时撤销未接受的位置。

例如，一个容量为 4 的环形窗口保存 \([a,b,c,d]\)，暂时写入草稿 \([e,f]\) 时覆盖了 \(a,b\)。如果第一个候选 \(e\) 就被拒绝，仍然有效的历史应恢复为 \([a,b,c,d]\)。仅缩短长度，无法恢复已覆盖的字节。额外保留 lookahead 空间、把草稿写进临时页，或保存被覆盖内容，都能建立可回滚的状态。滑动缓存与投机 iterator 的接口讨论中，有过这类覆盖后无法 trim 的实际案例。[7]

可以让 prompt 长度跨过窗口边界，强制接受 0 个、1 个和全部候选，再与逐 token 解码比较回滚后的条件分布。这项测试先确认状态正确，然后才比较性能。概率接受规则见投机解码。

10. Muon 与 μP：把小模型找到的尺度迁移过来

残差结构负责控制前向状态，优化器和参数化负责控制每次权重更新。IQuest-Q1 对主要矩阵使用 Muon；embedding、LM head、Norm 和 router 使用 Adam。Muon 对动量矩阵做近似正交化，再按矩阵形状校准更新尺度。

设矩阵尺寸为 \(m\times n\)，正交化后的更新为 \(U\)，其采用的尺度为

$$ \Delta W\propto0.2\sqrt{\max(m,n)}\,U. $$

形状因子让不同尺寸矩阵的更新 RMS 更容易对齐。μP 则规定宽度和深度变化时，各模块的初始化与学习率怎样跟着改变。将隐藏宽度记为 \(d\)、深度记为 \(L\)，这一训练配方的线性层学习率随 \(d^{-1/2}L^{-1/4}\) 缩放，LM head 随 \(d^{-1}\) 缩放；两条残差分支还使用随 \(L^{-1/2}\) 变化的输出尺度，attention 的尺度并入输出 RMSNorm。[1]

这些是跨模型尺寸的缩放关系。落到一个已发布 checkpoint，具体常数由它的参数和配置给出。要复现实验，应同时保存 base shape、各参数组学习率、初始化方式与分支 scale，才能重建一次更新的大小。更完整的推导见 μP 与超参数迁移和从 SGD 到 Muon。

训练稳定性还可以用两个学习率来观察：固定预算下效果最好的 \(\eta_{\rm opt}\)，以及搜索中仍能稳定训练的最大 \(\eta_{\rm safe}\)。两者的对数比

$$ H=\log\frac{\eta_{\rm safe}}{\eta_{\rm opt}} $$

描述有效学习率附近还剩多少稳定空间。若 \(H\) 较大，调参和扩大模型时拥有更多余量；“能够跑完”之外，还要观察是否在高效的学习率附近训练。

在相同数据、达到相同训练 loss 的对照中，这套架构与训练配方相对 Qwen3-MoE-style 基线取得约 1.93 倍的计算效率，对应约 52% 的训练 FLOPs。这个数字描述整套配方的联合结果；分配给 Norm、优化器或其他组件的贡献，需要进一步的单项消融。[1]

11. 架构怎样接到 CLI 后训练

预训练与中训练合计使用 29T token，上下文训练经过 32K、128K、512K 的阶段扩展。代码与工具轨迹带来一种特别的监督结构：模型写出的动作、工具返回的观察、用户指令，虽然都进入上下文，却可以使用不同的 loss mask。

后训练先建立基本的 CLI 交互能力，再在不同任务、harness 和版本上学习。一个可重复评测单元包括任务、工具协议、环境、harness 版本与 verifier。模型在某个工具格式上表现变差时，应先固定这些条件，定位是能力变化、序列化变化，还是执行环境变化。

多教师 on-policy distillation 使用学生自己生成的轨迹，再让领域教师评价学生选择的 token。设学生在采样时给该 token 的概率为 \(p_k\)，对应教师概率为 \(q\)，蒸馏信号可以写成

$$ \tilde a=\operatorname{clip}(\log q-\log p_k,-c,c), $$

其中 \(c>0\) 控制信号幅度。若教师给某 token 的概率为 0.3，学生为 0.1，未裁剪信号为 \(\log3>0\)，会提高学生对这一选择的倾向。采样概率、轨迹和 advantage 在这次更新中保持固定，梯度作用于当前学生的 log-probability。

这里的四个领域教师是完整模型，分别提供不同任务能力；主干 MoE 中的 256 个专家则是单层 FFN 模块。教师信号整合之后，还可以在共同参考 checkpoint 上组合参数增量，并校准全局范数。两种能力整合方式分别沿着“学习分布”和“合并参数”进行，评测都要回到固定任务与工具环境。[1]

12. 计算与诊断练习

练习一：512K 的混合 KV，以及窗口再缩一半

单请求、BF16、8 个 KV 头、头维度 128。先求 25 层 full 与 63 层 SWA 的总缓存，再把 SWA 窗口从 4,096 改为 2,048。

每层每 token 为 4,096 B。全局部分为 50 GiB；局部部分为 \(63\times4,096\times4,096/2^{30}=0.984375\) GiB，合计 50.984375 GiB。窗口减半后局部为 0.4921875 GiB，总量为 50.4921875 GiB，只降低约 0.97%。在这个长度上，全局层决定容量的大头。

练习二：零 Value 的 sink 为什么能把输出减半

真实历史的指数权重为 \([2,1,1]\)，Value 为 \([1,3,-1]\)，sink 的指数权重为 4。

真实历史的加权分子为 \(2\times1+1\times3-1=4\)，原分母为 4，原输出为 1。加入 sink 后分母为 8，输出为 0.5。Sink 获得 50% 概率；其余三个位置总共获得 50%。也可用 \(\sigma(\log4-\log4)=0.5\) 验证。

练习三：两个 GPU 的 attention 输出应该怎样合并

本地两个 Key 的指数权重为 \([1,3]\)、Value 为 \([0,4]\)；远端一个 Key 的指数权重为 2、Value 为 1。

本地分母为 4，归一化输出为 3；远端分母为 2，输出为 1。完整输出是 \((4\times3+2\times1)/(4+2)=7/3\)。若加入指数权重为 2 的零 Value sink，输出为 \(14/(6+2)=1.75\)。每个分片都重复加入 sink 会把总分母变成 10，得到错误的 1.4。

练习四：更长的草稿链能带来多少推进

起草 7 个 token，每一步条件接受率均为 0.8。求平均推进量；再把接受率改为 0.3。

使用有限等比数列：\(\mathbb E[n]=(1-a^8)/(1-a)\)。当 \(a=0.8\) 时约为 4.161；当 \(a=0.3\) 时约为 1.428。起草与验证耗时也要计入，低接受率下应比较更短候选链的实际吞吐。

练习五：模型结果变了，先检查哪个缩放

普通 attention 的 FP8 输出通过了参考检查，增加 sink 后误差明显。应检查哪些张量？

保留同一组 Query、Key 和 mask，分别比较真实历史 LSE、sink logit 与最终 sigmoid gate。核对 Query 的反量化 scale、GQA 的头到组映射、sink key 的 dtype，以及 LSE 的对数约定。若普通输出和 LSE 一致而 sink logit 不一致，优先定位旁路点积；再用显式追加零 Value 的 dense attention 验证修复。

练习六：Stable SplitNorm 的残差接错了会怎样

将一个普通 block 的 attention 残差从 \(z=N(x)\) 改成原输入 \(x\)。设输入在同一方向放大 10 倍，其他权重固定，会观察到什么？

忽略 \(\epsilon\) 时，\(N(10x)=N(x)\)，因此正确普通 block 的归一化入口与 attention 分支基本保持不变。若残差直接使用 \(10x\)，输出会多出随输入尺度变化的分量。这个实验检查前向语义；深层训练的收敛结果需要训练实验另行测量。

13. 在 CPU 上把关键等式跑一遍

下载 lab.py，安装 NumPy 后运行：

python3 -m pip install numpy
python3 lab.py

实验用小型确定性张量验证四件事：显式追加 sink 与 LSE 缩放相等；分片合并与完整 attention 相等；25/63 层布局得到正确 KV 字节数；普通 block 的残差确实从归一化后的状态出发。它还展示重复计入 sink 和直接相加部分输出造成的误差。

修改窗口大小、sink 分数或输入幅度，先写出预期变化，再运行验证。将这些断言迁移到真实 kernel 时，继续加入不同 mask、序列边界、低精度 scale 和非连续 layout。这样从架构公式到部署实现，每一步都有可比较的中间结果。
