Kimi K2：MuonClip 与万亿参数 Agent 模型

交互2026-10-19

Kimi K2 是 Moonshot AI 在 2025 年 7 月发布的开源 MoE 模型：总参数 1.04T，激活 32.6B，用 15.5T token 预训练，全程没有一次 loss spike。它真正新的东西有三块：

  • MuonClip：在 Muon 优化器上加一个叫 QK-Clip 的权重裁剪，解决 Muon 在大规模训练中注意力 logit 爆炸的问题；
  • 提高 token 效率的数据改写：高质量 token 不够用时，用改写而不是多轮重复来“放大”数据；
  • Agent 能力的后训练：大规模合成工具调用轨迹，加上可验证奖励与“自我批评 rubric 奖励”结合的 RL。

2. 从 Adam 到 Muon：正交化动量

2.1 先回忆 SGD 动量和 Adam

训练就是反复做 \(W \leftarrow W - \eta\,\Delta\)。不同优化器的区别只在“更新方向 \(\Delta\) 怎么从梯度 \(G\) 算出来”：

  • SGD + 动量：\(M_t = \mu M_{t-1} + G_t\)，\(\Delta = M_t\)。更新的大小和梯度成正比，梯度大的方向走得快。
  • Adam：维护一阶矩 \(m\) 与二阶矩 \(v\)，\(\Delta = \hat m / (\sqrt{\hat v}+\epsilon)\)。逐元素除以“梯度的典型大小”，相当于把每个元素的步长归一到 \(\pm 1\) 附近。在 \(\beta_1=\beta_2\to 0\) 的极端下，Adam 退化为 \(\operatorname{sign}(G)\)，即 signSGD。

这两者都把参数当成一堆独立的标量。但神经网络里绝大多数参数是矩阵 \(W\in\mathbb R^{n\times m}\)，它的作用是一个线性算子 \(x\mapsto Wx\)。对矩阵来说，更自然的问题是：这一步更新会把输出 \(Wx\) 改变多少？

2.2 谱范数下的最速下降

Muon 背后的观点（Bernstein & Newhouse 的“在范数约束下做最速下降”）是：对矩阵参数，应该约束更新的谱范数（最大奇异值）\(\|\Delta\|_2\)，因为它正好是“对任意单位输入，输出最多变化多少”。于是问题是

$$\Delta^\star = \arg\max_{\|\Delta\|_2 \le 1} \langle G, \Delta\rangle .$$

设 \(G = U\Sigma V^\top\) 是奇异值分解。\(\langle G,\Delta\rangle = \operatorname{tr}(\Sigma\, U^\top \Delta V)\)，而 \(U^\top\Delta V\) 的对角元绝对值都不超过它的谱范数 1，所以最大值 \(\sum_i \sigma_i\) 在 \(U^\top \Delta V = I\) 时取到：

$$\Delta^\star = U V^\top =: \operatorname{msign}(G).$$

这就是“正交化”：把梯度的所有奇异值都换成 1，只保留它的奇异向量（方向）。它常被记作 \(\operatorname{msign}\)（matrix sign），类比标量的 sign：Adam 在逐元素意义下取符号，Muon 在矩阵意义下取符号。等价的写法是 \(\operatorname{msign}(G) = (GG^\top)^{-1/2}G\)。

Muon 的完整更新是：

$$M_t = \mu M_{t-1} + G_t,\qquad O_t = \operatorname{msign}(M_t),\qquad W_t = W_{t-1} - \eta\, O_t .$$

动量先在原始梯度上累积，再整体正交化。动量系数通常取 \(\mu=0.95\)，Moonlight 和 K2 都用这个值。

2.3 Newton–Schulz 迭代：不做 SVD 也能正交化

每步对每个矩阵做 SVD 太贵，而且不适合 GPU。Muon 用一个只含矩阵乘法的迭代逼近 \(UV^\top\)。先归一化 \(X_0 = M/\|M\|_F\)，保证所有奇异值都在 \((0,1]\)；然后迭代

$$X_{k} = a X_{k-1} + b\,(X_{k-1}X_{k-1}^\top) X_{k-1} + c\,(X_{k-1}X_{k-1}^\top)^2 X_{k-1}.$$

关键观察：如果 \(X = U\Sigma V^\top\)，那么 \((XX^\top)X = U\Sigma^3V^\top\)，\((XX^\top)^2X = U\Sigma^5 V^\top\)。所以这个迭代不改变奇异向量，只对每个奇异值独立地施加奇多项式

$$\sigma \mapsto f(\sigma) = a\sigma + b\sigma^3 + c\sigma^5 .$$

只要 \(f\) 把 \((0,1]\) 里的值都推向 1 附近，迭代几次后 \(X_k \approx U V^\top\)。Muon 用的系数是 \(a=3.4445,\ b=-4.7750,\ c=2.0315\)。这里的设计取舍是：\(f'(0)=a\approx 3.44\) 很大，小奇异值每步被放大三倍多，几步就能拉上来；代价是 \(f\) 并不精确收敛到 1，而是让奇异值在 1 附近振荡。按这组系数，初始奇异值只要不小于 0.01，迭代 5 步后都落在大约 \([0.68,\ 1.13]\) 里。对优化来说这已经够了：Moonlight 的实验里迭代 10 步比 5 步正交化得更准，但训练效果没有更好，所以用 5 步。

开销：对 \(n\times m\)（\(n\le m\)）的矩阵，一步迭代大约是 \(XX^\top\)（\(2n^2m\)）、平方（\(2n^3\)）和两次乘回 \(X\)（\(4n^2 m\)）。5 步加起来比前向反向小得多；实测优化器带来的额外延迟一般只占前向反向的 1%–3%。

def newton_schulz5(G, steps=5, eps=1e-7):
    a, b, c = 3.4445, -4.7750, 2.0315
    X = G.bfloat16() / (G.norm() + eps)
    transposed = X.size(0) > X.size(1)
    if transposed: X = X.T          # 让 X X^T 是较小的那个方阵
    for _ in range(steps):
        A = X @ X.T
        B = b * A + c * A @ A
        X = a * X + B @ X
    return X.T if transposed else X

2.4 为什么正交化有帮助

直观解释：梯度矩阵往往是“低秩、病态”的——少数几个奇异方向占了绝大部分能量。SGD 和 Adam 的更新会主要沿这几个方向走，其它方向几乎不动。正交化之后所有奇异方向的步长相同，那些弱但有用的方向也能被学到。换句话说，正交化让更新矩阵“各向同性”，权重不会只沿少数主导方向学习。

Moonlight 给了两类证据：

  • 缩放律：在 399M–1.5B 的一组 dense 模型上，对 AdamW 做了网格搜索的强基线；Muon 直接复用 AdamW 的最优超参。拟合出的曲线是 Muon \(2.506\times C^{-0.052}\)、AdamW \(2.608\times C^{-0.054}\)，在算力最优训练下 Muon 只需约 52% 的 FLOPs 就能达到 AdamW 的 loss（“约 2 倍计算效率”）。
  • 奇异值熵：对 Moonlight（Muon 训练）和 Moonlight-A（AdamW 训练）的权重矩阵算 SVD 熵 \(H(\sigma) = -\frac{1}{\log n}\sum_i p_i\log p_i,\ p_i = \sigma_i^2/\sum_j\sigma_j^2\)，Muon 训练出来的矩阵在所有 checkpoint、所有矩阵组上熵都更高，超过 90% 的矩阵如此；在 MoE 的 router 矩阵上差距最明显。熵越高，说明奇异值分布越平，矩阵用到的“方向”越多。

把“原始梯度、Adam 式符号更新、Newton–Schulz 正交化”放在两种尺度上对比。上半部分是 2×2 矩阵作用在单位圆上的像：病态的梯度把圆压成细长椭圆，正交化后接近一个圆（奇异值都接近 1）。下半部分是一个 32×16 的随机矩阵，奇异值按幂律衰减，柱状图显示三种更新的奇异值（各自除以最大值）。所有数都在页面上实时计算：奇异值由 Jacobi 方法求 \(G^\top G\) 的特征值得到。

3. Moonlight 的两处修改：权重衰减与更新 RMS 对齐

原始 Muon 在小规模语言模型上很强，但扩到大模型、多 token 时收益会消失。Moonlight 找到两个原因并修掉，K2 原样继承了这两处修改。

3.1 加回权重衰减

原始 Muon 没有权重衰减。Moonlight 观察到训练久了权重和层输出的 RMS 一直增长，超出 bf16 的高精度区间。他们加入 AdamW 式的解耦权重衰减：

$$W_t = W_{t-1} - \eta_t\,(O_t + \lambda W_{t-1}).$$

在一个 800M 模型、100B token（约 5 倍算力最优 token 数）的过训练实验里，原始 Muon 早期收敛更快，但后期被带权重衰减的 Muon 反超，后者也优于 AdamW。为什么 Muon 特别需要它，可以从更新的“形状”理解：Muon 每步的更新是满秩、每个方向步长相同的，不像 Adam 那样大多数方向几乎不动，所以权重范数更容易持续增长；权重衰减提供一个平衡点。这个“奇异值容易增长”的性质，也正是注意力 logit 爆炸的根源。

3.2 更新 RMS 随矩阵形状变化

Adam 的更新逐元素大约是 \(\pm1\) 量级，所以它的更新 RMS（均方根）不依赖矩阵形状，实际在 0.2–0.4 左右。Muon 不是这样。引理：形状为 \([A,B]\) 的满秩矩阵，Muon 更新 \(O = UV^\top\) 的 RMS 是 \(\sqrt{1/\max(A,B)}\)。

证明很短。设 \(n=\max(A,B)\ge m=\min(A,B)\)，满秩时 \(O = \sum_{k=1}^{m} u_k v_k^\top\)，\(\{u_k\}\)、\(\{v_k\}\) 各自正交归一。则

$$\|O\|_F^2 = \operatorname{tr}(O^\top O) = \operatorname{tr}\Big(\sum_k v_k v_k^\top\Big) = m,\qquad \operatorname{RMS}(O) = \sqrt{\frac{\|O\|_F^2}{nm}} = \sqrt{\frac{1}{n}} .$$

这带来两个问题：大矩阵（比如 dense MLP，\(\max(A,B)\) 很大）的更新太小，学不动；小矩阵（比如把 MLA/GQA 的每个 KV 头当成独立参数）更新太大，训练不稳。修法是把每个矩阵的更新乘上 \(\sqrt{\max(A,B)}\) 抵消形状影响，再乘 0.2 对齐 AdamW 的典型更新 RMS：

$$W_t = W_{t-1} - \eta_t\big(0.2\cdot O_t\cdot\sqrt{\max(A,B)} + \lambda W_{t-1}\big).$$

这样做的另一个好处是 Muon 可以直接复用为 AdamW 调好的学习率和权重衰减——这对实践很重要，因为非矩阵参数（embedding、LM head、RMSNorm 的 gamma）仍然用 AdamW，两套优化器共享一组超参。Moonlight 做过一组扫描：把 Muon 更新 RMS 设成 0.05/0.1/0.2/0.4/0.8，2k 步时 0.2 与 0.4 最好且相近（训练 loss 3.198 / 3.199），AdamW 基线是 3.512。

Moonlight 还比较了三种控制更新 RMS 的方法：统一乘 \(0.2\sqrt{H}\)（基线）、把更新直接归一到 RMS=0.2（Update Norm）、按形状乘 \(0.2\sqrt{\max(A,B)}\)（Adjusted LR）。后两者都比基线好且彼此接近，Adjusted LR 计算更便宜，于是被采用；K2 的优化器里用的就是它：\(O_t = \text{Newton-Schulz}(M_t)\cdot\sqrt{\max(n,m)}\cdot 0.2\)。

3.3 分布式 Muon 与 SFT 阶段

把 Muon 用到大规模训练，还要解决分布式的问题。AdamW 的更新逐元素计算，所以 ZeRO-1 可以把优化器状态任意切片。Muon 需要完整的矩阵才能做 Newton–Schulz。Moonlight 的 Distributed Muon 在 ZeRO-1 基础上多两步：在数据并行组内把本地分片的（带动量的）梯度 gather 成完整矩阵，算完整更新，只保留自己那一片去更新参数。内存上 Muon 只有一个动量缓冲，是 AdamW 的一半；通信量是 Distributed AdamW 的 \((1, 1.25]\) 倍（多出来的 gather 用 bf16）。

Moonlight 还做了预训练与 SFT 优化器的交叉实验：Muon 预训练 + Muon SFT 最好；如果预训练用 AdamW，SFT 换成 Muon 没有明显优势。K2 据此在 SFT 和 RL 阶段也用 Muon，并建议用户微调 K2 时用 Muon。

4. 注意力 logit 爆炸

4.1 现象

Muon 在 K2 的规模上遇到了一个新的失稳模式。先定义要观察的量：对一个注意力头 \(h\)，\(Q^h = XW_q^h,\ K^h = XW_k^h\)，softmax 的输入是 \(\frac{1}{\sqrt d}Q^hK^{h\top}\)。每个头在一个 batch 里的最大 logit 是

$$S^h_{\max} = \frac{1}{\sqrt d}\max_{X\in B}\ \max_{i,j}\ Q^h_i K^{h\top}_j .$$

K2 团队在一个中等规模（激活 9B、总参 53B 的 MoE）用原始 Muon 训练时，看到最大 logit 很快超过 1000。logit 到这个量级，softmax 几乎变成 one-hot，梯度要么消失要么剧烈，通常会伴随 loss spike，偶尔发散。他们在实验里发现这个问题在 Muon 下比 AdamW 下更频繁。Moonlight 当时其实已经观察到了苗头：训练早期部分层的最大 logit 超过 100，只是 logit 超过 100 的比例只有约 \(10^{-4}\)，且后来自己降下去了，所以没出事。到 K2 的规模就不再安全。

4.2 为什么由权重的谱范数决定

logit 有一个简单的上界：

$$|q_i\cdot k_j| \le \|q_i\|\,\|k_j\| \le \|x_i\|\,\|x_j\|\,\|W_q\|_2\,\|W_k\|_2 .$$

注意力层的输入经过 RMSNorm，\(\|x\|\) 是有界的，所以 logit 能无限增长只能是 \(W_q\) 或 \(W_k\) 的谱范数在增长。更准确地说，logit 是双线性型 \(x_i^\top W_q W_k^\top x_j\)，乘积 \(W_qW_k^\top\) 把两个谱范数乘在一起，任何一个奇异值的增长都被“平方地”放大。

4.3 为什么 Muon 更容易出事

K2 团队对此给出的是一个假设而非证明：Muon 的更新所有奇异值相等、有效秩满；Adam 的更新谱偏斜、有效秩低。把权重写成 \(W_{t-1} = \sum_i\sigma_i u_iv_i^\top\)，更新写成 \(\Delta W_t = \sum_j\bar\sigma\,\bar u_j\bar v_j^\top\)。权重和更新的有效秩都更高时，某个更新方向 \(\bar u_j\bar v_j^\top\) 与权重已有的奇异方向 \(u_iv_i^\top\) 对齐的概率更大，一旦对齐，对应奇异值就被逐步加性地推高。再经过上面的“平方放大”，就变成 logit 爆炸。Moonlight 的 SVD 熵结果（Muon 训练的权重有效秩更高）被引用为支持证据。

4.4 已有办法为什么不够

  • Logit soft-cap（Gemma 2）：把 logit 换成 \(c\tanh(s/c)\)。它只截断 softmax 的输入，但 \(q\cdot k\) 本身仍然可以继续增长，只是被“藏”在 tanh 后面；在饱和区梯度也趋于零。根本问题（权重谱范数增长）没解决。
  • QK-Norm：对每个头的 \(q\)、\(k\) 做归一化再点乘，logit 天然有界。但它不适用于 MLA。原因要看 MLA 的推理方式：MLA 只缓存每个 token 的压缩向量 \(c^{KV}_t\in\mathbb R^{512}\)，推理时把 key 的上投影 \(W^{UK}\) 吸收进 query 一侧，直接用 \(q^\top W^{UK} c_t\) 计算分数，每个头的完整 key \(k = W^{UK}c\) 从来不被显式算出来。QK-Norm 要对 \(k\) 做非线性的归一化，就破坏了这个吸收，等于放弃 MLA 省 KV cache 的意义。

5. QK-Clip 的推导与 MuonClip

5.1 核心想法：事后缩放权重

QK-Clip 不改前向、不改反向，而是在优化器更新之后，看这一步前向里观察到的 \(S^h_{\max}\)，如果超过阈值 \(\tau\)，就把这个头的 \(W_q\)、\(W_k\) 按比例缩小。最大 logit 只是一个“该压多狠”的信号。

推导只用到 logit 关于 \(W_q\)、\(W_k\) 是双线性的。若

$$W_q \leftarrow \gamma^{\alpha}W_q,\qquad W_k\leftarrow \gamma^{1-\alpha}W_k,$$

那么对同样的输入，

$$q_i\cdot k_j \ \to\ \gamma^{\alpha}\gamma^{1-\alpha}\,q_i\cdot k_j = \gamma\, q_i\cdot k_j .$$

取 \(\gamma = \min(1, \tau/S_{\max})\)，缩放后（在同一批数据上）最大 logit 恰好变成 \(\min(S_{\max},\tau)\)。\(\alpha\) 控制 query 与 key 各承担多少，通常取 0.5，两边各乘 \(\sqrt\gamma\)。下一步的数据不同、权重又更新了一步，所以这不是严格的硬上界，而是持续把权重拉回“在当前数据上 logit 不超过 \(\tau\)”的区域。

5.2 为什么要按头裁剪

朴素做法是全局用一个 \(\gamma=\min(1,\tau/\max_h S^h_{\max})\) 缩放所有头。但实际上只有少数头会爆炸，全局缩放会把正常的头也压下去，相当于凭空给它们加了强正则。所以 K2 对每个头单独算 \(\gamma_h = \min(1,\tau/S^h_{\max})\)，只动超标的头。演示里可以切换两种方式，看正常头被“误伤”多少。

5.3 MLA 里怎么裁

MLA 的每个头，query 和 key 都由两部分拼成：不带位置编码的“内容”部分（C）和带 RoPE 的部分（R）：

$$q^h = [\,q^{C,h};\ q^{R,h}\,],\qquad k^h = [\,k^{C,h};\ k^{R}\,],\qquad q^h\cdot k^h = q^{C,h}\cdot k^{C,h} + q^{R,h}\cdot k^{R}.$$

要注意 \(k^R\) 是所有头共享的（它由输入直接投影得到，再加 RoPE，只有一份 64 维）。如果缩放它，会同时影响所有头，违背“只动超标的头”。所以 K2 的方案是：

  • \(q^{C}\) 和 \(k^{C}\)（头专属）：各乘 \(\sqrt{\gamma_h}\) → 第一项乘 \(\gamma_h\)；
  • \(q^{R}\)（头专属）：乘 \(\gamma_h\) → 第二项乘 \(\gamma_h\)（因为 \(k^R\) 不动）；
  • \(k^{R}\)（共享）：不动。

两项都乘了 \(\gamma_h\)，所以整个 logit 恰好缩放 \(\gamma_h\)，与 5.1 的推导一致。落实到参数上，就是缩放 query 上投影里该头对应的 \(W_{qc}^h\)、\(W_{qr}^h\)，以及 key 上投影（\(W^{UK}\)）里该头对应的 \(W_{kc}^h\)。这些都是头专属的权重切片，缩放互不影响。

5.4 MuonClip 算法

把 Muon、权重衰减、RMS 对齐和 QK-Clip 合在一起，就是 K2 的 MuonClip 优化器：

for each step t:
    # 1. Muon（含 Moonlight 的两处修改）
    for each matrix W (n×m):
        M_t = μ·M_{t-1} + G_t
        O_t = NewtonSchulz(M_t) · sqrt(max(n, m)) · 0.2      # 对齐 AdamW 的更新 RMS
        W_t = W_{t-1} − η·(O_t + λ·W_{t-1})                  # 解耦权重衰减
    # 2. QK-Clip（逐头）
    for each attention head h in every attention layer:
        S = S_max^h            # 前向时顺手记录，不需要额外计算
        if S > τ:
            γ = τ / S
            W_qc^h ← W_qc^h · sqrt(γ)
            W_kc^h ← W_kc^h · sqrt(γ)
            W_qr^h ← W_qr^h · γ

实现上唯一的额外开销是前向时为每个头记录一个 max（在 FlashAttention 类 kernel 里可以顺带算出），以及偶尔对少量权重切片做一次标量乘法。

5.5 实验证据

  • 中等规模、无裁剪：9B 激活 / 53B 总参的 MoE 用原始 Muon，最大 logit 很快超过 1000。
  • 小规模消融：0.5B 激活 / 3B 总参的 MoE，一个用原始 Muon，一个用 MuonClip 且阈值故意设得很低（\(\tau=30\)）。loss 曲线几乎重合，下游评测也没有统计显著的下降。
  • K2 本身（\(\tau=100\)）：最大 logit 一开始很快涨到 100 被卡住，大约训练 30% 的步数之后才自行回落到正常区间，全程没有调整 \(\tau\)。前 70000 步里有 12.7% 的注意力头至少触发过一次 QK-Clip；70000 步以后，所有头的 \(S_{\max}\) 都已降到 100 以下，QK-Clip 不再生效。也就是说它只在早期“临时介入”，训练稳定后自动退出。
  • 结果：15.5T token 的逐步训练 loss 曲线（未平滑、未降采样）没有任何 spike。

一个玩具动力学就能复现这些现象：每个头的 \(W_q\)、\(W_k\) 谱范数按“对齐带来的乘性增长 − 权重衰减”演化，增长率随训练衰减（模拟“权重和更新方向对齐”在早期最强）；少数头增长率特别大。logit \(S^h = \kappa_h\sigma_q\sigma_k\)。打开 QK-Clip 时，每步更新后按 5.1 的规则缩放。

6. Token 效率与数据改写

6.1 token 效率是新的瓶颈

高质量的人类数据越来越有限，token 效率（每个 token 带来的性能提升）成了缩放中的关键系数。提升它有两条路：优化器（Muon 每个 token 学得更多）和数据（让每个 token 携带更多有效信号，即提高 token utility）。最朴素的“多学几遍”（多 epoch 重复）会过拟合、泛化变差。

6.2 知识类数据的改写

知识密集的文本有个两难：只过一遍学不全，重复多遍收益递减还容易过拟合。K2 的改写框架有三个部件：

  • 多风格、多视角的提示：受 WRAP（Rephrasing the Web）启发，用一组精心设计的提示让 LLM 以不同风格、不同视角忠实地改写原始文本，增加语言多样性但不改事实。
  • 分块自回归改写：长文档直接整篇改写会丢信息（LLM 有隐性的输出长度上限）。做法是把文档切成段，每段在保留前文上下文的条件下依次改写，再拼回完整的一篇。
  • 忠实度校验：比较每段改写与原始文本的语义一致性，作为训练前的第一道质量控制。

改写到底有没有用？K2 团队在一个早期 checkpoint 上用 SimpleQA 准确率比较了三种方案：

同样是“看十遍”，十个不同的改写版本各看一遍最好。实际大规模使用时，每个语料最多改写两次。

6.3 数学数据

数学文档按 SwallowMath 的方法改写成“学习笔记”风格；另外把其他语言的高质量数学材料翻译成英文来增加多样性。合成数据作为持续缩放的手段还远没有成熟，难点是推广到更多领域时保证事实正确、减少幻觉和毒性、以及规模化。

6.4 总体语料

15.5T token，四个领域：网页、代码、数学、知识。大部分处理流程沿用 Kimi K1.5，每个领域都做了正确性、质量验证和针对性的数据实验。

7. 架构：MLA、384 专家与稀疏度缩放律

7.1 MLA 回顾（按 K2 的尺寸）

长上下文推理的主要显存开销是 KV cache。MLA（Multi-head Latent Attention，DeepSeek-V2 引入）的思路是把每个 token 的 K/V 压缩到一个低维隐向量，只缓存这个隐向量。K2 的尺寸如下：

  • Query：\(x\in\mathbb R^{7168}\to c^Q\in\mathbb R^{1536}\)（下投影），再上投影成 64 个头，每头 \(q^C\in\mathbb R^{128}\)、\(q^R\in\mathbb R^{64}\)（后者加 RoPE）。
  • Key/Value：\(x\to c^{KV}\in\mathbb R^{512}\)，另外直接投影出一个共享的 \(k^R\in\mathbb R^{64}\)（加 RoPE）；\(c^{KV}\) 上投影成每头 \(k^C\in\mathbb R^{128}\)、\(v\in\mathbb R^{128}\)。
  • 推理时 KV cache 每 token 每层只存 \(c^{KV}\)（512）和 \(k^R\)（64），共 576 个数。61 层、BF16 下每 token 约 \(576\times 61\times 2\approx 70\) KB。作为对比，同样 64 头、每头 key 192 维 + value 128 维的标准 MHA 要存 \(64\times 320=20480\) 个数，是 MLA 的 35 倍多。

按这些尺寸算，每层注意力参数约 1.01 亿，61 层合计约 6.2B。

7.2 MoE 配置

除第一层是 dense FFN（中间维 18432）外，其余 60 层都是 MoE：384 个路由专家 + 1 个共享专家，每 token 选 8 个路由专家，专家 FFN 中间维 2048（SwiGLU，每个专家 \(3\times 7168\times 2048\approx 44\)M 参数）。和 DeepSeek-V3 不同，K2 没有专家分组（V3 先选组再在组内选专家，用于限制跨节点通信）。

7.3 稀疏度缩放律

专家该设多少个？先定义稀疏度为“总专家数 / 激活专家数”。K2 团队在 Muon 下做了小规模的受控实验：固定激活专家数 8、共享专家 1（即固定激活参数和 FLOPs），只改变总专家数。结论是稀疏度越高，训练和验证 loss 都越低。在算力最优的缩放律下，要达到验证 loss 1.5，稀疏度 48 相比稀疏度 8、16、32 分别节省 1.69×、1.39×、1.15× 的 FLOPs。

收益在递减（从 32 到 48 只省 15%），而更高的稀疏度意味着更多专家参数要存、要通信，基础设施更复杂。K2 取了 48：384/8。

7.4 注意力头数：64 而不是 128

DeepSeek-V3 把头数设成层数的两倍左右（128），目的是更好地利用显存带宽。但上下文变长后，注意力的计算随头数线性增长：在 128K 序列长度下、总专家数固定 384 时，头数从 64 加到 128 会让推理 FLOPs 增加 83%。

这个 83% 可以粗算出来。生成第 \(L\) 个位置的 token 时，每个头要和前面 \(L\) 个 key 做点积、再对 \(L\) 个 value 加权求和；按每头 128 维算（忽略 64 维的 RoPE 分量），两步各是 \(2\cdot L\cdot 128\) FLOPs。于是每层注意力是 \(4\cdot H\cdot L\cdot 128\)，代入 \(H=64\)、\(L=131072\)、61 层：

$$4\times 64\times 131072\times 128\times 61 \approx 262\ \text{GFLOPs}.$$

其余所有矩阵乘按激活参数算，每 token 约 \(2N_{\text{act}}\approx 65\) GFLOPs。头数加倍时，注意力这部分翻倍（+262），注意力投影的参数也多出约 5B（+10 GFLOPs），总增幅约 \((262+10)/(65+262)\approx 83\%\)。也就是说，在 128K 上下文下，注意力计算已经是推理的大头，头数直接决定成本。

收益这一边，受控实验（头数 = 层数 vs 头数 = 2× 层数，同 token 数）显示加倍头数只让验证 loss 降低 0.5%–1.2%。在 Agent 场景长上下文很关键，这点收益不值得，于是 K2 用 64 头。

计算器按 MLA 和 MoE 的尺寸估算参数量和每 token 的 FLOPs。K2 预设下它给出的总参数是 1.026T，比 1.04T 少约 17B，差的是一层 MTP（multi-token prediction，预训练时额外预测后面 token 的模块，结构和一个 MoE 层相同，约 17B 参数）。K2 训练时带这一层，但公开权重不含它（num_nextn_predict_layers=0），加上它就是 1.043T。

8. 训练基础设施与训练配方

8.1 集群

K2 在 NVIDIA H800 集群上训练，每节点 8 卡、2 TB 内存，节点内 NVLink/NVSwitch，节点间 8×400 Gbps RoCE。

8.2 并行策略：能在任意 32 的倍数个节点上训练

训练资源是动态变化的，所以他们没有为某个固定规模优化，而是设计了一个能在“任意 32 的倍数个节点”上跑的方案：

  • 16 路流水线并行（PP），带虚拟 stage（interleaved）；
  • 16 路专家并行（EP）；
  • ZeRO-1 数据并行，切分优化器状态。

PP×EP = 256 卡 = 32 节点，构成一个模型并行组。BF16 参数加 FP32 梯度累积缓冲约 6 TB（\(1.04\text{T}\times(2+4)\ \text{bytes}\)），分布在 256 卡上。优化器状态的放法取决于规模：节点多时由 ZeRO-1 摊得很薄；只有 32 节点时把一部分卸载到 CPU。这样每卡用于各种状态的显存约 30 GB，其余给激活。同一套并行配置可以用于小规模和大规模实验，这对研究效率很重要。

8.3 EP 通信与 interleaved 1F1B 的重叠

MoE 的 all-to-all（把 token 发给专家、再收回）很慢，需要和计算重叠。K2 的做法是在标准 interleaved 1F1B 调度上增加 warmup 阶段的 micro-batch 数，让一个 micro-batch 的 EP 通信与另一个的计算重叠。他们没有用 DeepSeek-V3 的 DualPipe：DualPipe 要存两份参数和梯度，显存翻倍，只能靠更大的 PP（更多 bubble）或 EP（开销更高）来补，对万亿模型代价太大。

interleaved 1F1B 的问题是 stage 更多，PP 通信更多。缓解办法是把每个 micro-batch 反向里的权重梯度计算拆出来（类似 zero-bubble 的 B/W 拆分），和对应的 PP 通信并行执行。这样除 warmup 阶段外，所有 PP 通信都能被重叠。

8.4 更小的 EP

K2 只有 64 个注意力头，注意力计算时间比 V3 短，留给 EP 通信重叠的时间也短。所以要尽量缩短 EP 操作：选最小可行的 EP=16。小 EP 组的另一个好处是专家负载均衡的约束更宽松，不需要额外调就能接近最优速度。

8.5 激活显存的三板斧

扣掉参数、梯度缓冲和优化器状态后，剩下的显存放不下完整的 MoE 激活，尤其是 1F1B warmup 阶段积累激活最多的前几个 stage。三种手段：

  • 选择性重计算：对计算便宜但占显存大的部分重算——LayerNorm、SwiGLU、MLA 的上投影；另外 MoE 的 down-projection 也重算。后者是可选的，但能在训练早期专家不均衡时防止显存溢出崩溃。
  • 对不敏感的激活用 FP8 存储：MoE up-projection 和 SwiGLU 的输入压成 FP8-E4M3，1×128 的 tile、每 tile 一个 FP32 scale。小规模实验没有可测的 loss 上升。注意他们没有用 FP8 做计算——初步研究中观察到性能下降的风险。
  • 激活卸载到 CPU：剩余所有激活都卸载到 CPU 内存，由 copy engine 流式卸载和加载，与计算和通信 kernel 重叠。1F1B 阶段卸载上一个 micro-batch 的前向激活，同时预取下一个的反向激活。PCIe 流量可能干扰 EP 通信，但测试显示 EP 通信仍完全被重叠。

8.6 训练配方

  • 上下文 4096，MuonClip，WSD 学习率调度，共 15.5T token；
  • 前 10T：500 步 warmup 后恒定学习率 2e-4；后 5.5T：从 2e-4 余弦衰减到 2e-5；
  • 权重衰减 0.1，全局 batch 6700 万 token，全程不变；
  • 预训练末尾：退火 + 长上下文激活，学习率 2e-5 → 7e-6，先以 4K 长度训 400B token，再以 32K 长度训 60B token；最后用 YaRN 把上下文扩到 128K。

9. SFT 与大规模 Agent 数据合成

9.1 SFT 的总原则

SFT 用 Muon。指令数据的两条原则是最大化提示多样性和保证回答质量。不同任务领域有各自的数据流水线，混合使用人工标注、提示工程和验证；候选回答由 K1.5 和内部的领域专家模型生成，再由 LLM 或人工评审打分过滤。

9.2 工具调用数据的合成流水线

真实环境能提供真实的交互信号，但成本、复杂度、隐私和可达性都限制了规模。K2 借鉴 ACEBench 的合成框架，建了一条模拟真实工具使用场景的流水线，生成数万条多样、高质量的训练样本。分三个阶段：

  • 领域演化与工具生成：两路来源。一是直接从 GitHub 抓取 3000 多个真实 MCP（Model Context Protocol）工具的规格；二是分层“演化”出合成工具——从几个大类（如金融交易、软件应用、机器人控制）出发，每类再演化出多个具体应用领域，为每个领域合成带清晰接口、描述和语义的专用工具，共 2 万多个。t-SNE 可视化显示两者覆盖了工具空间的互补区域。
  • Agent 多样化：合成各种系统提示，配上工具库里不同的工具组合，得到数千个能力、专长和行为模式不同的 agent。
  • 基于 rubric 的任务生成：为每个 agent 生成从简单到复杂的任务，每个任务配一个明确的 rubric：成功标准、预期的工具使用模式、评估检查点。
  • 多轮轨迹生成：LLM 生成的用户画像（有不同沟通风格与偏好）和 agent 多轮对话；工具执行由一个工具模拟器完成，它在功能上相当于一个世界模型：每次调用后维护和更新状态，支持有持久影响的多步交互，并引入受控随机性，产生成功、部分失败和边界情况。
  • 质量评估与过滤：LLM 评审按 rubric 判断每条轨迹，只保留满足成功标准的。
  • 混合真实执行环境：模拟的保真度有上限，所以在真实性要紧的场景（尤其编码和软件工程）用真实沙箱，执行真代码、跑测试，以测试通过率等客观指标作为反馈。

整体上，大规模生成 + 质量过滤本质上就是一种大规模拒绝采样（rejection sampling）。

9.3 工具调用的 token 模板

K2 的工具调用格式有几个值得记下的设计：

  • 工具声明用 TypeScript：比 OpenAI 兼容的 JSON Schema 短得多，又能表达类型和约束。为了兼容第三方框架，部分训练数据仍用 JSON 声明。
  • 调用 ID：格式 functions.{工具名}:{计数}，计数在整段对话里从 0 递增；一个回复里可以放多个调用（并行工具调用）。
  • 约束解码：受 lm-format-enforcer 启发，做了一个叫 enforcer 的模块。一旦生成了 <|tool_call_section_begin|>，后续工具相关 token 必须符合模板，参数 JSON 必须符合声明的 schema。

10. 强化学习：可验证奖励、自我批评与三个技巧

SFT 之后是 RL。K2 团队的判断是 RL 比 SFT 有更好的 token 效率和泛化，所以在 K1.5 的基础上扩大了任务多样性和训练 FLOPs，搭了一个类 Gym 的可扩展框架。

10.1 可验证奖励的“Gym”

  • 数学、STEM、逻辑：两条原则。覆盖多样：专家标注、内部 QA 抽取流水线和开源数据集，用标签系统有意补足覆盖不足的领域；逻辑任务包括结构化数据任务（多跳表格推理、跨表聚合）和谜题（24 点、数独、谜语、密码算术、摩尔斯码解码）。难度适中：太易、太难都没有学习信号，用 SFT 模型的 pass@k 估计难度，只留中等难度的题。
  • 复杂指令遵循：混合规则验证——能用代码判断的约束（长度、风格）由代码解释器确定性判断，需要细致理解的由 LLM 评审；再加一层 hack-check 专门检测“声称满足了指令其实没有”的欺骗行为。指令来源三路：数据团队写的复杂条件提示与 rubric、受 AutoIF 启发的 agentic 指令增强、一个专门生成能探出失败模式和边界情况的新指令的微调模型。
  • 忠实度：受 FACTS Grounding 启发，训练了一个句子级的忠实度评审模型，检测“在上下文中没有证据支撑的事实陈述”，作为奖励模型。
  • 代码与软件工程：竞赛题来自开源数据集和合成来源，为保证合成题的奖励正确，引入从预训练数据中检索出的人写单元测试；软件工程任务从 GitHub 收集大量 PR 和 issue，构造“用户提示/issue + 可执行单测”的开发环境，跑在 Kubernetes 上，支持超过 10000 个并发沙箱实例。
  • 安全：从人工整理的、覆盖常见风险类别（暴力、诈骗、歧视等）的种子提示出发，用自动提示进化流水线模拟复杂越狱（角色扮演、文学叙事、学术讨论）。三个组件：攻击模型迭代生成对抗提示，目标模型作答，评审模型按任务 rubric 给出“是否绕过”的二值标签。

10.2 超越验证：自我批评 rubric 奖励

创意写作、开放问答这类主观任务没有可验证的答案。K2 的办法是让模型给自己的输出打分（Self-Critique Rubric Reward）：

  • 自我批评的策略优化：K2 actor 对覆盖广泛场景的通用提示生成多个回答，K2 critic 按一组 rubric 做成对比较，给所有回答排序。rubric 包括：核心 rubric（代表 Kimi 认为的助手的基本价值，见下）、规定性 rubric（用于消除 reward hacking）、数据团队针对具体指令场景人工写的 rubric。某些 rubric 可以设为必选，但 K2 仍可以结合自己的先验去权衡。critic 能力在 SFT 阶段用开源和内部偏好数据初始化。
  • 闭环的 critic 精炼：RL 过程中，用可验证奖励任务上的 on-policy rollout 持续更新 critic，把 RLVR 里的客观信号蒸馏进评审模型。这样 critic 的主观判断有可验证数据做锚，并随策略的演化同步重新校准。

核心 rubric 有三条：清晰与相关（简洁且完整回应意图，非必要不长列表，需要做选择时给出唯一明确答案）；对话流畅与投入；客观落地的互动（避免元评论和对用户的奉承）。规定性 rubric 两条：不准以夸赞开头（“好问题！”）；不准写解释“这个回答为什么好”的句子。这套 rubric 也有局限：它可能偏好显得自信、果断的回答，在本该表达不确定性或多视角的场景里，模型可能过度确定。

10.3 RL 目标函数

沿用 K1.5 的策略优化算法。对每个问题 \(x\)，从旧策略 \(\pi_{\text{old}}\) 采样 \(K\) 个回答，最小化

$$L_{\text{RL}}(\theta) = \mathbb E_{x}\left[\frac1K\sum_{i=1}^K\Big(r(x,y_i)-\bar r(x) - \tau\log\frac{\pi_\theta(y_i|x)}{\pi_{\text{old}}(y_i|x)}\Big)^2\right],\qquad \bar r(x)=\frac1K\sum_i r(x,y_i).$$

怎么理解这个平方损失？在 \(\theta=\theta_{\text{old}}\) 处 log 比值为 0，梯度是

$$\nabla_\theta L = -\frac{2\tau}{K}\sum_i \big(r_i-\bar r\big)\,\nabla_\theta\log\pi_\theta(y_i|x),$$

所以第一步梯度下降等价于带均值基线的策略梯度：比平均好的回答概率上升，差的下降。随着 \(\pi_\theta\) 偏离 \(\pi_{\text{old}}\)，损失要求 \(\tau\log(\pi_\theta/\pi_{\text{old}})\) 去“拟合”优势 \(r_i-\bar r\)，而不是无限推高，这起到类似 KL 正则的稳定作用（\(\tau\) 越大更新越保守）。这个目标也用 Muon 优化。

10.4 三个技巧

  • 预算控制：RL 往往让回答越来越长。长回答在复杂推理里有用，但在非推理任务里不划算。K2 对每个样本按任务类型设最大 token 预算，超出的回答被截断并惩罚。这显著提升了 token 效率，各领域都鼓励简洁而有效的解。
  • PTX 损失：为防止联合 RL 训练中遗忘高质量数据，挑选一批高质量样本，通过辅助的 PTX 损失（InstructGPT 里的做法：在 RL 目标上加预训练式的语言建模损失）并入 RL 目标。既利用好数据，也降低对 RL 中有限任务集过拟合的风险，提升跨领域泛化。
  • 温度衰减：创意写作和复杂推理在训练初期需要高采样温度来探索，防止过早收敛到次优解；但后期或评测时温度高会带来过多随机性。所以用温度衰减调度，从探索逐渐转向利用。

11. RL 基础设施

11.1 共置架构与引擎切换

和 K1.5 一样，K2 的同步 RL 用共置（colocated）架构：训练引擎和推理引擎在同一批机器上，一个工作时另一个释放或卸载 GPU 资源。每轮由中心控制器先调推理引擎生成数据，再让训练引擎训练，然后把新参数发给推理引擎。

rollout 期间训练引擎的参数卸载到 DRAM，恢复时只需一次 H2D 拷贝。难的是推理引擎：它要从训练引擎拿到新参数，而两者分片方式不同。到 K2 规模，用网络文件系统做重分片和广播不可行（需要每秒数 PB 的总带宽）。他们做了一个和训练节点共置的分布式 checkpoint engine：每个 worker 从训练引擎拿本地参数副本，然后在所有 checkpoint engine worker 间广播完整参数集，推理引擎只取自己需要的那一片。为控制显存，更新逐参数、流水线式进行。

“广播全部参数”比理论最优的“只传需要的”多传好几倍数据，但它让训练和推理引擎完全解耦、更易维护测试；而且因为同步开销小、网络带宽利用率高，实际上反而更快。K2 的完整参数更新不到 30 秒。代码开源在 MoonshotAI/checkpoint-engine。

具体的流水线是这样的：每卡三个等大缓冲区——一个 H2D 缓冲、两个 IPC 缓冲（共享给推理引擎直接访问）。理想是三阶段流水（H2D、广播、推理引擎重载）；但在 H800 上并发 H2D 与广播会占满共享的 PCIe，三阶段退化成串行。所以实际用两阶段：先所有设备做一次同步 H2D，然后广播和重载并行。规模大时每卡分片小，整套参数一次就能放进 H2D 缓冲，开销消失。

11.2 启动与故障恢复

训练引擎启动时，每个 worker 只从磁盘读部分或不读参数，再广播给同伴，保证所有 worker 合起来只读一次 checkpoint。推理引擎是独立副本，不想引入额外同步屏障，所以复用 checkpoint engine：由它集体读盘，再用上面的方法更新未初始化的推理引擎。这也让系统对单点故障更鲁棒：单个推理副本可以独立重启。

11.3 Agentic rollout

  • 环境反馈（虚拟机、代码解释器）会阻塞，GPU 空闲。两个对策：重环境部署成可单独扩容的专用服务；大量并发 rollout 摊薄昂贵交互的延迟。
  • 单条轨迹可能极长。用 K1.5 的 partial rollout：长尾的未完成任务暂停，下一轮迭代继续，不阻塞整轮。
  • 仿 OpenAI Gym 设计统一接口，方便接入新环境。

13. 小结

把 K2 拆开看，最值得带走的是三点：

  • 优化器层面：Muon 的 token 效率优势在万亿规模上兑现了，代价是一个新的失稳模式（满秩更新让 \(W_q W_k^\top\) 的谱范数更容易增长）。QK-Clip 用“logit 对 \(W_q, W_k\) 双线性”这一点，在权重层面直接修正，逐头、按需、训练稳定后自动退出。MLA 下要小心共享的 RoPE key，只缩放头专属分量。
  • 数据层面：在高质量 token 受限时，“改写多份各看一遍”优于“原始文本看多遍”，K2 给了一个干净的 SimpleQA 对照。
  • Agent 层面：大规模合成（工具库 → agent → 带 rubric 的任务 → 模拟器轨迹 → 评审过滤）配合真实沙箱，再用可验证奖励与自我批评 rubric 奖励统一做 RL，critic 本身也用可验证信号持续校准。

K2 之后，Moonshot 的注意力路线转向 KDA 线性注意力与 MLA 的混合，即 Kimi Linear，它也是后来 K3 的骨架。
