Kimi K3：KDA、注意力残差与 Stable LatentMoE

交互2026-10-19

Kimi K3 是 Moonshot AI 在 2026 年 7 月发布的旗舰模型，接在 K2 之后：总参数 2.78T（通常说 2.8T），激活 104B，原生视觉，上下文 1M token，权重全部开源。架构、数据和训练配方的改进合起来，相对 K2 带来约 2.5 倍的整体缩放效率。

和 K2 相比，K3 几乎每个部件都换了：注意力从全 MLA 换成 Kimi Linear 的 KDA–MLA 混合（并对 KDA 做了两处改动）；残差连接换成“注意力残差”（AttnRes）；MoE 换成 896 个专家、每 token 激活 16 个的 Stable LatentMoE，配上新激活函数 SiTU-GLU 和新的负载均衡方法分位数均衡（Quantile Balancing）；优化器变成逐头 Muon。后训练是按领域和推理强度训练 9 个专家再做多教师在线蒸馏，基础设施则围绕“3T 级 MoE + 1M 上下文 Agent RL”重做了一遍。

2. 混合注意力：KDA 的两处改动与 Gated MLA

2.1 KDA 回顾

K3 的大部分层是 KDA（Kimi Delta Attention），一种线性注意力：它不保留所有历史 token 的 KV cache，而是维护一个固定大小的状态矩阵 \(S_t\)，每来一个 token 就更新一次（delta 规则、分块算法和 3:1 混合的推导见 Kimi Linear）。递推是（单头，\(d_k=d_v\)）

$$S_t = \big(I-\beta_tk_tk_t^\top\big)\operatorname{Diag}(\alpha_t)S_{t-1} + \beta_tk_tv_t^\top,\qquad \tilde o_t = S_t^\top q_t ,$$

\(\alpha_t\in(0,1)^{d_k}\) 是逐通道的一步保留率，\(\beta_t\in(0,1)\) 是 delta 规则的写入强度。\(q,k\) 经过 ShortConv、Swish、L2Norm，\(v\) 经过 ShortConv、Swish，\(\beta_t\) 是 sigmoid。衰减的 logit 由低秩投影加每头的偏置给出：\(z_t^h = W_\alpha^{\uparrow}W_\alpha^{\downarrow}x_t + b_\alpha^h\in\mathbb R^{d_k}\)。训练用分块形式，块内的输出是

$$O_{[t]} = (\Gamma\odot Q_{[t]})S_{[t]} + \operatorname{Tril}\big[(Q_{[t]}\odot\Gamma)(K_{[t]}/\Gamma)^\top\big]\big(U_{[t]}-W_{[t]}S_{[t]}\big).$$

2.2 改动一：有下界的衰减

问题出在 \(K/\Gamma\)：\(\Gamma\) 是保留率的累积乘积，它的倒数随块内位置指数增长，有限精度下会溢出。Kimi Linear 的处理是在对数域算相对衰减，再把块切成 16 个 token 的二级小块：非对角的小块可以直接用 Tensor Core 做稠密矩阵乘；对角的小块（相对位置跨度包含 0 的那部分）仍需要按位置对显式计算，这是块内计算的主要瓶颈。

K3 换掉了从 logit 到对数衰减 \(g=\log\alpha\) 的映射：

$$\text{Kimi Linear：}\ g_t^h = -e^{A_h}\operatorname{Softplus}(z_t^h)\in(-\infty,0),\qquad \text{K3：}\ g_t^h = g_{\min}\operatorname{Sigmoid}\big(e^{A_h}z_t^h\big)\in(g_{\min},0),\qquad \alpha_t^h = e^{g_t^h}.$$

\(A_h\) 是可学习的每头对数尺度（初始化为 0），\(g_{\min}=-5\) 固定。于是每个保留率 \(\alpha>e^{-5}\approx 6.7\times10^{-3}\)，一个 16-token 小块内的累积对数衰减落在 \((-80,0)\)，倒数小于 \(e^{80}\)。BF16 的最大有限值约 \(3.39\times10^{38}\approx e^{88.7}\)，所以倒数一定在 BF16 范围内。有了这个有限范围，对角小块也能直接用稠密 Tensor Core 矩阵乘，按位置对计算的路径被整个去掉。

代价是模型不再能在一步之内“完全清空”某个通道（最少保留 0.67%）。不过一个通道连续几步都取下界，几步之后也就几乎清零了（例如 4 步后 \(e^{-20}\approx 2\times10^{-9}\)）。这种参数化和 RNN 文献里“有下界的循环门”是同一类思路。

2.3 改动二：全秩输出门

输出门决定每个通道读出多少。Kimi Linear 的输出门是低秩的（\(W_g^{\uparrow}W_g^{\downarrow}\)），K3 改成输入相关的全秩投影：

$$y_t = W_o\big[\operatorname{Sigmoid}(W_gx_t)\odot\operatorname{RMSNorm}(\tilde o_t)\big].$$

2.4 Gated MLA

全局注意力层仍是 MLA（只缓存压缩隐向量 \(c_t=W_cx_t\)，用上投影重建 key/value）。和 K2、K2.5 不同，K3 按 Kimi Linear 的做法对所有 MLA 层用 NoPE：查询和键都不加位置编码，位置与近因信息完全由 KDA 层提供，MLA 层只负责不受限制的全局内容交互。这样扩展上下文时不用重调 RoPE 底数或 YaRN。

MLA 也加了一个与 KDA 一致的、输入相关的逐通道全秩输出门：

$$y_t = W_o\big[\operatorname{Sigmoid}(W_gx_t)\odot\tilde o_t\big],$$

让每个 token 能调节它从全局注意力读出的通道。另一个细节：flash attention 在低精度下的舍入误差是有偏的，为了消除它，训练时注意力输出保持 FP32。这让输出 tile 的片上占用翻倍，于是他们重新设计了训练 kernel，让输出 tile 与 KV 暂存缓冲区复用（而不是与 query tile 复用），腾出共享内存给更深的 KV 流水线，反而提高了吞吐。

3. 注意力残差：在深度上做注意力

3.1 动机

标准的（PreNorm）残差连接 \(h_{l+1}=h_l+f_l(\cdot)\) 把之前所有层的输出以固定的单位权重累加到一个状态里。可以这样类比：这像是 RNN 在时间上把所有历史压进一个隐状态；Transformer 在序列维上用注意力替代了循环，AttnRes 就在深度维上做同样的事——每层按数据相关的权重，有选择地取用之前各层的输出。均匀累加还有一个具体问题：隐状态随深度不受控地增长，每一层的贡献被逐层稀释（PreNorm dilution）。

3.2 完整形式

第 \(l\) 层有一个可学习的伪查询 \(w_l\in\mathbb R^d\)（不依赖输入），key 和 value 都是之前的层输出：

$$k_i = v_i = \begin{cases} h_1 & i=0\ (\text{token embedding})\\ f_i(h_i) & 1\le i\le l-1\end{cases},\qquad \alpha_{i\to l} = \frac{\exp\big(w_l^\top\operatorname{RMSNorm}(k_i)\big)}{\sum_{j=0}^{l-1}\exp\big(w_l^\top\operatorname{RMSNorm}(k_j)\big)},\qquad h_l = \sum_{i=0}^{l-1}\alpha_{i\to l}\,v_i .$$

RMSNorm 防止输出幅度大的层主导权重。注意权重虽然由固定的 \(w_l\) 打分，但因为 key 是当前 token 在各层的实际输出，所以权重对每个 token 不同（输入相关）。深度不到 100 层，\(O(L^2d)\) 的计算可以接受；真正的开销是要把所有层的输出一直保留（\(O(Ld)\) 显存），在流水线并行下还要跨 stage 传输。

3.3 分块形式（Block AttnRes）

把 \(L\) 层分成 \(N\) 个块。块内的层输出直接求和成一个块表示 \(b_n=\sum_{j\in\mathcal B_n}f_j(h_j)\)，\(b_0=h_1\)（embedding 总是一个源）。块 \(n\) 的第 \(i\) 层在以下 value 上做注意力：

$$V = \begin{cases}[b_0,\dots,b_{n-1}] & i=1\\ [b_0,\dots,b_{n-1},\ b_n^{i-1}] & i\ge2\end{cases}$$

其中 \(b_n^{i-1}\) 是块内前 \(i-1\) 层的部分和。显存与通信从 \(O(Ld)\) 降到 \(O(Nd)\)。推理时，“对已完成的块做注意力”可以并行地一次算出，再用 online softmax 与块内顺序累积的部分和合并，显著降低推理开销。经验上 \(N\approx8\) 就能拿回大部分收益。K3 用 8 个 12 层的块（96 > 93，所以最后一块是不满的），算上 embedding 共 9 个源。

4. Stable LatentMoE

4.1 LatentMoE：路由专家在压缩空间里工作

扩大专家池和每 token 激活的专家数能扩大“专家专门化”的空间。但在普通 MoE 里每个被选中的专家都接收完整的 \(d\) 维表示，通信量和专家权重的读取量随激活专家数线性增长。LatentMoE 的做法是把模型宽度与路由专家的宽度解耦：共享专家保留全宽路径处理通用变换；路由专家在宽度为 \(\ell\) 的压缩空间里工作：

$$u = \sum_{i\in\mathcal T_k(x)}p_i\,E_i^{\text{routed}}\big(W^{\downarrow}x\big)\in\mathbb R^{\ell},\qquad y = \sum_{j=1}^{N_s}E_j^{\text{shared}}(x) + W^{\uparrow}\operatorname{RMSNorm}(u).$$

K3 中 \(d=7168\)，\(\ell=3584\)，\(N_s=2\)，896 个路由专家激活 16 个，稀疏度 56。算一下通信：每 token 发往专家的数据量是 \(16\times3584=57344\) 个数，和 K2 的 \(8\times7168\) 完全相同——激活专家数翻倍，而通信量不变。每个路由专家的参数是 \(3\times3584\times3072\approx33\)M，92 个 MoE 层 × 896 个专家合计约 2.72T，占总参 2.78T 的绝大部分；每 token 激活的路由专家参数约 \(92\times16\times33\text{M}\approx48.6\)B。

4.2 两个失效模式

这么极端的稀疏度放大了原始设计的两个问题：

  • 路由分支是 \(W^{\downarrow}\) → 门控多分支的专家 FFN → \(W^{\uparrow}\)，几乎是四个矩阵乘串联。这种病态结构加上 2.8T 的规模，会让路由分支内部的激活爆炸。
  • 给近 \(10^3\) 个专家做负载均衡，超出了现有无辅助损失偏置更新还能表现良好的范围。

Stable LatentMoE 用三个部件对付它们：\(W^{\uparrow}\) 之前的 RMSNorm、SiTU-GLU（压激活爆炸），以及分位数均衡（负载均衡）。

4.3 归一化

原始 LatentMoE 直接对聚合后的 \(u\) 做 \(W^{\uparrow}\)，而 \(u\) 的尺度随被选中的专家和路由权重变化。K3 在聚合和上投影之间插入 RMSNorm（上面公式里那个），降低路由分支对尺度变化的敏感性，再与全宽的共享分支相加。这不仅稳定了训练，还一致地改善了验证 loss 和下游指标。

4.4 SiTU-GLU

GLU 是 \(\operatorname{Sigmoid}(W_gx)\odot W_ux\)；SwiGLU 把门换成 \(\operatorname{Swish}(z)=z\,\sigma(z)\)。SwiGLU 的两个乘数都是无界的，两个大坐标同时出现就会产生激活离群值，在低精度下增加溢出风险。原始 GLU 的 sigmoid 门有界，但失去了 Swish 在正半轴近似线性的响应。K3 的折中是对 Swish 的线性因子和 up 分支都加平滑上限 \(\operatorname{softcap}(z,\beta)=\beta\tanh(z/\beta)\)：

$$\operatorname{SiTU\text{-}GLU}(x) = \Big[\beta_1\tanh\!\Big(\frac{W_gx}{\beta_1}\Big)\odot\operatorname{Sigmoid}(W_gx)\Big]\odot\Big[\beta_2\tanh\!\Big(\frac{W_ux}{\beta_2}\Big)\Big],\qquad \beta_1=4,\ \beta_2=25 .$$

它有三条性质：

  • 局部一致：\(\beta\tanh(z/\beta) = z + O(z^3/\beta^2)\)，所以在原点附近与 SwiGLU 一阶相同；\(\beta_1,\beta_2\to\infty\) 时逐点退化为 SwiGLU。
  • 有界：\(|\tanh|\lt1\)、\(0\lt\sigma\lt1\)，每个输出坐标满足 \(|\cdot|\le\beta_1\beta_2=100\)。
  • 负半轴仍然衰减到 0：sigmoid 因子保留，所以 Swish 的负尾巴形状不变；cap 主要控制大的正激活。与对门的预激活做硬截断相比，平滑上限在饱和边界之外仍有非零梯度，训练表现更好。

5. 分位数均衡（Quantile Balancing）

5.1 无辅助损失的偏置均衡

K3 沿用 DeepSeek-V3 式的无辅助损失路由：路由分数 \(s_i=\operatorname{Sigmoid}(W_rx_i)\)，选专家时加一个每专家的偏置 \(b_j\)，但混合权重不含偏置：

$$\mathcal T_i = \operatorname{argtop}_k(s_i + b),\qquad p_{i,j} = \frac{s_{i,j}}{\sum_{r\in\mathcal T_i}s_{i,r}},\ j\in\mathcal T_i .$$

偏置只影响分派，不影响混合权重和路由器的梯度。原方法每步按负载误差的符号固定步长更新：\(b_j\leftarrow b_j+\gamma\operatorname{sign}(\bar\ell-\ell_j)\)。\(\gamma\) 小则适应慢，大则负载振荡。专家数到 896 时这个权衡很难调。

5.2 从最优均衡指派推导

符号更新的问题在于它只知道“该往哪边调”，不知道“该调多少”。要一步调到位，先把均衡路由写成一个指派问题：\(m\) 个 token、\(n\) 个专家，每个 token 选 \(k\) 个，每个专家恰好接 \(q=mk/n\) 个，最大化总分：

$$\max_{x_{ij}\in\{0,1\}}\sum_{i,j}x_{ij}s_{ij}\quad\text{s.t.}\quad\sum_jx_{ij}=k,\qquad \sum_ix_{ij}=\frac{mk}{n}.$$

二部图 b-匹配多面体是整的，所以松弛到 \(x\in[0,1]\) 不损失最优性。对两组等式约束引入乘子 \(\alpha_i\)（token 侧）、\(\beta_j\)（专家侧），交换 max 与 min 后内层可以逐元素求解：\(x_{ij}^*=1\) 当且仅当 \(s_{ij}-\alpha_i-\beta_j\gt0\)。代回得到凸的对偶目标

$$\min_{\alpha,\beta}\ \sum_{i,j}\max\big(0,\ s_{ij}-\alpha_i-\beta_j\big) + k\sum_i\alpha_i + \frac{mk}{n}\sum_j\beta_j .$$

固定 \(\beta\) 对 \(\alpha_i\) 求最小：目标关于 \(\alpha_i\) 分段线性，斜率是 \(k\) 减去“大于 \(\alpha_i\) 的 margin 个数”，所以恰好有 \(k\) 个 \(s_{ij}-\beta_j\) 在 \(\alpha_i\) 之上时最小——取第 \(k+1\) 大的值，也就是 \((1-k/n)\) 分位数。对称地，固定 \(\alpha\) 时

$$\beta_j^* = \operatorname{quantile}_{1-k/n}\big(s_{:,j}-\alpha\big),$$

即专家 \(j\) 的所有 margin 中第 \(q+1\) 大的值。两个更新都是同一个分位数，只是一个沿 token 轴、一个沿专家轴，这就是名字的来源。最优解处，token \(i\) 选中的专家恰是 \(s_i-\beta^*\) 的 Top-\(k\)，所以路由只需要专家侧阈值（偏置 \(b=-\beta\)），token 侧的 \(\alpha\) 是与 batch 绑定的中间量，用完即弃。推理时就是带冻结偏置的普通 Top-\(k\)。

5.3 训练中的实际更新

每步只用一次前向：路由时把 Top-\(k\) 改成在 \(s_i+b^{(t)}\) 上取 Top-\((k+1)\)，前 \(k\) 个是实际走的路由，第 \(k+1\) 个就是截断值 \(\alpha_i^{(t)}\)（专家要进入 token \(i\) 的 Top-\(k\) 必须超过它），省掉单独的 token 侧分位数计算。然后

$$\hat b_j^{(t+1)} = -\operatorname{quantile}_{1-k/n}\big(s_{:,j}-\alpha^{(t)}\big),\qquad b^{(t+1)} = \hat b^{(t+1)} - \operatorname{mean}\big(\hat b^{(t+1)}\big)\mathbf 1 .$$

第二行去掉一个不影响 Top-\(k\) 的公共偏移。为了因果性，更新只在下一步生效，一个 batch 永远不用由它自己算出的偏置来路由。

和符号更新的关系：对偶目标对 \(\beta_j\) 的次梯度是“目标负载减实际负载”，对它做 SignSGD 正好是原来的固定步长符号更新；QB 则直接跳到这个坐标的精确最小值。这解释了 QB 为什么没有类似学习率的超参，以及为什么近千个专家也能几步就平衡。另一个相关方法 BIP（基于二元整数规划的负载均衡）求解的是不等式约束版本，会多出 \(\max(0,\cdot)\) 截断，只能压制过载专家、不能提拔欠载专家，平衡慢得多。

5.4 直方图估计分位数

一个全局 batch 有数百万 token，分散在各个 rank 和梯度累积步上，收集全部 margin 求精确分位数不可行。做法是给每个专家维护直方图：对“所需偏置” \(r_{ij}=\alpha_i-s_{ij}\) 计数（它的 \(k/n\) 分位数就是 \(\hat b_j\)）。因为 sigmoid 分数在 \((0,1)\)，截断值 \(\alpha_i\) 在 \((b_{\min},1+b_{\max})\)，所以 \(r_{ij}\in[b_{\min}-1,\ b_{\max}+1]\)，在这个区间上均匀分 \(B\) 个桶，每步重算区间。各 rank 在所有 micro-batch 上本地累加计数，步末一次整数 all-reduce 得到全局直方图，找到累计计数达到 \(\lceil q\rceil\) 的桶，在桶内线性插值。误差不超过一个桶宽；\(B=1000\) 时最多几个 \(10^{-3}\)，没有可测的残余不均衡。通信量只有每层每步 \(nB\) 个整数，与 token 数无关；而且计数可加，结果严格等于全局 batch 的分位数（而不是各 rank 分位数的平均）。再对估计值做 EMA 还能进一步降低批间噪声。

模拟器在合成的路由分数上实际运行三种方法。每步随机生成一个新 batch（专家有固定的偏好偏差，且随步数缓慢漂移，模拟路由器在学习），按当前偏置路由、统计负载、再更新偏置。纵轴是 MaxVio = 最大负载 / 目标负载。

6. 原生视觉与逐头 Muon

6.1 原生多模态

K3 从训练一开始就联合优化语言和视觉，文本、图片、视频在同一个上下文里由同一个骨干处理，没有事后的模态对齐阶段。这是“视觉在环”的长程行为的基础：模型写代码、看渲染结果的截图或视频帧、再改，全在一个 token 流里，不需要跨模型交接。

6.2 MoonViT-V2：从零开始、用下一个 token 预测训练

和 K2.5 最大的不同是视觉编码器不再用对比学习预训练的模型（如 SigLIP）初始化，而是从零开始、用下一个 token 预测训练。主要理由是稳定性：把预训练编码器接到 LLM 上联合优化时，SigLIP 初始化的 MoonViT-3D 梯度范数持续偏高、频繁尖峰；从零训练的 MoonViT-V2 全程稳定。另一个理由是让编码器的表示直接由语言建模目标塑造，而不是由偏好全局语义的对比损失塑造。MoonViT-V2 在各项视觉评测上与 SigLIP 初始化的基线持平，说明在这个规模下对比预训练作为初始化是不必要的。

结构：27 层 ViT，约 0.4B 参数，用 RMSNorm，去掉线性层和注意力投影的所有 bias（进一步稳定从零训练）；图片和视频共享全部参数，注意力分解为帧内空间和帧间时间两步，并在时间维上池化；投影前做 2×2 的 pixel shuffle，视觉 token 数减为 1/4。按 patch 14 算一下最大输入：\(3584\times3584\) 的图是 \(256\times256=65536\) 个 patch，pixel shuffle 后 16384 个 token，在 1M 上下文里放得下几十张。

6.3 逐头 Muon

K3 仍用 Muon（K2 的 QK-Clip 也保留了，两者见 Kimi K2），但对注意力投影做了逐头化：不对整个 \(Q,K,V\) 投影矩阵做 Newton–Schulz，而是把动量矩阵沿头的维度切开，每个头的块单独正交化。直觉是：整体正交化把所有头当成一个耦合的块，梯度/动量大的头主导共同的更新方向，小的头得不到充分归一化；逐头正交化让每个头的更新尺度一致。这让各头的学习动态更均衡、大规模训练更稳定，而且对细长的每头块做 Newton–Schulz 比对整个矩阵更便宜。

7. 预训练：缩放律、配方与 1M 上下文

7.1 数据

文本仍是网页、代码、数学、知识四个领域，沿用 K2 的规则过滤、分类器质量打分、去重和改写（多风格提示、分块自回归改写、忠实度校验）。视觉语料沿用 K2.5 的分类：图像描述、图文交错文档、OCR、感知、视频、视觉编程数据；坐标监督同时给绝对坐标和归一化到 [0,1] 的坐标。新增的是大规模“程序化多模态数据”：把代码片段与它渲染出的视觉结果配对，覆盖 SVG、3D 资产、网页、游戏和 CAD 图纸。

7.2 缩放律与学习率调度

架构、数据和训练的改动也改变了最优训练区间，所以他们重新做了缩放律来调 batch size、学习率、每参数 token 数（TPP）和模型形状。在留出的 OOD 验证集上，这些改动合起来带来约 2.5 倍的整体缩放效率（相对 K2）。

一个和 K2 相反的结论：缩放律研究一致偏向余弦衰减而不是 WSD。他们指出两种调度的最优超参（峰值学习率、batch size）差别很大，用同一组超参比较会偏袒与之更匹配的那个；为公平起见各自独立做缩放律搜索，在各自最优超参下余弦衰减的最终 loss 一致更低。（K2 用的是 WSD。）

7.3 配方

  • 原生多模态：视觉和文本 token 交错在同一个下一个 token 预测目标里；
  • 优化器：逐头 Muon + K2 的权重裁剪（QK-Clip）；负载均衡用 QB；
  • 余弦学习率，1% 线性 warmup，权重衰减 0.1；
  • 上下文：预训练从 8K 开始，后期扩到 64K；cooldown 阶段从 256K 扩到 1M（四阶段课程），把昂贵的长序列计算集中在总预算的一小部分。

7.4 长上下文

因为没有显式位置编码（MLA 用 NoPE，位置由 KDA 的门控衰减隐式编码），模型直接外推到 1M，不需要 RoPE 缩放或插值。长文档和长视频的数据清洗包括精确与模糊去重（视频还用帧的感知哈希）、启发式与分类器质量过滤、结构校验；真正长且连贯的数据稀缺，所以上采样，避免 cooldown 期长上下文分布被短序列淹没。但长度本身不带来长程能力，所以还合成了长上下文数据：把多模态文档和子任务打乱拼接，使嵌入的任务只有关注散布在整个 1M 上下文里的信息才能解决，防止注意力退化成局部模式。

8. 后训练：9 个专家与多教师在线蒸馏

三阶段：SFT 建立基础 agent 能力；RL 在不同推理强度下训练各领域专家；多教师在线蒸馏（MOPD）把它们合并成一个模型。

8.1 SFT 与聊天模板

在 K2/K2.5 的 SFT 数据上大幅扩充复杂 agent 任务：用之前 Kimi 系列的领域模型合成轨迹，经多阶段验证和人工参与标注。所有数据用新的 XTML 聊天模板序列化，并且从 SFT 开始就做量化感知训练（MXFP4 权重、MXFP8 激活，见 8.5）。

XTML（eXtensible Token Markup Language）是一种类 XML 标记，但尖括号语法换成三个保留特殊 token：[open]、[sep]、[close]，外加停止符 [end_of_msg]。每个结构边界都是一个显式特殊 token，消除了元素边界处的分词歧义，也简化约束解码。几个设计点：

  • 消息分区与 KV cache：全局选项（工具声明、推理强度）放在所有输入消息之前，它们很少变；一次性选项（tool_choice、response_format）放在输入消息之后，所以每次请求改它们不会让历史的 KV cache 失效。会话中途动态加载的工具通过额外的 tool-declare 消息插入，不必重建前文。
  • 通道：助手消息分 think、response、tools 三个通道（借鉴 OpenAI Harmony 格式）。思考模式和指令模式只靠生成前缀区分（[open]think[sep] 或 [open]response[sep]）。K3 只支持“保留思考”：思考模式下历史里的 think 通道总被保留（即使为空）。
  • 工具调用：每个调用带 tool 和 index 属性，结果消息重复同样的 tool/index；参数有类型，字符串参数直接以原样出现（代码不再是转义的 JSON 字符串）。
  • 推理强度：作为 thinking-effort 类型的全局选项消息，用自然语言写明请求的级别；模式预留 low/medium/high/max 四级，K3 支持其中一部分。所有选项都翻译成上下文里的短自然语言指令，预训练模型本来就会遵循指令，新选项几乎不需要额外训练，即“低对齐税”。

8.2 RL：三个领域 × 三档强度

不为单个任务训练专门的 RL 模型，而是在三个大领域上扩展 RL，每个领域在每档推理强度下各训练一个专家：(i) 通用任务（通用体验、视觉、推理、忠实度、搜索、知识工作）；(ii) 通用 agent（长程助手任务、深度研究、段落级写作）；(iii) 编码 agent（软件工程、编码体验、kernel 任务、Web 开发）。三个领域 × {low, high, max} = 9 个专家。随 RL FLOPs 增加，工具调用步数持续上升，各项能力全面提高。

算法：在同步 RL 框架的 partial rollout 上扩展。每轮对 \(N\) 个提示各采 \(K\) 条，保持 \(N\times K\) 条在跑；当一个比例 \(\lambda\in(0,1)\) 的轨迹完成（\(\lambda NK\) 条）就暂停生成，进入策略优化，不等长尾。暂停的 rollout 排队，在下一轮开始时优先恢复（靠第 12 节的沙箱基础设施保存环境状态）。一个提示的 \(K\) 条都完成就立即送去优化，优化算法沿用 K2.5。这样一条长轨迹会跨越多轮，带来数据陈旧（off-policy）问题；他们的算法用逐 token 的正则把策略更新限制在局部邻域内，能容忍高度陈旧的数据。

8.3 推理强度 RL 与生成式奖励模型

逐题预算：每题 \(x\) 有一个由冷启动模型估计的初始预算 \(b_0(x)\)；轨迹总 token 数 \(T(y)\) 超过 \(\tau\cdot b_0(x)\) 时，任务奖励直接改为 \(-1\)。通用任务的 \(T(y)\) 只算思考 token；agent 任务算全部输出 token（含推理和工具调用参数）。按 \(\tau\) 做分阶段课程：先用较大的 \(\tau\) 训练 max 档（仍封顶以压制过度思考），再把 \(\tau\) 退火到更小值得到 high 和 low 档。\(\tau\) 的调整按领域、在人工指导下进行。各档专家的轨迹再一起用于 SFT 和 MOPD。

Agentic GRM：不可验证的通用任务沿用 K2.5 的锦标赛式成对比较组奖励，但评审是一个 agent，必须遵守固定流程：(1) 阅读结果、产物或文本；(2) 生成 rubric；(3) 按 rubric 给每个候选打分；(4) 把分数记到计分板。为防止奖励被“越来越长”的输出 hack，类比预算控制：冷启动模型估计初始长度 \(\ell_0\)，乘子 \(\sigma\)，输出超过 \(\sigma\ell_0\) 的候选在成对比较里自动判负。

8.4 多教师在线蒸馏（MOPD）

训练学生时，对领域 \(d\) 和采样的强度 \(e\)，由对应的教师 \(\pi^{(d,e)}_{\text{teacher}}\)（9 个之一）指导。学生自己生成（on-policy），每个 token 的奖励是教师与学生的对数概率差：

$$r_{\text{opd}}^d(y_t\mid e,x,y_{\lt t}) = \operatorname{clip}\Big(\operatorname{sg}\Big(\log\frac{\pi_{\text{teacher}}^{(d,e)}(y_t\mid x,y_{\lt t})}{\pi_\theta(y_t\mid e,x,y_{\lt t})}\Big),\ -R_{\max},\ R_{\max}\Big).$$

\(\operatorname{sg}\) 是 stop-gradient，裁剪到 \(\pm R_{\max}\) 是为了避免极端的优势值。这个奖励在期望上等于负的逐 token 反向 KL：把它当作稠密奖励放进 RL 框架，就是在学生自己的分布上最小化 \(\mathrm{KL}(\pi_\theta\,\|\,\pi_{\text{teacher}})\)。好处是它和 RL 用同一套基础设施（包括 partial rollout）。注意教师的条件里没有 \(e\)：每个教师本身就是某一档强度的专家。更细粒度的 top-\(k\) 蒸馏目标也试过，收敛速度和最终效果都没有明显优势。

8.5 面向部署的后训练

MXFP4 QAT：MoE 专家权重占了绝大部分参数内存，所以把它们量化成 MXFP4（激活用 MXFP8），而注意力投影、latent MoE 投影、共享专家和路由器保持高精度。整个后训练（SFT 和 RL）都做量化感知训练；RL 中 rollout 与训练用同一量化方案，消除训练–推理不一致。

草稿模型：K3 预训练时就带一个结构与骨干 block 相同的 MTP 层。EAGLE-3 的草稿模型是单个解码层，结构与 MTP 层一致，所以把预训练的 MTP 层微调成 EAGLE-3 式草稿：目标模型冻结，只训草稿层和特征融合投影。训练时按 EAGLE-3 的“训练时测试”协议展开 7 步，除第一步外草稿都吃自己之前的输出。草稿输入融合目标模型的低、中、高层特征，分别取第 1、第 4 和最后一个 AttnRes 块的输出；拼接后用无偏置矩阵 \(W_{E3}\) 投影回隐藏维，\(W_{E3}\) 初始化为 \([0\ 0\ I]\)，使融合表示一开始就等于 MTP 层预训练时看到的高层特征，再逐渐学会用低、中层特征。

损失直接优化接受率。无损的投机采样中，草稿分布 \(q\) 的 token 被接受的概率是 \(\sum_x\min(p(x),q(x))\)（\(p\) 为目标分布）。对容量有限的草稿模型，最小化 KL 并不保证最大化这个接受率，所以用 LK 损失——接受率的负对数：

$$\mathcal L_{\text{LK}} = -\log\sum_{x\in\mathcal V}\min\big(p(x),q(x)\big),$$

\(p,q\) 都在温度 1 下计算，不加真实标签的交叉熵项。草稿微调同样用 MXFP4/MXFP8 的 QAT 配置。

9. RL 环境与任务合成

RL 的上限取决于任务和环境的质量。K3 在这方面做了七类工作：

  • 统一的白盒 RL 环境：用一个固定 agent harness 训练会过拟合到特定的工具 schema、系统提示、上下文管理或交互协议。他们把 harness 表示为可配置、可组合的模块（工具接口、系统提示、上下文管理策略、skills、记忆、子 agent 等），可以拼出 Kimi Code、Claude Code、Codex、OpenClaw、Hermes 等主流 harness 或全新的组合；RL 时给不同任务组动态构造不同配置。
  • 知识图谱引导的任务合成：建一个自我演化的、分层的有向无环知识图谱。从粗粒度种子节点开始，每个节点分配一个 agent 去做多次网页搜索调查概念，加新节点前先在已有图里找等价或相关概念以减少重复；边总是从粗到细；agent 判断概念已足够“原子”时停止扩展。合成时按目标分布在不同粒度采样节点（单个或相关组合），结合祖先节点的上下文组成搜索查询，取回真实材料，再由合成 agent 生成不同类型的任务。
  • agent 环境中的可验证问题：多步信息检索（计划、逐步取证、给出可验证答案）；专业人士的日常工作（投行、数据分析、法律，在沙箱里操作领域工具，数十到数百步完成交付物）；多步可验证视觉推理：在有 Python 解释器的沙箱里反复写代码裁剪、放大、变换图片、做精确计算或验证中间结果，执行结果（包括生成的图）作为新的观察。
  • Kernel 优化任务：从单算子到融合的 mega-kernel，来源包括 Flash Linear Attention 等高质量仓库，覆盖 CUDA、Triton、CuTe DSL、Gluon、ThunderKittens、TileLang 和 BF16/FP8/FP4。奖励兼顾正确性和性能：每个 kernel 有 PyTorch 参考实现，数值误差超阈值奖励为 0；性能对比专家实现，持平得 0.5，逼近硬件 roofline 趋近 1。还有一个持续扩展的 hack 检测系统，惩罚 CUDA graph 重放、缓存输入、降低精度等作弊。
  • 个人助理任务：Gmail、Notion、Slack、Canvas 等应用的逼真 mock 实现，保留核心语义但可复现、无外部 API 限流。任务模仿人力、法律、金融的真实工作流；agent 在一个持续演化的环境里跨多个模拟日工作，遇到数十个跨应用的相互依赖事件，单个 rollout 可达数千次工具调用、数百万 token 上下文。每个事件有自己的评判标准（确定性规则或 LLM 评审）。
  • 自主执行任务（AET）：每个任务给定初始状态、受约束的目标、基于工具的动作空间、执行预算和独立的验证器。agent 只看到目标、上下文、约束和验证接口，没有参考轨迹，要自己分解、选工具、规划、纠错和决定何时结束；奖励来自验证器对最终环境状态的评估而不是 agent 自述。验证器类型包括黑盒系统复刻、量化因子发现、税务审计等。防 hack：agent 与验证器隔离，公开验证器给诊断反馈、隐藏验证器评估留出场景，有限提交次数下用惩罚式奖励。
  • Web 开发任务：从一句话描述到多段规格，产物包括网站、交互游戏、3D/WebGL、可视化、SVG、全栈应用；在容器沙箱里用多种 agent 脚手架运行。奖励 = 确定性检查（功能测试；复刻类任务比结构和像素相似度）+ 内部奖励模型评审（看源码，或观察并操作产物）；构建失败、运行报错或“伪造而非实现”时奖励清零。

10. 基础设施（一）：KDA 的 kernel 与上下文并行

10.1 不同场景的 kernel

  • 训练与 prefill：分块形式块内并行、块间串行，朴素执行时两阶段交替，串行传递状态时 SM 空闲。FlashKDA 是基于 CUTLASS 的分块 kernel，把块内计算和跨块状态传递重叠：拆成 token 并行的阶段和头并行的递推，各自调度调优，明显快于 Triton 参考实现，并作为 flash-linear-attention 的后端自动调用。
  • 单卡内上下文并行（长 prefill）：张量并行按头切分，但不会缩短递推；纯 TP 部署下 prefill 超长序列，每个 rank 只有几个头，大部分 SM 闲着。关键观察是每一段的状态转移可以独立于入口状态计算，事后再精确组合。所以一个 SM 级的规划器把序列切给同一张卡的多个 SM，并行算各段的转移，再合并恢复每段的精确初始状态——完全在卡内，没有跨卡通信。

10.2 KDA 上下文并行（KCP）

跨卡的上下文并行里，softmax 注意力要交换随长度增长的 KV 块；线性注意力只需要传固定大小的状态。普通线性注意力的递推是加法的，每个 rank 从 \(S=0\) 算出本地状态，再对前面的 rank 求和即可。KDA 不行：记 \(M_t=(I-\beta_tk_tk_t^\top)\operatorname{Diag}(\alpha_t)\)，\(S_t=M_tS_{t-1}+\beta_tk_tv_t^\top\)，一段 token 的效果依赖于进入这段时的状态。

KCP 把每段的效果拆成两个能本地算出的量：累积转移 \(\mathbf M_{[i]} = M_{T_i}\cdots M_1\)（\(d_k\times d_k\)）和从零开始的本地状态 \(\tilde S_{[i]}\)（\(d_k\times d_v\)）。线性性给出

$$S_{[i+1]}^{t} = \tilde S_{[i+1]}^{t} + \mathbf M_{[i+1]}^{t\leftarrow1}\,S_{[i]}^{T_i},\qquad S_{[i]}^{T_i} = \sum_{j=1}^{i}\Big(\prod_{l=j+1}^{i}\mathbf M_{[l]}\Big)\tilde S_{[j]} .$$

二元组 \((\mathbf M,\tilde S)\) 的组合 \((\mathbf M_2,\tilde S_2)\circ(\mathbf M_1,\tilde S_1) = (\mathbf M_2\mathbf M_1,\ \tilde S_2+\mathbf M_2\tilde S_1)\) 满足结合律，所以可以用前缀扫描恢复每个 rank 的入口状态。实现上每个 rank 先本地算出两者，用一次 all-gather 交换，然后 rank \(i+1\) 从 \(S=0\) 开始依次执行 \(S\leftarrow\mathbf M_{[j]}S+\tilde S_{[j]}\) 处理同一文档的前序片段。通信量固定（每头一个 128×128 的 \(\mathbf M\) 和一个 128×128 的 \(\tilde S\)），计算线性扩展。

11. 基础设施（二）：3T 级预训练

并行组合：带虚拟 stage 的流水线并行、专家并行、ZeRO-1 数据并行、Pipeline ZeRO-2 梯度分片和上面的上下文并行。共享专家在 EP rank 间复制；专家分派和合并的 all-to-all 与计算重叠。三个难题：EP rank 间 token 负载不均；激活、梯度、优化器状态超出显存；视觉编码器高度可变的计算暴露在关键路径上。

11.1 MoonEP：完美均衡的专家并行

传统 EP 的 token 负载在 rank 间不均，计算失衡拖慢吞吐，动态变化的形状还造成显存碎片。MoonEP（已开源）在 DeepEP 的计算流上增加了冗余专家的在线规划与迁移：前向时根据当前 micro-batch、当前层的路由结果规划冗余专家并在专家计算前预取；反向时把冗余专家的梯度先放本地 reduce 缓冲，算完再归约回原 rank 的梯度缓冲。

  • 有界冗余下的完美均衡：要求每个 rank 恰好收到 \(S\times K\) 个 token（\(S\) 序列长度、\(K\) 每 token 选择的专家数）。问题是需要多少冗余专家。设 \(E\) 个专家、EP 大小 \(R\)。可以证明总存在一个均衡方案，使每个 rank 的冗余专家不超过 \(E/R\)，且这个界基本是紧的。证明的构造是：反复取一个欠载 rank 和一个过载 rank，从过载的那里迁 token 把欠载的恰好填满，每个 rank 最多被填一次，所以它的远程 token 只来自一个 rank，涉及那个 rank 上至多 \(E/R\) 个本地专家。紧性：让 rank 0 上的专家完全没有 token、其余专家平分全部 token，rank 0 至少需要 \(\lceil E(R-1)/R^2\rceil\approx E/R\) 个冗余专家。预留 \(E/R\) 个槽就保证规划永远可行，训练不会中断；而先前的方法（ECHO、UltraEP）预设冗余数或设每 rank token 上限，找不到可行方案时训练被迫停止，上限还要手调。
  • 在线规划：每步求精确最优太贵。离线用整数线性规划对代表性情况求精确解作参照，线上用一个近似最优、开销可忽略、且总满足 \(E/R\) 上界的 GPU 规划 kernel。
  • 零拷贝通信：规划 kernel 预先算好每个 token 的目的地，融合的 permute/unpermute 直接把 token 送到远端按专家分组的位置，返回通信缓冲的视图给计算用。最坏不均衡下，DeepEP 要同样免拷贝需要 \(S\times K\times R\) 的缓冲，MoonEP 因完美均衡只需要固定的 \(S\times K\)。
  • 静态形状、免同步：每个 rank 恰收 \(S\times K\) 个 token，所有层的计算形状静态已知，消除了每层 MoE 的主机–设备同步和启动开销。
  • 专家 GEMM 调度：rank 间总量均衡了，rank 内各专家的 token 数仍偏斜；用一个按当前 token 分布自适应参数的调度器（参数由硬件指标的解析代价模型选择，系数离线自动调优），共享专家的 GEMM 放到单独的 stream 上重叠。

11.2 显存

  • 统一激活管理器：反向需要保存的每个张量都关联一个可插拔的存储后端；重计算、量化、卸载/远程卸载只是存储策略，可以在张量粒度自由组合，通过轻量注解声明、与模型代码解耦。重计算按函数粒度，支持跨层重计算。所有显存都在主计算 stream 上分配、由单一内存池管理，避免多 stream 碎片；激活按层预取、与计算重叠。K3 中大部分激活用块级 FP8 量化 + 卸载/远程卸载，逐元素算子用重计算。
  • 省显存的 MoE：原生实现中“排列后的概率”的梯度依赖前向输出 output；受 SonicMoE 启发，通过数学变换改写成只依赖中间激活和上游梯度的形式，代价是一个轻量的逐元素计算；group GEMM 前向只保存 dispatch 的输入，反向时重算 dispatch 恢复 GEMM 的输入，引入的通信与部分 GEMM 反向重叠。
  • 省显存的注意力残差：块表示在块边界层生成一次、被后续所有层共享并常驻 GPU；AttnRes 计算整体包在 checkpoint 里，每层为反向保存的激活与标准残差结构相同。流水线并行下用基于缓存的流水线通信，只增量传输新生成的块，micro-batch 结束即释放，达到显存占用的理论下界。
  • PP rank 间均衡激活：interleaved 1F1B 下激活在 PP rank 间不均（warmup 导致前面的 rank 常驻更多），用 Mooncake Transfer Engine 把激活远程卸载到其他 PP rank 的内存里。
  • Pipeline ZeRO-2 梯度分片与卸载：梯度在 DP rank 间分片，分片存在 CPU 内存里，GPU 上只保留双梯度缓冲；DP 归约到双缓冲后再累加到 CPU 分片。
  • 基于 P2P 的 Muon 正交化：分布式优化器把参数均匀切到各 DP rank，而 Newton–Schulz 需要完整矩阵。朴素做法是每个 rank 对整个参数缓冲做 all-gather，显存大且通信成瓶颈；K3 让每个 rank 只通过点对点通信从相应 owner 取回自己负责的参数的各个分片，按模型 chunk 缓冲流水线化，隐藏通信。

11.3 多模态编码器

  • 编码器内的动态 CP：大图和长视频让视觉编码器计算时间暴涨并造成设备间不均。单张大图沿 patch 维切到多卡，注意力通过跨 CP rank 的 gather-KV 计算；再把每个 CP 组分成若干子 CP 组，把多张大图负载均衡地分配上去，避免通信占比随规模增长。
  • 把编码器计算塞进 PP bubble：K2.5 引入了解耦编码器流程（DEP），把 ViT 与文本训练分阶段。K3 观察到在 interleaved 1F1B 下，前几个 micro-batch 的文本前向都排在最开头，最后几个的文本反向都在最末尾，于是进一步拆分 ViT 计算：前几个 micro-batch 的 ViT 前向同步提前做，其余的前向塞进流水线 bubble，反向同理。大部分 ViT 计算被藏进 bubble。

12. 基础设施（三）：1M 上下文的 Agent RL

沿用 K2 的共置 RL，让每个 1M 上下文的 K3 RL 实验控制在几百张 GPU 内，并用 partial rollout 降低超长轨迹的尾延迟。新问题是长上下文 rollout 需要额外的 DRAM 来保留 KV cache，与训练侧状态竞争。

  • 外部 KV cache 池（write-back）：1M 上下文多步 rollout 中，前缀 KV cache 未命中极其昂贵；partial rollout 在每轮开始时让大量未完成的长 prefill 请求同时到达，投机解码又加快了请求周转，都会触发抢占、降低命中率。他们把前缀保留与 GPU 驻留解耦：正在解码的块留在 GPU；可复用的空闲前缀只在被逐出 GPU 时才写回 CPU DRAM 中的外部池，下次复用前预取回来。KDA 状态和对应的 MLA KV 块一起卸载、一起预取，生命周期对齐。相比 write-through，只为离开活跃解码路径的前缀付出 DRAM 和带宽。为腾出 DRAM，训练迭代结束后把训练状态（权重和优化器状态）卸载到 NVMe；rollout 结束后释放外部池。
  • rollout 自动限流：多步 rollout 中上下文随轨迹推进逐渐变长，按整条轨迹平均长度设固定并发既难估又在早期过于保守，设太高则后期 KV cache 吃紧触发抢占。在请求调度层用运行时信号（活跃请求数、排队数、KV cache 利用率）动态控制发往推理引擎的请求数。
  • 复用梯度缓冲做非策略模型前向：参考模型这类只做前向的模型权重太大，不常驻 GPU；放在 CPU，需要时把它们物化到策略模型的 FP32 梯度缓冲里（反正之后真实梯度会覆盖）。在 ZeRO-2 分片与卸载下每卡只保留两个 VPP chunk 的梯度缓冲，就按 chunk 流式加载：一个槽算当前 chunk，另一个预取下一个。

12.1 沙箱：AgentENV

多种沙箱运行时并用（容器、GPU 沙箱，以及新的基于 microVM 的 AgentENV，与合作方共同开发并开源）。AgentENV 的三个设计目标：

  • 高保真隔离：agent 越强探索越激进，甚至尝试 reward hacking。早期用容器沙箱时观察到几次由 agent 意外操作导致的内核 panic 和死锁；复杂任务又需要接近真实的环境（挂载磁盘、跑容器、甚至起虚拟机）。用 Firecracker 跑隔离的 microVM，隔离性和保真度都超过容器。
  • 灵活的生命周期：增量 checkpoint（只保存上次以来的脏页），checkpoint 与恢复延迟低至 133 ms 和 49 ms。之上三个操作：暂停/恢复（暂停的沙箱不占内存和 CPU；agent 等待模型推理的时间可占沙箱生命周期的 98%）；fork（从原沙箱的精确状态复制一个新的而原沙箱继续运行，用于无副作用的奖励评判）；定期快照用于故障恢复。
  • 高效、高密度：可能需要在几秒内创建数万个、各带不同镜像的沙箱。用 OverlayBD 镜像格式、自定义 ublk 驱动、存储层共享和 P2P 传输，大规模下启动延迟低于 1 秒；写时复制内存和页缓存优化让实际负载下的内存超分比达到 6.5 倍。

整个 K3 训练和评测共创建了 51,219,741 个沙箱、涉及 1,505,678 个镜像。

13. 基础设施（四）：推理与线上服务

13.1 KDA 感知的前缀缓存

混合架构让前缀缓存变复杂：KDA 的递推状态和 MLA 的 KV cache 大小与生命周期完全不同，而一个缓存的前缀只有当两者能在同一边界一起恢复时才可复用。

  • 统一的分页布局：把 KDA 状态和 MLA KV 放进同一个分页块池，页字节数统一，共用一套分配、引用计数和逐出逻辑。页内各头的状态逐头连续存放，每个头的字节流自成一体，是跨节点传输的最小单位；prefill/decode 分离且两边 TP 度不同时，在传输路径上重排，GPU 侧零重排。
  • 解耦哈希粒度与物理块：基于块哈希的前缀缓存只能复用块对齐的前缀。KDA 每条序列只有一个大状态，快照只能在稀疏的边界上做，这把共享的块大小逼到 1024–6144 token；在这么粗的粒度下缓存几乎没用（短于一块的请求永远不能复用，分块 prefill 在跨过整块之前不导出可缓存前缀）。K3 让前缀哈希在 MLA 页内的细粒度哈希块（如 512 token）上进行，物理块仍是粗的分配单位；KDA 状态的 checkpoint 只存在（一部分）哈希端点上——那是查询唯一可能引用的位置。被后续推进取代的中间 checkpoint 会回收，对话轮次边界上的保留供跨请求复用；缓存的 checkpoint 是只读快照，命中时先拷贝到请求的私有状态。
  • 两阶段查找：MLA 阶段按链式哈希匹配整块，在第一个缺失块处退回到块内的哈希端点；KDA 阶段要求候选边界上每个 KDA 缓存组都有 checkpoint。命中位置是同时满足两者的最长边界，总是哈希块的整数倍，不必是物理块的整数倍。举个例子：前 2800 个 token 与缓存前缀一致的请求，在 \(B=2560=5\times512\) 处命中（位于一个 6144-token 物理块深处），从 \(B\) 继续 prefill，不重算 \([0,B)\)。
  • 并发调度下的一致性：三条规则各对应一个具体的失效模式——分配私有副本前先在所有组里钉住所有命中块（共享空闲链表可能把别组刚命中的块逐出）；本调度步内刚分配或注册、拷贝尚未落地的块不参与匹配；KDA checkpoint 要么在所有组都可命中、要么都不可（逐出一个组的就原子地作废兄弟）。

13.2 kernel

  • KDA decode + 投机解码：decode 时瓶颈从并行变成管理每步原地更新的状态。MTP 投机解码中，如果验证拒掉部分草稿 token，状态已经越过最后接受的 token，无法简单回滚；为每个草稿位置存一份状态快照又会成倍增加状态读写，在线上大 batch 下不可接受。观察是：任何被接受前缀之后的状态完全由草稿 token 的投影输入决定，而它们比状态小得多。所以只缓存投影输入，在片上重建被接受 token 的状态，只写回验证通过的 token 和 bonus token 的状态（与同期工作 ReplaySSM 独立提出的设计相同）。重放的 token、bonus token 和下一个草稿窗口在一个融合 kernel 的同一个递推循环里处理，覆盖短卷积、输入归一化、门控、KDA 递推和输出归一化。验证延迟随验证 token 数次线性增长，低于缓存状态的基线。
  • Block AttnRes：两阶段调度——批量的块间阶段每块读一次缓存的块表示，然后每层用 online softmax 合并块内部分和。两个阶段都以访存为主。prefill 时为避免每个 TP rank 都物化块表示，对激活用序列并行：TP all-reduce 拆成 reduce-scatter 和 all-gather，块内 kernel 插在两者之间作用于序列分片的隐状态，每个 token 的块表示只在一个 rank 上物化。decode 时块间 kernel 放在侧 stream 上与主 stream 重叠；块内阶段把 AttnRes 输出与部分和更新的合并以及随后的 RMSNorm 融合进前面的 TP all-reduce，省掉一个单独的 kernel。
  • Stable LatentMoE：latent 下投影与路由器合并成一个 GEMM；latent 权重在 rank 间分片，用 multimem store 指令把输出 all-gather 融合进 GEMM epilogue，并与共享专家计算等重叠。路由专家在小 batch 下的 group GEMM 退化成对权重的访存受限流式读取，传统的面向计算的 tile 式 kernel 不适合；改用 WarpDecode 的以 token 为中心的设计（每个 warp 负责一个输出神经元，直接从显存流式读对应权重），并把 warp 再细分成处理不同专家子集的 lane team，最后 warp 内归约；权重布局离线重排，大幅降低运行时反量化开销。

13.3 集群级调度

  • 缓存亲和调度：1M 上下文下一个典型的编码请求带 400K token 的前缀、只需增量 prefill 4K，命中前缀缓存比未命中便宜几个数量级。所以把请求路由到持有其前缀缓存的集群（跨集群搬缓存太慢）。但亲和性把会话绑死在一个集群，集群故障会中断所有会话；于是用一致性哈希把每个会话钉在两个集群上：主集群服务，预先指定的备集群在主集群故障时接管（需要重新 prefill）。一致性哈希让不同会话的备集群均匀分布，故障后重新 prefill 的工作被分散到许多集群。
  • 基于预算的准入控制：线上流量混合了 2K 以下的短请求和长达 1M 的超长请求，单请求成本跨约三个数量级，基于“平均请求”的容量规划、排队模型和限流都失效。典型故障是一波长请求占满算力，之后到达的短请求无法及时调度，所有流量的首 token 时间（TTFT）都变差。做法是给不同请求类别分配各自的资源预算，突发的长上下文流量最多吃掉自己那份。

15. 小结

  • 沿着三个维度扩展：序列上沿用并改进 Kimi Linear 的 KDA–MLA 3:1 混合（有下界的衰减让对角小块也走 Tensor Core；全秩输出门；MLA 也加门并用 NoPE）；深度上用 Block AttnRes 让每层对之前的块做 softmax 选择；宽度上用 LatentMoE 把激活专家翻倍而不增加通信。
  • 为极端稀疏度补稳定性：聚合后加 RMSNorm、有界的 SiTU-GLU（输出不超过 β₁β₂=100）、以及从最优指派对偶推出来的分位数均衡（一步跳到坐标最优，不用调步长，直方图让全局分位数的通信与 token 数无关）。
  • 后训练：领域 × 推理强度的 9 个专家，用逐题预算课程控制强度，再用带裁剪的逐 token 对数比奖励做多教师在线蒸馏；部署侧从 SFT 起就做 MXFP4 QAT，MTP 层直接改成 EAGLE-3 草稿并优化接受率本身。
  • 系统：KDA 的状态是固定大小的，这一点被反复利用——KCP 只需一次固定大小的 all-gather，前缀缓存把状态当成哈希端点上的 checkpoint，投机解码只缓存小得多的投影输入。
