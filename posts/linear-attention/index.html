Linear attention：把历史写进状态

交互2026-10-20更新于 2026-10-22

普通 attention 会保存每个历史位置的 K/V，新 query 到来时再逐项读取。Linear attention 选择另一种记忆方式：把历史持续写入一个固定形状的状态，新 query 直接读取这个状态。上下文继续增长时，状态的张量形状保持不变。

这种做法把问题从“保留每个位置”转成“怎样压缩和更新历史”。要理解它的速度、容量和质量，需要同时看求和的重排、归一化分母、遗忘门以及状态写入规则。

把历史求和放到 query 之前

先选择特征映射 \(\phi\)，把 query 和 key 映射到 \(r\) 维空间，并定义相似度 \(\phi(q_t)^\top\phi(k_j)\)。使用非负特征时，可以把这些相似度归一化成权重。位置 \(t\) 的输出为：

$$y_t=\frac{\sum_{j\le t}\phi(q_t)^\top\phi(k_j)v_j^\top}{\sum_{j\le t}\phi(q_t)^\top\phi(k_j)+\epsilon}.$$

这里把 value 看作列向量，公式的输出为行向量；\(v_j\) 有 \(d_v\) 个分量。分子利用矩阵乘法的结合律，把与历史有关的项先求和：

$$\htmlData{symbol=state}{S_t}=\sum_{j\le t}\phi(k_j)v_j^\top\in\mathbb R^{r\times d_v},\qquad z_t=\sum_{j\le t}\phi(k_j)\in\mathbb R^r,\qquad y_t=\frac{\phi(q_t)^\top S_t}{\phi(q_t)^\top z_t+\epsilon}.$$

这种重排精确计算的是所选特征核定义的 attention。标准 softmax 使用指数点积相似度；若希望逼近它，需要另外分析特征映射的近似能力。实际线性模型也可以直接学习适合递推状态的参数。

每个输入怎样更新两个状态

新 token 到来时，只需追加一个外积和一个向量：\(S_t=S_{t-1}+\phi(k_t)v_t^\top\)，\(z_t=z_{t-1}+\phi(k_t)\)。然后用当前 query 读取它们。外积表示 key 的每个特征分量分别携带 value 的全部分量，因而状态是一个矩阵。

三次更新后，\(S=\begin{bmatrix}5&3\\7&5\end{bmatrix}\)，\(z=[2,2]^\top\)。query 为 [2,1]，分子是 [17,11]，分母是 6，所以输出为 [17/6,11/6]。沿着原始定义逐项计算权重，也会得到同一个结果。

分母维护了总权重的尺度。把相同 key/value 重复写入，分子和分母同时按次数增长，归一化后的输出保持一致。\(\epsilon\) 用来处理很小的分母；在误差比较中，dense、递推和分块三条路径应使用同一种加法或截断规则。

固定状态究竟有多大

一个头需要保存 \(rd_v+r\) 个元素。若使用 FP32 状态，每个元素 4 B，\(r=d_v=128\)，一个头占 \((128^2+128)\times4=66,048\) B，约 64.5 KiB。批量请求、层数和头数都会线性放大这份状态。

作为比较，一个普通 KV 头在每个历史位置保存两份 128 维 BF16 向量，需要 \(2\times128\times2=512\) B。66,048/512=129，因此在这个具体配置下，线性状态的容量相当于 129 个 KV 位置。短序列时要直接比较两份实际账本；长序列时，固定状态会逐渐体现容量优势。

计算成本同样取决于状态维度。一个 token 的状态更新和读取各涉及 \(r d_v\) 量级工作，总长度 \(T\) 时约为 \(O(Trd_v)\)。特征维度 \(r\) 提高了记忆表达能力，也增加了每步读写和乘加。

把单头状态换成服务预算也很直接。若 32 层、每层 16 个线性状态头，每头 64.5 KiB，一条请求共需 32.25 MiB，32 条请求需 1032 MiB。卷积缓存、门控辅助状态和其他 attention 层还要另加。混合架构的一部分层使用固定状态，另一部分层仍保存随长度增长的 KV，应分别按层统计。

计算上，每个 token 的外积更新与状态读取都要接触整个 \(r\times d_v\) 矩阵。单个很小的请求可能无法提供足够任务占满 GPU；把多条独立请求、多个头和各层调度起来，才能利用设备并行度。训练使用更大 chunk 时，矩阵乘获得更多复用，而块末状态更新与块内临时张量也会增长。因此 chunk 大小同时影响吞吐、峰值内存与数值累加顺序。

遗忘门怎样分配历史权重

持续累加会让很早的内容长期占据状态。引入标量遗忘门 \(\htmlData{symbol=gate}{\alpha_t}\in[0,1]\)，令 \(S_t=\alpha_t S_{t-1}+\phi(k_t)v_t^\top\)，并对归一化状态使用相同门控。历史位置 \(j\) 到当前 \(t\) 的保留系数为 \(\prod_{u=j+1}^{t}\alpha_u\)。每经过一次更新，旧内容就乘上这一轮的门。

最后一轮门为 0.25 时，三个保留系数为 [0.125,0.25,1]，分子为 \(0.125\times2+0.25\times4+8=9.25\)，分母为 1.375，输出 \(74/11\approx6.727\)。通道级门控则为状态的不同方向学习不同的衰减速度。

递推变换 \(S\mapsto aS+b\) 可以组合为 \((a_2,b_2)\circ(a_1,b_1)=(a_2a_1,a_2b_1+b_2)\)。组合具有结合性，因此训练可以使用 parallel scan 或分块算法；生成时仍按 token 逐步更新。

Delta rule 先读旧答案，再写误差

加法更新会把重复出现的相似 key 持续叠加。Delta rule 先用当前 key 读取旧状态，再写入目标与预测的差：

$$\widehat v_t=S_{t-1}^{\top}k_t,\qquad S_t=S_{t-1}+\beta_t k_t(v_t-\widehat v_t)^{\top}.$$

这里 \(S\) 采用 key 特征在行、value 分量在列的布局，\(\beta_t\) 控制更新幅度。对单位范数的 key，再次读取该 key 时，误差会乘以 \(1-\beta_t\)。标量状态从 2 逼近目标 5、\(\beta=0.5\) 时，连续三次得到 3.5、4.25、4.625。

key 范数改变了实际更新力度。标量 key=2、旧状态=1、目标 value=5、\(\beta=0.5\)，旧读出为 2，新状态为 \(1+0.5\times2\times(5-2)=4\)，新读出达到 8。单位范数或其他稳定化约束因此是算法定义的重要组成部分。门控线性 attention、DeltaNet 和 Gated DeltaNet 使用不同的更新与归一化方案，部署时状态形状和 kernel 必须对应具体模型。

训练时把历史和块内关系分开

一个 chunk 的输出由两部分组成：当前 query 读取上一个 chunk 的状态，以及当前 chunk 内的因果关系。令 \(Q_c,K_c\) 已经完成特征映射，\(A_c=\operatorname{tril}(Q_cK_c^\top)\)，则分子为 \(Q_cS_{\mathrm{prev}}+A_cV_c\)，分母为 \(Q_cz_{\mathrm{prev}}+A_c\mathbf1+\epsilon\)。块末再更新 \(S\leftarrow S+K_c^\top V_c\)、\(z\leftarrow z+\sum K_c\)。

这条分解让块内工作使用矩阵乘法，又让块间只传递固定状态。正确性可以用三角 dense 核、逐 token 递推和不同 chunk 大小互相校验。带门控或 delta 更新时，要使用对应的块内递推展开；边界状态仍需与逐 token 路径一致。

跨 chunk 保存的状态要有清晰的提交时机。某个 chunk 完成后，状态应包含该 chunk 的所有有效 token；继续处理下一块时，只追加新的位置。若重试逻辑把同一块再次写入，状态会重复累加，即使张量形状完全合法，输出也会偏移。可以给状态附上“已消费 token 数”，并用前缀重跑与状态续写两条路径验证相同边界。

Packed sequence 训练把多条短序列放进一个连续张量，kernel 需要明确的序列边界。在每条新序列开始处，状态回到该序列的初始值。有效 token 的梯度也应只依赖同一序列的历史。测试时把两条差异很大的序列拼接，逐条独立运行作参考，既能发现前向状态泄漏，也能发现反向的边界处理问题。

Padding、状态复用与精度问题

加了左 padding 后，有效输出变小。检查 padding 是否同时影响分子和分母。只把 padding 的 value 置零，会让它对 \(S\) 的更新消失，但 \(\phi(k)\) 仍可能进入 \(z\)。例如有效项的分子为 6、分母为 2，额外 padding key 向分母加 1 后，输出从 3 降到 2。对加法归一化状态，padding 步应保持 \(S,z\) 均不变；也可以先 unpad，再用序列边界描述有效 token。

请求单独运行正常，复用状态后串内容。确认状态属于哪条请求、哪一层与哪一个模型版本。请求完成或新序列开始时重置状态；batch 重排时，状态槽位随请求 ID 一起移动。保存 prefix 状态时还要保存卷积等辅助状态，后续分支使用独立的可写副本。

长序列逐渐出现数值偏差。分别记录状态最大值、分母最小值和输出误差，先用 FP32 状态对照 BF16。非负特征累积会扩大数值范围，门控可限制历史增长；很小的分母会放大量化误差。评估时同时观察长距离检索、顺序记忆和语言建模质量，状态容量与任务中的信息量需要共同匹配。

固定状态还改变了检索问题的形式。普通 KV 为每个位置保留独立向量，线性状态把多个关联压在同一个矩阵里；相似 key 可能竞争相同的状态方向。可以固定状态维度，逐步增加需要记住的独立 key-value 对，比较精确检索与重复覆盖。再分别增大特征维度、加入遗忘门和使用 delta 更新，观察容量、更新速度与任务质量怎样共同变化。

计算与实现练习

1. 读取二维状态

S=[[5,3],[7,5]]，z=[2,2]，query=[2,1]，ε=0。输出是多少？

展开解答

分子 [17,11]，分母 6，输出 [2.8333,1.8333]。可以再用 keys=[1,0]、[0,1]、[1,1] 对照得到权重 [2,1,3]/6。

2. 三次遗忘之后还剩多少

某次写入之后的三个门依次为 0.8、0.5、0.25，这份历史的保留系数是多少？

展开解答

系数为 0.8×0.5×0.25=0.1。它仍需与其他历史的系数及 query-key 相似度共同归一化。

3. 非单位 key 的更新

标量状态 S=1，key=2，目标 value=5，β=0.5。求 delta 更新后的状态和读出，并给出避免过冲的一个方向。

展开解答

旧读出 2，新状态 4，新读出 8。更新力度包含 key 范数平方，归一化 key 或让 β 随范数调整，都能控制有效步长；具体规则需要与训练算法保持一致。

验证三种计算顺序

下载 NumPy 实验，运行 python3 lab.py --seed 7 --chunk 5 --length 19。输出检查递推与 dense 核、分块路径、门控展开和 delta 更新。把 chunk 改为 1、4、7，再加入“在输入前插入 padding，但有效输出保持不变”的断言。若改用 ELU+1 特征映射，三条参考路径应一起更换映射。
