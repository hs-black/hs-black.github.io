LLM 工程学习路径：从张量到推理服务

交互2026-10-20

一个请求变慢了，是 prompt 太长、KV 读得太多、CPU 没有及时提交，还是请求排在队列里？把这些问题拆开，需要同时看懂模型的计算、数据的存放和系统的时间线。

每一阶段都有三件事：用动画跟踪数据，亲手算一遍，再运行实验验证判断。主线按先修关系排列；“延伸阅读”用于继续深挖。完成练习并解释实验结果后，再勾选对应课程。

起点：能读 Python，知道矩阵乘法和概率。训练分支还需要链式法则。

共同练习对象：一个两层 Transformer，逐步接上分页 KV、连续调度和采样器。

打开综合项目 →下载引擎代码下载实验记录模板

勾选记录保存在当前浏览器。它表示你完成了练习与验证。

每次实验留下什么

  1. 预测：先写下公式、单位与假设。改变 batch、长度或页大小，会改变哪个成本？
  2. 证据：记录命令、环境、正确性误差、延迟分布和内存。模拟 tick、CPU 秒和 GPU 毫秒分开写。
  3. 解释：观察与预测不一致时，缩小输入，检查 tensor、mask、位置、队列与生命周期。
  4. 验收：换一组输入仍然成立；优化后输出正确；能够说明适用条件和代价。

综合项目的交付标准

让不同到达时间、不同 prompt 长度的请求完成生成；输出与逐请求完整前向一致。改页大小和 batch，结果不变，页面能全部回收。分别注入位置错位、padding mask 遗漏和页面泄漏，展示检查在哪一步捕获它们。

最后写一页实验记录：一个明确问题、一份容量估算、一个受控变量、正确性证据和测量结果。有 GPU 时，再把 NumPy 算子换成 PyTorch / Triton，沿相同检查路径继续优化。
