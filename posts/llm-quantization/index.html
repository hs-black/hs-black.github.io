LLM 量化：字节、误差与计算

交互2026-10-20更新于 2026-10-22

100 亿个 BF16 参数占约 20 GB。若每个参数能用 4 bit 保存，整数码本身只需 5 GB。这个变化会影响模型能否装进显存，也会影响 decode 每步搬运权重的时间。量化真正要解决的是：用更少的字节保存有用信息，并让实际 kernel 高效地消费这种表示。

一套量化方案包含数值格式、分组与 scale、校准目标、计算精度和执行布局。沿着一个线性层 \(y=Wx\) 来推导，能看清每个选择怎样传到最终输出。

实数怎样变成几个 bit

仿射量化把实数 \(x\) 映射到整数码 \(q\)：

$$q=\operatorname{clip}\left(\operatorname{round}\left(\frac{x}{\htmlData{symbol=scale}{s}}\right)+z,q_{\min},q_{\max}\right),\qquad \hat x=s(q-z).$$

\(s>0\) 是 scale，\(z\) 是 zero-point，用来让实数 0 对齐某个整数码。对称量化取 \(z=0\)。4 bit 有 16 个编码，具体解释由格式决定：补码整数可表示 −8 到 7，窄范围对称方案常使用 −7 到 7；NF4 则使用适配权重分布的一组非均匀重构值。

这里 round 取最近整数，恰好处在中点时取偶数。没有裁剪时，最近取整的重构误差最多约为 \(s/2\)。若 \(x\) 超过可表示范围，误差由裁剪距离主导。Scale 过大使小值刻度变粗，过小又会裁剪大值，因此选择范围是在这两类误差之间取舍。

分组量化让每个组独立选择 scale，把范围差异很大的通道分开。若每 128 个权重共用 2 B scale，实际位宽是 \(4+16/128=4.125\) bit/权重。4096×4096 的矩阵，整数码占 8 MiB，scale 占 0.25 MiB，总计 8.25 MiB，原 BF16 权重为 32 MiB。

打包布局与计算精度

两个 INT4 可以装进一个字节。若低四位保存第一个值、高四位保存第二个值，补码 −7 的编码是 0x9，7 的编码是 0x7，组合得到 0x79。解包时要恢复符号，再乘以对应 scale。检查打包应包含负数、边界码和奇数尾部，避免只在正数样例中验证。

真正的整数点积还要处理 zero-point。两个向量都使用仿射量化时：

$$x^\top w\approx s_xs_w\left[\sum_i q_{x,i}q_{w,i}-z_w\sum_i q_{x,i}-z_x\sum_i q_{w,i}+n z_xz_w\right].$$

这里 \(n\) 是点积长度。后面三项把整数零点的偏移扣除。实际 W4A16 路径通常读取低位权重和高精度激活，在 tile 内反量化，再用硬件支持的乘法与较高精度累加。累加精度需要考虑长点积的动态范围；输入存储精度和累加精度分别配置。

怎样衡量一次量化是否伤害模型

逐元素权重误差只描述 \(\Delta W\)。线性层真正传出的误差是 \(\Delta y=\Delta W x\)，因此相同权重误差在不同输入上可能产生完全不同的影响。若一个输入通道的幅度是另一个的 10 倍，同样的该通道权重误差会使输出误差扩大 10 倍，平方损失扩大 100 倍。

把一组校准输入组成矩阵 \(X\in\mathbb R^{d_{in}\times n}\)，可优化层输出重构目标 \(\|WX-\hat WX\|_F^2\)。对权重的一行，令误差向量为 \(\delta\)，目标包含 \(\delta^\top H\delta\)，其中 \(H=XX^\top\) 描述输入的幅度和通道相关性。校准数据应覆盖部署的文本类型、序列长度、模板和多模态输入比例。

GPTQ 怎样利用还没量化的权重补偿误差

量化一个坐标后，该坐标的误差已经固定。GPTQ 利用二阶信息调整其余坐标，减小当前固定误差对层输出的影响。考虑两维例子：

$$H=\begin{bmatrix}1&0.5\\0.5&1\end{bmatrix},\qquad\delta_0=-0.4,\qquad\mathcal L=0.16-0.4\delta_1+\delta_1^2.$$

直接保留第二个权重给出 \(\delta_1=0\)，损失为 0.16。对 \(\delta_1\) 求导，\(-0.4+2\delta_1=0\)，得到 \(\delta_1=0.2\)，损失降到 0.12。通道相关性使第二个坐标可以抵消一部分第一个坐标的输出误差。

完整算法按列推进，并结合分块、阻尼和近似二阶信息控制校准成本。后续坐标也要落到整数网格上，因此它是逐步协调舍入误差的过程。工程验证可以先固定校准数据，比较逐层输出误差，再检查整模型的任务质量和长文本退化。

AWQ 与 SmoothQuant 怎样移动数值范围

给输入通道选择对角矩阵 \(D\)，线性层恒等式为 \(Wx=(WD)(D^{-1}x)\)。AWQ 利用激活信息选择通道缩放，使敏感权重在量化时得到更合适的刻度。缩放也会改变同组其他权重的范围，因此需要把候选 scale 放进量化后的层输出误差中比较。

SmoothQuant 用同一类恒等变换平衡激活与权重的离群范围。若以行向量激活写作 \(Y=XW\)，变换为 \((XD^{-1})(DW)\)。激活难量化的通道被缩小，权重对应通道被放大，从而更适合 W8A8 路径。部署时应核对融合后的缩放位置、通道轴和数据类型，先验证未量化变换的数值等价，再测量化误差。

PTQ 在训练后选择量化参数与校准策略；QAT 在训练中把量化效应放入前向，让参数适应舍入与裁剪。两者都需要用最终推理格式验证，尤其要保证 scale 的编码方式、分组轴和解包顺序与 kernel 一致。

低位权重怎样在常见硬件上兑现收益

小 batch decode 每轮只为少量 token 使用权重，权重读取往往占主导。低位格式减少搬运量，有机会显著降低延迟。Prefill 一次处理许多 token，权重可被更多行复用，计算比例上升；这时反量化指令、布局转换和矩阵乘硬件路径更容易决定性能。

Kernel 还受形状与分组对齐约束。比如输入维度 3420、分组大小 64，尾部只有 28 个元素。实现需要掩码处理、填充，或选择另一条执行路径。性能测试应覆盖实际模型各层形状，分别记录 decode 的小 M 和 prefill 的大 M；仅测试整齐的 4096×4096 矩阵，无法解释真实模型的所有层。

一个直接的带宽估计是 \(t_{read}=M_W/\mathcal B\)：\(M_W\) 是本卡权重字节数，\(\mathcal B\) 是有效读取带宽。把它与实测逐层时间比较，再观察反量化、scale 读取和 Tensor Core 利用率。输出精度也要按真实累加方式测试，尤其是大 reduction 维度和离群激活。

分组越细，scale 读取越多，也越难在同一个矩阵乘 tile 内共享。一组跨越 kernel 的计算分块时，线程可能要读取多份 scale 或额外转换布局；提前把权重重排为目标 kernel 的格式，可以把部分工作放到加载阶段。这个预处理后的表示仍需要计入驻留显存，尤其是在同时支持多个 backend 或保留原始权重的服务中。

多卡时还要查看通信精度。只量化静态权重会降低每卡读取权重的时间，而张量并行的激活通信可能保持 BF16。随着本地计算变快，通信在 step 时间中的比例会上升。选择更多卡之前，分别画出权重读取、矩阵乘与 collective 的时间，并检查量化格式是否支持当前分片维度与组边界。

显存和吞吐要按整条服务路径计算

量化权重之后，KV cache、临时 workspace、通信缓冲和运行时仍各有预算。一个 8.25 MiB 的量化矩阵加载后若同时保留原 BF16 参数，实际驻留就要把两份相加。先记录稳态驻留，再测最长 prefill 的峰值，最后增加并发观察 KV 增长。

质量排查从固定输入的层输出开始：比较最大误差、相对 RMS 误差和异常值位置。若误差集中在少数通道，检查 scale 与分组轴；若所有值都整体放大，检查 scale 的编码和应用次数；若只有长输入退化，检查校准长度与激活分布。性能排查则沿 batch、上下文长度和输入形状扫描，保留 backend、kernel 名称、模型 revision 与数值格式，形成能解释差异的记录。

例如 70 亿参数、每 128 个权重共享 2 B scale 的理想 INT4 表示，权重约为 \(7\times10^9\times0.515625=3.609375\) GB，约 3.36 GiB。若缓存配置是 32 层、8 个 KV 头、每头 128 维、BF16，8 条长度 8192 的请求另需 8 GiB KV。权重与缓存合计约 11.36 GiB，随后还要加入运行中的临时内存。这个例子说明并发增大后，缓存可能成为更主要的容量因素。

一个有用的验收记录应至少保留两类样本：模型质量样本和系统负载样本。前者覆盖部署任务与容易出现离群激活的输入，后者覆盖短请求、长 prefill 和稳定 decode。把质量损失、首 token 延迟、每 token 延迟、吞吐和峰值内存放在同一张表里，才能比较不同量化策略提供的实际取舍。

计算与排错练习

1. 整数码与字节

Scale=0.125，窄范围对称 INT4，输入 [−0.875,0.875]。求整数码、重构和按低位优先打包的字节。

展开解答

整数码为 [−7,7]，重构与原值一致。−7 的补码为 9，第二个 7 放在高四位，字节是 0x79。

2. 元数据占多少

4096×4096 权重，每 128 个权重共用 2 B scale，使用 INT4。总量与 BF16 压缩比是多少？

展开解答

整数码 8 MiB，scale 0.25 MiB，总计 8.25 MiB。32/8.25≈3.879 倍，等效 4.125 bit/权重。

3. 相关性反号之后

H 的两个非对角元素从 0.5 变成 −0.5，仍固定 δ₀=−0.4。最优 δ₁ 是多少？

展开解答

目标变为 0.16+0.4δ₁+δ₁²，导数为 0.4+2δ₁，最优 δ₁=−0.2，损失仍为 0.12。补偿方向随相关性的符号变化。

4. Prefill 更慢的量化模型

权重文件减少 3.8 倍，decode 变快，prefill 反而慢。设计三个测量来定位原因。

展开解答

先固定实际 M/N/K 形状，对比 BF16 与量化 kernel 稳态时间；再拆出解包、反量化与布局转换；最后沿 M 增大检查 Tensor Core 利用率和是否切换执行路径。小 M 的带宽收益与大 M 的计算效率需要分别评估。

从打包到层输出误差

下载 Python 实验并运行 python3 lab.py --group-size 128。它使用标准库检查补码打包、舍入误差、等效位宽、二阶补偿与通道缩放恒等式，输出的补偿损失从 0.1600 降到 0.1200。把分组大小改为 32、256，计算元数据变化；再修改二次目标的相关项，先手算最优补偿方向，再用网格枚举检查。
