01 · 从字节开始

同样一百亿个参数，位宽减半，权重字节就减半

一个 BF16 / FP16 权重占 2 byte；INT8 占 1 byte；4 bit 打包后平均占半个 byte。10B 权重的原始存储约为 20、10、5 GB。

十进制 GB；只算权重数据，不含 scale、zero-point、对齐、KV cache 与临时工作区。

量化前，先固定线性层的维度约定

X ∈ ℝᴹˣᴷ，W ∈ ℝᴺˣᴷ
Y = XWᵀ ∈ ℝᴹˣᴺ
维度 在推理中的含义 量化粒度示例
M 本次参与计算的 token 数 activation 可按 token 取 scale
K 输入通道 / reduction 维度 weight 沿 K 每 g 个一组
N 输出通道 每行拥有自己的分组 scale

W4A16 表示存储的权重 4 bit、激活 16 bit；它没有说明 KV 精度，也没有说明最终在哪种硬件指令上相乘。

4 bit 有 16 个编码，数值范围由格式决定

格式 可表示整数 需要约定的细节
无符号 INT4 0…15 常配合 zero-point 表示负数
有符号补码 INT4 −8…7 最高位有负权重，解码时符号扩展
对称窄范围 INT4 −7…7 本实验不用编码 −8
FP4 / NF4 依格式定义的非均匀格点 不能套用同一整数反量化公式

02 · 量化三步

先缩放，再取整，最后截到能存的范围

把连续数轴变成有限格点：1.22 ÷ 0.25 = 4.88，四舍五入得到 q = 5。整数超出范围就 clamp 到边界；scale 决定一格有多宽。

此处采用对称的 −7…7 编码作教学示例；具体 INT4 kernel 的编码与 zero-point 约定可能不同。

zero-point 让整数零点对齐实数 0

q = clip(round(x/s) + z, qmin, qmax)
x̂ = s(q−z)

教学例子：x 的范围 [−1,2]，使用无符号 4 bit。s=(2−(−1))/15=0.2，z=5。

x q=round(x/0.2)+5 反量化 x̂
−1 0 0.2×(0−5)=−1
0 5 0
0.6 8 0.6
2 15 2

z 通常取整数并限制在编码范围内；一般范围的端点不一定都精确命中。全零组要单独处理，避免 scale=0 后除零。

工程 · 算清楚，再实现

舍入误差有上界，裁剪误差可以大得多

范围内的舍入

若 x 没有被 clip，最近格点距离最多 s/2。取 s=0.125，x=0.1875 正好在 q=1 与 q=2 之间；ties-to-even 取 2，x̂=0.25。

范围外的裁剪

同样 s=0.125、q∈[−7,7]，最大实数为 0.875。x=2 会被裁到 0.875，误差 1.125，远大于 s/2。

未裁剪：|x−x̂| ≤ s/2
高分辨率、近似均匀误差时：E[e²] ≈ s²/12

s²/12 需要误差近似均匀等假设；比较实际 LLM 质量时仍要测真实数据、真实层输出与任务指标。

03 · 反量化

存的是 5，计算时按比例读成 1.25

反量化 x̂ = s × q，把整数重新解释为近似浮点数。取整丢掉的信息不会回来，这里留下 +0.03 的误差；截断到边界时误差可能更大。

一般仿射量化还带 zero-point z：q = clamp(round(x/s) + z)，x̂ = s(q − z)。

工程 · 算清楚，再实现

两个 INT4，怎样真正装进一个字节

byte = (q₀ & 0xF) | ((q₁ & 0xF) << 4)

−7 的 4-bit 补码为 9；7 左移 4 位得 112。9|112=121=0x79。解码时 u≥8 就取 u−16，恢复符号。

工程 · 算清楚，再实现

真正的整数点积，要扣掉 zero-point

y ≈ sₓs𝑤 Σₖ (qₓ,ₖ−zₓ)(q𝑤,ₖ−z𝑤)

取 qₓ=(6,3)、zₓ=4、sₓ=0.5；q𝑤=(5,2)、z𝑤=3、s𝑤=0.25。

整数累加 = (6−4)(5−3)+(3−4)(2−3)=5
y = 0.5×0.25×5 = 0.625

反量化后 x=(1,−0.5)，w=(0.5,−0.25)，浮点点积同样为 0.625。

常见 INT8 路径在 INT32 中累加，再乘 scale。分组 scale 不同的部分要分别缩放；不能先把所有组加完再随便乘一个 scale。

04 · 离群值

一个 8，拉大了所有人的刻度

为了装下最大的 8，共用 scale 变成 8/7。0.2、0.4、−0.3 都舍入到 0。范围越大，同样位数的格点越粗，小值更容易被抹掉。

玩具权重；采用上一页的对称 −7…7 量化范围。

权重误差相同，对输出的影响可以差 100 倍

Δy = Δw · x
|Δy| ≤ ‖Δw‖₂ ‖x‖₂

教学例子：x=(10,0.1)。误差 Δw=(0.01,0) 导致 Δy=0.1；误差 Δw=(0,0.01) 只导致 Δy=0.001。

为什么要看激活

同样的权重绝对误差，乘上不同输入会被放大或缩小。仅最小化 ‖W−Ŵ‖，可能忽略重要通道。

还要看通道相关性

多个通道的误差会相加或抵消。校准数据的 XXᵀ 保存这些相关性，是二阶补偿的依据。

scale 的搜索，是舍入损失与裁剪损失的交换

把少量 outlier 裁掉，能缩小 s，让大量常见数分得更细；代价是 outlier 自身误差变大。

for clip_limit in candidate_limits:
    scale = clip_limit / qmax
    W_hat = dequant(quant(W, scale), scale)
    loss = mean_square(X @ W.T - X @ W_hat.T)
choose_limit_with_smallest_loss_on_calibration_data()

这里优化的是教学线性层输出重构误差。部署前还要用独立评估集看困惑度、任务准确率和长上下文行为。

校准数据覆盖输入类型与长度；别用最终测试集挑参数，再把同一分数当成泛化效果。

05 · 更细的 scale

分组以后，小值重新有了自己的刻度

per-channel 或 per-group 量化，让一小片权重共用一个 scale。误差通常更小，但要多存 scale，也要让 kernel 高效读取它们。

人为分组与最近偶数舍入仅展示原理；真实矩阵按通道或固定 group 分组。异常通道也可保留更高精度。

工程 · 算清楚，再实现

group 越小越灵活，也越要多存元数据

每权重有效位数 = b + 8m/g

b 是权重位宽，m 是每组 metadata 字节，g 是组大小。取 INT4、每组一个 FP16 scale：m=2。

g bits/weight 相对 FP16 压缩倍数
32 4+16/32=4.5 3.5556×
128 4+16/128=4.125 3.8788×
256 4+16/256=4.0625 3.9385×

有 zero-point、padding 或分组尾部时继续加账。真实文件与显存还含未量化层、索引、对齐与 workspace。

SmoothQuant 把激活的难点搬到权重

XWᵀ = (XS⁻¹)(WS)ᵀ，S=diag(s₁…sₖ)

激活第 j 通道特别大时，把 X 的该通道除以 sⱼ，权重对应列乘以 sⱼ；浮点输出保持不变。

sⱼ = max|Xⱼ|ᵅ / max|W[:,j]|¹⁻ᵅ

α 控制迁移程度：更大 α 更压低激活范围，同时让权重更难量化。使用校准数据选择折中，面向 W8A8 等路径。

等价变换只是起点。加入量化后是否变好，取决于新的 activation / weight 误差之和；scale 往往可融合进相邻算子。

06 · 数据走到计算单元

文件变小，只完成了一半

W4A16 里，权重以 4 bit 搬进芯片，kernel 在局部解包、按 scale 还原，再与 16 bit 激活计算。把整份权重先展开回 HBM，会吃掉搬运上的节省。

图中采用 W4 → W16 的示意路径；实际 kernel 取决于硬件。W8A8、FP8 等可使用对应低精度矩阵指令。

W4A16 kernel 的真实工作不止“少读 4 倍”

阶段 执行动作 观察什么
HBM → 片上 搬 packed weights、scales、activation 读取字节与 cache 命中

一种常见路径是在片上把 W4 转成 FP16 再乘 A16。若先把整个矩阵反量化写回 HBM，再调用普通 GEMM，会吃掉很多带宽收益。

07 · 别把三份精度混在一起

只压缩权重，KV cache 不会跟着变小

W4A16 表示权重 4 bit、激活 16 bit。长上下文或大量并发时，KV cache 仍可能占显存的大头；量化 KV 需要单独的格式、scale 与 attention kernel 支持。

条形长度为示意，并非某一模型的实际显存占比。

08 · 计算精度

低位输入，不等于用低位把长串乘积加完

矩阵乘是很多乘积求和。INT8 路径常用 INT32 累加，避免低位累加很快溢出，再按 scale 转回输出。浮点低精度 FP8 则用指数与尾数表示数值，编码和整数不同。

三个乘法为示意。支持的指令、累加类型与缩放粒度要和 GPU、模型及 kernel 一起选择。

工程 · 算清楚，再实现

GPTQ 的目标是保住层输出，而非逐个权重

把校准激活转置为 A=Xᵀ∈ℝᴷˣᴹ。对一个输出通道，原权重为 w，量化误差为 δ=ŵ−w。

损失 = ‖δA‖₂² = δ(AAᵀ)δᵀ
H = AAᵀ

H 的对角项描述通道能量，非对角项描述通道相关性。只对每个 w 四舍五入，相当于没有利用这些相关性。

完整 Hessian 是 2H；比例因子不影响下面的最优补偿。实际会加 λI 让病态或低秩矩阵更稳定。

工程 · 算清楚，再实现

量化一列后，把误差分摊给仍可修改的列

e = wⱼ−Q(wⱼ)，要求 δⱼ=−e
最小化 δHδᵀ，得到 δ = −e·H⁻¹[j,:]/H⁻¹[j,j]

推法：约束目标加上 λ(δⱼ+e)，求导得 2Hδᵀ+λeⱼ=0；用 δⱼ=−e 解出 λ，再代回。

逐列执行

当前列写成量化值；其余列先补偿，再接受下一列的量化误差。已经量化的列保持固定。

GPTQ 的工程实现

采用固定列顺序、分块更新与逆 Hessian 的 Cholesky 形式，减少逐元素串行操作和重复矩阵处理。

手算两维补偿：让损失从 0.16 降到 0.12

L(δ₂)=0.16−0.4δ₂+δ₂²
∂L/∂δ₂=−0.4+2δ₂=0 → δ₂=0.2

这是量化当前列之后、下一列尚未量化时的条件最优值；下一列最终仍要落到自己的格点。

AWQ 用通道缩放保护更敏感的权重

W′ = WS，X′ = XS⁻¹
量化后的输出：X′ Q(W′)ᵀ

激活更大的输入通道通常更敏感。把相应权重列放大，再把激活反向缩小，可以降低该通道反量化后的有效步长。

搜索什么

从激活统计构造候选通道 scale；对各候选量化权重，再比较校准数据上的层输出误差。

为什么不能无限放大

组内最大值也可能被推高，使整组 scale 变粗，伤害其他通道。必须同时看整层重构误差。

AWQ 不是把少数权重永远留在 FP16；核心是等价缩放，让统一的低位格式更好地保留重要通道。
