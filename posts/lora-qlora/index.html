LoRA / QLoRA：参数高效微调

交互2026-10-20更新于 2026-10-22

一个 \(4096\times4096\) 的线性层有 1677 万个参数。让每个参数都能更新，还需要为它保存梯度、Adam 的两个状态，可能再保留一份 FP32 主权重。LoRA 把任务需要的变化写成两个小矩阵，让大模型保留原有权重，同时学习一条额外的计算分支。

理解这条分支，需要一起看三个量：它能表达什么变化，反向传播怎样穿过它，以及训练时哪些张量仍然占显存。这样才能判断一次微调的瓶颈究竟在 rank、激活还是量化重建。

1. 把低秩增量写进前向

采用 PyTorch 线性层的存储方向，底座权重 \(W\in\mathbb R^{d_o\times d_i}\)，输入 \(X\in\mathbb R^{N\times d_i}\)。\(N\) 是这次前向的 token 行数，\(d_i,d_o\) 是输入与输出宽度。LoRA 增加 \(A\in\mathbb R^{r\times d_i}\) 和 \(B\in\mathbb R^{d_o\times r}\)，得到

$$Y=XW^\top+\htmlData{symbol=scale}{s}(XA^\top)B^\top,\qquad s=\frac{\alpha}{\htmlData{symbol=rank}{r}}.$$

\(r\) 是低秩分支的中间宽度，\(\alpha\) 控制增量尺度；这里使用标准 LoRA 的 \(\alpha/r\) 缩放。输入先经 A 从 \(d_i\) 维压到 \(r\) 维，再经 B 展开到 \(d_o\) 维，与底座输出相加。等价的权重增量为 \(\Delta W=sBA\)，满足 \(\operatorname{rank}(\Delta W)\le r\)。这约束了任务变化的方向数，底座 W 可以保持满秩。

把 B 的第 j 列记作 \(b_j\)，A 的第 j 行记作 \(a_j^\top\)，便有 \(BA=\sum_{j=1}^{r}b_ja_j^\top\)。每一对因子贡献一个外积。增加 rank，相当于允许更多外积共同表达变化；真正需要多少方向，要用相同数据与训练预算下的验证质量判断。

2. 梯度怎样穿过冻结的底座

记中间结果 \(Z=XA^\top\)，上游梯度 \(G=\partial\mathcal L/\partial Y\)，形状为 \([N,d_o]\)。对矩阵乘法应用链式法则，得到

$$\frac{\partial\mathcal L}{\partial B}=sG^\top Z,\qquad \frac{\partial\mathcal L}{\partial A}=s(GB)^\top X,\qquad \frac{\partial\mathcal L}{\partial X}=GW+s(GB)A.$$

第一项的形状是 \([d_o,N][N,r]=[d_o,r]\)，第二项是 \([r,N][N,d_i]=[r,d_i]\)。输入梯度中的 \(GW\) 仍然需要计算，它把训练信号传回更早层的 adapter。冻结 W 的含义是关闭 W 的参数更新；包含 W 的前向仍参与自动求导。因此，应设置底座参数的 requires_grad=False，并让优化器只持有可训练参数。

这些梯度也解释了训练时保存什么：计算 dB 要用 Z，计算 dA 要用 X，计算输入梯度要再次读取 W、A、B。对一个 [N=8192,d=4096] 的 BF16 输入，X 占 64 MiB；rank 16 的 Z 只占 256 KiB。两个小矩阵节省了参数及优化器状态，输入激活仍然需要跨过前向与反向的间隔。采用 checkpoint 后，区段内部的 X、Z 可以在反向时重算，代价是再次执行底座和低秩分支。

量化底座还把重建路径带进反向：计算输入梯度时，需要用冻结的量化 codes 和 scales 恢复参与乘法的权重块。实现可以在 kernel 内按 tile 重建，或者使用更大的临时缓冲区。峰值显存与时延应同时记录前向、反向和 optimizer step，才能判断激活重算、省下的参数字节和额外解码工作如何共同影响训练。

PEFT 的标准初始化给 A 随机值、B 零值。这样初始增量为零，模型从底座行为起步。第一轮 \(GB=0\)，A 的梯度为零；只要 Z 与 G 有效，B 就能收到梯度。更新 B 后，A 的路径也随之打开。若把两个矩阵都置零，两边的梯度都会为零。

这个顺序提供了很实用的验收方法：先记录一个固定 batch 的 loss、A/B 梯度范数和更新前后的参数差值。第一轮 A 的梯度为零符合初始化设计；如果 B 也始终没有梯度，就应沿着 loss、目标模块与 checkpoint 边界向前查找。

3. 从一层数到整模

一层 LoRA 的参数数为 \(r(d_i+d_o)\)，额外前向约做 \(2Nr(d_i+d_o)\) FLOPs。对 \(d_i=d_o=4096,r=16\)，参数数为 131,072，BF16 权重占 256 KiB，只有原矩阵的 0.78125%。额外 FLOPs 也具有相同比例；实际时延还受小矩阵利用率和 kernel 启动影响。

低 rank 也改变了硬件形状。对单行 decode，上例两次 LoRA 乘法合计 262,144 FLOPs，读取 A、B 共 262,144 B，权重流量对应的算术强度约 1 FLOP/B。若把 32 行相同 adapter 的输入合批，并让权重在这 32 行之间复用，这一项就能提升到约 32 FLOP/B；实际值还包含输入输出流量。相同的参数量，在逐请求小 kernel 和分组 GEMM 中会有很不同的吞吐。这也是服务端按 adapter 与 rank 组织计算的原因。

若模型有 32 层，每层只给 Q、V 两个同尺寸投影添加 adapter，总计 8,388,608 个可训练参数。采用 BF16 参数和梯度、FP32 主权重与 Adam 两个状态，每参数 16 B，共 128 MiB。若实现使用 FP32 adapter 且没有额外主权重，参数、梯度、m、v 同样合计 16 B。明确存储方案，才能复算这份账。

GQA 模型的投影尺寸会改变结果。hidden size=4096、32 个 query 头、8 个 KV 头、每头 128 维时，Q 的输出宽度是 4096，V 的输出宽度是 1024。rank 16 的 Q、V adapter 分别有 131,072 和 81,920 个参数。整模预算应先列出实际命中的模块及尺寸，再求和。

训练峰值还包括冻结底座、保存的激活、反向临时空间和分配器预留。单个 BF16 张量 [batch=2, length=4096, hidden=4096] 已占 64 MiB。长度翻倍时，它也翻倍，层内还有 MLP 中间值等保存项。长序列微调的下一步通常是调 micro-batch、attention 实现和 激活重计算。

4. QLoRA 如何压缩冻结底座

QLoRA 在冻结底座上使用低位编码，并保留浮点 adapter：

$$Y=X\,\operatorname{dequant}(Q(W))^\top+s(XA^\top)B^\top.$$

权重以 4-bit 索引保存，kernel 在计算时按块重建为计算 dtype。NF4 的索引指向一个含 16 个值的非均匀码本，靠近零的重建点更密。对一个 block，先计算 \(a=\max_i|w_i|\)，再选择 \(c_i=\arg\min_j|w_i/a-v_j|\)，重建为 \(\hat w_i=a v_{c_i}\)。全零块可以保存 scale=0。

以 block=[−0.8,−0.2,0,0.4,1] 为例，scale=1，对应重建值约为 [−0.6962,−0.1848,0,0.4407,1]。两个 4-bit 索引打包成一个字节，这五个元素需要三个字节；最后一个半字节只占存储空间，计算按原始元素数截断。

scale 本身也占容量。每 64 个权重保存一个 FP32 scale，相当于每权重多 0.5 bit。double quant 再把 scale 编码为低位数据：若第一层 scale 用 8 bit，每 256 个 scale 共用一个 FP32 二级 scale，主项摊销为

$$\frac8{64}+\frac{32}{64\times256}=0.126953\ \text{bit/权重}.$$

这样权重与 scale 的主项约为 4.127 bit/权重，实际文件还包含块边界、偏移与对齐。另一个 QLoRA 组件是 paged optimizer，它管理 CPU/GPU 间的优化器状态迁移。迁移缓解显存峰值，也会占用主机链路；训练日志要同时记录换页与 step time。

5. 接入、保存与合并是一条完整路径

PEFT 接入时，先建立量化底座，准备 k-bit 训练，再添加 LoRA。以下片段中的 model_path 指向已准备的模型：

qconf = BitsAndBytesConfig(
    load_in_4bit=True, bnb_4bit_quant_type="nf4",
    bnb_4bit_use_double_quant=True,
    bnb_4bit_compute_dtype=torch.bfloat16)
base = AutoModelForCausalLM.from_pretrained(
    model_path, quantization_config=qconf)
base = prepare_model_for_kbit_training(base)
model = get_peft_model(base, LoraConfig(
    r=16, lora_alpha=16, target_modules="all-linear",
    bias="none", task_type="CAUSAL_LM"))
model.print_trainable_parameters()

all-linear 会按模型结构选择目标层。打印模块名、参数数量与 dtype，可以确认训练的范围。存储 dtype、矩阵乘计算 dtype、adapter 梯度 dtype 是三个独立配置点；例如 bnb_4bit_compute_dtype 描述低位线性层的计算类型。

保存 adapter 时，还应保存底座不可变 revision、rank、缩放、目标模块、额外训练层、tokenizer 与模板。加载验收使用相同输入逐层比较输出，再比较最终 logits。若训练修改了 embedding 或输出头，modules_to_save 必须包含相应权重。

在 eval 模式下，浮点合并使用 \(W'=W+sBA\)，代入线性层即可得到相同的数学结果。低位发布还多一次重编码：\(Q(\hat W+sBA)\) 会产生新的舍入误差。固定任务可以合并后重新验证；多 Adapter 服务则保留公共底座与独立分支。

重编码的影响可以用一个均匀量化格点看清：假设间距为 0.1，冻结权重重建为 0.2，adapter 学到 0.04 的增量，分支计算使用的有效权重为 0.24。重新量化后落回 0.2，新增变化被舍入。实际 NF4 的格点间距随区间而变，合并后的 block scale 也可能改变。因此比较发布路径时，应固定样本，同时记录 logits 差值和任务指标；合并省去低秩分支的读取与启动开销，发布质量由重编码后的模型重新验收。

6. 从异常现象定位原因

loss 有值，adapter 梯度却为空。首先确认目标模块真的进入前向，再检查冻结与 checkpoint 边界。旧式 reentrant checkpoint 要求至少一个输入和输出参与梯度；冻结 embedding 后，输入可能不带梯度，而区段内部仍有待训练 adapter。使用支持的 non-reentrant 路径、显式传入 use_reentrant=False，并用同一小 batch 比较开关 checkpoint 时每层 adapter 梯度。

训练 loss 很低，实际回答质量差。把一个样本展开成 token、attention mask 与 labels，核对回答监督区间、padding 的 −100，以及模板加入的角色和结束标记。小数据过拟合测试先检验训练链是否工作，再用独立数据比较任务质量。

合并或重新加载后输出明显改变。记录第一个出现差异的层，核对底座 revision、\(\alpha/r\)、目标模块、额外保存层和是否重复合并。量化发布再增加一组“同量化底座 + 浮点 adapter”的对照，把重编码误差与配置错误分开测量。

手里有多个任务的微调增量时，模型合并进一步研究这些增量怎样组合。共同基座、参数坐标与词表索引需要对齐，再比较任务向量、TIES、DARE 对各项能力的影响；合并系数由独立验证集选择。

7. 计算与排错练习

练习 1：rank 8 的整模预算

24 层，每层 Q、V 都是 \(2048\times2048\)，rank=8。求 adapter 参数数、BF16 权重大小及 16 B/参数的训练状态。

展开参考解答

每个投影 \(8(2048+2048)=32768\) 个参数，整模为 \(24\times2\times32768=1572864\)。BF16 权重为 3 MiB；训练状态为 24 MiB。

练习 2：第一步 A 为什么不动

沿用图中的 x、A、B=0、目标 [1,0]。求 dB、dA，并用学习率 0.1、无 weight decay 的 SGD 更新 B。

展开参考解答

z=−1，y=[1,2]，G=[0,2]。dB=[0,−2]ᵀ，dA=[0,0]。更新后 B=[0,0.2]ᵀ，下一次 y=[1,1.8]，dA=[0.36,0.72]。

练习 3：4-bit 权重的元数据

有 1,048,576 个权重，每 64 个保存一个 FP32 scale。求 codes、scales 和总 KiB。

展开参考解答

codes 为 524288 B=512 KiB；16384 个 scale 为 65536 B=64 KiB。总量 576 KiB，主项为 4.5 bit/权重。

练习 4：长序列 OOM

同一模型和 rank，长度从 2048 增为 8192 后峰值从 11 GiB 变成 19 GiB。optimizer bytes 不变。设计两个能区分原因的实验。

展开参考解答

固定长度改变 micro-batch，记录前向末尾与反向峰值；再固定 batch 开关激活重计算，记录峰值和 step time。随长度/batch 增长且重计算后下降的保存项指向激活。同步记录临时 workspace，可以继续判断反向峰值。

8. 运行梯度与量化实验

下载 lab.py。NumPy 实验用 FP64 核对低秩梯度与合并，包含 NF4 码本、打包、全零块和奇数尾部。

python3 -m pip install numpy
python3 lab.py
python3 lab.py --rank 1

默认应打印 gradient finite difference: PASS、NF4 检查通过，以及浮点 rank 2 训练损失接近 0。NF4 底座的独立测试损失约 0.003459。把 rank 从 2 改为 1，比较表达容量；再改变 block 大小，对照量化误差与 scale 字节数。
