LoRA / QLoRA：参数高效微调

冻结一个大模型，怎样仍然学会新任务？

2026-10-20 · → 逐步推进 · ← 回看 · 拖动时间轴

工程细节

要更新的参数，也会带来梯度和优化器状态

一个 4096 × 4096 的线性层有 16,777,216 个权重。微调它，不只需要存权重，还要为更新保留梯度和状态。

全量微调

每个 W 元素都可移动；表达能力强，更新账本也大。

LoRA

冻结 W，只训练一个低秩增量 ΔW；节省可训练参数的梯度与优化器状态。

先修：矩阵乘法、链式法则；可配合 优化器 与 量化。

工程细节

把每个维度写清楚

Y = XWᵀ + s(XAᵀ)Bᵀ；s = α / r
张量形状意义
X[N, dᵢ]N 个 token 的输入
W[dₒ, dᵢ]冻结的原始线性层
A / B[r, dᵢ] / [dₒ, r]先投影到 r 维，再展开
Y[N, dₒ]两条分支相加的输出

r 是 rank 上限，α 是缩放超参数。这里使用标准 LoRA 的 α/r；其他缩放变体要单独写明。

逐步算一遍

两条分支，算出同一个输出

x = [1, 2]，W = I，A = [1, −1]，B = [2, 1]ᵀ，s = 0.5。

先沿冻结的 W 计算原模型输出。

数值和时延均为教学示例。

工程细节

低秩约束落在增量上

ΔW = s BA = s Σⱼ bⱼ aⱼᵀ；rank(ΔW) ≤ r

bⱼ 是 B 的第 j 列，aⱼᵀ 是 A 的第 j 行。每一对只贡献一个外积；r 对外积叠起来，组成这次任务需要的变化。

约束的是变化

W 可以保持满秩。LoRA 并没有把整个预训练权重压成 rank r。

选 r 的含义

增加 r 会增加可用方向；是否提高任务质量，要看验证集和目标层。

逐步算一遍

两个外积，逐格拼成 ΔW

A = [[1, 0, 2], [0, 1, −1]]，B = [[2, 1], [−1, 3]]，s = 1。

先展开第一个 rank 方向。

数值和时延均为教学示例。

工程细节

rank 16 的参数账本

P = r(dᵢ + dₒ) = 16 × (4096 + 4096) = 131,072
项目全量 WLoRA A+B
参数数16,777,216131,072
BF16 权重32 MiB256 KiB

一次前向的主矩阵乘法约 2Ndᵢdₒ FLOPs；adapter 约 2Nr(dᵢ+dₒ)。这里同样是 0.78125%，但小 kernel 的运行时间不一定按 FLOPs 等比例。

工程细节

从一个线性层，数到整个模型

教学模型有 32 层；每层只给两个 4096 × 4096 的 Q、V 投影加 rank 16。

P = 32 × 2 × 131,072 = 8,388,608
可训练状态每参数字节合计
BF16 参数 + BF16 梯度2 + 232 MiB
FP32 master + Adam m、v4 + 4 + 496 MiB
总计16128 MiB

这是指定 dtype 下的账本；若 adapter 直接用 FP32，且没有额外 master，参数、梯度、m、v 也共 16 B/参数。底座、激活和临时空间另算。

工程细节

把链式法则写成三次矩阵乘法

Z = XAᵀ；G = ∂L/∂Y
∂L/∂B = sGᵀZ；∂L/∂A = s(GB)ᵀX
梯度形状检查
GᵀZ[dₒ, N] × [N, r] → [dₒ, r]
(GB)ᵀX[r, N] × [N, dᵢ] → [r, dᵢ]
∂L/∂X = GW + s(GB)A[N, dᵢ]，继续传向更早的层

不为 W 计算更新梯度，不等于截断经过 W 的梯度。更早层的 adapter 仍需要 ∂L/∂X。

逐步算一遍

B 从零开始，第一步先学 B

取 x=[1,2]，W=I，A=[1,−1]，B=[0,0]ᵀ，s=1；目标 y*=[1,0]，L=½‖y−y*‖²。

B=0 时 ΔW=0，模型从原有行为出发。

数值和时延均为教学示例。

工程细节

为什么不能把 A 和 B 都初始化为零？

当 A=B=0，Z=XAᵀ=0，因此 ∂L/∂B=0；GB=0，因此 ∂L/∂A=0。两个因子都没有信号。

常见初始化

A 用随机数，B 用零。初始 ΔW=0，第一轮 B 可以收到梯度。

检查顺序

先确认 B 梯度非零；A 在第一轮为零是正常的，更新 B 后再检查 A。

PEFT 标准默认使用 Kaiming-uniform 初始化 A、零初始化 B；若改用其他初始化，需要重新确认初始模型是否等于底座。

工程细节

最小训练循环保留了哪些状态？

W.requires_grad_(False)
z = x @ A.T
y = x @ W.T + (alpha / rank) * z @ B.T
loss = task_loss(y, target)
loss.backward()       # 梯度继续流向 x、A、B
optimizer.step()      # optimizer 只持有可训练参数
optimizer.zero_grad()

不要把整个冻结底座包在 no_grad() 中：它会让早期 adapter 的梯度路径断开。优化器只更新 A、B，与前向是否参与自动求导是两件事。

工程细节

增加 rank，买到多少表达能力？

假设目标增量的奇异值是 [4, 2, 1, 0.5]。只衡量权重矩阵的 Frobenius 误差，最佳 rank r 近似会留下前 r 个方向。

r保留的平方能量剩余平方误差
116 / 21.25 = 75.3%4 + 1 + 0.25 = 5.25
220 / 21.25 = 94.1%1.25
4100%0

真实任务关心的是输入分布上的输出误差与质量。这个手算例子说明容量变化，不能替代相同数据、训练步数和预算下的验证。

工程细节

QLoRA：底座低位存，adapter 高精度学

Y = X · dequant(Q(W))ᵀ + s(XAᵀ)Bᵀ

底座权重冻结为 4-bit 编码。计算时把所需权重重建为计算 dtype；adapter 和它的梯度使用浮点数。

压缩的是哪一项

底座的权重存储；NF4、double quant 进一步压低这一项的字节数。

仍然存在的项

激活、adapter 梯度与优化器状态、解量化临时空间、非量化层。

重建可以由 kernel 分块完成，不要求常驻一整份 BF16 底座。具体临时空间取决于实现。

工程细节

NF4 的 4 bit，是码本中的索引

一个 block 先用 absmax 缩放到 [−1,1]，每个数映射到 16 个重建值中最近的一项。靠近零的档位更密。

a = maxᵢ |wᵢ|；cᵢ = argminⱼ |wᵢ/a − vⱼ|；ŵᵢ = a·v[cᵢ]

例如码本含 −1、−0.6962、−0.1848、0、0.4407、1 等值。NF4 不是均匀 INT4，也不是符号位/指数位/尾数位的 FP4。

全零块可令 scale=0，重建也全为零。码本与 block scale 都是解码信息的一部分。

逐步算一遍

五个权重，变成五个 4-bit 索引

block=[−0.8, −0.2, 0, 0.4, 1]，absmax=1；下方逐个显示码本索引和重建值。

先存储 scale=1，再为每个权重选择最近的档位。

最后一个半字节用零的索引 7 补齐；原元素数仍是 5，padding 不参与计算。

工程细节

再量化一次的是 scale

若每 64 个权重保留一个 FP32 scale，scale 开销为 32/64 = 0.5 bit/权重。

scale 开销 ≈ 8/64 + 32/(64×256)
= 0.126953 bit/权重

教学账本：第一层 scale 用 8-bit 保存；每 256 个 scale 再共享一个 FP32 二级 scale。大张量下权重与 scale 合计约 4.127 bit/权重。

还有居中偏移、块边界、码本与对齐等元数据。上式是主项摊销，不是任意形状张量的精确文件字节数。

工程细节

只看一份激活，也能看见长度的代价

一个 BF16 张量 [batch=2, length=4096, hidden=4096]：

2 × 4096 × 4096 × 2 B = 64 MiB

把序列长度翻倍，这一张量变成 128 MiB。模型里还有残差、归一化、MLP 中间张量；保存策略会决定哪些需要一直留到反向。

优化器状态很小、长序列仍然 OOM 时，先查看激活峰值随长度的曲线，再调整 micro-batch 或重计算。

工程细节

Paged optimizer 与 KV 分页，处理不同的账本

Paged optimizer

利用 CPU/GPU 间的统一内存分页，在显存压力下迁移优化器状态。迁移可以缓解峰值，也会消耗链路时间。

PagedAttention

按请求管理推理时增长的 KV cache；解决缓存分配和共享问题。

两者都出现 page，但分页对象和生命周期不同。训练能放进去后，还应记录 page fault、传输量和 step time，判断是否在反复换页。

工程细节

存储 dtype、计算 dtype、梯度 dtype 分开看

对象一个常见选择检查点
底座权重NF4 编码 + scales真正被冻结
线性层计算BF16硬件与 kernel 支持
LoRA 参数 / 梯度FP32 或 BF16框架可能自动上转 dtype
loss / 归一化累加通常更高精度溢出、NaN 与数值误差

工程细节

合并，是把增量写回权重

W′ = W + sBA；XW′ᵀ = XWᵀ + s(XAᵀ)Bᵀ

在 eval 模式且 dropout 关闭时，浮点数学上两条路径等价。实现中允许合理的浮点误差，并用相同输入的 logits 验证。

固定一个任务

合并后直接用普通线性层，去掉额外 LoRA 分支。

多个任务同时服务

保留共享底座和独立 adapter，便于在同一 batch 中使用不同增量。

工程细节

量化后的合并，通常会再产生一次误差

Ŵ = dequant(Q(W))
dequant(Q(Ŵ + sBA)) 一般不等于 Ŵ + sBA

左侧把合并后的权重重新量化；右侧保持原有量化底座，并在浮点分支上加 adapter。舍入让两条路径不再严格一致。

单标量例子：单位步长量化，底座 1，增量 0.4。分支输出是 1.4；重新量化后成为 1。合并格式和目标 kernel 确定后，再做质量与性能验收。

工程细节

显存从 11 GiB 涨到 19 GiB，先改哪项？

教学观测：同一模型、同一 rank，把长度从 2048 改为 8192；底座与 optimizer bytes 不变，反向前的峰值上升。

从证据定位

增长发生在前向后、反向前，并随长度变化。优先检查保存的激活和 attention 路径。

用一次实验验证

固定长度，减小 micro-batch；或开启 checkpoint，记录峰值下降与 step time 增加。

直接把 rank 从 16 降到 8，最多只减少一部分 adapter 状态，未必触及这 8 GiB 的主要来源。

练习 1

rank 8，到底省了多少？

24 层，每层 Q、V 都是 2048 × 2048；r=8。算 adapter 参数数、BF16 权重和 16 B/参数的训练状态。
展开参考解答

每个投影：8×(2048+2048)=32,768。总数：24×2×32,768=1,572,864。

BF16 权重：1,572,864×2=3 MiB。训练状态：×16=24 MiB。冻结底座与激活未包含。

练习 2

为什么第一步 A 不动？

x=[1,2]，A=[1,−1]，B=[0,0]ᵀ，W=I，s=1；目标 [1,0]，L=½‖y−y*‖²。求 dB、dA，并用学习率 0.1 更新 B。
展开参考解答

z=−1，y=[1,2]，G=[0,2]。dB=Gᵀz=[0,−2]ᵀ；dA=(GB)ᵀx=[0,0]。

B←B−0.1dB=[0,0.2]ᵀ。下一次 y=[1,1.8]，dA=[0.36,0.72]；A 开始有学习信号。

练习 3

4-bit 的账，为什么不止 0.5 B/权重？

有 1,048,576 个权重，每 64 个一块。每块用 FP32 scale；暂不做 double quant。精确计算 codes 与 scale 占多少 KiB。
展开参考解答

codes：1,048,576÷2=524,288 B=512 KiB。块数：16,384；scales：×4=65,536 B=64 KiB。

合计 576 KiB，即 4.5 bit/权重。这里块整除且只计 codes 与 scale；额外元数据另算。

练习 4

合并以后 logits 变了，先排哪几项？

eval 模式下，未量化底座 + adapter 与合并模型差异很大；重新量化后的模型又有小幅质量下降。分别设计排查顺序。
展开参考解答

前者先核对底座 revision、目标层、α/r、是否重复合并、是否遗漏 modules_to_save，并用逐层输出定位最早差异。

后者先与“解量化底座 + 浮点 adapter”的同配置基线比较，再测量重新量化误差和验证集指标；量化后的等价性不能仅靠代数证明。
