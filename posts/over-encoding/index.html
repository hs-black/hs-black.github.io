Over-Encoding：用查表扩展语言模型容量

交互2026-10-22

隐藏宽度为 4096、词表含 131,072 个 token 的模型，读取一个 BF16 输入词向量只取 8 KiB。预测下一个 token 时，同样大小的输出矩阵却要计算 131,072 个分数，约需 10.7 亿次浮点运算。输入和输出可以共享权重，但它们使用这份权重的方式差别很大。

这个不对称提供了一条扩容路线：把更多参数放进输入侧的查表结构，让每个位置只读取少量行；主干继续在原有 token 序列上计算。Over-Encoding（OE）沿着这条路线，为相邻 token 的组合建立大表。问题随后变成：组合怎样寻址，发生碰撞时怎样学习，大表怎样跨设备存放，以及增加的容量能否转化为目标能力。

输入和输出为何值得分别扩展

普通输入 embedding 是矩阵 \(E\in\mathbb R^{V\times d}\)：\(V\) 是基础词表大小，\(d\) 是隐藏宽度。给定 token ID \(x_t\)，取出 \(E[x_t]\) 即可。矩阵有 \(Vd\) 个参数，当前 token 只读取 \(d\) 个元素。增大行数会增加存储，当前一次查表的向量长度保持不变。

输出头则把隐藏状态 \(h_t\in\mathbb R^d\) 映射为 \(V\) 个 logits。若使用完整 dense 词表投影，矩阵乘法约为：

$$F_{\mathrm{head}}\approx2dV\quad\text{FLOPs/token},\qquad B_{\mathrm{lookup}}=d\,b_e\quad\text{B/token}.$$

其中 \(b_e\) 是每个 embedding 元素的字节数，BF16 为 2。前式按一次乘加计 2 FLOPs；后式计一行的有效载荷。以 \(d=4096,V=131072\) 代入，分别是约 1.074 GFLOPs 和 8192 B。实际查表还受访存粒度与缓存命中影响，输出头还需考虑矩阵布局和 batch 复用。

OE 保留基础 tokenizer 和输出词表，在输入侧增加局部组合的 embedding。每个位置仍预测下一个基础 token，序列长度也保持原样。若还想扩展预测监督，可以组合多 token 预测；这会改变输出侧的目标和成本，需要单独核算。

从一个 token 到一个局部上下文

假设示例词表是：padding=0、we=1、read=2、write=3、code=4，因此 \(V=5\)。序列“we read we write read code”对应 [1,2,1,3,2,4]。到当前位置时，既有当前 token，也有它前面的几个 token。一个长度为 \(n\) 的 suffix n-gram 可以编码为：

$$u_{t,n}=\sum_{j=0}^{n-1}x_{t-j}V^j,\qquad \htmlData{symbol=hash-row}{r_{t,n}}=u_{t,n}\bmod M_n.$$

\(x_{t-j}\) 是位置 \(t-j\) 的基础 ID，序列开始前补 0；\(M_n\) 是第 \(n\) 阶表的行数。以当前 token 作最低位，bigram “we read”的完整编号是 \(2+5\times1=7\)。为每个组合直接建表需要 \(V^n\) 行：十万词表的 trigram 有 \(10^{15}\) 个潜在组合。取模把寻址范围限制在可配置的表内。

若 bigram 表有 7 行，“we read”的编号 7 与“read code”的编号 14 都落到第 0 行。它们共享同一条可训练向量。把表扩为 11 行后，两者分别落到第 7 与第 3 行，得到独立参数。这个例子正好说明新增行数的作用：减少不同局部模式被迫共享参数的情况。

实际实现可以递推计算编号的模，避免先构造巨大的整数。计算 trigram 时依次乘以 \(V\)、加下一个 ID，并在每步取模，结果与完整整数最后取模一致。哈希规则、词表版本、序列边界和 padding ID 都属于模型配置，训练与推理需要保持一致。

哈希碰撞怎样进入梯度

先用均匀独立哈希估计表的使用程度。若有 \(U\) 种不同 n-gram 被分配到 \(M\) 行，一个给定行没有收到任何模式的概率是 \((1-1/M)^U\)，所以期望使用行数为：

$$\mathbb E[\text{使用行数}]=M\left[1-\left(1-\frac1M\right)^U\right].$$

\(U=1000,M=1000\) 时，期望只使用约 632.3 行；约 367.7 个模式落进已经占用的行。若 \(M=10000\)，期望使用约 951.7 行。真实语言频次有明显长尾，确定性取模也可能有结构相关性；这个公式提供容量规划的基线，实际统计还应加上按训练 token 频次加权的碰撞率。

共享参数会把梯度叠到同一行。设位置 \(t\) 的损失对读出向量的梯度为 \(g_t\)，则表中第 \(r\) 行的梯度是：

$$\nabla_{E[r]}L=\sum_{t:\,r_t=r}g_t.$$

两个模式要求相近的更新时，共享有利于统计积累；要求相反的更新时，梯度会抵消。散列冲突因此同时涉及地址和任务。诊断时可以按行记录访问频率、模式数量、梯度范数及方向相似度，再比较扩表、换哈希头和降低 n-gram 阶数后的验证效果。

取模参数也有结构陷阱。对 bigram 编号 \(x_t+Vx_{t-1}\)，若取 \(M=V\)，结果恒等于 \(x_t\)：前一个 token 完全失去作用。选择与词表进制关系合适的表长、给不同头使用不同映射，能保留更多组合差异。大规模实现还要核对乘法的整数位宽；同一哈希在 CPU 与 GPU 上应有明确的溢出或模运算约定。

层次组合、低维切片与表示

只用长 n-gram 会让大量罕见组合获得很少更新。OE 把多个阶数叠加：当前词的向量保留通用信息，bigram 和 trigram 提供更具体的局部上下文。把第 \(n\) 阶拆成 \(K_n\) 个低维表后，可写成：

$$h_t=E_1[x_t]+\sum_{n=2}^{N}\sum_{k=1}^{K_n} W_{n,k}E_{n,k}[r_{t,n,k}].$$

这里 \(N\) 是最大阶数，表 \(E_{n,k}\in\mathbb R^{M_{n,k}\times q_{n,k}}\) 每行宽度为 \(q_{n,k}\)，投影 \(W_{n,k}\in\mathbb R^{d\times q_{n,k}}\) 把它映射到隐藏宽度 \(d\)。各头可以取不同表长和映射。低维表读出后只对当前行做小矩阵投影，主干输入仍为 \(d\) 维。

新增参数分为大表和投影两部分：

$$P_{\mathrm{extra}}=\sum_{n,k}\big(M_{n,k}q_{n,k}+d\,q_{n,k}\big),\qquad F_{\mathrm{proj/token}}\approx2d\sum_{n,k}q_{n,k}.$$

例如两个表，各 10M 行、行宽 128，主干宽 4096。表参数共 2.56B，投影约 1.05M；BF16 表权重约 5.12 GB，每个 token 读取两行共 512 B，投影约 2.10 MFLOPs。扩表改变的是前一项；增加头数和行宽还会增加每个 token 的读取与投影成本。

多个头应提供不同的寻址信息。若所有低维头使用相同映射，那么任意一对模式会在全部头上一起碰撞，分头主要相当于重新组织同一块向量。不同映射让一次局部碰撞可以被其他头区分；在理想独立均匀哈希下，一对模式在 \(K\) 个大小均为 \(M\) 的表中全部碰撞的概率为 \(M^{-K}\)。训练收益还取决于每个头的维度与数据覆盖。

查词、查潜在类别与查上下文

LookupLM 把前面几个 token 的哈希向量拼到 RNN 层的输入，研究了用较少额外计算增加长尾表达容量。它把“存更多模式”和“执行更宽的递归网络”拆成两个扩容选择。短语、罕见拼写和人名之类的局部组合，为这种记忆提供了直接用途。

N-Grammer 则先把输入表示按头做离散聚类，再用相邻潜在类别组成 bigram。查表地址由表示所属的类别决定，类别相近的输入可以共享组合；读出的 bigram 与原表示分别 LayerNorm 后拼接。聚类、离散映射和组合表共同形成一条表示路径。

OE 使用基础 token IDs 组成多阶 suffix，主要在输入处把投影后的向量相加。这使查表地址可以在主干计算之前确定。三种设计的区别集中在三个选择：地址来自原始 ID 还是潜在类别、局部范围覆盖几步、查出的内容在什么位置融合。接下来的Engram保留确定性寻址，再用中间隐藏状态控制读出内容的作用。

大表怎样分片才保留稀疏性

参数稀疏使用，需要存储和通信路径一起配合。若普通 FSDP 在前向前把整个 embedding 参数组 all-gather，每个 rank 会收到大量当前 batch 没有访问的行。随着表长增长，查表 FLOPs 变化很小，参数通信却不断增加，吞吐随之下降。

按行分片可以保留访问稀疏性。设有 \(p\) 个 rank，用 \(\operatorname{owner}(r)=r\bmod p\) 决定行归属，\(\lfloor r/p\rfloor\) 为片内编号。当前 rank 将请求 ID 发给对应 owner；owner 读出向量并发回；反向再把行梯度送回 owner，按 ID 累加。OE 的工程实现采用这种请求、返回和梯度回传的路径。

为了公平比较通信，取每个 rank 平均发出的字节，假定请求均匀、各 rank token 数相同且暂不合并重复请求。一次全参数 gather 的量级与行分片前向的量级分别为：

$$B_{\mathrm{gather}}\approx\frac{p-1}{p}\,P_{\mathrm{table}}b_e, \qquad B_{\mathrm{rows}}\approx\frac{p-1}{p}\,T_{\mathrm{local}}H\,(b_{id}+q b_e).$$

\(P_{\mathrm{table}}\) 是所有表的参数数，\(T_{\mathrm{local}}\) 是每 rank 的 token 数，\(H\) 是每 token 读取的行数，\(q\) 是统一行宽，\(b_{id}\) 是请求 ID 字节数。左式随总表长增长，右式随激活行数增长。反向还有向量梯度回传；是否重算、参数组怎样划分，会影响完整训练 step 的通信次数。

默认例子中，两表权重共 5.12 GB，一次 gather 平均每 rank 发出约 4.48 GB；行分片前向约 3.61 MiB。行分片还要管理请求排序、回复顺序与重复 ID。相同位置必须拿回正确向量；多个位置命中同一行时，反向应累加全部梯度。

语言的高频组合可能集中到某些行，产生热点。可以先测 owner 间请求数分布和最长队列，再尝试请求去重、热门行缓存或复制。缓存训练中的可变权重还涉及更新同步；推理表冻结后，复用更直接。分片策略应同时记录优化器状态：BF16 权重只是表容量的一部分，FP32 master 权重与 Adam 两份矩会明显增加训练存储。

优化器还决定未访问行怎样变化。以 dense Adam 为例，某行当前梯度为零，但之前累积的动量仍会衰减并推动参数；AdamW 的权重衰减也可作用于整表。只更新本次命中行的实现，则需要另行约定这些状态。选择稀疏优化器时，可以用“访问一次、空闲十步、再次访问”的序列，观察参数和矩估计是否符合预定规则，再决定如何保存每行的更新时间。这样既能量化扫描整表的成本，也能避免把优化算法变化混进分片实验。

表中的罕见行还容易受训练预算影响。把访问次数按行统计，能分开看见从未使用的容量、只收到几次更新的行，以及频繁更新的热点。固定总表参数时，可以比较“少量宽行”和“大量窄行”：前者给每个模式更丰富的表示，后者降低冲突。两者投影开销、访问覆盖和泛化表现的变化应一起记录。

最小正确性实验是比较单表、按行分片和改变请求顺序后的结果：前向向量逐项一致，反向每行梯度与集中式 scatter-add 一致。再用相同请求分别扩大表长与增大 batch，测通信量和吞吐。这样能分辨瓶颈来自总参数、激活流量、还是请求调度。

怎样判断新增容量花得值

增加输入表后，总参数和每 token 的激活成本分开变化。评估时固定主干、tokenizer、训练 token 数与学习率计划，先扫描行数、阶数、头数和行宽；同时记录表的实际占用率、频次分布、读取字节、投影 FLOPs 与总训练成本。

更长 n-gram 有更具体的上下文，也有更稀疏的更新。若训练 loss 继续下降，而新来源验证集的改善变小，可以按 n-gram 训练频次分桶，比较高频模式、低频模式与未见组合；再在不改变主干的情况下缩短阶数或增强去重。这把记住局部模式的收益接到泛化测量上。

参数预算对照也值得单独做：同样增加一笔参数，分别扩 embedding、增加 MoE 专家和扩大 dense 主干，再在相同训练计算与推理负载下比较。输入表擅长提供可复用的局部表示，动态计算仍负责组合这些信息与远处上下文。具体预算中的最佳分配，需要把质量、训练成本、主机容量和服务延迟一起列出。

计算与诊断

1. 查表容量和输出计算

两个表各 16M 行、行宽 128、BF16，主干宽 4096。求表权重容量、每 token 读取字节与投影 FLOPs。输出词表从 64k 增到 128k 时，完整输出头每 token 多多少 FLOPs？k 按 1000 计。

展开解答

表权重为 \(2\times16\times10^6\times128\times2=8.192\) GB；每 token 读 \(2\times128\times2=512\) B；两次投影约 \(2\times4096\times256=2,097,152\) FLOPs。输出头增加 \(2\times4096\times64000=524,288,000\) FLOPs，约 0.524 GFLOPs/token。投影参数另计，约 1.05M。

2. 哈希为什么失去上下文

词表大小 V=5，bigram 编号为当前 ID 加 5 倍前一 ID。取模 M=5 与 M=7 时，比较“we read”[1,2]、“write read”[3,2] 的行号。哪种选择能区分它们？

展开解答

完整编号分别为 7 与 17。模 5 都是 2，只剩当前 token 的 ID；模 7 分别为 0 与 3。一般地，\((x_t+Vx_{t-1})\bmod V=x_t\)。检查不同前缀固定结尾时行号是否变化，可以直接发现这种退化。

3. 同一行收到两份梯度

两个位置都访问第 3 行，梯度分别为 [1,−2] 与 [−0.5,1]。学习率 0.1，原行 [0.2,0.3]，无动量无衰减。正确更新是什么？若回传时只保留最后一份梯度，会得到什么？

展开解答

总梯度为 [0.5,−1]，新行是 [0.15,0.4]。覆盖更新只用 [−0.5,1]，会得到 [0.25,0.2]。交换请求顺序后覆盖结果还会改变；求和结果保持一致，适合作为分布式回传检查。

4. 表扩大后吞吐下降，怎样定位

表长扩大 4 倍，batch、头数和行宽保持不变。GPU 计算时间近似不变，step 时间增长。设计三个观察量，区分参数 gather、稀疏热点与优化器扫描。

展开解答

先看前向前通信字节是否随表长增长 4 倍；若成立，重点检查全参数 gather。再统计各 owner 的请求量、all-to-all 完成时间与最慢 rank，定位热点和等待。最后单独测 optimizer step，检查是否扫描整表及其状态；全表衰减或 dense 状态更新会引入随表长增长的带宽。分别替换为行分片、均衡请求测试和明确的稀疏优化器语义，再保持数据一致比较。

一个可复现的稀疏查表实验

下载实验并运行 python3 lab.py --seed 7。NumPy 实验独立验证滚动取模与 Python 大整数编号一致、M=V 的退化、均匀哈希的期望占用率、按行分片的前向等价与碰撞梯度累加，并核对容量和通信算例。

结果应显示 M=5 时固定结尾的所有 bigram 共用一行，M=7 时能区分；集中式与分片查表、梯度的最大差为 0；1000 个模式放入 1000 行的平均占用接近 632.3。把 --ranks 4 改为 2 或 8，地址归属变化，向量与梯度仍一致；再把模拟表行数改小，观察冲突怎样增加。
