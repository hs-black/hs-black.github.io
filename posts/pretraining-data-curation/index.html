预训练数据怎样筛选：去重、质量与多样性

交互2026-10-22

预训练预算是 100B tokens，原始网页有 1T tokens。直接均匀抽样，会反复读到转载、站点模板和搜索结果页；只取最高分的 100B，又可能把代码、论坛对话和小语种一起挤掉。数据筛选决定了有限的训练步数会遇到什么，也决定了哪些知识和表达方式有机会进入模型。

去重、质量评分和数据配比因此连在一起：去重调整一份内容出现的次数，质量过滤改变各类文本的存活率，采样把剩余文本转换为模型实际看到的 token 分布。先把这三个动作拆开计算，才能解释一次数据清洗为什么有效，以及收益来自哪里。

过滤就是一次分布变换

把语料按来源或能力分为若干域。域可以是通用网页、代码、数学，也可以按语言划分。设域 \(i\) 原先占全部 token 的比例为 \(p_i\)，过滤后保留该域 token 的比例为 \(r_i\)。从保留语料均匀抽取 token 时，新的域占比是：

$$\htmlData{symbol=retained-share}{p'_i}=\frac{p_i r_i}{\sum_j p_j r_j}.$$

分母是全库的 token 保留率。假如网页、代码、数学的原始占比为 60%、30%、10%，对应保留率为 20%、80%、90%，总保留率只有 45%，新占比却变成 26.7%、53.3%、20%。同一个过滤器，已经做了一次强烈的混合比例调整。

文档保留率与 token 保留率需要分别记录。一篇十万 token 的日志与一篇千 token 的教程，各算一篇文档；对训练预算，它们相差百倍。计数时沿用训练 tokenizer，并保留截断、packing、有效 loss mask 后的统计，才能把数据报表接到训练输入。

这个现象在真实语料里很常见：分类器偏好解释完整的文章，简短问答和代码片段就可能成批失去分数。可以在每个域内分别看分数分位数、保留量和最终验证损失，再决定采用统一门槛、分域门槛，还是保留后显式重新配比。后者的优化方法见数据配比怎样学出来。

从重复字串到 MinHash

重复存在不同粒度。一篇文章可能完整转载，也可能只复制一段答案，还可能在每个页面重复同一段导航。整篇内容哈希能找到相同文档；长重复字串检测能找到跨文档共享的片段；近似去重则允许少量改字和段落增删。

Lee 等人的文本去重工作同时研究了 ExactSubstr 与 NearDup。前者借助 suffix array 寻找反复出现的长子串，后者使用 MinHash 找高度重叠的文档。这两种粒度对应两种训练现象：反复看到同一个长片段会提高逐字复现它的机会，而大量近似文档会挤占训练预算。评估时可以同时记录重复片段的曝光次数、生成中的逐字复现率和独立验证损失。

近似去重先把文档转成词的连续 \(n\)-gram 集合。例如“the cat sat on the mat”的 3-gram 有四个。两篇文档的集合记为 \(A,B\)，Jaccard 相似度定义为：

$$\htmlData{symbol=jaccard}{s}=J(A,B)=\frac{|A\cap B|}{|A\cup B|}.$$

集合会合并同一文档内部重复出现的 n-gram，所以它衡量共享内容的覆盖程度。句序改变仍可能保留大量短 n-gram；对模板占比很高的网页，先抽取正文能让这个量更接近正文的相似程度。

MinHash 给所有可能的 n-gram 施加同一个随机排列，取集合中排名最小的元素作为签名。两个集合最小元素相同，恰好发生在并集中排名第一的元素属于交集时。因此，一次理想 MinHash 签名相等的概率就是 \(s\)。做多次独立排列，签名相等比例便可估计 Jaccard；工程实现通常用一族哈希函数近似排列。

签名压缩了文档，但仍需避免遍历所有文档对。LSH 把签名分成 \(b\) 个 band，每个 band 有 \(r\) 个哈希值。一个 band 内全部相等就形成候选对；任意 band 相等都能命中。独立哈希假设下：

$$\htmlData{symbol=candidate}{P_{\mathrm{cand}}(s)}=1-(1-s^r)^b.$$

这里 \(s\) 是两篇文档的 Jaccard，\(r\) 控制单个 band 的严格程度，\(b\) 提供多次命中的机会。FineWeb 使用 5-gram、14 个 band、每个 8 个哈希，共 112 个值。对 \(s=0.75\)，命中概率约 77.2%；对 \(s=0.5\)，约 5.3%。一个“相似度目标”在 LSH 中对应一条平滑概率曲线。

候选对得到后，保留策略还决定最终语料。若 A 与 B 相似、B 与 C 相似，A 与 C 可以差异很大。把相似关系做传递闭包后，每个连通分量只留一篇，可能一起删除 C；按顺序只与已保留代表比较，则可能保留 A 和 C。代表选择还可以考虑正文长度、质量分数和抓取时间。相似度、候选生成、成组规则、代表排序应分别写入数据版本配置。

语义去重把问题移到表示空间

“如何释放 CUDA 显存”和“怎样清理 GPU 上不用的张量”词面可能差异很大，却围绕同一个操作。SemDeDup 用预训练模型把文档编码为向量，让语义接近的内容在表示空间相邻。对单位长度向量 \(z_a,z_b\)，余弦相似度就是 \(z_a^\top z_b\)，接近 1 表示方向接近。

处理大量向量时，SemDeDup 先聚类，再在簇内寻找相似对。文本实验用 OPT-125M 的文档末 token 最后一层表示；向量模型、截断长度和池化方式共同决定“语义重复”的含义。教程和练习可能表达相近知识，却提供不同监督；阈值需要通过保留样本审查和下游能力实验来选择。

算法默认按离簇中心从远到近排序。对排在第 \(j\) 位的向量，计算它与所有更早向量的最大相似度：

$$m_j=\max_{i\lt j}z_i^\top z_j,\qquad \text{保留 }j\text{ 当 }m_j\le 1-\epsilon.$$

这里 \(\epsilon\) 是允许删除的语义距离门槛，增大它会扩大删除范围；第一个向量直接保留。比较集合包含所有更早向量，因此一个已被删除的中间样本仍然能导致后续样本被删。这个细节可以用 A—B—C 的相似链验证，也解释了为什么换成“只与保留代表比较”会得到另一份语料。

若总文档数为 \(N\)，等大地分成 \(K\) 簇，簇内全对比较的数量约为 \(N^2/(2K)\)。真实成本由 \(\sum_c n_c(n_c-1)/2\) 决定，其中 \(n_c\) 是第 \(c\) 簇的大小。一个异常大簇就能主导算力与峰值内存。分块计算相似度并逐列累积最大值，可以把一张 \(n_c\times n_c\) 矩阵的存储改为 tile 和最大值向量；簇边界附近的近邻则可能漏检，可抽样跨簇检索估计召回。

为什么跨快照去重会改变质量

网页抓取有时间维度。一篇高质量教程可能连续十个月存在，每月快照都有一份；一个随机生成的垃圾页也可能只出现一次。全局去重把教程的十次采样机会压为一次，独立去重每个快照则保留了它跨时间出现的频次。两种选择形成不同的训练分布。

FineWeb 在 96 个 Common Crawl 快照上比较过这些选择。按新到旧做全局去重时，较早快照最多有约 90% 的内容被移除。对旧快照的进一步分析显示，剩下的独有部分质量较低；按快照独立去重，再随机混合的方案表现更好。这揭示了一个可迁移的问题：重复频次可能同时携带“内容冗余”和“稳定存在的有用内容”两种信号。

可以设计三条可解释的训练分布：全局每簇留一篇；每个快照每簇留一篇；全局每簇留一篇，再用温和的出现次数函数加权，例如 \(w(m)=\sqrt m\)。这里 \(m\) 是内容跨快照出现的次数。第三种是用于检验机制的实验方案，它把物理存储去重和训练曝光权重分开。若性能随加权恢复，就有证据表明损失来自采样变化；若一直下降，应继续检查代表选择和内容覆盖。

质量分数怎样定义

质量分类器学到的是正负样本之间的边界。用教程作正例，它会偏好结构清楚的解释；用代码仓库作正例，它会偏好程序语法和注释。DCLM 把语料池、训练预算与评测协议固定下来，比较过滤方案；其中一个有效方案用 fastText 二元分类器，正例来自 OpenHermes 2.5 与 ELI5，负例来自随机抽取的 RefinedWeb，再按分数保留前 10% 文档。正例定义和门槛本身都是算法的一部分。

FineWeb-Edu 则把教育价值作为具体目标，用模型辅助标注训练分类器，选出更偏教育内容的子集。教育类任务可能受益，代码补全、口语对话或新事件覆盖需要单独观察。把“质量”拆成语言通顺度、信息密度、目标能力匹配和来源覆盖，通常比一个总分更容易解释取舍。

筛选后可以统计每域的 token 份额和重复曝光。若域 \(i\) 有 \(U_i\) 个唯一 token，训练总预算为 \(D\)，分配比例为 \(\alpha_i\)，平均曝光轮数约为：

$$\htmlData{symbol=exposure}{E_i}=\frac{D\alpha_i}{U_i}.$$

例如数学语料剩 2B tokens，100B 的训练中安排 10%，平均读 5 轮。进一步提高该域质量门槛，会减少 \(U_i\)，同时提高重复程度。做过滤比较时应同时报告唯一 token 量、总消费 token 量和每域曝光轮数，这样才看得见质量提升与重复训练的共同作用。

在十亿文档上实现与评估

MinHash 的关键资源首先是签名与排序。若有一亿篇文档，每篇 112 个 64-bit 哈希值，仅签名就有 \(10^8\times112\times8=89.6\) GB，另有文档 ID、桶索引与排序缓冲。Datatrove 将这条流程拆成签名生成、桶内匹配、聚类、按删除清单重读过滤几个阶段。哈希值可分桶写盘并排序归并，避免把所有文档对放进内存。

阶段边界也形成可复现性约定：同一篇文档的稳定 ID、输入顺序、哈希种子和代表优先级必须固定。用分片号与片内序号定位文档时，最终重读需要复现相同分片和枚举规则。一个有用的诊断是把同一小语料分别分成 1、2、4 个 shard，比较最终保留的稳定 ID；差异通常能定位到跨分片匹配或 tie-break 规则，而不是训练随机性。

语义去重则额外付出编码成本。十亿个 768 维 FP16 向量约占 1.536 TB；加载整簇相似矩阵还会叠加平方级内存。先缓存向量，再记录簇大小分布、最大簇和跨簇召回，能决定资源该用于编码吞吐、索引、还是分块点积。更换 embedding 模型时，需要重新抽样检查相似对，因为距离门槛也随表示空间改变。

评测集污染需要单独处理。固定验证集后，在训练语料中查找题干、答案和长重叠片段，并沿来源、时间和近似簇检查拆分。只删除整篇完全相同的文档，会留下网页中嵌入的题目和改写版本。匹配策略应保留命中证据，人工检查短通用句造成的误删，再报告污染处理前后指标。验证集继续保持独立，才能评估模型对未见内容的泛化。

最后做一个预算一致的对照：固定架构、tokenizer、上下文长度、packing 规则、训练 token 数、学习率计划和随机种子集合，比较原始抽样、词面去重、语义去重、质量过滤，以及组合方案。把验证结果按域展开，并报告数据处理成本。一个过滤器提高总均分却损伤代码或小语种时，下一步就有明确选择：调整正例、设置分域门槛，或在保留池上重学采样比例。

计算与实验设计

1. 签名预算与漏检

一亿篇文档，14 个 band，每个 8 个 64-bit 哈希值。签名占多少 GB？Jaccard 为 0.75 的文档对，至少一个 band 命中的概率是多少？若把 band 数加倍，两项怎样变化？

展开解答

十进制容量为 89.6 GB。命中概率为 \(1-(1-0.75^8)^{14}\approx0.772\)。增到 28 个 band，容量变为 179.2 GB，概率为约 0.948。增加 band 提高召回，也会让较低相似度的候选增多，需要一起核算桶匹配和候选处理成本。

2. 算清过滤后的分布

三域 token 份额为 [0.6,0.3,0.1]，保留率为 [0.2,0.8,0.9]，原库共 1T tokens。求各域剩余量及新份额。若训练 300B tokens，并给三个域各 1/3 配比，哪个域平均读取最多轮？

展开解答

各域剩余 [120B,240B,90B]，总量 450B，新份额 [26.67%,53.33%,20%]。显式均匀配比使各域消费 100B，曝光轮数依次为 [0.833,0.417,1.111]，第三域最多。过滤后均匀读取语料和均匀读取域会得到不同的训练输入。

3. 相似关系为什么会删掉第三篇

向量 A、B、C 依次相隔 20°，相似门槛为 0.9，顺序为 A、B、C。按 SemDeDup 的“所有更早向量”规则与“只比较已保留向量”规则，分别保留谁？

展开解答

相邻相似度 \(\cos20°\approx0.940\)，A 与 C 为 \(\cos40°\approx0.766\)。所有更早向量规则保留 A，B 因 A 被删，C 又因 B 被删。只比较已保留向量时，C 只需与 A 比较，因此保留 A、C。这个三点反例可以直接成为保留策略的单元检查。

4. 全局去重后验证损失变差，怎样定位

两次训练总 token 数相同，全局去重比逐快照去重差。设计三个可区分原因的对照，并说明各自证据。

展开解答

第一，固定全局代表集合，按原跨快照频次重新加权；若恢复性能，重复频次改变采样是主要因素。第二，固定每簇曝光总量，分别取最新、最高质量和随机代表；差异反映代表选择。第三，固定域份额和曝光轮数，比较全局独有部分与重复簇代表的分域验证结果，检查全局去重是否提高了低质量独有内容的份额。所有对照使用同一训练计划，并报告多个种子的差异。

可复现的小语料实验

下载实验 lab.py，运行 python3 lab.py --seed 7 --trials 30000。它只依赖 NumPy：用真实字符串构造 n-gram 集合，检查精确重复与近似匹配；通过随机排列实验验证 MinHash 碰撞概率；独立模拟 14×8 band 的命中；重现三向量相似链，并计算过滤后的份额与容量。

运行结果应显示 MinHash 经验碰撞率接近精确 Jaccard，LSH 命中约 77.2%，两种语义保留规则分别返回 [A] 与 [A,C]，最后所有断言通过。把语义门槛改为 --semantic-threshold 0.95，三个向量都会保留。把词级 n-gram 从 3 改为 5，观察短文本编辑怎样改变相似度；这能帮助选择候选策略，真实质量收益仍通过固定预算训练测量。
