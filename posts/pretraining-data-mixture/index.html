数据配比怎样学出来：DoReMi、DoGE 与 RegMix

交互2026-10-22

手头有 100B tokens 的训练预算，网页、代码和数学该各分多少？直接按语料库存比例抽样，体量最大的网页会吃掉绝大部分步数；硬按三个域均分，体量小的数学库又会被翻来覆去读上几十轮；如果凭直觉拉高代码比例，共享参数也会跟着偏移，连带影响其他域的效果。配比这件事归根结底要回答两个问题：我们希望模型在哪类任务上变强，以及在当前训练状态下，哪种数据最能把它往那个方向推。

现在主流的自动配比方法大致分三条路：

  • DoReMi：先训一个参考模型当标尺，看每个域还有多少“能学但还没学会”的空间；
  • DoGE：拿域梯度和目标梯度做内积，直接估算多练某个域一步能帮目标任务降多少 loss；
  • RegMix：干脆训几百个便宜的小模型，把“配比 → 验证 loss”的曲面拟合出来，再从里面挑最优点。

下面逐一拆开它们的推导、核心假设，以及落进真实训练器时最容易踩的工程坑。

先约定训练目标与计量单位

把语料分成 \(K\) 个域，给每个域分配 token 采样概率 \(\alpha_i\)（满足 \(\alpha_i\ge 0\) 且 \(\sum_i\alpha_i=1\)）。记模型参数为 \(\theta\)，域 \(i\) 在有效 token 上的平均负对数似然为 \(L_i(\theta)\)（单位 nat/token），训练时优化的加权损失就是：

$$L_{\mathrm{train}}(\theta,\htmlData{symbol=alpha}{\alpha})=\sum_{i=1}^{K}\alpha_i L_i(\theta).$$

有三个计量口径必须先对齐，不然配比数字根本没法跨实验比较。第一，算 \(L_i(\theta)\) 要先把有效 token 的损失加起来再除以有效 token 数，padding 和被 mask 的位置都不能算进分母。第二，采样最好先按 \(\alpha_i\) 选域，再从该域切定长 token block；如果按原始文档抽样，长文档会悄悄吃掉更多 token，实际配比就会偏离计划值。第三，一旦换了 tokenizer，同一批语料切出来的 token 总量和每 token 的 loss 尺度都会跟着变，老配比不能直接照搬。

除了训练配比，评估目标还可以另设一套域权重 \(v_i\)，写成 \(L_{\mathrm{target}}=\sum_i v_i L_i^{\mathrm{val}}\)：各域同等重要就取均匀 \(v_i\)，想贴合线上流量就按请求分布设 \(v_i\)。两者的分工很清楚——训练配比 \(\alpha\) 是我们要调的旋钮，目标权重 \(v\) 是用来打分的尺子。先把 \(v\) 钉死再反过来学 \(\alpha\)，才不会挑着挑着把评价标准一起挪动了。

DoReMi：相对参考模型的学习空间

网页域的平均 loss 是 4.8，代码只有 2.4。如果只盯着最高 loss 砸预算，算力几乎全会流向网页。问题在于，loss 高不一定说明还有得学——网页里塞满了哈希串、URL 和随机 ID，换谁来都猜不准。想要把“固有噪声”和“还没学会的规律”分开，DoReMi 的做法很直白：先用初始配比训一个小参考模型，再把它冻住，拿它当标尺。

记参考模型在域 \(i\) 的平均 token 损失为 \(L_i^{\mathrm{ref}}\)，正在训练的 proxy 小模型损失为 \(L_i(\theta)\)。DoReMi 求解的是一个带参考基线的 Group DRO 极小极大问题：

$$\min_\theta\max_{\alpha\in\Delta^K}\sum_i\alpha_i\big[L_i(\theta)-L_i^{\mathrm{ref}}\big].$$

其中 \(\Delta^K\) 是所有非负且和为 1 的权重单纯形。两个 loss 一相减，固有噪声在两边差不多高，正好抵消掉；反过来，参考模型能压得很低、proxy 却还落后的地方，差值（excess loss）就会冒出来。内层 \(\max\) 把权重推向 excess loss 最高的域，外层再让 proxy 专门补课。当然，这把尺子本身有多准，也直接取决于参考模型的容量、初始配比和训练时长。

真正落地更新权重时，DoReMi 并不是直接拿域均值相减，而是先逐 token 截断到非负，再按域求平均。设域 \(i\) 在当前 batch 中有 \(n_i\) 个有效 token，第 \(j\) 个 token 的 proxy 与参考损失分别是 \(\ell_{ij}\) 和 \(\ell_{ij}^{\mathrm{ref}}\)，域打分为：

$$\htmlData{symbol=excess}{\lambda_i}=\frac{1}{n_i}\sum_{j=1}^{n_i}\max(\ell_{ij}-\ell_{ij}^{\mathrm{ref}},0).$$

为什么要先截断再平均？看个简单例子：某域两个 token 的差值分别是 \(+1\) 和 \(-1\)，逐 token 截断后均分是 \(0.5\)，说明还有位置没追上参考模型；要是先平均再截断，正负一抵消就成了 \(0\)，这个域会被误判成“已经学透”。

拿到域打分后，做一次指数权重更新并归一化，再混入少量均匀分布保底：

$$\tilde\alpha_i=\frac{\alpha_i\exp(\eta_\alpha\lambda_i)}{\sum_j\alpha_j\exp(\eta_\alpha\lambda_j)},\qquad \alpha_i^{\mathrm{new}}=(1-c)\tilde\alpha_i+\frac{c}{K}.$$

这里 \(\eta_\alpha\) 控制每步调权的幅度，\(c\) 给出每个域的探索下限（原论文取 \(\eta_\alpha=1,\; c=10^{-3}\)）。这个保底不只是为了防权重彻底归零——只有每轮都给各域留一点采样机会，曾经被降权的域才会被重新观测、有机会拿回权重。写代码时建议直接在对数域用 log-sum-exp 做归一化，免得 \(\eta_\alpha\lambda_i\) 偏大时指数溢出。

权重更新完，再用新配比去训 proxy 参数 \(\theta\)。这里有一个很容易写错的细节：参考模型是冻结的，所以未截断的 excess loss 对 \(\theta\) 求梯度，和直接对加权 NLL 求梯度完全一样；正数截断只用于域打分 \(\lambda_i\)，千万别套到模型反向传播的 loss 上。否则那些已经比参考模型学得更好的 token 会直接梯度归零，proxy 反而停在参考模型的水平上不再进步。

随着 proxy 越训越强，\(\alpha^{(t)}\) 也会一路变化：最后一步的权重只反映训练末期的短板，而全程轨迹平均 \(\bar\alpha=\frac{1}{T}\sum_{t=1}^{T}\alpha^{(t)}\) 才概括了从头学到尾的整体需求。DoReMi 最终把 \(\bar\alpha\) 固定下来，拿去从头训练大模型（原论文就是用 280M proxy 跑出来的平均配比去训 8B 模型）。

DoGE：一次更新能帮助谁

DoReMi 盯着每个域自己的差距，但一个域本身还有提升空间，不见得就能帮到我们真正关心的目标任务。DoGE 换了个问法，直接把配比选择写成双层优化：内层按配比 \(\alpha\) 训模型，外层挑能让目标损失最低的 \(\alpha\)。每试一组配比都完整训一遍太贵了，所以 DoGE 先退一步，只估算往前迈一小步时目标 loss 会怎么变。

在当前参数 \(\theta\) 处，记域 \(i\) 的梯度为 \(g_i=\nabla_\theta L_i(\theta)\)，目标梯度为 \(g_{\mathrm{tar}}=\nabla_\theta L_{\mathrm{target}}(\theta)\)。按步长 \(\eta_\theta\) 做一次加权梯度下降，新参数是：

$$\theta'=\theta-\eta_\theta\sum_i\alpha_i g_i.$$

把目标损失在 \(\theta\) 附近做一阶泰勒展开，就能看出每个域在这一步里出了多少力：

$$L_{\mathrm{target}}(\theta')\approx L_{\mathrm{target}}(\theta) -\eta_\theta\sum_i\alpha_i\underbrace{g_{\mathrm{tar}}^\top g_i}_{\htmlData{symbol=alignment}{W_i}}.$$

内积 \(W_i = g_{\mathrm{tar}}^\top g_i\) 的几何含义很直白：域梯度和目标梯度同向（\(W_i>0\)），沿该域负梯度更新就能拉低目标 loss；反向（\(W_i\lt 0\)）反而会拖后腿。注意这里用的是内积而不是余弦相似度，梯度模长也被保留了下来——一个梯度几乎为零的域，就算方向完全一致，这一步也推不动参数。

如果直接把全部权重押给 \(W_i\) 最大的那个域，配比每步都会剧烈抖动。DoGE 因此在单纯形上加了一项 KL 散度正则（强度为 \(\mu\)）来做熵镜像更新，既朝预测收益高的方向挪，又保持配比连续：

$$\alpha^{\mathrm{new}}=\arg\min_{\alpha\in\Delta^K} \left[-\eta_\theta\sum_i\alpha_i W_i+\mu\,\mathrm{KL}(\alpha\Vert\alpha^{\mathrm{old}})\right] \implies \alpha_i^{\mathrm{new}}\propto\alpha_i^{\mathrm{old}}\exp\!\left(\frac{\eta_\theta W_i}{\mu}\right).$$

如果不想押注某个特定下游任务，而是希望所有域整体变好（universal 设置），就把目标设为全部域的损失之和，此时 \(g_{\mathrm{tar}}=\sum_j g_j\)（改成平均值只是所有得分整体缩小 \(K\) 倍，跟着调 \(\mu\) 就完全等价），对齐分数自然拆成两项：

$$W_i=\|g_i\|^2+\sum_{j\ne i}g_j^\top g_i.$$

第一项看这个域自己还有多大梯度可降，第二项看它能不能顺带拉低其他域的 loss。如果是冲着特定的域外目标去的，直接拿目标数据抽 batch 算 \(g_{\mathrm{tar}}\) 即可——前提是目标 batch 足够稳，别让梯度方向跟着采样噪声乱晃。

在上面的交互图里，负号代表目标 loss 下降。把步长 \(\eta_\theta\) 慢慢拉大就能看到，一阶预测还在往下降，二阶曲率项却已经反超，最后把实际 loss 推高了。严格来说，只要目标函数 Hessian 沿更新路径的谱范数不超过 \(H\)，一阶展开的误差上界就是 \(\frac{1}{2}H\eta_\theta^2\big\|\sum_i\alpha_i g_i\big\|^2\)。工程上正好拿它做体检：固定当前参数和 batch，挑几个小步长做可回滚的试更新，拿实测的 loss 变化去对点积预测；只要偏差按步长平方迅速放大，就说明当前步长下局部线性近似已经靠不住了。

上面的推导用的是朴素 SGD，而真实训练几乎都在跑 Adam 这类带预条件的优化器。把当前步的预条件矩阵记作 \(P\)，实际更新方向其实是 \(-P g_i\)，对应的一阶帮助也就变成了 \(g_{\mathrm{tar}}^\top P g_i\)。直接拿原始梯度点积当代理信号通常还能凑合用，但一旦换了优化器、开了梯度裁剪，或者把各域梯度归一化改成 cosine 相似度（丢掉了模长），代理信号和真实下降幅度之间就可能脱节，最好先在小 batch 上对照实测结果确认一遍。

和 DoReMi 一样，DoGE 也是在 proxy 训练全程记录 \(\alpha^{(t)}\)，跑完后对轨迹取平均，再拿这份固定配比从头去训大模型。

RegMix：用小模型拟合配比曲面

DoGE 看的是当前这一步的局部斜率，看不到完整训练里的长期效应——比如先学什么后学什么、域之间怎么抢容量、小语料反复读几轮后会不会过拟合。RegMix 干脆绕开梯度估计，直接把配比当黑盒超参数来做实验设计：挑 \(M\) 组不同的固定配比，各训一个极便宜的 proxy 小模型，记下训练结束后的目标验证损失 \(y_m\)，然后拿这些观测点拟出一个回归模型 \(f_\phi\)，去预测更大候选集里的配比效果。

记第 \(m\) 次试验的配比为 \(\alpha^{(m)}\)，拟合回归器与搜索最优候选可以写成两步：

$$\phi^*=\arg\min_\phi\sum_{m=1}^{M}\big[f_\phi(\alpha^{(m)})-y_m\big]^2, \qquad \alpha^*=\arg\min_{\alpha\in\mathcal A}f_{\phi^*}(\alpha).$$

这里 \(\mathcal A\) 是可以快速枚举的大规模候选配比集合。实际采点时，RegMix 用 Dirichlet 分布把稀疏、极端和相对均匀的配比都覆盖到，再对比线性回归与 LightGBM 这类非线性模型。模型能不能表达域间交互非常关键：配比受 \(\sum_i\alpha_i=1\) 约束，把代码从 10% 提到 20%，就必须从别的域里扣出 10%——扣网页和扣数学完全是两回事。线性模型只能给每个域一个固定斜率，而二次项（比如 \(\alpha_1\alpha_2\)）或树模型才能刻画“谁和谁混在一起更合算”。也正因为存在加和为 1 的共线性，解读回归系数时不能孤立看单个权重，必须指明被替换掉的是哪个域。

RegMix 真正押注的，并不是小模型预测出的绝对 loss 有多准——换到大模型上，绝对 loss 肯定整体往下掉——而是相对排序跨规模保持稳定：在小模型上排前几名的配比，挪到大模型上大概率还是好配比。原论文用 512 个 1M（非 embedding）参数的小模型、每个训 1B tokens，就把更大模型的配比排序预测得相当准。

真落到工程里，至少要做两层校验：先留出一批没进训练集的配比，用 Spearman 相关检查回归器本身有没有过拟合；再从预测结果里挑出排头、居中、垫底的几组，拿到中等规模模型上实训复验，确认前几名的差距大于随机种子波动。如果小模型选出来的第一名在中模型上被稳稳反超，就别再往同尺寸里狂加 proxy 了——那只会把一个已经偏离目标的代理曲面拟合得更精确。

搜索空间 \(\mathcal A\) 里还得把语料库存上限写进去。假设目标训练总预算是 \(D\)，域 \(i\) 的唯一 token 库存是 \(U_i\)，最多允许重复读 \(e_i^{\max}\) 轮，就必须加上硬约束：

$$D\alpha_i\le e_i^{\max}U_i.$$

不然很容易掉进一个坑：体量小的数学域在短 proxy 里连一轮都没读完，显得收益极高；照搬到长训练里却被翻来覆去读了二十轮，过拟合直接把排名颠倒过来。尽量让 proxy 的重复曝光轮数贴近真实训练，跨预算迁移才站得住脚。

配比进入训练器后发生什么

公式推完只是起点，把动态配比塞进分布式训练器里，最容易出岔子的往往是几个不起眼的工程细节。头一个坑是跨卡 loss 归约。假设 rank 0 上域 A 有 100 个有效 token、均值 loss 是 1，rank 1 上只有 10 个有效 token、均值 loss 是 3。直接拿两张卡的均值再求平均，算出来是 2；而真正的全局 token 均值其实是 \((100\times 1+10\times 3)/110\approx 1.182\)。差出这么多，配比算法会误以为域 A 很难，猛给它加权。正确做法只有一个：按域分别 all-reduce 损失总和与有效 token 数，汇总完再做除法。

第二个坑藏在梯度累积里（DoReMi 官方实现专门提醒过这一点）。如果一个 optimizer step 拆成了好几个 microbatch，而你在累积中途就更新了 \(\alpha\)，那前面几个 microbatch 用的是旧权重，最后一个用的是新权重，一次参数更新里混进了两套配比。稳妥的做法是在累积窗口开头把 \(\alpha\) 冻住，整个窗口跑完后再汇总打分、更新下一窗口的权重；如果非要让当前步立刻用上刚算出来的新权重，就只能按域分开存梯度或者多做一次反向，拿显存或算力去换。

想知道自己有没有写串，最省事的单元测试是固定数据顺序，把单个大 batch 拆成几个 microbatch，直接比对参数更新量和 \(\alpha\) 轨迹。只要有效 token 计数、权重版本和 loss scaling 全对齐，两条路径应该只差浮点归约误差（拿 FP64 当基线就能把浮点噪声剥出来），比盯着最终 loss 曲线排查快得多。

第三个坑属于 DoGE：显存要扛住逐域梯度。模型参数量为 \(P\)，同时把 \(K\) 个域的 FP32 梯度留在显存里就要吃掉 \(4KP\) 字节——哪怕只是 280M 参数、8 个域，光这一项就是 8.96 GB。省显存常见有两种折中：一种是先算出目标梯度，再逐个域算完内积就立刻释放梯度，代价是要额外安排加权梯度的累积或再跑一遍 backward；另一种是只抽一部分参数块来估算内积，省事但会改变代理信号。动手前先挑几个固定 batch，比一下“抽块近似”和“全参数梯度”给出的域排序是不是一致，再决定这笔账划不划算。

相比之下，RegMix 的算力全花在几百个互相独立的短训练上，天然好并行。按 Transformer 经典的 \(6ND\) 粗算一笔账：512 个 1M 参数、各训 1B tokens 的 proxy 合计约 \(3.07\times 10^{18}\) FLOPs；一个 1B 参数、25B tokens 的目标模型约 \(1.5\times 10^{20}\) FLOPs，proxy 只占大约 2.05%。不过这只是 FLOPs 账——小模型本身 GPU 利用率偏低，再加上词表头开销、作业调度和后续候选复验，实际墙钟成本会比 2% 高出一截。

怎样选择方法并验证迁移

方法反馈信号核心假设优先做的诊断
DoReMi相对冻结参考的正 excess参考模型能标出可学习空间逐 token 截断顺序；参考配比敏感性
DoGE域梯度与目标梯度内积目标 batch 稳定；局部一阶展开有效点积预测 vs. 试更新实测 loss 变化
RegMix多次 proxy 训练的目标 loss回归不欠拟合；跨规模排序稳定未见配比留出集与中等规模复验

不管选哪条路线，配比落到采样器之后，训练日志里至少要盯紧四个数：计划配比、实际吃进去的有效 token 占比、各域唯一 token 库存和实际重复轮数。对比基线也别省——在相同 token 预算下，拉出自然库存比例、均匀配比和人工经验配比一起跑，而且看结果时要把目标 loss 按域拆开，确认平均分上涨是全面进步，而不是某一个强势域拉高了均值。另外，挑配比用的验证集和最终验收的评测集必须分开，不然筛得多了，验证集本身就成了隐形训练集。

最后一条工程铁律是配比必须跟着语料版本走。做一次去重，代码库存一缩水，同样的 \(\alpha\) 就会把重复曝光轮数拉高；换一套质量过滤规则，域内难度变了，excess loss 和梯度方向也跟着变。所以顺序不能反：先冻结数据筛选管线，再去学配比；语料一动，配比就得复验。至于总算力在模型尺寸和 token 数之间怎么切，接着可以看训练预算怎样分配。

计算与诊断

1. 逐 token 截断与指数更新

两域初始权重各 1/2，A 域两个有效 token 的 excess 分别为 [1, −1]，B 域为 [0.2, 0.2]。取步长 \(\eta_\alpha=1\)、保底系数 \(c=0\)，求新权重。如果改成先平均再截断，结果会怎样？

展开解答

逐 token 截断后两域得分是 [0.5, 0.2]，新权重 A 为 \(e^{0.5}/(e^{0.5}+e^{0.2})\approx 0.5744\)，B 为 0.4256。如果先平均再截断，得分变成 [0, 0.2]，A 跌到 0.4502，B 升到 0.5498——两种顺序连该给谁加权都反过来了。

2. 点积预测怎样被大步长推翻

目标梯度为 [1, 0]，两个域梯度分别是 [1, 1] 与 [−1, 2]，当前权重各占 1/2，目标 Hessian 为单位矩阵。求一阶预测和真实一步变化，并判断是否应该增大步长。

展开解答

两个域与目标的点积分别是 1 和 −1，加权梯度为 [0, 1.5]，与目标梯度正交，所以一阶预测为 0。但二次目标的真实变化是 \(\eta_\theta^2\times 1.5^2/2=1.125\eta_\theta^2\)，任意正步长都会把 loss 推高。这时候调步长没用，得先改配比把更新方向扳回有益侧，再按曲率挑步长。

3. 小模型的最佳比例能直接迁移吗

数学域有 2B 唯一 tokens，proxy 总预算 4B，测得最佳数学份额为 25%。目标训练预算 200B，最多希望数学读 4 轮。原配比在两个预算下分别读多少轮？目标训练里数学份额最高能给到多少？

展开解答

Proxy 消费 1B 数学 token，平均只读 0.5 轮；照搬到 200B 目标训练里会消费 50B，平均要读 25 轮。按 4 轮上限算，\(200\text{B}\cdot\alpha_{\mathrm{math}}\le 4\times 2\text{B}\)，数学份额最多只能给 4%。要么扩充数学库存、放宽重复上限，要么在满足约束的新空间里重新验证排序——光靠放大小模型，跨不过这道语料天花板。

4. 两个训练器为什么得到不同配比

同一模型和数据，一份实现每个 microbatch 更新权重，另一份每个 optimizer step 更新。怎么设计一个最小实验把差异定位出来？

展开解答

先把规模缩到最小：两个域、两个 microbatch，每步记下各域的有效 token 数、损失总和、token excess 和当前权重版本。第一步冻住模型参数，核对整步汇总的统计量和拼接成一个大 batch 算出来的是否一致；第二步冻住整步权重 \(\alpha\)，核对累积梯度和整批梯度是否一致——如果这两步都对得上，差异就锁死在权重更新时点上。最后恢复动态更新，把两个 microbatch 的顺序对调，只要结果跟着变，就能坐实混合权重版本的影响，再按显存预算决定用固定窗口还是分域存梯度。

一个能跑完的配比实验

下载 NumPy 实验，直接跑 python3 lab.py --seed 7（纯 NumPy，几秒就能在 CPU 上跑完）。脚本把前文的几个关键结论都做成了可复现的数值校验：DoReMi 的逐 token 截断顺序和指数更新权重比、分布式 token 归约偏差、DoGE 的一阶超梯度与二次目标精确步进，以及一组迷你 RegMix 回归——训练 80 个单参数二次任务的 proxy，用二次回归拟合配比到目标 loss 的映射，再在 200 组留出配比上测预测误差。

跑起来能看到两个很有意思的对照：DoGE 部分，一阶近似和真实超梯度的误差会严格跟着步长平方缩下去；RegMix 部分，回归器在同分布留出集上能精准到浮点精度（MSE 低于 \(10^{-24}\)），可一旦把目标位置从 0.4 挪到 1.2，原推荐配比马上就会在新目标上产生明显的损失差距——回归拟合得再准，也替你保证不了目标偏移后的迁移。你还可以把 --proxy-steps 40 改成 5，顺手看看缩短 proxy 训练步数会怎样把推荐配比拉偏。
