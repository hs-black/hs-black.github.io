数据配比怎样学出来：DoReMi、DoGE 与 RegMix

交互2026-10-22

100B tokens 的训练预算，网页、代码和数学各分多少？按库存比例抽样，最多的网页会占去大部分步数；三个域均分，小规模数学库可能被读很多轮。手动提高代码份额，还会改变共享参数怎样服务其他域。一个合理配比需要回答两个问题：希望模型在哪些任务上进步，哪类数据在当前训练状态下最能推动这种进步。

DoReMi 用参考模型估计每个域尚可学习的空间，DoGE 用梯度估计训练一个域对目标任务的帮助，RegMix 用许多小模型测量“配比到效果”的映射。这三条路线都能输出一组采样概率，但它们从不同的反馈信号出发，因此适用条件和调试方法也不同。

先约定训练目标与计量单位

把数据分为 \(K\) 个域，给每个域分配 token 概率 \(\alpha_i\)，满足 \(\alpha_i\ge0\) 且 \(\sum_i\alpha_i=1\)。模型参数为 \(\theta\)，域 \(i\) 的平均有效 token 负对数似然为 \(L_i(\theta)\)，单位是 nat/token。一次训练目标是：

$$L_{\mathrm{train}}(\theta,\htmlData{symbol=alpha}{\alpha})=\sum_{i=1}^{K}\alpha_iL_i(\theta).$$

平均有效 token 损失需要先累计损失之和，再除以有效 token 数；padding、被 mask 的位置不参与计数。采样时可以先选域，再从该域读取定长 token block；若按原始文档抽样，应额外处理长度差异。换 tokenizer 后，同一批文档在各域的 token 量和损失尺度都会变化，原配比需要重新测量。

评估目标可以另设域权重 \(v_i\)，写作 \(L_{\mathrm{target}}=\sum_i v_iL_i^{\mathrm{val}}\)。均匀 \(v_i\) 表示每个域同等重要，按用户请求分布设 \(v_i\) 表示服务某类实际负载。训练配比 \(\alpha\) 是可调整的输入；目标权重 \(v\) 定义好坏。固定目标后再学配比，才能避免在筛选候选时不断移动评价标准。

DoReMi：相对参考模型的学习空间

网页域平均损失 4.8，代码域 2.4，直接追逐最高 loss 会把很多预算给网页。可是高损失可能来自难以预测的随机标识符，也可能来自模型尚未学会的知识。DoReMi 先在一个初始配比上训练小参考模型，再冻结它，用它作为“这类数据已经可以学到什么程度”的比较点。

设参考模型在域 \(i\) 的 token 平均损失为 \(L_i^{\mathrm{ref}}\)，proxy 小模型的损失为 \(L_i(\theta)\)。理想的参考相对 Group DRO 目标是：

$$\min_\theta\max_{\alpha\in\Delta^K}\sum_i\alpha_i\big[L_i(\theta)-L_i^{\mathrm{ref}}\big].$$

\(\Delta^K\) 是所有非负且和为 1 的域权重集合。内层最大化会把权重给 excess loss 最高的域，外层训练 proxy 去补这个差距。参考模型在随机噪声上也会有高 loss，两者相减能削弱这种难度对配比的影响；参考模型擅长而 proxy 落后的部分则获得更多关注。参考训练的配比、容量和训练时长一起决定了这个比较点。

实际权重更新先在每个有效 token 上取正 excess，再按域平均。设域 \(i\) 在当前 batch 中有 \(n_i\) 个有效 token，第 \(j\) 个 token 的 proxy 与参考损失分别为 \(\ell_{ij}\)、\(\ell_{ij}^{\mathrm{ref}}\)，打分为：

$$\htmlData{symbol=excess}{\lambda_i}=\frac1{n_i}\sum_{j=1}^{n_i}\max(\ell_{ij}-\ell_{ij}^{\mathrm{ref}},0).$$

逐 token 截断会保留每个尚未追上的位置。两项 excess 为 [+1,−1] 时，得分是 0.5；先平均再截断会得到 0，因此操作顺序会改变采样策略。

随后做指数权重上升，归一化，再混入少量均匀权重：

$$\tilde\alpha_i=\frac{\alpha_i\exp(\eta_\alpha\lambda_i)}{\sum_j\alpha_j\exp(\eta_\alpha\lambda_j)},\qquad \alpha_i^{\mathrm{new}}=(1-c)\tilde\alpha_i+\frac cK.$$

这里 \(\eta_\alpha\) 控制配比更新幅度，\(c\) 控制每个域的探索下限；原实验使用 \(\eta_\alpha=1,c=10^{-3}\)。从 log 权重出发，用 log-sum-exp 归一化，可以让较大分数下的计算保持稳定。每轮都观测各域，才能让曾经降权的域获得新的打分。

Proxy 参数用更新后的域权重训练。参考模型固定，因此未截断 excess 目标对 \(\theta\) 的梯度就是加权 NLL 梯度。正 excess 负责域打分，proxy 的模型更新仍学习完整的加权域损失。实现时要保持这两条路径清楚，否则会把已经优于参考的 token 从训练梯度中一并丢掉。

训练期间的 \(\alpha^{(t)}\) 会随模型能力变化。DoReMi 输出轨迹平均 \(\bar\alpha=T^{-1}\sum_{t=1}^T\alpha^{(t)}\)，再从头训练大模型。最后一步权重只描述训练末期的短板；平均权重汇总了整个学习过程。原研究使用 280M proxy 为 8B 模型选配比，迁移收益应在目标架构、tokenizer 和训练长度上重新验证。

DoGE：一次更新能帮助谁

某个域自身还没学好，并不直接说明它最能帮助目标任务。DoGE 把问题写成双层优化：内层用配比 \(\alpha\) 训练模型，外层选择使目标损失最低的配比。完整训练过程很贵，于是先估计一次小更新的效果。

在当前参数 \(\theta\) 处，域梯度为 \(g_i=\nabla_\theta L_i(\theta)\)，目标梯度为 \(g_{\mathrm{tar}}=\nabla_\theta L_{\mathrm{target}}(\theta)\)。用步长 \(\eta_\theta\) 做一次加权梯度下降：

$$\theta'=\theta-\eta_\theta\sum_i\alpha_i g_i.$$

在 \(\theta\) 附近对目标损失做一阶展开，得到：

$$L_{\mathrm{target}}(\theta')\approx L_{\mathrm{target}}(\theta) -\eta_\theta\sum_i\alpha_i\underbrace{g_{\mathrm{tar}}^\top g_i}_{\htmlData{symbol=alignment}{W_i}}.$$

域梯度与目标梯度同向时，沿该域的负梯度更新会降低目标损失；反向时，一阶预测是升高。\(W_i\) 是点积，同时保留方向和长度。梯度很短的域即便方向完全一致，对这一步的影响也可能很小。

DoGE 在单纯形上用熵镜像更新，兼顾预测进步与保持配比连续。若 \(\mu\) 是 KL 正则的强度，更新写为：

$$\alpha^{\mathrm{new}}=\arg\min_{\alpha\in\Delta^K} \left[-\eta_\theta\sum_i\alpha_iW_i+\mu\,\mathrm{KL}(\alpha\Vert\alpha^{\mathrm{old}})\right],\qquad \alpha_i^{\mathrm{new}}\propto\alpha_i^{\mathrm{old}}\exp(\eta_\theta W_i/\mu).$$

在 universal 设置中，目标是所有域的损失之和，\(g_{\mathrm{tar}}=\sum_j g_j\)。若改用平均值，所有得分缩小 \(K\) 倍，可以相应调整 \(\mu\) 保持更新尺度。此时 \(W_i=\|g_i\|^2+\sum_{j\ne i}g_j^\top g_i\)，同时包含本域可学习程度和跨域帮助。指定域外目标时，则用目标域 batch 估计 \(g_{\mathrm{tar}}\)。目标数据足够稳定、能代表期望能力，是这个打分有意义的前提。

图中负号表示目标损失下降。步长增大后，二阶项可能抵消一阶收益。若目标 Hessian 沿更新线段的谱范数不超过 \(H\)，Taylor 余项的绝对值有上界 \(H\eta_\theta^2\|\sum_i\alpha_i g_i\|^2/2\)。这给出一个直接诊断：固定 batch 和当前参数，分别用几个小步长做可回滚的试更新，比较点积预测与实测目标 loss 差异；偏差随着步长平方增长，说明局部近似正在失效。

真实训练常用 Adam 一类预条件更新。若暂时把预条件矩阵 \(P\) 视为固定，更新方向是 \(-P g_i\)，相应的一阶帮助变成 \(g_{\mathrm{tar}}^\top P g_i\)。原始梯度点积仍可用作代理信号，但更换优化器、梯度裁剪或参数子集时，需要重新检查它和实测进步的相关性。把所有域梯度归一化后用 cosine，也会改变对梯度长度的处理。

DoGE 在 proxy 训练过程中记录配比轨迹，最后对各步权重取平均，再用得到的固定配比从头训练目标模型。迁移实验同时检验两件事：局部梯度信号能否找到有用的数据，以及这个学习过程总结出的配比能否帮助更大的模型。

RegMix：用小模型拟合配比曲面

局部梯度提供当前一步的反馈，而一次完整训练能包含早期到晚期的学习顺序、域间竞争和重复曝光。RegMix 的做法是训练多组便宜的 proxy，每组固定一种配比，记录训练结束后的目标验证损失，再拟合一个回归器预测其他配比。

第 \(m\) 次试验的配比为 \(\alpha^{(m)}\)，测得损失为 \(y_m\)，回归器为 \(f_\phi\)。平方误差拟合与候选搜索可以写成：

$$\phi^*=\arg\min_\phi\sum_{m=1}^{M}\big[f_\phi(\alpha^{(m)})-y_m\big]^2, \qquad \alpha^*=\arg\min_{\alpha\in\mathcal A}f_{\phi^*}(\alpha).$$

\(M\) 是实际训练的 proxy 数，\(\mathcal A\) 是可以快速枚举的大量候选配比。实际研究比较了线性回归和 LightGBM，并用 Dirichlet 分布覆盖稀疏、集中和较均匀的配比。回归器表达域间交互尤其重要：提高代码份额会同时降低其他域份额，某个域的边际收益依赖它与谁混合。

例如三域二次回归可包含 \(\alpha_1\alpha_2\) 项，表示两个域共同出现时的额外影响。由于 \(\sum_i\alpha_i=1\)，线性特征之间有约束；系数分析要说明哪个域被替换，以及使用的特征和正则。把代码份额从 10% 提到 20%，同时减少网页，与同时减少数学，是两个不同干预。

RegMix 的主要迁移假设是候选配比的相对排序在模型规模和 token 预算之间较稳定。大模型的绝对 loss 会下降，回归器在小模型上拟合出的 loss 数值也会失准，但好的配比仍可能排在前面。原实验用 512 个 1M 非 embedding 参数的模型、每个训练 1B tokens，预测更大模型的配比排序；在具体预算下观察到了较高的排序相关性。

实际使用时需要留出“未参与拟合的配比”，检查它们的预测排序；再挑选最好、居中、边缘几组，用中等规模模型验证跨规模排序。统计指标可以用 Spearman 相关，也要看前几名差距是否超过种子波动。若小模型最佳配比在中模型上被稳定反超，继续增加同规模回归样本可能只会更准确地拟合一个偏离目标的代理任务。

搜索空间还要表达语料供应约束。给定总预算 \(D\)、域唯一 token 量 \(U_i\)，若希望每域最多读取 \(e_i^{\max}\) 轮，可以加入 \(D\alpha_i\le e_i^{\max}U_i\)。低资源数学域在短 proxy 里可能只读一遍，迁移到长训练时却读二十遍，排名就可能改变。代理训练的曝光状态与目标训练接近，是提高排序可迁移性的一条具体办法。

配比进入训练器后发生什么

最常见的偏差之一来自分布式损失归约。一个 rank 上域 A 有 100 个有效 token、均值 loss 为 1；另一个有 10 个、均值为 3。直接平均两个 rank 的均值是 2，全局 token 均值却是 \((100\times1+10\times3)/110=1.182\)。配比算法会把前者当成域 A 更难，从而改变整个训练输入。正确统计是按域 all-reduce 损失之和与 token 数，再相除。

梯度累积也给动态权重加入时间尺度。DoReMi 官方实现说明了这一点：若一个 optimizer step 含多个 microbatch，较早 microbatch 的梯度可能按上一轮权重计算，最后一个按新权重计算。这样一次更新使用了混合的权重版本。可以在累积窗口开始时冻结 \(\alpha\)，窗口结束后统一汇总分数并更新下一窗口的权重；若希望整步使用刚计算的权重，则需保存分域梯度或重算，额外占用显存或算力。

验证办法是固定数据次序，把一个大 batch 改为若干 microbatch，对比参数更新和配比轨迹。有效 token 计数、权重版本与 loss scaling 全部一致时，两者应接近；剩下的浮点归约差异可以通过更高精度基线定量判断。这个实验比只看最终训练 loss 更快定位采样与优化器之间的约定。

DoGE 则需要逐域梯度。参数量为 \(P\)，同时保存 \(K\) 份 FP32 梯度需 \(4KP\) 字节；280M 参数、8 域就是 8.96 GB。可以先得到目标梯度，再逐域计算点积并释放梯度，或只选部分参数块估计帮助。前者需要安排加权模型梯度的累积或第二次 backward，后者减少开销但改变代理信号。对若干固定 batch，用完整梯度与参数块估计比较域排序，再决定近似是否划算。

RegMix 把计算放在多个独立训练上，容易并行，但总成本要计入所有 proxy、回归、候选复验与失败配置。用粗略的 Transformer 训练估算 \(6ND\)，512 个 1M 参数、1B tokens 的 proxy 约需 \(3.07\times10^{18}\) FLOPs；一个 1B 参数、25B tokens 的模型约需 \(1.5\times10^{20}\) FLOPs，比例约 2.05%。这里 \(N\) 的口径相同且忽略 embedding 等额外项；小模型的实际利用率、词表开销和作业启动会影响墙钟成本。

怎样选择方法并验证迁移

方法反馈信号主要约定优先做的诊断
DoReMi相对冻结参考的正 excess参考能刻画可学习差距逐 token 打分；参考配比敏感性
DoGE域梯度与目标梯度点积目标代表需求；局部步进可预测点积预测与试更新的 loss 变化
RegMix多次 proxy 训练的目标 loss回归泛化；跨规模排序稳定未见配比与中等规模复验

三者的结果最终都要落到采样器上：记录计划配比、实际消费的有效 token 份额、各域唯一 token 量与重复轮数。再与自然份额、均匀域份额和经验配比做固定预算比较。目标函数按域展开，能看见平均提升来自普遍进步还是某个强势域；同时保留与选择过程独立的最终评测，避免反复筛选候选把验证集变成新的训练信号。

数据清洗与配比也应一起版本化。一次去重减少代码库存，会提高同一 \(\alpha\) 下的曝光轮数；一次质量过滤改变域内难度，会改变 excess 和梯度。先冻结数据筛选管线，再学习配比；语料版本改变后复验，而模型与 token 预算的更大取舍可以接着看训练预算怎样分配。

计算与诊断

1. 逐 token 截断与指数更新

两域初始各 1/2，A 域两项 excess 为 [1,−1]，B 域为 [0.2,0.2]。取权重步长 1、平滑系数 0，求新权重。若先平均再截断，会怎样？

展开解答

逐 token 截断后得分为 [0.5,0.2]，新权重 A 为 \(e^{0.5}/(e^{0.5}+e^{0.2})\approx0.5744\)，B 为 0.4256。先平均后截断得 [0,0.2]，A 变成 0.4502，B 为 0.5498。两种操作连优先方向都不同。

2. 点积预测怎样被大步长推翻

目标梯度 [1,0]，两个域梯度为 [1,1] 与 [−1,2]，各占 1/2。目标 Hessian 为单位矩阵。求一阶预测和真实一步变化，并判断是否应该增大步长。

展开解答

两个域点积为 1 与 −1，加权梯度为 [0,1.5]，与目标梯度点积为 0。一阶预测为 0；二次目标的真实变化是 \(\eta_\theta^2\times1.5^2/2=1.125\eta_\theta^2\)，任意正步长都会升高损失。需要先调整配比使更新方向有益，再依据曲率选择步长。

3. 小模型的最佳比例能直接迁移吗

数学域有 2B 唯一 tokens，proxy 总预算 4B，最佳数学份额 25%。目标训练预算 200B，最多希望数学读 4 轮。原配比在两个预算下分别读多少轮？目标中的最大数学份额是多少？

展开解答

Proxy 消费 1B，平均 0.5 轮；目标消费 50B，平均 25 轮。曝光约束要求 \(200B\alpha_{math}\le4\times2B\)，故份额最多 4%。可以增加数学库存、改变曝光上限，或在满足约束的配比空间里重新验证排序；只缩放模型参数无法保持原实验条件。

4. 两个训练器为什么得到不同配比

同一模型和数据，一份实现每个 microbatch 更新权重，另一份每个 optimizer step 更新。怎样构造能定位差异的实验？

展开解答

先用两个域、两个 microbatch，保存每个域的有效 token 数、损失之和、token excess 和权重版本。冻结模型参数，核对整步统计是否等于拼接 batch 的统计。再冻结整步权重，比较累积梯度与整批梯度；若一致，差异来自动态更新时点。最后恢复权重更新，把微批顺序对调，观察混合权重是否使结果变化，并按需要选择固定窗口或保存分域梯度的方案。

一个能跑完的配比实验

下载 NumPy 实验，运行 python3 lab.py --seed 7。实验检查指数更新的解析赔率、逐 token excess 的截断顺序、DoGE 的一阶超梯度和二次函数精确步进，再训练 80 个单参数二次任务 proxy，用二次回归拟合配比到目标损失，在未见配比上检验预测。

输出中一阶近似与真实超梯度的误差会随模型步长减小；回归在匹配任务的留出集上误差接近浮点精度。将目标位置从 0.4 移到 1.2 后，实验会显示原推荐与新最优配比的损失差距。这个可控任务把“回归准确”和“代理目标迁移”分开检查。可将 --proxy-steps 40 改为 5，观察训练预算改变怎样移动推荐；所有实验在 CPU 上完成。
