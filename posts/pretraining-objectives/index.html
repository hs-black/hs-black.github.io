一段文本提供什么监督：从去噪、FIM 到多 token 预测

交互2026-10-22

给模型一段代码：return a + b。你可以让它顺着看到 return a + 去猜 b，可以把中间的 a + 挖空、让它看着两头补齐，也可以在读到 return 时一口气预测后面好几个 token。数据还是那份数据，换一种组织方式，模型做的就是完全不同的题。

所有的预训练目标，追到底都在定两件事：预测时能看见什么，以及哪些位置要算 loss。这两件事一改，后面的序列长度、注意力计算量、词表显存乃至数据切块方式都会跟着动——下面我们顺着 T5 / UL2、FIM、MTP 一路拆开，把这笔账算清楚。

先把“读到什么”和“预测什么”分开

先统一一下记号：每个训练样本给出条件序列 \(c\) 和目标序列 \(y_1,\ldots,y_U\)。预测第 \(j\) 个目标时，模型看到条件 \(c\) 以及已经给出的目标前缀 \(y_{<j}\)，输出词表上的概率分布。再引入一个开关 \(m_j\in\{0,1\}\) 标记这一步算不算 loss，令有效监督总数 \(M=\sum_{j=1}^{U} m_j\)，整个样本的平均损失（单位 nats / 有效目标 token）就是：

\[ \htmlData{symbol=loss}{\mathcal L}=\frac{1}{\htmlData{symbol=count}{M}}\sum_{j=1}^{U}\htmlData{symbol=mask}{m_j}\big[-\log p_\theta(y_j\mid c,y_{<j})\big]. \]

训练时靠 teacher forcing 把真实的目标前缀整段送进去，一次前向就能并行算出所有位置的交叉熵；至于怎么防止模型偷看答案，全靠输入右移一位加上因果注意力掩码。

写代码时最容易混为一谈的，就是「能不能看见」和「算不算 loss」。拿最普通的 next-token prediction（NTP）来说，原文 \(x_1,\ldots,x_T\) 拆成输入 \(x_1,\ldots,x_{T-1}\) 和标签 \(x_2,\ldots,x_T\)，位置 \(t\) 只能看到 \(x_{\le t}\)。在实现上，attention_mask 管信息流，labels=-100 管交叉熵计不计分，两套开关各管各的：前缀只当条件、不参与训练时，把它的标签标成忽略，但注意力依然要放行；反过来遇到 padding，除了忽略标签，注意力里也得把它屏蔽掉，不能让有效 token 去关注它。

T5 与 UL2：把上下文安排在缺口两侧

只预测下一个词，模型永远只能看左侧前文。如果想让它同时利用前后文，最直接的办法就是把原文挖空，拆成已知上下文和待恢复片段。T5 的 span corruption 把每段连续挖掉的文本替换成一个带编号的哨兵符号（sentinel），目标序列再按顺序吐出这些编号和缺失内容，末尾补一个结束 sentinel 收尾。

举个例子，原文 A B C D E F G H 挖掉 B C 和 G 后，encoder 收到的是 A <s0> D E F <s1> H，decoder 要生成的目标是 <s0> B C <s1> G <s2>。encoder 走双向注意力，天然把每个缺口两侧拼成了共同条件；decoder 还是按顺序做因果生成，靠编号对齐正在填哪个坑，并通过 cross-attention 读取 encoder 的输出。

算一下序列长度的账：假设原文长 \(T\)，总共挖掉 \(K\) 个 token、拆成 \(S\) 个连续片段，算上 sentinel，encoder 输入和 decoder 目标的长度分别是：

\[T_{\rm enc}=T-K+S,\qquad U_{\rm dec}=K+S+1.\]

如果 encoder 或 decoder 末尾还加 EOS，对应长度再加 1。一眼就能看出连续挖空的好处——一整段只花一个 sentinel，比把同样多的 token 挖成零散单点省得多。按 T5 的经典配置（挖空约 15%、平均每段长 3 个 token），decoder 目标序列比原文短一大截，每层 decoder self-attention（\(O(U_{\rm dec}^2)\)）、cross-attention（\(O(T_{\rm enc}U_{\rm dec})\)）和对应线性层的开销都会跟着缩水，真正的大头留在 encoder 的双向注意力（\(O(T_{\rm enc}^2)\)）上。

UL2 更进一步，用模式标记把三种互补的去噪形态塞进同一个模型里一起训：

  • R-denoising：短而稀疏的缺口，主打局部语义补全；
  • X-denoising：更长的片段或更高的挖空比例，逼着模型组织大段生成；
  • S-denoising：把前缀当双向条件、续写后缀，对齐常见的自回归生成。

一旦把多种任务混在一起训，马上就会撞上一个隐蔽的坑：抽样比例不等于梯度里的实际权重。设任务 \(k\) 的抽样概率是 \(\pi_k\)，平均每个样本贡献 \(u_k\) 个有效目标 token；如果把所有 token 汇总在一起求平均，任务 \(k\) 长期分到的监督份额其实是：

\[w_k=\frac{\pi_k u_k}{\sum_r\pi_r u_r}.\]

代入具体数字感受一下：两种任务各抽一半，目标平均长度分别是 30 和 120，后者最终会吃掉 80% 的计分位置。如果真想让两种任务按指定比例平分权重，要么先在各任务内部按有效 token 求均值再加权相加，要么反推抽样概率去抵消目标长度差。不同数据域之间的配比问题可以接着看数据配比怎样学出来。

FIM：通过重排，让因果模型使用右侧条件

写代码补全时，光标前后往往都有现成的上下文，但纯从左到右的因果模型看不见光标右边。FIM（Fill-in-the-Middle）用了一个非常讨巧的办法，完全不改模型结构和因果 mask：把一段文本切成 prefix、middle、suffix 三段，按 prefix–suffix–middle 顺序重新拼起来，再插上分段标记。以 AB | CD | EF 为例，训练流就变成：

<PRE> A B <SUF> E F <MID> C D <EOS>

模型顺着这条重排后的序列读到 <MID> 时，前缀 AB 和后缀 EF 都已经在因果前缀里了，于是自然能看着两头预测 C，再带着真实的 C 预测 D。除了这种 PSM 排列，训练时通常还会混入 SPM（suffix–prefix–middle）变体，让模型熟悉不同的前后文顺序。

注意算 loss 的范围：原始 FIM 论文直接对重排后的整条序列做常规语言模型损失，prefix、suffix、middle 乃至特殊标记全部计分；如果只给 middle 计分，就退化成纯条件补全，常规续写拿到的监督会少一大块。所以看验证曲线时别只盯整条流的总 loss——把 middle 单独拆出来看，再对照实际代码补全的通过率，才不会被前两段拉低的总 loss 蒙过去。

工程落地时最容易踩的坑，是FIM 变换和定长切块的先后顺序。如果你先把一整篇长文档做了 FIM 重排，再按 4K token 硬切成一个个训练窗口，prefix 和 suffix 很可能落在前一块，middle 却被切到了下一块里。结果配置里写着「50% FIM」，实际送进模型的窗口里，真正同时看见完整前后文的 middle 没剩多少。排查这种 bug 最管用的土办法，就是随机抽几十个最终打包好的窗口还原打印出来，直接数一数有多少 middle token 在同一个窗口里同时看到了 prefix 和 suffix——顺手也记得把几个分段标记占掉的长度算进窗口预算。

MTP：让一个表示承担多个未来位置的监督

如果不想打乱文本顺序，另一条路是往更远的未来看。在多 token 预测（MTP）里，主干网络先把读到的前缀编成位置 \(t\) 的共享表示 \(z_t\in\mathbb R^d\)，再挂上 \(H\) 个独立的预测头，第 \(h\) 个头专门猜 \(h\) 步之后的 \(x_{t+h}\)。以 Gloeckle 等人的架构为例，每个距离配一个独立的因果 Transformer 分支 \(f_h\)，最后共享同一份词表投影矩阵 \(W_U\in\mathbb R^{V\times d}\)（\(V\) 是词表大小）：

\[ p_h(\cdot\mid x_{\le t})=\operatorname{softmax}\!\left(W_U f_h(z_{\le t})\right). \]

其中 \(h=1\) 就是标准的 next-token prediction；多出来的远期头相当于逼着共享主干别只顾着凑紧邻词的局部搭配，得提前把后面几步的语义装进当前表示里。推理时也很灵活：平时只跑第一个头就是普通续写，想提速时还可以把其余几个头接进投机解码里出草稿。

设 \(m_{t,h}=1\) 表示位置 \(t\) 往后第 \(h\) 步的标签存在、且仍在同一篇文档内，\(a_h\ge 0\) 是各头的权重。按全部有效预测对统一归一化，MTP 的损失写成：

\[ \mathcal L_{\rm MTP}=\frac{\sum_{t,h}a_h\htmlData{symbol=pairmask}{m_{t,h}}[-\log p_h(x_{t+h}\mid x_{\le t})]}{\sum_{t,h}a_hm_{t,h}}. \]

假设多篇长度分别为 \(L_b\) 的文档拼在同一个序列里，取等权 \(a_h=1\)、预测距离 \(h=1,\ldots,H\)，有效监督对的总数是 \(\sum_b\sum_{h=1}^H\max(L_b-h,0)\)——越靠文档末尾，能看的未来越少，最后 \(h\) 个位置对第 \(h\) 个头来说根本没有合法标签。写打包代码时千万别偷懒直接对整条序列做数组右移，否则前一篇文档的尾巴会拿后一篇的开头当标签；注意力侧的文档隔离和标签侧的边界检查必须同时成立。顺带一提，如果把上面的全局平均改成「每个头各自取平均再求和」，短文档里远期头的有效对数更少、分母更小，单个远期样本的梯度权重反而会被拉高。

多挂几个预测头，最先报警的往往不是算力，而是词表显存。假设一个 batch 有 \(N\) 个主干位置、\(H\) 个头、词表大小 \(V\)，把所有头的 logits 一次性全物化出来要占 \(NHV\) 个元素。代一组常见数字 \(N=8192,\ H=4,\ V=128000\) 算一下，单单一份 BF16 logits 就要吃掉约 7.8 GiB，还没算 softmax 中间量和反向梯度。

Gloeckle 等人的解法很干脆：先算完共享主干，再让 \(H\) 个头逐个跑前向和反向，把每个头传回的梯度直接累加到共享表示的梯度缓冲区上，最后统一往主干反传一次。每跑完一个头，它的 logits 和交叉熵激活就可以立刻释放，词表维度的显存峰值顺势从 \(O(NHV)\) 压回 \(O(NV)\)，代价只是在循环期间一直留着共享表示和它的累计梯度。

标签写对之后，还要把梯度的分母写对

无论是去噪比例波动、padding，还是 MTP 的文档截断，都会让每个 microbatch 里的有效标签数忽多忽少。拿个最简单的例子算一下：两个 microbatch 分别只有 2 个和 8 个有效标签，损失之和分别是 6 和 8。如果先各求均值再平均，得到 \((6/2+8/8)/2=2.0\)；而把全部 10 个标签合在一起算真正的 token 均值，结果是 \((6+8)/10=1.4\)。前一种写法不知不觉给第一个 microbatch 里的每个 token 塞了 4 倍权重。

想让梯度累积和「完整大 batch 一步」在数学上完全等价，分母就必须统一。设一个累积窗口内第 \(r\) 个 microbatch 的损失和是 \(S_r\)、有效标签数是 \(M_r\)，真正的全局目标是：

\[ \mathcal L=\frac{\sum_r S_r}{\sum_r M_r}. \]

每个 microbatch 反传时直接除以整个窗口的总计数 \(\sum_r M_r\)（而不是自己的 \(M_r\)），累加出的梯度才不会跑偏——这也是 Hugging Face 在修复梯度累积 bug 时揪出的同一个问题。到了多卡数据并行时再多走一步：如果 \(R\) 个 worker 之间对梯度取平均，就先 all-reduce 汇总出全局有效标签数 \(M_{\rm global}\)，每个 worker 反传 \(R S_{\rm local}/M_{\rm global}\)，等框架把 \(R\) 份梯度平均之后，分子上的 \(R\) 正好消掉，落回全局 token 均值（若框架外层还自带「除以累积步数」，记得一并抵消）。验收方法也很直接：关掉 dropout、锁死数据顺序，对比「完整 batch 一步」和「分批累积一步」的参数更新，两者在数值误差内必须完全重合。

目标预测时能看到的条件计分位置成本账里额外要记的项
NTP左侧前缀下一个 token原文位置与词表投影
T5 / UL2encoder 输入（缺口两侧或前缀）与目标前文恢复片段或后缀encoder / decoder 长度、任务目标占比
FIM重排后的前缀、后缀与已生成 middle整条重排后的流（原始 FIM）分段标记开销、有效补全窗口比例
MTP当前及更早的输入多个距离的未来标签独立头算力、有效预测对数、词表 logits 峰值

横向比较这些目标时，最怕拿「同样步数」或「同样 loss 数值」硬比——不同目标的序列长度、额外预测头和计分位置全不一样。靠谱的做法是把 tokenizer、数据、模型规模和评测集全锁死，分别看两条线：等 FLOPs 看算力花在刀刃上的效率，等原文 token 看数据压榨得够不够充分。训练预算怎么折算可接着看Scaling Laws 与训练预算，完整训练流程可对照SmolLM3 的训练过程。

顺着这个思路再往前迈一步，预测的基本单位甚至不必是单个 token。概念模型先把文本压成更短的句子或片段表示，再在表示空间里预测下一步，代价是编码与还原都要额外花算力，数字、专有名词这类精确细节也更容易在压缩时丢掉。

把目标落实成可检查的实现

练习一：去噪究竟节省了哪些位置？

一段 1000 token 的原文挖掉 150 个 token，构成 50 个 span。采用末尾 sentinel，另给 decoder 目标加上 EOS。求 encoder、decoder 长度，以及每层三类注意力的长度乘积。

推导与答案

Encoder 长度是 \(1000-150+50=900\)，decoder 目标长度是 \(150+50+1+1=202\)。每层三类注意力的位置对矩阵规模分别是：encoder self-attention \(900^2=810{,}000\)，decoder self-attention \(202^2=40{,}804\)，cross-attention \(900\times202=181{,}800\)（因为 decoder 是因果的，实际有效注意力位置只有全矩阵的一半左右，支持因果掩码的算子可以直接省掉另一半计算）。

练习二：MTP 与文档边界

两篇长度分别为 4 与 3 的文档打包在一起，预测未来 3 个 token。求有效监督数；若直接当成长度 7 的单篇文档处理，会多出多少项？

推导与答案

第一篇对 \(h=1,2,3\) 分别贡献 \(3+2+1=6\) 对，第二篇贡献 \(2+1+0=3\) 对，共 9 对。要是当成长度 7 的单篇文档直接右移，会算出 \(6+5+4=15\) 对——多出来的 6 对全跨过了文档边界，属于脏标签。实现时每个预测距离都要同时检查目标下标未越界且 doc_id 相同，再用真实的 9 对做全局均值的分母；如果文档末尾带 EOS，把 EOS 算进各篇长度即可。

练习三：相同任务概率为什么得到不同权重？

任务 A、B 各抽一半，平均目标长度分别是 20 和 80。想让两个任务的 token 平均损失最终各占一半，怎么改？

推导与答案

直接把所有 token 汇总求平均，A、B 的实际权重是 20% 和 80%。拉回 50% / 50% 有两条路：要么在各自任务内部按有效 token 归一化，再算 \(0.5\mathcal L_A+0.5\mathcal L_B\)；要么继续用全局 token 平均，但把抽样概率倒过来调成 A 占 0.8、B 占 0.2，凑出 \(0.8\times20=0.2\times80\)。两者的差别在于吞吐结构：调抽样概率会让长任务 B 每步见到的独立样本数少得多，batch 内的梯度方差也更大。

练习四：FIM 损失下降，补全却没有进步

FIM 训练流的平均交叉熵一直在降，但编辑器里的中间补全表现原地踏步。怎么用最小的对照实验定位原因？

分析与答案

第一步别急着重训，先把验证损失按 prefix、suffix、middle 三段拆开算——整体 loss 下降，很可能全靠前两段的常规续写拉动，middle 本身根本没降。接着统计最终训练窗口里，有多少 middle token 真的能同时看见完整的 prefix 和 suffix。如果比例偏低，在相同语料和 FLOPs 下做一组 A/B 对照，只切换「窗口内做 FIM」和「整篇文档做完 FIM 再切窗」，在相同的测试样本上对比 middle NLL 和固定采样预算下的补全通过率：条件完整率和补全指标一起抬升，说明就是 packing 顺序的问题；要是 middle NLL 明显降了但通过率还是不动，锅就不在预训练目标，转头查评测集构造、解码预算或编译／单测环境。
