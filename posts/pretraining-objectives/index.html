一段文本提供什么监督：从去噪、FIM 到多 token 预测

交互2026-10-22

给模型一段代码：return a + b。可以让它看到 return a + 后预测 b；也可以把 a + 挖掉，让它根据两边补齐；还可以在读到 return 时，同时预测后面的几个 token。同一份数据由此产生了不同的学习问题。

预训练目标的核心，是决定预测时可以看见什么，以及哪些预测会贡献梯度。这两个决定会进一步改变目标长度、注意力计算、词表投影和数据打包。把它们写清楚，才能判断一个新目标带来的收益来自更合适的监督、更大的计算量，还是评估条件发生了变化。

先把“读到什么”和“预测什么”分开

设一个训练样本提供条件序列 \(c\) 和目标序列 \(y_1,\ldots,y_U\)。模型在第 \(j\) 次预测时读取条件 \(c\) 与已经给定的目标前缀 \(y_{<j}\)，输出词表上的概率分布。令 \(m_j\in\{0,1\}\) 表示这一位置是否参与训练，单个样本的有效监督数为 \(M=\sum_jm_j\)：

\[ \htmlData{symbol=loss}{\mathcal L}=\frac{1}{\htmlData{symbol=count}{M}}\sum_{j=1}^{U}\htmlData{symbol=mask}{m_j}\big[-\log p_\theta(y_j\mid c,y_{<j})\big]. \]

这里使用自然对数，损失的单位是 nats／有效目标 token。Teacher forcing 把真实的目标前缀送入模型，一次前向即可并行计算各位置的交叉熵。目标 token 自己是否被藏好，由注意力可见性和输入右移共同保证。

普通 next-token prediction 把原文 \(x_1,\ldots,x_T\) 变成输入 \(x_1,\ldots,x_{T-1}\) 和标签 \(x_2,\ldots,x_T\)。位置 \(t\) 的隐藏状态只能依赖 \(x_{\le t}\)。实现时，attention_mask 决定信息流，labels=-100 之类的约定决定交叉熵是否计分。前缀只提供条件时，它的标签可以忽略，目标仍需要读取它；padding 的标签被忽略后，还要在注意力计算中正确处理 padding。

T5 与 UL2：把上下文安排在缺口两侧

预测下一个词只利用左侧前文。若希望模型学会联合解释前后文，可以把一段原文拆成已知部分与待恢复部分。T5 的 span corruption 将连续缺失片段替换为 sentinel：每个片段有自己的编号，目标依次给出这些编号及其内容，末尾再放一个结束 sentinel。

例如，原文 A B C D E F G H 挖掉 B C 与 G 后，encoder 输入是 A <s0> D E F <s1> H，目标是 <s0> B C <s1> G <s2>。编号让 decoder 知道正在填哪一个缺口；encoder 的双向注意力让缺口两侧成为共同条件。decoder 依旧按目标顺序做因果预测，并通过 cross-attention 读取 encoder 表示。

若原文有 \(T\) 个 token，删除 \(K\) 个，分成 \(S\) 段，则 encoder 长度与目标长度分别为：

\[T_{\rm enc}=T-K+S,\qquad U_{\rm dec}=K+S+1.\]

两个长度都计入 sentinel；在 encoder 输入或 decoder 目标末尾添加 EOS 时，对应长度再加一个位置。由此可见，连续挖掉一整段，比把同样数量的 token 挖成许多单点更节约特殊符号。T5 的经典配置使用约 15% 的腐坏比例与平均长度约 3 的 span，目标序列因此显著短于原文。实际开销还取决于 encoder／decoder 层数以及 cross-attention：每层的注意力项分别随 \(T_{\rm enc}^2\)、\(U_{\rm dec}^2\)、\(T_{\rm enc}U_{\rm dec}\) 增长，线性层则随各自序列长度增长。

UL2 把几种条件安排放进同一模型。R-denoising 使用较短、较稀疏的缺口；S-denoising 把前缀作为双向可读的条件，生成后缀；X-denoising 使用更长的片段或更高的腐坏比例，让模型承担更大范围的重建。模式标记告诉模型本次承担哪种任务。任务形态互补：短缺口偏向局部语义，长缺口要求组织较长输出，前缀任务直接训练顺序续写。

混合比例需要连同归一化方式一起说明。设任务 \(k\) 的抽样概率为 \(\pi_k\)，每个样本平均提供 \(u_k\) 个有效目标。若把所有目标 token 汇总后求平均，它的长期监督份额接近：

\[w_k=\frac{\pi_k u_k}{\sum_r\pi_r u_r}.\]

因此，等概率抽两种任务、目标平均长度分别为 30 和 120 时，后者贡献约 80% 的计分位置。若希望优化“每个任务等权”的目标，可以先对各任务的有效 token 求平均，再按指定任务权重组合。两种写法对应两种明确的训练目标；日志同时记录样本占比、目标占比与计算时间，配比才有可解释的含义。数据域之间的配比问题可接着看数据配比怎样学出来。

FIM：通过重排，让因果模型使用右侧条件

代码补全常常同时拥有光标前后的内容。FIM 将一段文本分成 prefix、middle、suffix，再按 prefix–suffix–middle 顺序拼接，并加入分段标记。以 AB | CD | EF 为例，训练流变成：

<PRE> A B <SUF> E F <MID> C D <EOS>

当因果模型走到 <MID> 时，前缀 AB 和后缀 EF 都已经出现，因此能据此生成 C。生成 D 时，它还看到了真实的 C。自然语言位置与模型中的序列位置由重排连接起来，因果 mask 沿重排后的顺序工作。FIM 也包含 suffix–prefix–middle 等变体，用不同排列扩展模型遇到的条件形式。

原始 FIM 训练在重排后的完整流上继续使用语言模型损失，包括 prefix、suffix、middle 及相应特殊符号。只给 middle 计分会形成另一个条件补全目标。评估时可以同时报告常规续写损失、middle 条件损失，以及实际代码补全成功率：前两者衡量概率拟合，后者检验给定前后文能否补出可执行的代码。

一个很实际的问题出现在FIM 变换与定长切块的先后顺序。先变换长文档，再每 4K token 切成独立上下文，可能把 prefix 与 suffix 留在前一块，把 middle 留在后一块。配置写着“50% FIM”，其中真正同时具备前后文的补全样本却少得多。有效 FIM 比例应该按最终送进模型的窗口统计：middle 的目标位置究竟有多少能读取所需的两个条件片段。

诊断时可以把文档 ID、三个片段的边界、切块位置一同打印出来，随机抽几十个最终窗口直接还原。对照实验固定原始语料、窗口长度与 token 预算，一组先切窗口再做 FIM，另一组先变换再切块；同时比较有效补全比例和相同测试集上的 infill 指标。选择切块策略时还要保留文档语义边界，并确保分段标记的额外长度被纳入窗口预算。

MTP：让一个表示承担多个未来位置的监督

另一条路线保持输入顺序，把监督延伸到更远的未来。位置 \(t\) 的共享表示 \(z_t\in\mathbb R^d\) 编码已读到的文本，第 \(h\) 个预测头负责 \(x_{t+h}\)。Gloeckle 等人的 MTP 架构给每个距离设置独立 Transformer head，再共享词表投影矩阵；远期预测也由当前前缀产生。

\[ p_h(\cdot\mid x_{\le t})=\operatorname{softmax}\!\left(W_U f_h(z_{\le t})\right),\qquad W_U\in\mathbb R^{V\times d}. \]

这里 \(V\) 是词表大小，\(f_h\) 是距离 \(h\) 的因果预测分支。第一个头承担通常的 next-token prediction，其他头给共享主干增加跨越多个位置的学习信号。若模型只依靠紧邻词之间的局部搭配，远期预测会迫使表示保留更有用的上下文。在推理时，第一个头可以独立执行标准续写，其他头也可以参与投机解码中的候选生成与验证。

设 \(m_{t,h}=1\) 表示距离 \(h\) 的标签存在且仍在同一文档；头权重为非负的 \(a_h\)。采用按有效预测对归一化的约定时：

\[ \mathcal L_{\rm MTP}=\frac{\sum_{t,h}a_h\htmlData{symbol=pairmask}{m_{t,h}}[-\log p_h(x_{t+h}\mid x_{\le t})]}{\sum_{t,h}a_hm_{t,h}}. \]

若有多个独立文档，长度分别为 \(L_b\)，预测距离为 \(h=1,\ldots,H\)，并取 \(a_h=1\)，监督对数是 \(\sum_b\sum_{h=1}^H\max(L_b-h,0)\)。越靠近文档末尾，存在的未来标签越少。把这些标签直接从打包后的数组右移，容易预测到下一篇文档；attention 的文档隔离与 label 的边界检查需要同时成立。先对每个头各自取平均再求和，还会改变短文档中远期头的相对权重，应当在目标定义中明确下来。

增加预测头还会改变显存。设一批有 \(N\) 个主干位置、\(H\) 个头、词表大小 \(V\)，一次物化全部 logits 需要 \(NHV\) 个元素。示例取 \(N=8192,H=4,V=128000\)，单份 BF16 logits 就约 7.8 GiB；softmax、梯度及其他激活还会继续占空间。

原始 MTP 的实现安排是先算共享主干，然后逐个头做前向与反向，把各头传回的梯度累加在主干表示上，再一次性向主干反传。头间可以及时释放词表 logits，峰值的词表维度项由 \(O(NHV)\) 降到 \(O(NV)\)。共享表示与累计梯度仍需保存。实际吞吐取决于头的计算、分块词表损失、通信和算子调度；测量时应把峰值显存、总训练 FLOPs 与每秒处理的原文 token 分开记录。

标签写对之后，还要把梯度的分母写对

长短样本、去噪比例以及 MTP 的文档边界都会改变每批有效标签数。假设两个 microbatch 分别有 2 与 8 个标签，损失和分别为 6 与 8。如果先各自求均值再平均，得到 \((3+1)/2=2\)；把十个标签放在一起求平均，结果是 \((6+8)/10=1.4\)。前一种写法给第一批每个 token 四倍的权重。

梯度累积需要实现同一个全局目标。一个累积窗口内，第 \(r\) 批损失和为 \(S_r\)，有效标签数为 \(M_r\)，目标是 \(\mathcal L=\sum_rS_r/\sum_rM_r\)。各批反传时使用这个窗口共同的分母，便能复现完整大 batch 的梯度。Hugging Face 的梯度累积分析给出了同样的 token 归一化问题；它会在混合任务、padding 与可变长度数据中反复出现。

扩展到 \(R\) 个采用梯度平均的数据并行 worker，先汇总全局计数 \(M_{\rm global}\)，每个 worker 反传 \(R S_{\rm local}/M_{\rm global}\)，后续平均才得到全局 token 均值的梯度。累积框架若还有额外的除以步数操作，要把它一起纳入这个等式。最直接的检查是固定 dropout 和数据顺序，比较“完整 batch 一步”与“分批累积一步”的参数更新。

把目标落实成可检查的实现

练习一：去噪究竟节省了哪些位置？

一段 1000 token 的原文删除 150 个 token，构成 50 个 span。采用末尾 sentinel，另给 decoder 目标添加 EOS。求 encoder、decoder 长度，以及每层三类注意力的长度乘积。

推导与答案

Encoder 长度是 \(1000-150+50=900\)，decoder 目标长度是 \(150+50+1+1=202\)。Encoder self-attention 的位置对上界为 \(900^2=810000\)，decoder self-attention 为 \(202^2=40804\)，cross-attention 为 \(900\times202=181800\)。因果 decoder 的有效位置对约为全矩阵的一半；具体 kernel 可以利用因果结构。总训练成本还包括层数、隐藏维度、FFN 与词表投影，因此可由这些长度继续推 FLOPs。

练习二：MTP 与文档边界

两篇长度分别为 4 与 3 的文档被打包在一起，预测未来 3 个 token。求有效监督数。若直接把它当成长度 7 的一篇文档，会多出多少项？

推导与答案

第一篇有 \(3+2+1=6\) 对，第二篇有 \(2+1+0=3\) 对，共 9 对。合并为单篇会得到 \(6+5+4=15\) 对，多出的 6 对跨越文档边界。实现时为每个预测距离同时检查目标下标与文档 ID；随后用这 9 对作为全局 token 均值的分母。若文档序列包含 EOS，则把 EOS 算进各篇长度，再按相同规则计数。

练习三：相同任务概率为什么得到不同权重？

任务 A、B 各抽一半，平均目标长度为 20、80。希望每个任务的 token 平均损失最终各占一半，可以怎样实现？

推导与答案

直接汇总 token 时，A、B 权重为 20%、80%。一种实现是每个任务内部按有效 token 归一化，再计算 \(0.5\mathcal L_A+0.5\mathcal L_B\)。另一种实现是在保持汇总 token 均值的条件下，把样本抽样概率改成 A 为 0.8、B 为 0.2，使 \(0.8\times20=0.2\times80\)。两者改变的数据覆盖与采样方差不同，实验需要同时记录每个任务见过多少独立样本。

练习四：FIM 损失下降，补全却没有进步

FIM 训练流的平均交叉熵下降，但编辑器中的中间补全表现持平。给出一个能区分原因的最小对照实验。

分析与答案

先将验证损失拆为 prefix、suffix、middle 三部分，并按有效 token 汇总；整体下降可能主要来自前两部分。接着统计最终训练窗口中 middle 可以读取完整两侧条件的比例。固定语料和 FLOPs，仅切换“窗口内变换”与“文档变换后切窗”，在相同 prefix / suffix 的测试样本上比较 middle NLL 和固定采样预算下的补全成功率。如果条件完整率与 middle 指标同时改善，就应调整 packing；如果 middle NLL 改善而成功率不变，则进一步检查测试难度、解码预算和编译／单元测试结果。

python lab.py

脚本先验证 span corruption 能重建原文，检查 FIM 的标签右移，再构造一个切块破坏完整 FIM 条件的反例。随后对长度 4、3 的两篇文档建立 MTP 标签：共享表示为 \([7,3]\)，三个线性预测头的权重为 \([3,3,5]\)，词表大小为 5。每个头的梯度按顺序累加，有限差分分别检查共享表示与头权重；完整 batch 与按文档拆分的梯度也必须一致。
