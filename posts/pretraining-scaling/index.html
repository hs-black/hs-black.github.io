训练预算怎样分配：Scaling Laws 与模型、数据的取舍

交互2026-10-22

同样一笔算力预算，可以拿去训一个 1B 模型、喂 80B token，也可以训一个 4B 模型、只喂 20B token。前一个练得充分，后一个容量更大，花掉的训练 FLOPs 却几乎一样——最后谁的验证 loss 更低？如果模型上线后还要跑一万亿推理 token，答案又会怎么变？

Scaling law 做的就是把这类取舍量化出来：先用便宜的小实验量出模型大小、数据量和验证 loss 之间的关系，再在砸大钱之前，把预算押在收益最高的方向上。从 Kaplan 的幂律、Chinchilla 的算力最优配比，到数据见底后的重复训练，再到 Beyond Chinchilla 把推理账单算进来，背后其实只有一条主线——不断往约束里加真实条件，看最优配置往哪边挪。

先把预算写成约束

记 \(\htmlData{symbol=params}{N}\) 为模型参数量，\(\htmlData{symbol=tokens}{D}\) 为训练实际处理的 token 总数。每个参数做一次乘加大约是 2 FLOPs，所以稠密 Transformer 每过一个 token，前向算约 \(2N\) FLOPs，反向大约是前向的两倍（\(4N\)），合起来就是预训练里最常用的一阶估算：

\[\htmlData{symbol=compute}{C}\approx 6\htmlData{symbol=params}{N}\htmlData{symbol=tokens}{D}.\]

这里 \(C\) 的单位是 FLOPs，\(D\) 按实际喂进模型的 token 累加——同一条数据读两遍就记两次账。这个 \(6ND\) 只覆盖了权重矩阵乘法，真到超长序列时，注意力的二次项开销得单独加上，或者等架构和重计算策略定下来后再按实际算子数校准（具体怎么从矩阵形状推出来，可以看训练计算与显存）。

质量这边，需要在同一套 tokenizer、同一份验证分布和一致的训练配方下比较最终验证集的平均交叉熵（单位 nats/token，越低越好），否则不同实验的数字根本没法放在一张图里。为了公式好看、系数好读，先取一组基准规模 \(N_0=10^9\) 参数、\(D_0=20\times10^9\) token，把模型和数据写成相对倍数：

\[\htmlData{symbol=norm-n}{n}=N/N_0,\qquad \htmlData{symbol=norm-d}{d}=D/D_0.\]

经典的参数化形式把验证 loss 拆成三部分：

\[\widehat L(n,d)=\htmlData{symbol=floor}{E}+\htmlData{symbol=model-a}{A}n^{-\htmlData{symbol=alpha}{\alpha}}+\htmlData{symbol=data-b}{B}d^{-\htmlData{symbol=beta}{\beta}}.\]

拆开看很直观：\(E\) 是模型和数据都趋于无穷时的渐近底噪；\(A n^{-\alpha}\) 是模型容量不够带来的额外 loss，参数翻倍它就缩成原来的 \(2^{-\alpha}\)；\(B d^{-\beta}\) 是数据见得还不够多、优化没走完留下的额外 loss，token 翻倍它就缩成 \(2^{-\beta}\)。其中 \(A,B\) 的单位也是 nats/token，\(\alpha,\beta\gt 0\) 无量纲。要注意的是，在有限规模的实验数据里，常数项 \(E\) 和衰减指数 \(\alpha,\beta\) 很容易互相代偿，所以别把拟合出来的 \(E\) 当成自然语言的真实熵，先把它当作预测公式里一个跟着外推范围走的拟合参数来看。

为了方便手算和复核，下文交互图统一用一组对称的教学系数：\(E=1.5\)、\(A=B=0.8\)、\(\alpha=\beta=0.3\)。

为什么会有一个最优模型规模

预算一旦锁死，扩大模型就必然要砍训练步数。把总计算量也按基准规模归一化成 \(\htmlData{symbol=norm-c}{c}=C/(6N_0D_0)\)，算力约束就简化成了 \(nd=c\)，也就是 \(d=c/n\)。代回预测公式：

\[\widehat L(n,c/n)=E+A n^{-\alpha}+B c^{-\beta}n^{\beta}.\]

随着 \(n\) 往右增大，模型项 \(A n^{-\alpha}\) 一路往下掉，数据项 \(B c^{-\beta}n^{\beta}\) 一路往上抬：模型太小，喂再多数据也卡在容量天花板上；模型太大，没跑几步就把算力烧光了，训练严重欠拟合。一降一升，中间必然夹出一个最低点。

这里对 \(\log n\) 求导最顺手。因为约束取对数是 \(\log n+\log d=\log c\)——参数量每涨 \(1\%\)，训练 token 就得缩水 \(1\%\)，按相对比例微调时的边际变化直接就是：

\[\frac{\partial\widehat L}{\partial\log n}=-\alpha A n^{-\alpha}+\beta B d^{-\beta}.\]

最优点上导数为零，意思是再挪一点预算去加参数省下的 loss，正好抵消少看数据多出来的 loss：

\[\alpha A n_*^{-\alpha}=\beta B d_*^{-\beta}.\]

沿 \(\log n\) 再求一次导得到 \(\alpha^2 A n^{-\alpha}+\beta^2 B d^{-\beta}\gt 0\)，说明曲线严格凸，这个极小点全局唯一。把 \(d_*=c/n_*\) 代进去整理，闭式解直接出来：

\[\boxed{n_*=\left(\frac{\alpha A}{\beta B}\,c^{\beta}\right)^{1/(\alpha+\beta)}},\qquad d_*=c/n_*.\]

看一眼预算 \(C\) 的指数分布很有意思：最优参数量按 \(C^{\beta/(\alpha+\beta)}\) 涨，最优数据量按 \(C^{\alpha/(\alpha+\beta)}\) 涨——哪一边的衰减指数小（loss 掉得慢），想压低它就得往那边倾斜更多新增预算。如果两边指数接近（\(\alpha\approx\beta\)），预算扩大四倍时，模型和数据就各自翻倍。拿前面这组教学系数算一下：\(c=4\) 对应总算力 \(4.8\times10^{20}\) FLOPs，最优点正好落在 2B 参数、40B token，预测 loss 是 2.7996。

顺便澄清一个常见误解：“每个参数配 20 个 token”并不是放之四海而皆准的常数，而是这次优化算出来的结果。一般情况下，最优比例会随预算按 \(D_*/N_*\propto C^{(\alpha-\beta)/(\alpha+\beta)}\) 漂移，只有在 \(\alpha\approx\beta\) 时才近似恒定。Chinchilla 的真正价值，是把“模型和数据大致同步放大”立成了基线；至于具体项目里该配 20 还是 200，等后面把数据上限和推理成本算进来，这个比例会被大幅拉偏。

怎样让拟合值得信任

五个参数的曲线很软，随便怎么都能把已有实验点贴得很平，难的是在还没砸钱的大规模区域依然猜得准。布实验点通常有两种套路：一种按参数量和 token 数铺成二维网格，方便把模型衰减和数据衰减拆开估计；另一种先定几档 FLOPs，每档里沿等算力线从“小模型长训”排到“大模型短训”，直接看低谷落在哪。不管选哪种，千万别只沿着一条固定 \(D/N\) 比例一路放大——模型和数据绑在一起涨，拟合根本分不清 loss 下降是谁的功劳。

记 \(L_i\) 为第 \(i\) 次实验的实测 loss，\(\widehat L_i\) 为预测值。实际拟合里常用的目标是在对数空间套一层 Huber 损失：

\[r_i=\log\widehat L_i-\log L_i,\qquad \min_{E,A,B,\alpha,\beta}\sum_i\htmlData{symbol=huber}{H_\delta}(r_i),\] \[H_\delta(r)=\begin{cases}r^2/2,&|r|\le\delta,\\ \delta(|r|-\delta/2),&|r|\gt\delta.\end{cases}\]

对数残差近似衡量相对误差；套上 Huber 之后，小残差按平方严惩，偶发跑飞的大残差在超过阈值 \(\delta\) 后改按线性惩罚，不至于一两条异常 run 把整条曲线拽歪。Chinchilla 就是拿这个目标配多组初始值跑数值优化的。不过拟合完别光盯着平均误差——如果大模型的残差清一色偏正或偏负，哪怕整体误差很漂亮，往更大规模外推时也会系统性跑偏。

一个会改变结论的工程细节：训练终点与学习率终点

假设一条 100B token 的训练全程用 cosine decay。如果你直接拎出它在 20B 处的中间 checkpoint，拿去和一条专门在 20B 跑完退火的模型比，其实是在拿“半山腰”跟“终点线”比——前者学习率还高高挂着，根本没收敛完。把这种中间点当成“20B 预算下的最优 loss”塞进拟合，学习率 schedule 的拖累就会被错算成数据效率差。

验证这件事的对照实验非常直接：固定初始化、数据顺序和 20B 终点，唯一变量是学习率计划的长度——一组在 20B 退完，一组仍按 100B 节奏衰减，对比末尾验证 loss 就能立刻看出差距。所以用来拟合的每条实验，都得在各自预算终点走完完整退火；想省算力，可以共享前面的稳态训练前缀，只在各自目标 token 数前分叉跑完自己的退火尾段（别忘了把分叉开销记进账里）。至于模型变宽以后最优学习率本身怎么对齐，那是μP 与超参数迁移要解决的问题。

留出的应该是将来要去的区域

从同一条训练曲线里随机扣几个 checkpoint 当验证集，几乎测不出外推能力——左右紧挨着的相邻步高度相关，随便插值都能蒙对。真正靠谱的验证，是把最大的模型、最长的训练，或整条高 FLOPs 曲线完整留出来不参与拟合，看模型对这些未见过的完整 run 预测得准不准：不仅比绝对误差，更要看候选配置的排序对不对、预测低谷离真实低谷有多近（验证文档本身也要和训练语料做好按来源的近重复隔离，别让数据泄漏把曲线拉平）。

光有一个点估计还不够，我们得知道最优参数量能晃多大。做法是对独立的实验 run（同一配置跑了多个随机种子时按配置分组）做 bootstrap 重采样，每次重拟合再解一次目标预算下的 \(N_*\)，就能拿到决策区间。当然，重采样只管随机波动，挡不住换数据分布或幂律形态失效带来的系统偏差。拿到区间后，再顺手算一下区间内几个候选点的预测 loss——你会经常发现低谷底部很平，这时候挑一个好切并行、好上线的模型形状，比死磕小数点后两位的“理论最优点”划算得多。

高 \(D/N\)（极长训练）区域尤其要单独留出锚点验证。Beyond Chinchilla 发现，用常规 token/参数比拟合出来的幂律，拉到极长训练区会明显高估继续加 token 的收益。排查起来很简单：把残差对着 \(D/N\) 画出来，再补几个长训练锚点重拟合。只要残差随 \(D/N\) 出现持续弯曲，就说明实验范围太窄或函数形式不够用了，在原数据上再怎么折腾优化器迭代次数也救不回来。

有限的数据，能重复用几次

前面默认新鲜数据取之不尽，现实里高质量语料往往就那么多。假设去重后的可用数据池只有 \(\htmlData{symbol=unique}{U}\) 个 token，一共训了 \(D\) 个 token，平均下来就是 \(K=D/U\) 遍。问题在于，算力账单照样按全部 \(D\) 计费，可同一条数据读第二遍、第五遍时，带来的信息量明显在缩水。所以干脆引入有效数据量：把重复训练换来的收益，折算成等价的新鲜 token 数。

还没读完第一遍（\(D\le U\)）时全是新鲜数据，直接有 \(D_{\mathrm{eff}}=D\)；超过一遍后，记 \(R=D/U-1\) 为第一遍之后的额外遍数，用一个平滑饱和的形式来刻画：

\[\htmlData{symbol=effective}{D_{\mathrm{eff}}}=U\left[1+\htmlData{symbol=repeat-scale}{R_*}\left(1-e^{-R/R_*}\right)\right].\]

这里的衰减尺度 \(R_*\)（单位是遍）由重复训练实验拟合出来。检查几个边界就很直观：刚好读完一遍时 \(R=0\)，\(D_{\mathrm{eff}}=U\)；刚多读一点（\(R\ll R_*\)）时把指数展开，得到 \(D_{\mathrm{eff}}\approx U(1+R)=D\)，前几遍几乎和新鲜数据一样顶用；可一旦无限重复下去，有效数据量就会撞上天花板 \(U(1+R_*)\)，再烧算力也挤不出新东西了。

求个导，边际收益掉得有多快一目了然。在 \(D\ge U\) 区间对实际处理量 \(D\) 求导：

\[\frac{\mathrm dD_{\mathrm{eff}}}{\mathrm dD}=e^{-R/R_*}.\]

每多算一个 token 换回来的有效数据量，从第一遍末尾的 1 开始指数衰减。拿 \(R_*=3\) 举个例子：训到第四遍末尾（\(R=3\)）时，累计有效数据量达到 \(2.896U\)，但此刻再多喂一个 token，边际有效量只剩 \(e^{-1}\approx 0.368\)——重复还没完全失效，可每单位算力的性价比已经大打折扣。

把 \(D_{\mathrm{eff}}\) 塞回 loss 的数据项 \(B(D_{\mathrm{eff}}/D_0)^{-\beta}\)，同时算力账单依然按 \(6ND\) 算，你就有了统一标尺，能直接比较“继续刷旧数据”“把模型做大”和“去搞更多新数据”哪个更划算（Muennighoff 等人的完整拟合还会给过量参数加上类似的饱和项，这里先把注意力放在数据重复这一侧）。

工程上有一个极易踩的坑：别只盯着全局平均 epoch 数。很多时候一个权重拉得很高的小数据域（比如高质量代码或数学）早就被刷了十几遍，而网页大池子连一遍都没过完，全局平均值会把这种悬殊完全藏起来。靠谱的做法是分域记账——分别盯紧每个域去重后的池子大小和采样器实际消费量。真要量自己的 \(R_*\)，就锁死一份数据池，对 1、2、4、8 遍分别跑预算匹配的退火训练，在未见过的同分布验证集上看分域 loss 和下游指标。一旦训练 loss 还在掉、验证 loss 却开始趴窝，就说明重复红利快见底了。这部分和上下游直接咬合：数据筛选决定池子里到底有多少“干货”，数据配比决定每一份干货被反复端上桌多少次。

模型上线后，最优点向哪里移动

训练只付一次，推理会不断付费。只看权重矩阵乘法，每推理一个 token 大约花 \(2N\) FLOPs。假设产品把质量门槛定在验证 loss \(\htmlData{symbol=target}{\ell}\)，整个部署周期预计要处理 \(\htmlData{symbol=inference}{I}\) 个推理 token，那我们真正该压低的是训练加推理的总账：

\[\htmlData{symbol=total-cost}{C_{\mathrm{total}}}=6ND+2NI,\qquad \widehat L(N/N_0,D/D_0)\le\ell.\]

在这个单调公式里，达标之后继续多训纯属多花钱，所以最优解一定紧贴着 \(\widehat L=\ell\) 这条边界。一旦定下参数量 \(N\)，需要喂多少训练 token 可以直接反解出来：

\[D(N)=D_0\left[\frac{B}{\ell-E-A(N/N_0)^{-\alpha}}\right]^{1/\beta}.\]

注意分母必须为正，也就是说模型存在一个硬容量下界 \(N\gt N_0[A/(\ell-E)]^{1/\alpha}\)——比这还小的模型，喂再多数据也追不上目标 loss。越贴近下界，所需的训练 token 就涨得越陡。把 \(D(N)\) 代回总计算量，问题就塌缩成只关于 \(N\) 的一维搜索：大模型训起来省事，上线后每个 token 都在多烧钱；小模型训练时得多砸算力“过训”，换来上线后源源不断的便宜推理。

仍用前面的教学系数，把目标定在 \(\ell=3.1\)。如果只算训练账，最优点正好是 1B 参数、20B token；可一旦加上 100B 推理 token 的部署需求，最小化总 FLOPs 的方案就会挪到约 0.481B 参数、51.18B 训练 token——模型砍掉一半多，训练数据翻了两倍半，靠前期多花训练算力把全周期总账压了下去。

FLOPs 最少的配置，怎样变成 GPU 账单最少

FLOPs 一样多，不代表花的钱一样多。训练是算力打满的大矩阵乘，prefill 吃长序列并行，decode 往往卡在显存带宽且 batch 偏小，三者的硬件有效利用率差着好几倍。把这三个阶段实测的有效吞吐分别记为 \(F_{\mathrm{tr}},F_{\mathrm{in}},F_{\mathrm{out}}\)（单位均为 FLOP/s），输入与输出推理总量记为 \(I_{\mathrm{in}},I_{\mathrm{out}}\)，更贴近真实卡时的预算是：

\[T\approx\frac{6ND}{F_{\mathrm{tr}}}+\frac{2NI_{\mathrm{in}}}{F_{\mathrm{in}}}+\frac{2NI_{\mathrm{out}}}{F_{\mathrm{out}}}.\]

再给三个阶段各自乘上对应卡型的每秒价格，就换算成了真实花销。不过硬件账单并不平滑：模型小一圈能不能刚好塞进更少的 GPU 省掉跨卡通信、量化后矩阵形状能不能命中高效 kernel、KV cache 会不会把并发卡死，都会让账单出现明显的台阶（prefill、decode 和带宽的细账见推理数学）。实际落地时通常分两步走：先用平滑的 scaling law 把候选规模圈定在两三个可部署的形状里，再拿真卡实测它们的吞吐和高分位延迟，把实测数据代回成本表拍板。

把曲线变成一次训练决策

把前面这些零件拼起来，真正拍板一次预训练预算时，通常按四步走：

  1. 锁死口径再布实验：先定好 tokenizer、验证集和主力下游指标，挑几档能稳定跑通的模型形状，沿模型量与 token 量两个方向铺开小实验。每条 run 至少记全五笔账：总 token、各数据域的采样量、退火终点、验证 loss 和实测吞吐。
  2. 留出大规模验外推：拿留出的大模型或高算力曲线检验拟合。一旦发现高 \(D/N\) 区域残差起弯，或者数据池重复刷得快饱和了，就把这些盲区补成下一轮锚点。
  3. 用真实约束定最终形状：数据吃紧时，直接比较继续刷旧数据和扩充新数据的边际收益；推理量大时，切回固定质量的全周期成本重解一遍。如果低谷底部很平，直接让部署显存、并行切分和实测吞吐拍板。
  4. 拿外推误差当停机线：动手之前先问一句——两个方案预测出来的差距，有没有大过当前的外推误差？如果方案 A 和 B 只差 0.002 nats/token，而跨规模验证残差已经有 0.02，硬挑谁赢纯属掷硬币，下一笔预算更该花在能把它们拉开差距的补测实验上。

如果手里已经有一个训到一半的 dense 模型，预算决策还会多出一个岔路口：继续沿着 dense 往下训，还是找个时点通过upcycling 转成 MoE？做这个对比时别把两本账混在一起——从已有 checkpoint 出发只需权衡接下来的增量预算和部署容量，而从零规划时则要把前后两个训练阶段的成本加总。

这个小脚本全在 CPU 上跑，用已知幂律生成带噪声的合成观测：外层网格扫一遍 \(\alpha,\beta\)，内层用线性最小二乘解出 \(E,A,B\)（为了看清拟合过程，这里直接最小化平方残差）。接着程序会留出更大的模型和更长的训练做外推验证，对独立 run 做 bootstrap 给出最优规模区间，再演示新鲜数据幂律在有限数据池上会产生多大的乐观偏差；同时用稠密数值搜索复核闭式最优解，用有限差分核对 \(D_{\mathrm{eff}}\) 的导数。

默认种子跑下来，外推验证 RMSE 约 0.0093 nats/token；预算 \(c=16\) 时，真实最优是 4B，拟合预测的是 3.686B，80 次重采样的 10%—90% 区间落在 3.38B—4.02B，最后会输出 All checks PASS。你可以自己动手调几个参数感受一下：把 --noise 调大看决策区间怎么发散，在训练网格里补一档更大的实验点看区间能不能收紧，或者把有限数据实验里的 \(U\) 从 80B 砍到 40B，看新鲜数据拟合在长训练区的乐观误差怎么一路放大。

练习 1：同一预算的三种分配

沿用教学系数 \(E=1.5,A=B=0.8,\alpha=\beta=0.3\)（\(N_0=1\mathrm B,D_0=20\mathrm B\)），固定预算 \(C=4.8\times10^{20}\) FLOPs。分别算 1B、2B、4B 参数能分到多少训练 token 以及对应的预测 loss；再把预算翻四倍，求新的最优配置。

展开解答

由 \(D=C/(6N)\)，1B、2B、4B 分别能读 80B、40B、20B token，归一化后是 \((n,d)=(1,4),(2,2),(4,1)\)。

\[\begin{aligned}L(1,4)&=1.5+0.8+0.8\times4^{-0.3}\approx2.8278,\\L(2,2)&=1.5+1.6\times2^{-0.3}\approx2.7996,\\L(4,1)&\approx2.8278.\end{aligned}\]

当前归一化预算 \(c=4\)，因为两项系数和指数完全对称，最优解 \(n_*=d_*=\sqrt c=2\)（即 2B 参数、40B token）。预算翻四倍到 \(c=16\) 后，最优点同步翻倍到 4B 参数、80B token，预测 loss 降到约 2.5556。

练习 2：有限数据的下一遍值多少

可用数据 \(U=20\mathrm B\) token，重复尺度 \(R_*=3\)。训练到第 4 遍结束时，实际处理量、有效数据量与边际有效量分别是多少？此时再完整训练一遍，增加多少有效 token？

展开解答

第 4 遍结束时一共处理了 \(D=80\mathrm B\) token，第一遍之后的额外遍数 \(R=3\)：

\[D_{\mathrm{eff}}(80\mathrm B)=20[1+3(1-e^{-1})]\mathrm B\approx57.93\mathrm B.\]

此刻的边际有效量是 \(e^{-1}\approx0.368\)。如果再多训一整遍，实际 token 从 80B 涨到 100B（\(R\) 从 3 涨到 4），多出来的有效数据量只有：

\[\Delta D_{\mathrm{eff}}=60(e^{-1}-e^{-4/3})\mathrm B\approx6.26\mathrm B.\]

也就是说，多算了 20B token，平均每个 token 只顶 0.313 个新鲜 token（比第 5 遍刚开头时的 0.368 更低，因为这一整遍里收益还在继续掉）；换成 1B 模型的算力账单，这一遍照样得实打实花掉约 \(1.2\times10^{20}\) FLOPs。

练习 3：多练一个小模型，多久回本

目标 loss 定在 \(\ell=1.5+1.6\times2^{-0.3}\approx2.7996\)。方案甲是 2B 参数、40B token；方案乙换成 1B 参数，靠多喂数据追到同样的预测 loss。求方案乙需要多少训练 token，以及上线跑多少推理 token 后两者总 FLOPs 打平。

展开解答

方案乙的 \(n=1\)，模型项固定占掉 0.8，所以数据项必须压到 \(\ell-1.5-0.8=\ell-2.3\)：

\[D_{\text{乙}}=20\left(\frac{0.8}{\ell-2.3}\right)^{1/0.3}\mathrm B\approx96.07\mathrm B.\]

算一下训练账：甲花 \(4.8\times10^{20}\) FLOPs，乙花 \(5.7641\times10^{20}\) FLOPs，乙在训练阶段多垫了 \(9.6406\times10^{19}\) FLOPs。但上线后乙每推理一个 token 少算 \(2(2-1)\times10^9=2\times10^9\) FLOPs，于是回本点为：

\[I_{\mathrm{break}}=\frac{9.6406\times10^{19}}{2\times10^9}\approx4.8203\times10^{10}\text{ token}.\]

只要预计推理总量超过约 48.20B token，小模型方案的总 FLOPs 就更省。换算成真实显卡账单时，再把训练、prefill、decode 的实测吞吐和卡时单价代进去就行。

练习 4：拟合很好，外推为什么错了

团队从 4 条长训练曲线里各抽了 50 个 checkpoint，随机拿 160 个点拟合、40 个点验证，验证误差只有 0.003。可一到实操就全错了：独立跑出来的短预算模型总比预测好，往高 \(D/N\) 长训练外推时预测又越来越乐观。背后的两条机制是什么？怎么设计对照实验排查，验证集又该怎么重划？

展开解答

第一条机制是学习率退火没对齐。长训练途中的 checkpoint 学习率还高着，根本没收敛完，而独立跑的短预算模型已经走完了完整退火，所以后者实测 loss 必然比“按中间点拟合出来的曲线”更好。排查很简单：锁死数据顺序和短预算终点，拿“长 schedule 半途截断”和“预算匹配的完整退火”正面比末尾验证 loss，就能把 schedule 的影响单独剥出来。

第二条机制是长训练区的数据收益变慢。固定池子反复刷会产生重复饱和，哪怕数据不重复，超高 \(D/N\) 也容易超出原幂律的适用区，所以沿低比例曲线外推会越来越乐观。排查时固定一份去重后的数据池，分别跑 1、2、4、8 遍的预算匹配实验，并记清每个数据域的实际采样遍数，再拿扩池子后的新鲜数据对照，就能分清是重复拖了后腿，还是幂律本身开始弯了。

验证集要按完整 run 划分，直接把大模型、高算力或高 \(D/N\) 整条留出来，别让同一条轨迹上相邻的 checkpoint 混在训练和验证两边。残差也要分别对着参数量、token 数、遍数和 \(D/N\) 画开看，重采样按完整 run 或配置组来做，最后在目标预算附近补独立的确认实验把排序坐实。
