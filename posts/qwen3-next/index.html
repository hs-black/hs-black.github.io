1. 全局：一个 80B-A3B 的模型长什么样

先看骨架。Qwen3-Next-80B-A3B 有 48 层，隐藏维度 \(d=2048\)。每一层都是 Pre-Norm 残差结构：「token 混合器」（负责在序列维度上交换信息）加「通道混合器」（逐 token 的 FFN）。和 Qwen3 相比，有三处不同：

  • token 混合器有两种。每 4 层里，前 3 层用 Gated DeltaNet（一种线性注意力），第 4 层用 Gated Attention（带输出门的标准 softmax 注意力）。整体就是 12 × (3 × (Gated DeltaNet → MoE) → 1 × (Gated Attention → MoE))：第 \(i\) 层（从 0 数）当 \((i+1)\bmod 4 = 0\) 时是全注意力，也就是第 3、7、11、…、47 层。
  • 每一层的 FFN 都是 MoE。512 个 routed expert，每个 token 选 10 个，再加 1 个所有 token 都走的 shared expert；每个 expert 是中间维度 512 的 SwiGLU。
  • 主干之外还有一个 MTP 模块，训练时预测更远的 token，推理时当投机解码的草稿模型。

按各模块的形状逐项累加，参数分布如下（合计约 80B，其中非嵌入参数约 79B）：

2. 从 softmax 注意力到线性注意力

2.1 softmax 注意力的成本在哪里

先固定记号。一个注意力头里，第 \(t\) 个 token 有查询 \(q_t\in\mathbb R^{d_k}\)、键 \(k_t\in\mathbb R^{d_k}\)、值 \(v_t\in\mathbb R^{d_v}\)。因果 softmax 注意力的输出是

$$o_t=\sum_{j\le t}\frac{\exp(q_t^\top k_j/\sqrt{d_k})}{\sum_{l\le t}\exp(q_t^\top k_l/\sqrt{d_k})}\,v_j .$$

写成矩阵：\(O=\mathrm{softmax}(QK^\top/\sqrt{d_k}+B)V\)。这里 \(B_{ij}=0\) 表示位置 \(i\) 可以读取位置 \(j\)；未来位置 \(j>i\) 的 \(B_{ij}=-\infty\)，经过逐行 softmax 后权重为 0。两个成本：

  • 训练与 prefill（一次性处理整段输入）：要算 \(N\times N\) 的分数矩阵，FLOPs 是 \(O(N^2 d)\)。FlashAttention 不存这个矩阵，但计算量还是平方的。
  • decode（逐个生成新 token）：生成第 \(t\) 个 token 时要和之前所有 \(t-1\) 个键值做点积，所以每步 \(O(t\,d)\)，并且要把所有 \(k_j, v_j\) 存成 KV cache，显存随长度线性增长。上下文长度与并发序列数共同决定这部分显存；下面会按 Qwen3-Next 的实际头数逐项计算。

根源在于 softmax：\(\exp(q^\top k)\) 不能拆成「只依赖 \(q\)」乘「只依赖 \(k\)」的形式，所以每个查询都得重新扫一遍所有键。

2.2 核化：把 exp 换成特征内积

线性注意力的想法是把相似度 \(\exp(q^\top k)\) 换成某个特征映射的内积 \(\phi(q)^\top\phi(k)\)：

$$o_t=\frac{\sum_{j\le t}\big(\phi(q_t)^\top\phi(k_j)\big)v_j}{\sum_{l\le t}\phi(q_t)^\top\phi(k_l)} =\frac{\Big(\sum_{j\le t}v_j\phi(k_j)^\top\Big)\phi(q_t)}{\Big(\sum_{l\le t}\phi(k_l)\Big)^\top\phi(q_t)} .$$

第二个等号只用了矩阵乘法的结合律：\(\big(\phi(q)^\top\phi(k)\big)v = \big(v\,\phi(k)^\top\big)\phi(q)\)。括号里的求和与 \(q_t\) 无关，可以提前累加。

现代线性注意力（包括 Qwen3-Next 用的 Gated DeltaNet）做了两处简化：\(\phi\) 取恒等（或在 \(q,k\) 上做 L2 归一化之类的简单变换），并且去掉分母的归一化项（实践中归一化项数值上不稳定，输出端改用 RMSNorm 来控制尺度）。下面都用这个简化版：

$$o_t=\Big(\sum_{j\le t}v_j k_j^\top\Big)q_t .$$

2.3 递推形式：线性注意力是一个 RNN

令 \(S_t=\sum_{j\le t}v_jk_j^\top\in\mathbb R^{d_v\times d_k}\)，就得到

$$S_t=S_{t-1}+v_tk_t^\top,\qquad o_t=S_tq_t .$$

这就是一个以矩阵 \(S_t\) 为隐状态的 RNN。decode 时每步只做一次外积更新和一次矩阵-向量乘，代价 \(O(d_kd_v)\)，和已经生成了多少 token 无关；显存也只需要存 \(S_t\)，不需要 KV cache。

\(S\) 可以理解为一个联想记忆（associative memory）：写入时把「键 → 值」的映射以外积形式叠加进去，读出时用查询去「检索」：\(S q=\sum_j v_j(k_j^\top q)\)，即所有存过的值按键与查询的相似度加权求和。这和 90 年代的 fast weight programmer 是同一个东西：\(S\) 是一组「快权重」，由慢权重（投影矩阵）在每一步编程。

2.4 并行形式与分块形式

训练时不想一个个 token 地递推（GPU 上串行很慢）。展开递推得到并行形式：

$$O=\big((QK^\top)\odot M\big)V ,$$

和 softmax 注意力只差一个 softmax，但这样又回到了 \(O(N^2)\)。实际用的是两者的折中——分块形式（chunkwise）：把序列切成长度为 \(C\) 的块，块与块之间用递推传状态，块内部用并行形式。设第 \([i]\) 块开始时的状态为 \(S_{[i]}\)，块内的 \(Q_{[i]},K_{[i]},V_{[i]}\in\mathbb R^{C\times d}\)，则

$$O_{[i]}=\underbrace{Q_{[i]}S_{[i]}^\top}_{\text{块间：读历史状态}}+\underbrace{\big(Q_{[i]}K_{[i]}^\top\odot M\big)V_{[i]}}_{\text{块内：小的并行注意力}},\qquad S_{[i+1]}=S_{[i]}+V_{[i]}^\top K_{[i]} .$$

每块的成本是 \(O(C^2d+Cd^2)\)，总成本 \(O(NCd+Nd^2)\)，对 \(N\) 线性；而且全部是稠密矩阵乘，能吃满 Tensor Core。串行步数从 \(N\) 降到 \(N/C\)。Qwen3-Next 用的块长是 \(C=64\)。

2.5 问题：加性记忆会「撑爆」

线性注意力在语言建模困惑度上能接近 Transformer，但在需要精确回忆的任务（在上下文里找某个 key 对应的 value、多跳检索、长文问答）上明显落后。原因可以从联想记忆的角度直接看出来。假设所有键都是单位向量，读出第 \(i\) 个键：

$$S_t k_i = v_i + \sum_{j\ne i} v_j\,(k_j^\top k_i).$$

第二项是串扰。如果存的键两两正交，串扰为 0，检索精确；但 \(\mathbb R^{d_k}\) 里最多只有 \(d_k\) 个两两正交的向量。一旦存的东西多于 \(d_k\) 个（长上下文里必然如此），串扰不可避免，而且只会越积越多——加性更新只能往里加，不能删、不能改。同一个键先后写入两个不同的值，读出来的是两者之和，而不是最新的那个。

解决办法有两条，正好对应 Gated DeltaNet 的两个组成部分：

  1. 遗忘：给旧状态乘一个衰减系数 \(\alpha_t\in(0,1)\)，让旧记忆逐渐淡出（RetNet、GLA、Mamba2 走的是这条路）。
  2. 修改：写入之前先看看记忆里对这个键已经存了什么，只写入「差值」（DeltaNet 的 Delta 规则）。

3. Delta 规则：把记忆当成在线回归

3.1 推导

把 \(S\) 看成一个线性回归器，它的任务是「给定 \(k\)，预测 \(v\)」。在第 \(t\) 步，我们拿到一个新样本 \((k_t,v_t)\)，用一步在线梯度下降更新 \(S\)。损失取平方误差：

$$\mathcal L_t(S)=\tfrac12\lVert Sk_t-v_t\rVert^2,\qquad \nabla_S\mathcal L_t=(Sk_t-v_t)k_t^\top .$$

步长为 \(\beta_t\) 的一步梯度下降：

$$S_t=S_{t-1}-\beta_t(S_{t-1}k_t-v_t)k_t^\top = S_{t-1}+\beta_t\big(v_t-\underbrace{S_{t-1}k_t}_{\text{旧记忆的预测}}\big)k_t^\top .$$

这就是 Delta 规则（Widrow–Hoff 规则）。括号里是「目标值减去当前预测」：如果记忆已经能正确地把 \(k_t\) 映射到 \(v_t\)，就什么都不写；如果存的是错的值，就只写入修正量。整理一下：

$$\boxed{S_t=S_{t-1}\big(I-\beta_tk_tk_t^\top\big)+\beta_tv_tk_t^\top}$$

对比一下，普通线性注意力 \(S_t=S_{t-1}+v_tk_t^\top\) 也能看成梯度下降，只不过损失是 \(-\langle Sk_t,v_t\rangle\)（线性损失，永远不会饱和）。换成平方损失，就多出了「先擦再写」这一项 \(-\beta_t S_{t-1}k_tk_t^\top\)。

几个性质：

  • 如果 \(\lVert k_t\rVert=1\)、\(\beta_t=1\)，那么 \(I-k_tk_t^\top\) 是向 \(k_t\) 正交补的投影。更新后 \(S_tk_t=v_t\) 精确成立：键 \(k_t\) 方向上的旧内容被整个替换成新值，其它与 \(k_t\) 正交的方向不受影响。这就是「改写」。
  • 保持 \(\lVert k_t\rVert=1\)，\(\beta_t\in(0,1)\) 时是部分改写：\(S_tk_t=(1-\beta_t)S_{t-1}k_t+\beta_tv_t\)，在旧值和新值之间插值。\(\beta_t\) 由网络根据当前 token 决定（Qwen3-Next 里是 \(\sigma(W_bx_t)\)），相当于一个数据依赖的学习率。
  • 转移矩阵 \(I-\beta_tk_tk_t^\top\) 是广义 Householder 矩阵。当 \(\lVert k_t\rVert=1\)、\(0\le\beta_t\le 2\) 时，它的特征值是 \(1-\beta_t\)（在 \(k_t\) 方向）和 1（其它方向），谱范数不超过 1，因此同一输入下，两个历史状态的差不会被这一步放大。状态本身的大小还取决于持续写入的值。这也是为什么 Gated DeltaNet 要对 \(k\) 做 L2 归一化。

值得自己试的几件事：

  • 正交键：保持默认的 \(\alpha=\beta=1\)，两边误差都是 0。\(d\) 个正交键以内，加性记忆可以完整存下这些键值对。
  • 改写同一个键：第 4 个 token 用第 1 个 token 的键写入新值。加性更新读出的是两个值之和，误差很大；Delta 规则在 \(\beta=1\) 时精确地把旧值替换掉。
  • 8 个随机键：超过容量后两边都有误差，但 Delta 规则保证「最近写入的那个」总是精确的（\(\beta=1\) 时），误差集中在较早的键上；加性更新的误差摊在所有键上，而且整体更大。
  • 把 α 调小：旧记忆按指数衰减，早期键的误差趋向 \(\lVert v_i\rVert\)（被忘掉了），但给新内容腾出了空间。这就是门控的作用。

4. Gated DeltaNet：遗忘门 + Delta 规则

4.1 门控线性注意力

给加性更新加一个数据依赖的标量衰减 \(\alpha_t\in(0,1)\)：

$$S_t=\alpha_tS_{t-1}+v_tk_t^\top .$$

这就是 Mamba2（在每个头上用标量衰减）所对应的线性注意力形式；GLA 用的是逐维（向量）衰减。展开后，第 \(j\) 个 token 对第 \(t\) 步的贡献被乘上 \(\prod_{s=j+1}^{t}\alpha_s\)，即它「经过的所有门」的乘积。\(\alpha_t\) 接近 0 时整块清空记忆（比如遇到文档边界），接近 1 时保留。

门控擅长快速、整体地遗忘，但它对所有内容一视同仁：想忘掉某一个键值对，就必须连带衰减所有别的。Delta 规则正相反，擅长精确地修改某个键，但不能快速清空。两者正好互补，Gated DeltaNet 就是把它们合在一起。

4.2 门控 Delta 规则

把两者合起来：

$$\boxed{\htmlData{symbol=gdn-state}{S_t}=S_{t-1}\Big(\htmlData{symbol=gdn-decay}{\alpha_t}\big(I-\htmlData{symbol=gdn-write}{\beta_t}k_tk_t^\top\big)\Big)+\beta_tv_tk_t^\top,\qquad o_t=S_tq_t}$$

这里 \(S_t\in\mathbb R^{d_v\times d_k}\) 是处理完第 \(t\) 个 token 的记忆矩阵；\(\alpha_t\) 控制整份旧记忆的保留比例，\(\beta_t\) 控制当前键 \(k_t\) 方向上的改写强度。查询 \(q_t\in\mathbb R^{d_k}\) 从更新后的状态读出 \(d_v\) 维向量 \(o_t\)。

从在线学习的角度看，这等价于：先对旧状态做一步权重衰减（\(S\leftarrow\alpha_tS\)），再对平方损失做一步梯度下降。写成逐 token 的代码：

# 每个头，S 的形状是 [d_k, d_v]（代码里是转置的约定：读出用 qᵀS）
S = S * exp(g_t)                     # α_t = exp(g_t)，g_t ≤ 0
pred = S.T @ k_t                     # 旧记忆对 k_t 的预测
S = S + outer(k_t, beta_t * (v_t - pred))   # 只写入差值
o_t = S.T @ q_t

注意顺序：先衰减，再用衰减后的状态算预测。这和上面的公式一致：\(\alpha_tS_{t-1}(I-\beta_tk_tk_t^\top)=\alpha_tS_{t-1}-\beta_t(\alpha_tS_{t-1}k_t)k_t^\top\)。

4.3 门怎么参数化

Qwen3-Next 的 \(\alpha_t\) 沿用 Mamba2 的「离散化」写法。每个值头 \(h\) 有一个可学习的 \(A_h>0\)（以 \(\log A_h\) 存储）和偏置 \(\Delta_h\)，输入投影给出一个标量 \(a_t\)：

$$g_t=-A_h\cdot\mathrm{softplus}(a_t+\Delta_h),\qquad \alpha_t=e^{g_t}\in(0,1).$$

softplus 保证步长 \(\mathrm{softplus}(\cdot)>0\)，\(A_h>0\) 保证 \(g_t\lt 0\)。在 Mamba 的连续时间视角下，\(\mathrm{softplus}(a_t+\Delta_h)\) 是时间步长 \(\Delta t\)，\(e^{-A\Delta t}\) 是零阶保持离散化下的衰减。初始化时 \(A\) 取 \([0.01,16]\) 上的均匀分布，\(\Delta\) 取 1，于是不同的头一开始就有快慢不同的遗忘速度。写入强度 \(\beta_t=\sigma(b_t)\)，也是每个值头一个标量。在 log 空间里计算 \(g_t\)，可以把累积衰减 \(\prod\alpha\) 改写成 \(g\) 的前缀和；分块计算需要某一段的缩放时，再对局部前缀差取指数，避免直接连乘很长的衰减链。

5. 分块并行算法：训练时怎么算得快

门控 Delta 规则每次写入前，都要从旧状态读出当前键对应的预测 \(\alpha_tS_{t-1}k_t\)。这让块内各次写入相互依赖。WY 表示和 UT 变换可以把一串广义 Householder 乘积压缩成低秩形式，再用矩阵运算一起求出这些写入量。

5.1 块内展开

考虑一个长度为 \(C\) 的块，块开始时的状态为 \(S_0\)，块内位置记为 \(r=1,\dots,C\)。定义块内累积衰减

$$\gamma_r=\prod_{s=1}^{r}\alpha_s,\qquad \Gamma_{rj}=\gamma_r/\gamma_j\ (j\le r).$$

先看没有门控（\(\alpha\equiv1\)）的情况。可以用归纳法证明，块内第 \(r\) 步的状态总能写成

$$S_r=S_0+\sum_{j\le r}\big(u_j-S_0w_j\big)k_j^\top ,$$

其中 \(w_j\in\mathbb R^{d_k},u_j\in\mathbb R^{d_v}\) 满足

$$w_r=\beta_r\Big(k_r-\sum_{j\lt r}(k_j^\top k_r)\,w_j\Big),\qquad u_r=\beta_r\Big(v_r-\sum_{j\lt r}(k_j^\top k_r)\,u_j\Big).$$

（归纳步：把 \(S_{r-1}\) 的表达式代入 \(S_r=S_{r-1}+\beta_r(v_r-S_{r-1}k_r)k_r^\top\)，\(S_{r-1}k_r=S_0k_r+\sum_{j\lt r}(u_j-S_0w_j)(k_j^\top k_r)\)，整理即得。）

这两个递推是串行的：\(w_r\) 依赖于所有更早的 \(w_j\)。但把它们移项就会发现，它们其实是「下三角线性方程组」。记 \(A\) 为严格下三角矩阵，\(A_{rj}=\beta_r\,k_r^\top k_j\)（\(j\lt r\)），则

$$(I+A)\,W=\mathrm{diag}(\beta)K,\qquad (I+A)\,U=\mathrm{diag}(\beta)V .$$

\(T=(I+A)^{-1}\) 只是一个 \(C\times C\) 的单位下三角矩阵求逆（前代法，或者 solve_triangular），这一步叫 UT 变换。一个块里所有的 Householder 乘积，被压缩成了 \(W,U\) 两个 \(C\times d\) 的矩阵。

5.2 加上门控

有衰减时，第 \(j\) 个 token 写入的内容到第 \(r\) 步时已经被乘上了 \(\Gamma_{rj}\)，所以把每个贡献按「它之后经过的衰减」缩放即可。归纳过程完全相同，结果是：

$$A_{rj}=\beta_r\,\Gamma_{rj}\,k_r^\top k_j\ (j\lt r),\qquad U=(I+A)^{-1}\mathrm{diag}(\beta)V,\qquad W=(I+A)^{-1}\mathrm{diag}(\beta\odot\gamma)K .$$

再定义「真正要写入的新值」\(\Delta=U-WS_0^\top\in\mathbb R^{C\times d_v}\)（第 \(r\) 行是 \(u_r-S_0w_r\)：目标值减去旧状态对它的预测，正是 Delta 规则里的那个差）。于是块的输出和下一块的初始状态都是普通矩阵乘：

$$O=\mathrm{diag}(\gamma)\,QS_0^\top+\big(QK^\top\odot\Gamma\odot M\big)\Delta,$$ $$S_C=\gamma_C\,S_0+\Delta^\top\,\mathrm{diag}(\gamma_C/\gamma)\,K .$$

这里 \(M\) 是含对角线的下三角掩码。第一项是「从历史状态读」（带上从块首到当前位置的衰减），第二项是块内的小注意力。整体流程：

for 每个块 i（串行，共 N/C 次）:
    # 以下全是 C×C 或 C×d 的稠密矩阵运算
    A   = tril(β·(K Kᵀ)·Γ, -1)                # 块内键之间的相互作用
    T   = (I + A)⁻¹                           # UT 变换（三角求解）
    U   = T · diag(β) V ;  W = T · diag(βγ) K   # 可以对所有块并行预先算好
    Δ   = U − W S₀ᵀ                            # 减去旧状态的预测
    O_i = diag(γ) Q S₀ᵀ + (Q Kᵀ ⊙ Γ ⊙ M) Δ
    S₀  = γ_C S₀ + Δᵀ diag(γ_C/γ) K

成本分析：令序列长度为 \(N\)，块长为 \(C\)，键和值的维度都为 \(d\)。每块有若干 \(C\times C\times d\) 和 \(C\times d\times d\) 的矩阵乘；直接构造三角逆还会有 \(O(C^3)\) 工作。在常用的 \(C\le d\) 设置下，这一项可以并入前两项，总 FLOPs 为 \(O(N(Cd+d^2))\)，块间依次传递 \(N/C\) 次状态。与 softmax 注意力的 \(O(N^2d)\) 比较，运算量之比约为 \(N/(C+d)\)。实现可以直接求解带多个右端项的三角方程，省去显式求逆。实际训练和推理用的是 flash-linear-attention 库里的 Triton kernel chunk_gated_delta_rule，它还结合了块内分解和 kernel 融合。

decode 阶段不需要分块：每生成一个 token 就按 4.2 节的递推式走一步，代价是常数。

6. Qwen3-Next 里的 Gated DeltaNet 层

核心递推之外，一个完整的 Gated DeltaNet 层前后还包了一圈东西。按数据流依次是（\(x_t\in\mathbb R^{2048}\) 是 RMSNorm 之后的输入）：

  1. 输入投影。in_proj_qkvz：\(2048\to12288\)，切成 \(q\)（16 头 × 128）、\(k\)（16 头 × 128）、\(v\)（32 头 × 128）、\(z\)（32 头 × 128）。in_proj_ba：\(2048\to64\)，切成 32 个 \(b\) 和 32 个 \(a\)（每个值头各一个）。
  2. 短卷积。把 \(q,k,v\) 拼成 8192 个通道，做核长 4 的因果 depthwise 1D 卷积，再接 SiLU。它让每个 token 的 \(q,k,v\) 看到前 3 个 token 的局部信息，这对「归纳头」类型的模式（看到 A B … A 时预测 B）很有帮助——线性注意力本身没有位置编码，局部的位置感主要靠它。下一步计算所需的最小历史是最近 3 个 token 的这 8192 维卷积输入。实际 kernel 可以保留更长的物理窗口，以便原地更新或投机回退。
  3. 归一化。对每个头的 \(q,k\) 做 L2 归一化（保证 \(\lVert k\rVert=1\)，Delta 规则的转移矩阵稳定），\(q\) 再乘 \(1/\sqrt{128}\)。
  4. QK 头少于 V 头：16 个 QK 头、32 个 V 头，每个 \(q,k\) 头被 repeat_interleave 复制给 2 个值头使用。这和 GQA 方向相反（GQA 是多个 Q 头共享一组 KV），这里是两个值头共享一组 \((q,k)\)，但各自有独立的 \(v\)、\(\alpha\)、\(\beta\) 和状态。所以状态一共 32 份，每份 \(128\times128\)。
  5. 核心递推：门控 Delta 规则，训练 / prefill 用分块算法，decode 用逐 token 递推。
  6. 输出门。对每个头的输出（128 维）做 RMSNorm，乘上 \(\mathrm{SiLU}(z)\)，32 个头拼成 4096 维，再经 out_proj 回到 2048。这个「norm 后乘门」的结构和 Mamba2、Gated DeltaNet 的块设计一样。

每层参数量：\(2048\times12288+2048\times64+8192\times4+4096\times2048+\dots\approx33.7\text{M}\)。

decode 状态有多大？每层 32 头 × \(128\times128\) = 524,288 个数。若以 fp32 存（后来的 Qwen3.5 在配置里明确指定了 fp32 状态），36 层共 72 MiB；按最小历史计算，卷积缓存 36 × 8192 × 3 个 bf16 约 1.69 MiB。Transformers 的当前实现保留 4 槽，约 2.25 MiB；vLLM 的相应窗口为 3 + 投机 token 数，具体字节数还要乘并发序列数，并按 tensor parallel 切分。这些和上下文长度无关。作为对比，12 个全注意力层的 KV cache 是每 token 24 KiB（下一节细算），所以大约在 3K token 时两者相当，再往后 KV cache 就占大头了。

7. Gated Attention：SDPA 之后加一个门

7.1 Qwen3-Next 的注意力层长什么样

那 12 个全注意力层是在 Qwen3 的 GQA 注意力上改的：

  • 16 个查询头，2 个 KV 头（GQA，每 8 个查询头共享一组 KV）；
  • 每头维度从 128 提到 256；
  • 保留 Qwen3 的 QK-Norm（对每个头的 \(q,k\) 做 RMSNorm 后再算点积）；
  • 部分 RoPE：partial_rotary_factor = 0.25，只对 256 维里的前 64 维施加旋转位置编码，其余 192 维不直接施加 RoPE 旋转；rope_theta = 10,000,000。目的是改善向更长序列的外推；
  • 输出门：SDPA 的输出逐元素乘一个 sigmoid 门。

7.2 门的位置和形式

在注意力里加门的方式有很多。Qwen 团队系统比较了 30 多种在注意力里加门的方式（门放在 \(Q\)、\(K\)、\(V\) 投影之后，放在 SDPA 输出之后，放在输出投影之后；逐元素还是逐头；各头独立还是共享；乘性还是加性），用 15B MoE 和 1.7B 稠密模型在 3.5T token 上训练。结论是：在 SDPA（scaled dot-product attention）输出之后、输出投影之前，加一个逐元素、各头独立、依赖当前查询 token 的 sigmoid 门效果最好：

$$Y=\mathrm{SDPA}(Q,K,V)\odot\sigma(XW_\theta),\qquad \text{out}=YW_O .$$

具体实现上，q_proj 的输出维度是 \(16\times256\times2=8192\)：每个头输出 512 维，前 256 维是查询，后 256 维是门的 logit。注意力输出（16 × 256 = 4096 维）逐元素乘 \(\sigma(\text{gate})\)，再进 o_proj。多出来的参数是 \(2048\times4096\approx8.4\)M 每层。

7.3 为什么有用（一）：给低秩映射加非线性

看单个头。如果没有门，值投影 \(W_V\in\mathbb R^{d\times d_h}\) 和输出投影里对应这个头的那块 \(W_O^{(h)}\in\mathbb R^{d_h\times d}\) 之间只隔着一个「对 token 加权平均」：

$$\text{out}^{(h)}_t=\Big(\sum_j a_{tj}\,x_jW_V\Big)W_O^{(h)}=\sum_j a_{tj}\,x_j\,\big(W_VW_O^{(h)}\big).$$

\(W_VW_O^{(h)}\) 是一个秩不超过 \(d_h\) 的 \(d\times d\) 矩阵，而且在 \(j\) 维的加权平均是线性的，所以两个投影可以合并成一个低秩线性映射。在 SDPA 之后（或在 \(V\) 之后）插入一个非线性门，就打断了这个合并，提升了这段低秩映射的表达能力。实验中这一改动让困惑度最多降约 0.2，MMLU 提升约 2 个点。

7.4 为什么有用（二）：attention sink 与 massive activation

Attention sink：训练好的 LLM 里，很多头会把大量注意力分给序列第一个 token，即使它没有语义。一种解释是 softmax 的权重必须加起来等于 1：当一个头在当前位置「什么都不想看」时，它也得把概率放在某处，于是学会了一个无害的垃圾桶——第一个 token。

Massive activation：残差流里少数几个维度会出现比典型值大几个数量级的激活，常出现在第一个 token 或分隔符上，和 attention sink 相伴出现。这些巨大的值在 bf16 训练里容易带来数值问题。

输出门给了模型另一种「什么都不输出」的方式：直接把门关成接近 0。实测 SDPA 输出门的分数大多远小于 0.5，平均约 0.116，也就是门是稀疏的。在 1.7B 稠密模型上的对比：

8. 3:1 混合布局与长上下文成本

8.1 为什么不全用线性注意力

道理很直接：只用线性注意力，速度快但「回忆」能力弱；只用标准注意力，推理贵且慢。线性注意力的状态是固定大小的（这里每层 32 × 128 × 128），无论 Delta 规则写得多聪明，它都是对过去的有损压缩；而 softmax 注意力为每个历史位置分别保留 K/V，后续查询可以直接访问这些位置。混合的思路是：大部分层用线性注意力处理局部和「可压缩」的信息，少数全注意力层负责精确的长程检索。

Qwen 团队的系统实验有两点结论：

  • 在线性注意力的候选里，Gated DeltaNet 的 in-context learning 能力强于常用的滑动窗口注意力和 Mamba2；
  • 把 Gated DeltaNet 和标准注意力按 3:1 混合（75% 的层用 Gated DeltaNet，25% 用标准注意力），效果稳定地优于任何单一架构，同时效率更高。

至于为什么是 3:1 而不是 7:1，比例的消融数据没有公开。

8.2 算账：KV cache 与 FLOPs

decode 时的缓存和计算如下，记 \(L\) 为上下文长度。

KV cache。每个全注意力层每 token 存 \(2\times n_{kv}\times d_h=2\times2\times256=1024\) 个数，12 层共 12,288 个，bf16 下 24 KiB/token。256K（262,144）token 时是 6 GiB。如果 48 层全是同样的注意力层，就是 96 KiB/token、256K 时 24 GiB。作为参照，Qwen3-32B（64 层、8 个 KV 头、头维 128）是 256 KiB/token，256K 时 64 GiB。

每 token decode FLOPs。一个注意力层读 \(L\) 个 KV 的核心计算是 \(QK^\top\) 和 \(AV\) 各 \(2n_hd_hL\)，共 \(4n_hd_hL=16384L\)。一个 Gated DeltaNet 层的核心递推每头约 \(7d_kd_v\)（衰减、预测、外积写入、读出），32 头共约 3.7 MFLOPs，与 \(L\) 无关。其余（所有线性投影、MoE、输出头）按 \(2\times\) 激活参数计。

9. 高稀疏 MoE：512 选 10 + 1

9.1 MoE 层回顾

Mixture-of-Experts 把一个大 FFN 换成 \(E\) 个小 FFN（expert），每个 token 只用其中 \(k\) 个，由一个 router 打分决定用哪几个。Qwen3-Next 的 MoE 层（和 Qwen2-MoE 的结构相同）是：

$$p=\mathrm{softmax}(W_rx)\in\mathbb R^{512},\qquad \mathcal T=\mathrm{TopK}(p,10),\qquad \tilde p_i=\frac{p_i}{\sum_{j\in\mathcal T}p_j},$$ $$y=\sum_{i\in\mathcal T}\tilde p_i\,E_i(x)+\sigma(w_s^\top x)\,E_{\text{shared}}(x).$$
  • router \(W_r\in\mathbb R^{512\times2048}\)，softmax 之后取 top-10，再在这 10 个上重新归一化（norm_topk_prob = true）。
  • 每个 expert \(E_i\) 是 SwiGLU：\(E_i(x)=W_2^{(i)}\big(\mathrm{SiLU}(W_1^{(i)}x)\odot W_3^{(i)}x\big)\)，中间维度 512，参数 \(3\times2048\times512\approx3.15\)M。
  • shared expert 结构相同（中间维度 512），所有 token 都过，但输出乘一个由 token 决定的标量门 \(\sigma(w_s^\top x)\)。

每层 MoE 总参数 \(512\times3.15\text{M}+3.15\text{M}+1.05\text{M}\approx1.615\)B，每 token 激活 \(11\times3.15\text{M}+1.05\text{M}\approx35.7\)M，expert 部分的激活比约 \(11/513\approx2.1\%\)。

9.3 负载均衡：全局 batch 上的辅助损失

MoE 训练要防止路由塌缩到少数 expert。标准的负载均衡损失（LBL）是

$$\mathcal L_{\text{bal}}=N_E\sum_{i=1}^{N_E}f_i\,P_i ,$$

设一个统计批次有 \(T\) 个 token，每个 token 选择 \(k\) 个 expert。把 expert \(i\) 收到的路由次数除以 \(Tk\)，得到 \(f_i\)；把 softmax 概率 \(p_{t,i}\) 在 token 上取平均，得到 \(P_i=T^{-1}\sum_t p_{t,i}\)。在这一归一化下，两组数各自求和为 1，完全均匀时的损失参考值是 1。训练中通常把离散选择产生的 \(f_i\) 视为常数，让梯度经 \(P_i\) 调节路由倾向。

统计范围会影响 expert 能否专门化。若每个 micro-batch 只有几条序列，单独施加均衡会要求每个小批次都广泛使用 expert；当小批次集中在代码或数学领域时，这种约束可能抵消内容相关的分工。跨 micro-batch 和数据并行组汇总路由计数与概率、按全局 token 数归一化，就可以在更大范围内平衡负载，同时允许局部批次偏向某些 expert。Qwen3-Next 采用全局负载均衡，配置中的 router_aux_loss_coef 为 0.001。

10. 训练稳定性：零中心 Norm 与 router 初始化

10.1 零中心、带权重衰减的 RMSNorm

RMSNorm 的标准形式是 \(y=\dfrac{x}{\mathrm{rms}(x)}\odot\gamma\)，\(\mathrm{rms}(x)=\sqrt{\tfrac1d\sum_ix_i^2+\epsilon}\)，可学习的增益 \(\gamma\) 初始化为 1。Qwen3 用了 QK-Norm，训练中却观察到一些 LayerNorm 的权重变得异常大。Norm 的增益直接乘在激活上，在 QK-Norm 里它更是直接缩放注意力 logit，权重过大会让 softmax 过尖、数值不稳定。

自然的想法是给增益加权重衰减，但普通参数化下这不合理：权重衰减把参数往 0 拉，而 \(\gamma=0\) 意味着把输出清零，这不是「没有效果」的默认状态。所以通常 Norm 的增益是被排除在权重衰减之外的。

Qwen3-Next 的做法是换成零中心参数化（Gemma 用的也是这种形式）：

$$y=\frac{x}{\mathrm{rms}(x)}\odot(1+w),\qquad w\ \text{初始化为}\ 0 .$$

这和原来的形式表达能力完全一样（\(\gamma=1+w\)），区别在于参数的「零点」变成了「增益为 1」。这时再对 \(w\) 施加权重衰减，拉向的是 \(\gamma=1\)，即恒等缩放，这是一个合理的先验，能防止增益无限增长。这种 Norm 用在每层的输入 / 注意力后 Norm、最终 Norm 和注意力里的 q_norm / k_norm 上；线性注意力输出端的门控 RMSNorm 则是普通参数化（权重初始化为 1）。

10.2 归一化的 router 初始化

router 的打分是 \(s_i=w_i^\top x\)，\(w_i\) 是 \(W_r\) 的第 \(i\) 行。假设初始化时输入零均值、协方差为 \(\sigma_x^2I\)，那么 \(\mathrm{Var}(s_i)=\sigma_x^2\lVert w_i\rVert^2\)。行范数越大，打分分布越宽，进入 top-k 正尾部的概率也会受到影响；一旦路由偏斜，不同 expert 获得的训练机会就会分化。Qwen3-Next 用归一化的 router 初始化减小这一偏差。一种可以手算的实现来自 σ-MoE：先从 \(\mathcal N(0,1)\) 采样，把每一行缩放到单位范数，再整体缩放到目标尺度。这个例子解释了行范数归一化的作用；Qwen3-Next 的训练说明给出的是归一化初始化这一设计。对一个给定输入，初始打分 \(s_i=\lVert w_i\rVert\lVert x\rVert\cos\theta_i\) 的行范数因子一致，expert 之间的差别由夹角决定。实际训练仍需第 9 节的负载均衡来约束路由分布。

10.3 小结：几处稳定性设计

  • 注意力输出门：消除 attention sink 和 massive activation（第 7 节）；
  • 零中心 + 权重衰减的 Norm：防止 Norm 权重异常增长；
  • 归一化 router 初始化：避免早期路由的随机偏向；
  • Gated DeltaNet 内部：\(q,k\) 的 L2 归一化让转移矩阵谱范数不超过 1，输出 RMSNorm 控制尺度。

这些设计让小规模实验更可靠，大规模训练更平稳。对做预训练的人来说，前半句其实更重要——小模型上的消融结论能不能外推，很大程度取决于训练是否稳定。

11. 多 token 预测与投机解码

11.1 MTP 模块的结构

标准语言模型在位置 \(t\) 只预测 \(x_{t+1}\)。多 token 预测（MTP）在训练时额外让模型预测 \(x_{t+2}\) 等更远的 token，给主干更密的训练信号；推理时，这个额外的预测头可以当草稿模型用。Qwen3-Next 的 MTP 模块和 DeepSeek-V3 一样是串行组织的，结构如下：

  1. 输入两样东西：主干最后一层在位置 \(t\) 的隐状态 \(h_t\)，以及下一个 token \(x_{t+1}\) 的嵌入 \(e(x_{t+1})\)（与主干共享嵌入表）；
  2. 两者各自过一个 RMSNorm（pre_fc_norm_embedding、pre_fc_norm_hidden），拼接成 4096 维，经线性层 fc 投回 2048 维；
  3. 过 1 个完整的 Transformer 层（全注意力 + MoE，和主干的注意力层同构）；
  4. 最后一个 RMSNorm，再用（共享的）输出头预测 \(x_{t+2}\)。

训练目标是在主干的下一 token 交叉熵之外加上 MTP 头的交叉熵（DeepSeek-V3 的做法是乘一个权重 \(\lambda\) 后相加；Qwen3-Next 用的权重没有公开）。MTP 有两个作用：一是更密的训练信号本身提升了模型的整体表现；二是推理时当草稿模型。Qwen3-Next 只有 1 层 MTP，要起草多个 token，就把同一个 MTP 层递归地用多次：第二步的输入是它自己第一步的输出。如果训练时只见过主干给的隐状态，这种递归用法就和训练不一致，越往后猜得越差。所以 Qwen3-Next 专门做了「训练与推理一致的多步训练」，以提高多步起草时的接受率。

11.2 投机解码

投机解码让便宜的草稿模型先猜 \(\gamma\) 个 token，主干用一次前向并行验证。设当前位置的主干、草稿分布分别为 \(p_{\rm main}\)、\(p_{\rm draft}\)，草稿 token 为 \(z\)，接受概率是 \(\min(1,p_{\rm main}(z)/p_{\rm draft}(z))\)。遇到第一个拒绝位置，从归一化后的 \(\max(p_{\rm main}-p_{\rm draft},0)\) 采样一个纠正 token；若全部接受，再从主干分布多采样一个 token。这套接受与纠正规则保持主干的目标采样分布。

如果每个草稿 token 被接受的概率是独立同分布的 \(p\)，一次验证平均产出的 token 数是

$$\mathbb E[\text{tokens}]=\frac{1-p^{\gamma+1}}{1-p}.$$

MTP 头当草稿模型的好处：它只有一层，起草很便宜；它读的是主干的隐状态，比独立的小模型更「懂」主干，接受率更高；而且是和主干一起训练出来的，不用另外蒸馏。推荐的部署参数是 SGLang --speculative-num-steps 3 --speculative-num-draft-tokens 4、vLLM num_speculative_tokens: 2。

混合模型需要一起管理三种历史：全注意力的 KV、Gated DeltaNet 的矩阵状态，以及短卷积的局部输入。假设前缀 \(T\) 已完成计算，一轮验证接受了前 \(r\) 个草稿，继续生成所需的是位置 \(T+r\) 的这三份状态。KV 可以调整有效长度；递归矩阵和卷积窗口则恢复到对应检查点，或从较早的检查点重放已接受的输入。补采样出的纠正 token 随下一次前向写入缓存。

vLLM 的 GDN 路径把已接受数量同时传给卷积更新与递归状态更新，卷积窗口还会额外保留投机长度。一个直接的正确性实验是强制接受 0、1、全部草稿三个分支，逐一与“从头计算已接受前缀”得到的下一步 logits 比较；再改变 batch 行顺序并插入新请求，检查状态是否仍归属于原来的序列。这个实验能同时检验回退、状态寻址与请求隔离。

15. 工程实践：让同一个前缀得到同一个结果

15.1 Prefix 复用与 MTP 回滚，都在恢复一个计算边界

两个请求共享一段 system prompt，希望跳过重复的 prefill；一轮 MTP 验证拒绝了后两个草稿，希望从已经接受的位置继续。这两件事有同一个要求：恢复模型处理完某个前缀后的完整状态。

把“已经计算完前 \(t\) 个输入 token”定义为一个边界。对 Qwen3-Next 主干，这个边界包含 12 个注意力层的 KV、36 个 Gated DeltaNet 层的递归矩阵、36 个短卷积层的输入历史，以及下一步使用的位置。可把这一组对象记成

$$\mathcal C_t=\big(\{K_{1:t},V_{1:t}\}_{\rm attn},\;\{\htmlData{symbol=qn-recurrent-state}{S_t},\htmlData{symbol=qn-conv-history}{H_t}\}_{\rm GDN},\;t\big).$$

这里 \(S_t\) 是处理完第 \(t\) 个输入后的矩阵记忆；\(H_t\) 是继续短卷积所需的近期输入。\(\mathcal C_t\) 是整个模型的 snapshot，各层的位置必须一致。采样器刚刚产出的 token，要等下一次前向处理后，才进入这个 snapshot。

Prefix caching 可以保存常用前缀末端的 \(\mathcal C_t\)。新请求命中时，注意力 KV 的完整页可以引用同一份只读数据；开始续写后，再为新的 KV 页和会原地更新的 \(S_t,H_t\) 分配各自的空间。缓存键需要覆盖实际输入 token、模型与 adapter、位置编码设置等影响计算的条件。复用同一个前缀的两个分支，各自续写 A 和 B，结果应分别等于从头计算“前缀 + A”和“前缀 + B”。这个对照同时检验前缀命中和分支隔离。

递归矩阵只保留当前前缀的摘要。若只保存了长度 4096 的 \(S_{4096}\)，要复用长度 3072 的前缀，就需要另一个 3072 检查点，或从更早的检查点重放到 3072。因而混合模型的前缀索引还要记录“哪些边界保存了递归状态”。缓存更多边界能提高命中覆盖率，每个边界也会多占一份固定大小的状态。

MTP 验证也沿着这个边界提交。假设原前缀长度为 \(T\)，草稿有 \(g\) 个 token，验证接受前 \(r\) 个。下一轮从 \(\mathcal C_{T+r}\) 出发：KV 的有效长度退到 \(T+r\)，矩阵和短卷积历史恢复到同一个位置。实现可以保存草稿中间状态，也可以保存轮首状态后重放被接受的 \(r\) 个输入。前者用额外显存换恢复速度，后者把成本放在重放计算上。MTP 模块自己的注意力缓存也要遵守对应的输入边界。

一个一维例子能看到遗漏状态的后果。取卷积输入 \(u_t\)，左侧补零，卷积输出为 \(v_t=0.1u_{t-3}+0.2u_{t-2}+0.3u_{t-1}+0.4u_t\)。令 Delta 规则中的 \(q=k=1\)、\(\alpha=1\)、\(\beta=0.5\)，于是 \(S_t=0.5S_{t-1}+0.5v_t\)。这些教学参数让每次更新都能手算。

前缀输入为 \([1,2,3,4]\)。接受草稿 5 后，\(S=3.08125\)，卷积历史为 \([3,4,5]\)。草稿 6 虽然被拒绝，验证时已经把临时状态更新到了 \(S=4.040625\)、历史 \([4,5,6]\)。恢复两份状态后处理替代输入 7，得到 \(v=5.4\)、\(S=4.240625\)；若仅裁短 KV，继续使用被 6 改写的历史，就会得到 \(v=6\)、\(S=5.0203125\)。错误从一次拒绝开始，随后会随递归继续传播。

实际诊断时，固定权重和输入，分别强制接受 0、1、全部草稿，比较下一次前向的 logits 与完整前缀重算结果；再交换 batch 中两个请求的位置，检查结果是否仍跟随请求 ID。若完整接受正常、首次拒绝后立刻偏离，先比较接受边界处每层的矩阵状态和卷积历史。若交换 batch 后才偏离，检查请求到状态槽的映射。逐层找到第一个差异，比只观察最终生成文本更容易定位原因。

15.2 短卷积保存什么，决定了 prefill 能怎样切块

Qwen3-Next 的短卷积接在输入投影之后。每个 token 投影出 2048 个 Q 通道、2048 个 K 通道和 4096 个 V 通道，拼成 \(u_t\in\mathbb R^{8192}\)。核长为 4 的 depthwise 卷积，在每个通道上计算最近四个输入的加权和：

$$\widetilde u_t=\sum_{j=0}^{3}w_j\odot u_{t-j},\qquad H_t=(u_{t-2},u_{t-1},u_t).$$

这里 \(w_0\) 乘当前输入，\(H_t\) 保存下一步所需的三个旧输入；每个 \(u_t\) 都是这一层投影后、卷积前的 8192 维向量。随后才做 SiLU、拆回 Q/K/V、归一化 Q/K，并更新递归矩阵。卷积历史和矩阵摘要处在计算图的不同位置，需要分别保存。

把长 prompt 切成两段时，第二段的前 3 个位置仍会访问第一段尾部的输入。例如第一段以 \([u_{a-2},u_{a-1},u_a]\) 结束，第二段从 \(u_{a+1}\) 开始，第一次卷积应使用这四个向量。前一段的 \(S_a\) 同时作为第二段 Delta 递推的初始状态。这样，整段 prefill、分段 prefill 和逐 token decode 才能表示同一条递推。

缓存容量要区分数学上必需的历史与 kernel 的物理布局。三个旧输入足够计算下一步；原地更新实现可以保留含当前槽的 4 个位置，投机实现还可以附加草稿窗口。按 bf16、36 层、8192 通道计算，3 槽历史是 1.6875 MiB，4 槽是 2.25 MiB。若物理窗口为 \(3+g\) 槽，则用 \(36\times8192\times(3+g)\times2\) 字节计算，再乘并发序列数。矩阵状态若用 fp32，则单个主干 snapshot 为 72 MiB。

这些容量是整份模型的逻辑合计。部署时再按实际 TP 分片、KV 复制策略、状态 dtype 和检查点个数分到各张卡。尤其是只有 2 个 KV 头时，TP 继续扩大，KV 是否复制取决于框架的分片方式；直接把所有缓存除以 TP 会低估某些配置。

Continuous batching 还会反复回收请求槽。请求结束后，KV 页的引用计数、矩阵状态、卷积历史、有效长度与初始化标记一起释放或重置。短 prompt 的左侧补零只发生在序列起点；后续 chunk 从历史继续。可用长度 1、3、4、5 的 prompt 检查卷积边界，再将它们混在同一个 batch 中反复插入、移除，观察结果是否与逐请求执行一致。

15.3 单 token 的 10 个 expert，如何变成一个 batch 的小矩阵

80B-A3B 的 A3B 描述单个 token 的计算路径。部署时，一个 batch 中的请求通常会走不同 expert，整轮触达的权重集合会大得多。令 \(B\) 为这一轮进入某一 MoE 层的 token 总数，\(E=512\) 为 routed expert 数，\(k=10\) 为每 token 选择数。第 \(e\) 个 expert 收到 \(n_e\) 个 token，则

$$\sum_{e=1}^{E}\htmlData{symbol=qn-expert-tokens}{n_e}=\htmlData{symbol=qn-batch-tokens}{B}\,k,\qquad \overline n=\frac{Bk}{E}.$$

decode 每个请求只送一个新 token 时，\(B\) 等于本轮参与的请求数；prefill 时，\(B\) 还包含各请求本轮处理的多行输入。\(n_e\) 是这个 expert 的 GEMM 行数，它比模型总 batch 更直接地决定矩阵乘是否足够大。

以每个 token 独立、均匀地选 10 个不同 expert 为基准，一个 expert 未被某个 token 选中的概率是 \(1-10/512\)。因此，整轮至少被触达一次的 expert 数 \(U\) 的期望为

$$\mathbb E[U]=512\left[1-\left(1-\frac{10}{512}\right)^B\right].$$

当 \(B=32\) 时，平均每个 expert 只有 0.625 行，却会触达约 239.64 个 expert；当 \(B=512\) 时，平均每个 expert 有 10 行，几乎全部 512 个 expert 都被触达。真实路由有内容相关性，可把实测 \(n_e\) 直方图与这个均匀基准比较。每个 expert 的三块 SwiGLU 权重共 \(3\times2048\times512\) 个参数，bf16 是 6 MiB；按每个被触达 expert 读取一份权重估算，\(B=32\) 的这一层约涉及 1438 MiB 权重。权重复用与缓存命中率会继续改变实际 HBM 流量。

为了看清小矩阵的代价，假设一个教学 kernel 沿 token 维每 16 行分配一个 tile。\(n_e=1\) 和 \(n_e=15\) 都占一个 tile；\(n_e=17\) 占两个。整个 routed 分支的行填充率就是

$$\eta_{\rm rows}=\frac{\sum_e n_e}{16\sum_e\lceil n_e/16\rceil}.$$

分子是有效的 token–expert 计算行，分母是按 16 行取整后分配的行，空 expert 对分母贡献为零。单 token 选 10 个 expert 时，填充率只有 \(10/(10\times16)=6.25\%\)。实际 GEMM kernel 的 tile 大小、布局和 masking 策略由硬件与实现决定，这个公式提供了检查 padding 的方法。Grouped GEMM 把许多小 expert 组合进少量 launch；增大 batch 能增加每个 expert 的有效行，但也会增加等待时间和 KV 占用。

Expert parallel 再把这些行送到持有权重的 GPU。令 \(P\) 为 EP rank 数，隐藏维度 \(d=2048\)，每元素 \(b=2\) 字节。采用“每个 token–expert assignment 分别发送输入、返回输出”的基准协议，并假设 expert 均匀分布、命中本地的比例为 \(1/P\)，整组 GPU 一层的远程 payload 为

$$V_{\rm group}=2Bkdb\left(1-\frac1P\right).$$

开头的 2 对应 dispatch 和 combine 两个方向。这里每条消息在发送端计一次字节；\(V_{\rm group}\) 是整个 EP 组的总发送量。均衡时每个 rank 平均发送 \(V_{\rm group}/P\)，同时接收同量数据。以整组 \(B=256\)、\(P=8\) 代入，一层是 17.5 MiB，48 层合计 840 MiB；单个 rank 平均每层发送 2.1875 MiB、接收 2.1875 MiB。这份账本只计向量 payload，实际协议还要处理路由索引、权重、对齐、拓扑和同步。

同一 token 选中的多个 expert 若在同一张卡上，可以把输入按目的卡合并发送，并在返回前局部归并输出；通信量因此还取决于每个 token 触达多少个不同 rank。shared expert 处理全部 \(B\) 行，可以在通信期间执行它的矩阵乘，前提是 SM、带宽与依赖关系允许重叠。部署选择 prefill 吞吐路径还是 decode 低延迟路径，也与这组形状有关：大量 token 时优先连续布局与带宽，小 batch 时 launch、路由计数和同步更容易进入关键路径。

判断“MoE 很稀疏却没有变快”时，可以一次记录四组量：每个 expert 的 \(n_e\) 与最大值、有效行/分配行、dispatch/combine 的 GPU 时间、expert GEMM 的时间与 launch 数。保持输入和路由不变，分别改变 batch、Grouped GEMM 实现和 EP 布局。若 GEMM 很短而 launch 间隙明显，融合与 CUDA Graph 更值得尝试；若少数 rank 总是最后完成，检查 expert 热度、映射和副本；若通信随跨节点 assignment 明显增长，检查本地性和链路。这样能把算法的稀疏率转成可测量的硬件问题。

16. 计算与诊断练习

每题的数值都可以用下面的 NumPy 实验核对。计算缓存时使用 \(1\,\mathrm{MiB}=2^{20}\) 字节、\(1\,\mathrm{GiB}=2^{30}\) 字节。

练习 1：两步递推，怎样变成一次三角求解？

取一个标量头，初始状态 \(S_0=0\)，两个位置均有 \(q=k=1\)、\(\alpha=\beta=0.5\)，值为 \(v_1=2,v_2=4\)。先逐步求 \(S_1,S_2\)，再用第 5 节的 \(A,U,W,\Delta\) 验证块输出。这里采用未缩放的 \(q=1\)。

解。标量递推为 \(S_t=\alpha(1-\beta)S_{t-1}+\beta v_t=0.25S_{t-1}+0.5v_t\)，所以 \(S_1=1,S_2=2.25\)。块内 \(\gamma=(0.5,0.25)\)，\(\Gamma_{21}=0.5\)，严格下三角矩阵只有 \(A_{21}=\beta_2\Gamma_{21}k_2k_1=0.25\)：

$$I+A=\begin{pmatrix}1&0\\0.25&1\end{pmatrix},\quad U=\begin{pmatrix}1\\1.75\end{pmatrix},\quad W=\begin{pmatrix}0.25\\0.0625\end{pmatrix}.$$

因为 \(S_0=0\)，\(\Delta=U\)。输出为 \(O_1=1\)、\(O_2=0.5\times1+1.75=2.25\)；块末状态同样是 \(0.5\times1+1.75=2.25\)。若把 \(A_{21}\) 的衰减漏掉，三角求解会产生错误的第二个写入量，即使末尾再乘一次总衰减也补不回来。

练习 2：8 条 32K 请求，要保存多少推理状态？

使用 Qwen3-Next 的 12 个全注意力层、每层 2 个 KV 头、头维 256；KV 为 bf16。36 个 GDN 层每层保存 32 个 \(128\times128\) 的 fp32 矩阵，卷积历史按 8192 通道、3 个 bf16 槽计算。8 条请求各有 32768 个已处理 token，不共享前缀。求逻辑总容量；若每条请求额外保留两个“矩阵 + 卷积”的检查点，又增加多少？

解。每 token 的 KV 是 \(12\times2\times2\times256\times2=24576\) 字节，即 24 KiB。一条 32K 请求的 KV 为 768 MiB；递归矩阵为 \(36\times32\times128\times128\times4=72\) MiB；卷积为 \(36\times8192\times3\times2=1.6875\) MiB。一条请求合计 841.6875 MiB，8 条共 6733.5 MiB，约 6.576 GiB。

额外两个检查点增加 \(8\times2\times(72+1.6875)=1179\) MiB，约 1.151 GiB。原始 KV 页可以通过引用和有效长度复用。若运行时卷积使用 4 槽，先把每份卷积改成 2.25 MiB；MTP 自身缓存、临时 workspace、页尾空槽与框架元数据另行加入。这是逻辑容量账本，分到各 rank 时还需使用实际的分片与复制规则。

练习 3：拒绝草稿之后，为什么恢复一半状态仍然会错？

使用第 15.1 节的一维例子：接受 5 后 \(S=3.08125,H=[3,4,5]\)；暂算 6 后 \(S=4.040625,H=[4,5,6]\)。6 被拒绝，接下来处理 7。分别计算“完整恢复”“只恢复矩阵”“只恢复卷积”“两者都保留临时值”的结果。

解。正确历史给出 \(v=0.1\times3+0.2\times4+0.3\times5+0.4\times7=5.4\)，被污染的历史给出 \(v=6\)。因此四种结果分别为：

恢复方式下一步状态与完整恢复的差
矩阵与卷积都恢复4.2406250
只恢复矩阵4.5406250.3
只恢复卷积4.72031250.4796875
两者都保留临时值5.02031250.7796875

KV 的有效长度在四种情况下都可以裁到接受位置，但只有第一行满足完整前缀的递推。诊断时分别检查矩阵和卷积误差，就能分辨丢失的是哪一份历史。

练习 4：平均不到一行的 expert batch，实际浪费多少 tile？

某轮有 \(B=32\) 个 token，每个选 10 个 expert。路由结果中，120 个 expert 各收到 1 行，60 个各收到 2 行，20 个各收到 4 行，其余为空。假设每个非空 expert 按 16 行分配 tile。求有效行数、非空 expert 数和行填充率。再求 \(B=512\)、512 个 expert 恰好各收到 10 行时的填充率。

解。第一轮有效行数是 \(120+60\times2+20\times4=320=32\times10\)，非空 expert 有 200 个，分配 \(200\times16=3200\) 行，填充率为 10%。平均值 \(320/512=0.625\) 行包含了空 expert，所以要用实际直方图计算 padding。

第二轮有效行数为 5120，分配 \(512\times16=8192\) 行，填充率为 62.5%。这轮负载完全均衡，仍存在 tile 尾部空行。负载均衡与矩阵形状是两项独立的优化目标。行填充率描述这个 16 行教学模型的容量使用，GPU 利用率还取决于 GEMM、访存和调度。

练习 5：EP 的 17.5 MiB，究竟是谁发送的？

一个 8-rank EP 组共处理 256 个 token，每个选择 10 个 expert，隐藏维度 2048，输入与返回输出均为 bf16。均匀路由下，\(7/8\) 的 assignment 走远程。使用每 assignment 单独 dispatch 和 combine 的基准协议。求一层和 48 层的整组发送量，以及单个 rank 一层平均的发送/接收量。

解。远程 assignment 期望数量为 \(256\times10\times7/8=2240\)。每个方向发送 4096 字节，往返合计 \(2240\times4096\times2=18{,}350{,}080\) 字节，即 17.5 MiB。48 层是 840 MiB。均匀分配后，每个 rank 每层发送 \(17.5/8=2.1875\) MiB，也接收 2.1875 MiB。

整组发送量统计每条消息一次，已包含 dispatch 与 combine。用它估算链路时间时，需要将流量放回实际链路：单 rank 带宽、跨节点 uplink、双向流量和共享链路都会影响结果。若按目的 rank 合并同一 token 的多次发送，需重新统计目的 rank 并集，再更新这份账本。

练习 6：拒绝后怎样采样，才能保留主干分布？

一个三 token 词表 \((a,b,c)\) 上，主干概率 \(p=(0.5,0.3,0.2)\)，草稿概率 \(q=(0.6,0.1,0.3)\)。计算各草稿的接受概率、总接受概率、拒绝后的纠正分布，并验证最终输出分布为 \(p\)。

解。接受概率为 \(\min(1,p/q)=(5/6,1,2/3)\)。乘以草稿概率，直接接受三个 token 的概率质量分别是 \((0.5,0.1,0.2)\)，总和 0.8，拒绝概率为 0.2。

正差 \([p-q]_+=(0,0.2,0)\)，归一化后纠正分布为 \((0,1,0)\)。把拒绝后的这 0.2 全部补给 \(b\)，最终分布成为 \((0.5,0.3,0.2)=p\)。如果拒绝后直接重新按 \(p\) 采样，结果会变成 \((0.5,0.1,0.2)+0.2p=(0.6,0.16,0.24)\)。接受与纠正分布共同保证概率正确，状态回滚则保证下一步计算使用相同的已接受前缀。

18. 小结

  • 线性注意力把 softmax 换成内积后，注意力变成一个以 \(d_k\times d_v\) 矩阵为状态的 RNN：训练可以分块并行，decode 每步常数代价，没有 KV cache。代价是固定容量的有损记忆。
  • Delta 规则把写入改成「对平方损失做一步在线梯度下降」，能改写已有的键；门控能整体遗忘。Gated DeltaNet 把两者结合，靠 UT 变换做到块内并行。
  • Gated Attention 在 SDPA 输出后加逐元素 sigmoid 门，给低秩的 \(W_VW_O\) 加了非线性，并通过稀疏门消除 attention sink 和 massive activation。
  • 3:1 混合：36 层线性注意力 + 12 层全注意力，KV cache 降到全注意力版的 1/4，长上下文下仍保留精确检索能力。
  • 512 选 10 + 1 的 MoE：激活宽度和 Qwen3-30B-A3B 相当，总参数多 2.6 倍；配合全局 batch 的负载均衡和归一化的 router 初始化。
  • 零中心 Norm + 权重衰减：让 Norm 增益的权重衰减拉向 1 而不是 0。
  • MTP：一层的串行 MTP 模块，训练时提升效果，推理时做投机解码的草稿，并做了多步训练以提高多步起草的接受率。

如果只记一件事：Qwen3-Next 的效率来自两个正交的方向——沿序列方向用线性注意力把大部分层的成本从 \(O(L)\) 降到 \(O(1)\)，沿参数方向用高稀疏 MoE 把每 token 的计算和总参数解耦。两者叠在一起，才有「训练成本约为 Qwen3-32B 的 9.3%、32K 以上吞吐超过 10 倍」的结果。
