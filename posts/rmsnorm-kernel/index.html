RMSNorm 与 GPU 算子优化

交互2026-10-19更新于 2026-10-22

Transformer 中一行 hidden state 往往有几千个元素。RMSNorm 先用整行的均方根调整尺度，再逐元素乘可学习的增益。计算只含平方、归约和乘法，却会在模型的许多层反复出现：小 batch 时容易暴露启动开销，大 batch 时则要求尽量少搬动数据。

从均方根写出前向

把输入看作 \(R\times D\) 矩阵，R 是 token 行数，\(\htmlData{symbol=d}{D}\) 是 hidden 维度。每行独立归一化，增益 \(\gamma\in\mathbb R^D\) 在所有行之间共享。对其中一行 x，定义均方值 m、逆均方根 r 和输出 y：

$$m=\frac1D\sum_{j=0}^{D-1}x_j^2,\qquad \htmlData{symbol=r}{r}=(m+\htmlData{symbol=eps}{\varepsilon})^{-1/2},\qquad y_j=\gamma_jx_jr.$$

ε 通常取正值，为接近零的行提供有界的归一化系数；增益 γ 可以为不同特征学习不同尺度。LayerNorm 还会先减去行均值，RMSNorm 直接使用平方均值。忽略 ε 时，对输入乘正数 a，分子与均方根同时乘 a，所以归一化后的数值保持不变。

当 x=[1,2,3,4]、ε=0，平方和为 30，m=7.5，r≈0.365148。先乘 r 得到 [0.3651,0.7303,1.0954,1.4606]，再乘 γ=[1,1,2,0.5]，得到 [0.3651,0.7303,2.1909,0.7303]。增益改变各维相对幅度，因此最终 y 的 RMS 取决于 γ。

反向中的整行修正项

记上游梯度为 \(g_j=\partial\mathcal L/\partial y_j\)，先把增益乘进来，令 \(u_j=g_j\gamma_j\)。x 一方面直接出现在 y 中，另一方面通过均方值改变整行共用的 r。对 r 求导：

$$\frac{\partial r}{\partial x_i}=-\frac{x_i}{D}r^3.$$

把所有输出对 r 的依赖汇总，定义 \(a=D^{-1}\sum_j u_jx_j\)，输入梯度为

$$\frac{\partial\mathcal L}{\partial x_i}=r u_i-r^3x_i a.$$

第一项是固定归一化系数时的局部梯度；第二项来自 x 改变均方根后对整行输出的影响。实现时令 \(\hat x=xr\)，可以写成 \(dx=r[u-\hat x\,\operatorname{mean}(u\hat x)]\)，因此每行还需一次归约。前向把每行的 r 保存下来，反向即可复用。

γ 在所有 token 行之间共享，所以它的梯度沿行归约。恢复行索引 t 后，\(d\gamma_j=\sum_{t=0}^{R-1}g_{tj}x_{tj}r_t\)。dx 的归约沿 D，dγ 的归约沿 R，这个方向差异直接决定后面两个 kernel 的划分。

精度由每一步的类型决定

平方和采用 FP32 累加很重要。FP16 最大有限值约为 65504，输入 300 的平方已超过它；先转 FP32 再平方可以保留这个值。BF16 的指数范围较大，但尾数较短，长序列顺序加和可能很早就吞掉较小增量。归约树和 FP32 累加可以显著减小这种误差。

融合前还要确认类型转换的位置。bf16(x*r)*gamma 与 bf16(x*r*gamma) 的舍入点不同，逐位结果可能不同。要与一个模型实现对齐，应把其 ε、累加类型、归一化后转换和增益乘法顺序写进参考实现，再决定允许的误差。

有些实现先把 x 除以正的尺度 s，以控制平方范围。要保持原公式，必须同时把稳定项变成 \(\varepsilon/s^2\)：

$$\frac{x/s}{\sqrt{\operatorname{mean}((x/s)^2)+\varepsilon/s^2}}=\frac{x}{\sqrt{\operatorname{mean}(x^2)+\varepsilon}}.$$

若缩放 x 后仍加原 ε，等价于把原分母中的 ε 放大到 \(s^2\varepsilon\)。当输入有少量尖峰而整体 RMS 较小时，这种变化尤其明显。这个恒等式可以用于审查低精度转换、导出图和自定义 kernel 中的数值稳定化步骤。

融合减少中间张量的流量

把输入转换成 FP32、平方、求均值、加 ε、取 rsqrt、乘 r、转回 BF16、乘 γ，如果每一步独立执行，会产生多次 kernel launch 和中间张量写读。按这条具体的分解路径计算，大张量每元素约搬 36 B。融合 kernel 在片上完成这些步骤，BF16 输入读 2 B、最终输出写 2 B，主张量流量降为 4 B/元素。

R=4096、D=8192 时，主张量读写共 \(4RD=134217728\) B，即 128 MiB；保存 r 另加 16 KiB，冷读 γ 约 16 KiB。若把 HBM 带宽取为 3.35 TB/s，主张量传输下界约 40.1 μs。这个量级远大于少数逐元素算术所需时间，因此大输入的优化重点是流量和访存效率。

一行放到一个 block 里

R 行彼此独立，可以让一个 block 负责一行。D=4096、block=256 线程时，每线程负责 16 个值，先在寄存器里求局部平方和。32 个 lane 的局部和经过 warp shuffle，逐轮把覆盖范围加倍；5 轮后能得到一个 warp 的总和。

跨 warp 的合并需要 shared memory 中转：各 warp 的代表写入部分和，同步后由一个 warp 再次归约，求得整行 r。随后所有线程用同一个 r 缩放各自保留的 x。小 D 可以让一个 warp 负责一行，以降低 block 同步和资源开销。

输入留在寄存器里，可以在求得 r 后直接使用，减少第二遍读取。D 增大而线程数固定时，每线程保留的元素也增多，可能降低 occupancy 或产生 spill。比较“保留 x”和“归约后重读 x”两种策略时，同时记录 registers/thread、local-memory 流量和时间，才能判断寄存器容量是否值得换这次读取。

向量化、对齐与尾部

128-bit 加载一次可读取 8 个 BF16。沿行连续的数据满足相应对齐时，宽加载能减少访存指令数。假设 32 个 lane 各取 8 个 BF16，一条 warp 指令覆盖 512 B；标量路径需要更多指令才能覆盖同样的数据。

快速路径需要输入行首与输出行首满足对齐、末维连续，并正确处理剩余元素。D=1025 时，可以对 1024 个元素执行完整向量访问，最后一个元素使用有界标量访问。Triton 常把归约宽度补到 2048，并用 mask 让无效 lane 加零；均方值的分母仍取真实 D=1025。

下面的 Triton 前向为每行建立一个 program，输入、输出各用自己的行 stride，末维按连续布局访问：

@triton.jit
def rms_fwd(X, W, Y, R, sx, sy, D: tl.constexpr,
            eps: tl.constexpr, BLOCK: tl.constexpr):
    row = tl.program_id(0)
    col = tl.arange(0, BLOCK)
    valid = col < D
    x = tl.load(X + row*sx + col, valid, other=0.).to(tl.float32)
    w = tl.load(W + col, valid, other=0.).to(tl.float32)
    r = tl.rsqrt(tl.sum(x*x, axis=0) / D + eps)
    y = x * r * w
    tl.store(Y + row*sy + col, y, valid)
    tl.store(R + row, r)
# BLOCK = triton.next_power_of_2(D)
# grid = (rows,); num_warps 按 hidden size 与资源占用调优

编译器会根据布局把 load、归约和乘法映射到设备指令。宽行仍可能产生过高资源需求，因此 BLOCK 与 num_warps 的选择应通过实际代码和 profiler 检查。面对有非单位末维 stride 的输入，可以提供通用 stride 路径，或在调用边界选择适合该输入的实现。

残差、量化与反向的归约布局

Pre-norm 路径常先执行残差相加，再做 RMSNorm。如果分开处理 BF16 数据，相加读两份、写一份为 6 B/元素，norm 再读写为 4 B，共 10 B。融合后读两个输入、写回残差与归一化输出，共 8 B/元素，省去 norm 对残差结果的再次读取。

若下游 GEMM 消费 FP8，量化也可以在同一 kernel 内完成。动态 per-token 量化先对 y 求 \(\max|y|\)，计算尺度，再写低精度输出与每行尺度。对 E4M3 的最大有限值 448，常见尺度选择为 \(s_q=\max|y|/448\)，全零行需指定一个有效的非零尺度。输出量化的舍入点与残差是否保留，决定最终的流量和数值契约。

反向 dx 仍按行分工，读 x、dy、γ 和 r，完成一次行内归约。dγ 需要跨 token 相加，可以让 P 个 program 分别处理多行，写出 \(P\times D\) 的 FP32 部分和，再由第二阶段按列归约。这样每个 program 在寄存器里积累多行，减少对同一 γ 地址的 atomic 竞争。P 与临时缓冲大小也进入反向的资源账本。

反向缓冲容量怎样进入预算

假设 P=128 个 program 各产生 D=4096 个 FP32 的 dγ 部分和，临时缓冲为 \(128\times4096\times4=2\) MiB。第二阶段沿 P 归约，每个输出列得到一个 dγ。扩大 P 能增加第一阶段并行度，也会增加缓冲和第二阶段工作；当 R 较小时，过多 program 还可能只处理很少行。

残差融合也要保留训练所需的数据。若后续反向需要归一化前的残差值，就把残差写回或选择可重建它的保存策略。推理可以采用更激进的中间值复用，训练则要根据自动微分依赖确定存储生存期。两种路径共享前向数学，但完整的内存账本有所不同。

正确性与性能分别怎样验收

前向测试覆盖全零、极小值、正负大值、非 2 次幂 D、不同 γ 和非标准行 stride。反向先用 FP64 参考与中心差分，\(\partial L/\partial x_i\approx[L(x+he_i)-L(x-he_i)]/(2h)\)，例如 h=10⁻⁶。低精度 kernel 再与采用同样转换顺序的参考比较，分别报告最大绝对与相对误差。

R=1 的小输入侧重启动与调度，R 很大时更接近流量瓶颈。若性能在某个 D 后骤降，查看寄存器和 spill；若 D=1024 正确、1025 偏大，核对归约分母与尾部；若融合后误差明显，逐步比较转换、r 和增益乘法。用可区分这些机制的输入，比仅测试一个随机大矩阵更容易找到问题。

测得 128 MiB 主张量流量用时 50 μs，有效带宽约 2.684 TB/s。解释这个数字前，固定 cache 策略、重复次数、r 和 γ 是否计入，以及实际是否发生额外读写。数据驻留 L2 时，同一公式算出的带宽对应的是有效流量口径，硬件 HBM 计数器提供另一项观测。最后把 residual→norm→quantize 整条路径计时，确认局部优化传递到了模型执行。

练习与实验

1. 两维前向与反向

x=[1,2]，γ=[1,2]，dy=[3,−1]，ε=0。求 y、dx、dγ，并检查 x·dx。

展开解答

\(r=1/\sqrt{2.5}\approx0.632456\)，\(y=[r,4r]\approx[0.632456,2.529822]\)。\(u=[3,-2]\)，\(a=\operatorname{mean}(ux)=-0.5\)，所以 \(dx=ru-r^3xa\approx[2.023858,-1.011929]\)。\(d\gamma=dy\odot xr\approx[1.897367,-1.264911]\)。\(x\cdot dx=0\)，与 ε=0 时正比例缩放不改变输出一致。

2. Padding 的除数

D=5，x 与 γ 全为 1，ε=0。填充到 BLOCK=8 后误把平方和除以 8，输出会怎样？

展开解答

有效平方和为 5，错误均方值为 5/8，输出变为 \(\sqrt{8/5}\approx1.264911\)，放大约 26.49%。正确分母为 D=5，输出为 1。

3. 50 μs 还有多少空间

主张量流量 128 MiB，实测 50 μs，假设 HBM 峰值 3.35 TB/s。算有效带宽、传输下界和相对该下界的加速空间。

展开解答

有效带宽为 \(134217728/(50\times10^{-6})\approx2.684\) TB/s。传输下界约 40.1 μs，50/40.1≈1.25 倍，对应延迟降低约 19.9%。该估计沿用同一读写口径。
