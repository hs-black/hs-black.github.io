RoPE 与长上下文扩展

交互2026-10-20更新于 2026-10-22

同一组词换一个顺序，意思就可能改变。Attention 的点积先比较 query 和 key 的内容，模型还需要把位置关系放进比较过程。RoPE（rotary position embedding）在每个头内旋转 Q、K 的二维通道对，让点积随两个位置的距离变化。

这个旋转会贯穿推理引擎：输入如何填充、缓存追加到哪里、长上下文采用哪组频率，都决定同一对 token 是否得到一致的相位。把旋转公式和缓存生命周期一起检查，才能解释“短输入正常，长输入或分块输入开始出错”的现象。

从二维旋转推导相对位置

取一个二维向量 \(x=[x_0,x_1]^\top\)。位置 \(m\) 对应角度 \(m\omega\)，其中 \(\omega\) 的单位是弧度/位置。旋转后：

$$R(m\omega)x=\begin{bmatrix}\cos(m\omega)&-\sin(m\omega)\\\sin(m\omega)&\cos(m\omega)\end{bmatrix}\begin{bmatrix}x_0\\x_1\end{bmatrix}.$$

旋转矩阵保持向量长度。Query 位于 \(m\)、key 位于 \(n\)，先分别旋转，再做点积：

$$\big(R(m\omega)q\big)^\top R(n\omega)k=q^\top R((n-m)\omega)k.$$

中间用到了 \(R(m\omega)^\top R(n\omega)=R((n-m)\omega)\)：先抵消 query 的旋转，再看 key 多转了多少。因此在内容向量固定时，同时给两个位置加上相同偏移，点积保持不变。

在图的初始状态，\(m=3,n=1\)。旋转后的 query 为 \([0,1]\)，key 为 \([\sqrt3/2,1/2]\)，点积为 0.5。若这是维度 \(d=2\) 的完整 attention 头，缩放后的分数为 \(0.5/\sqrt2\approx0.353553\)。Softmax 随后把这个分数与其他可见 key 的分数一起归一化。

一个头中的不同距离刻度

RoPE 在实际旋转的偶数维度 \(\htmlData{symbol=rotary-dim}{d_r}\) 内，每两维组成一对。第 \(j\) 对使用频率 \(\omega_j=b^{-2j/d_r}\)，\(j=0,\ldots,d_r/2-1\)，\(b\) 是频率底数。若 \(d_r=8,b=10000\)，四对频率为 1、0.1、0.01、0.001。高频对更敏感地分辨近邻，低频对在更长距离上缓慢变化。

通道布局是实现契约的一部分。相邻配对使用 (0,1)、(2,3)、(4,5)、(6,7)，半区配对使用 (0,4)、(1,5)、(2,6)、(3,7)。两者通过通道置换可以互相转换，转换时投影权重的输出顺序和 cos/sin 展开也要同步。替换 kernel 后若所有位置都偏离参考，先用二维单位向量逐对检查配对和旋转方向。

# x: [tokens, heads, rotary_dim]，相邻配对
phase = positions[:, None, None] * inv_freq[None, None, :]
a, b = x[..., 0::2], x[..., 1::2]
y[..., 0::2] = a * cos(phase) - b * sin(phase)
y[..., 1::2] = a * sin(phase) + b * cos(phase)

这里 positions 的长度等于本次输入 token 数，频率向量长度为 \(d_r/2\)，中间的单元素轴让所有头共享位置。使用 partial RoPE 时，旋转前 \(d_r\) 维，再拼接保留的其余通道；attention 分数的缩放按模型定义的完整头维度处理。

分块输入怎样接上已有缓存

假设已有 \(P=3\) 个历史位置，新 chunk 含 2 个 token。新的逻辑位置是 [3,4]，分别决定 Q、K 的旋转角度。位置 3 可读 key 0 到 3，位置 4 可读 key 0 到 4。新 chunk 的局部数组索引是 [0,1]，映射到逻辑位置时需要加上缓存前缀长度。

图中的 position id 始终递增，实际写入地址按 \(\mathrm{slot}=m\bmod4\) 计算。旋转使用逻辑位置 \(m\)，attention 按逻辑位置判断可见性，再通过槽位或页表找到 K/V。分页缓存改变的是最后这一步地址映射。

批量输入还会增加 padding。对 mask=[0,0,1,1,1] 的左填充请求，可以用 cumsum(mask)-1 为有效 token 构造位置 [0,1,2]，padding 位置填安全占位值。随后把真实 token 的位置与引擎的 cache_position 分开核对：一些接口把后者定义为缓存写入坐标。验证目标是短请求单独运行和组 batch 运行时，有效位置的结果一致。

把位置和张量轴接到同一个实现

多数错误来自“公式相同，数组约定不同”。假设一个向量为 [1,2,3,4]，角度的 sin=1、cos=0。相邻配对的输出为 [−2,1,−4,3]，半区配对的输出为 [−3,−4,1,2]。这个四维例子能快速判断 checkpoint 的投影顺序与旋转 kernel 是否一致，随后再加入多个头、多个 batch 和不同位置。

位置数组也要跟请求一起走。两条请求的有效长度分别为 5 和 9，一轮 decode 的新位置分别是 5 和 9；调度器把它们放进同一张量时，每条请求使用自己的位置。若缓存槽位复用，槽位编号只能用于寻址，逻辑位置由请求状态提供。调试记录可以同时列出 request id、position id、物理 block/slot 和当前 cache 长度，使一次错误能追到具体的映射步骤。

在计算路径上，sin/cos 通常对同位置的多个头复用。高效 kernel 会把旋转与 Q/K 的布局变换、缓存写入接在一起，减少中间张量落回 HBM 的次数。对短 decode，额外的一次小 kernel launch 也可能很显眼；先确认位置与数值一致，再通过 profiler 比较融合前后的 launch 数、读写字节与每步时间。

长上下文怎样改变频率

训练长度为 \(L\) 时，第 \(j\) 对大约经历相位范围 \([0,L\omega_j]\)。例如 \(L=4096,\omega_j=0.001\)，范围约为 4.096 rad；扩展到 16384 后达到 16.384 rad。模型需要学习如何使用扩展后的相位和距离。

线性插值把目标长度设为 \(L'=sL\)，并使用 \(m'=m/s\)，等价于所有频率除以 \(s\)。当 \(s=4\)，位置 12000 映射到 3000，距离 8 映射到 2。这样扩大了可覆盖的距离，同时改变局部位置的分辨率。

调整底数会按通道产生不同的拉伸。\(d_r=8\) 时，把底数从 10000 改为 160000，四对新旧频率的比值为 [1,1/2,1/4,1/8]。高频端保持更多局部刻度，低频端承担更大的距离拉伸。加载 checkpoint 时，应一起读取原始窗口、旋转维度、底数和缩放参数。

YaRN 进一步按频段混合原频率与插值频率。用训练窗口内的转圈数 \(r_j=L\omega_j/(2\pi)\) 判断频段，构造 \(\gamma_j\in[0,1]\)：

$$\omega'_j=\gamma_j\omega_j+(1-\gamma_j)\frac{\omega_j}{s}.$$

取 \(s=4\)，\(\gamma=0,0.5,1\) 分别给出频率比 0.25、0.625、1。实现还可能采用按频率索引定义的 ramp，以及 attention 幅度调整。若旋转后的 Q、K 都乘以系数 \(a\)，点积就乘以 \(a^2\)；两边各乘 1.1，会把 logits 放大为 1.21 倍。

长序列故障的三条检查路径

越过缓存预分配长度才失准。重点检查 cos/sin 重建。若频率缓冲随模型转换为低精度，扩容重建时会使用已经舍入的频率。把整数位置和原始频率保留在可靠精度中，以 FP32 计算相位与三角函数，最后转换结果；同时比较扩容前后的重叠区。已被低精度舍入的频率再转回 FP32，只能得到舍入后的值，应从配置重新生成频率。

改变 chunk 大小就改变输出。逐步打印每次调用的逻辑起止位置、旋转位置、缓存长度和 mask 边界，再与完整前向逐层比较。一个直接反例是 chunk 内每次都用 [0,1,…] 旋转：跨块位置差随之改变。频率固定后，chunk=1、3、5 应给出误差容忍范围内一致的输出。

运行中切换长度策略后失准。旧 K 已按旧频率旋转，新 Q 使用新频率，净相位变成 \(n\omega-m\omega'\)。请求开始时固定频率策略最容易保持一致性。若必须更换策略，多层模型需要重建受影响的历史计算，因为旧 hidden state 也已经吸收了旧 attention 的结果。

位置精度本身也需要测试：FP16 无法区分 2048 和 2049；BF16 在更短的整数范围外就开始出现相邻位置合并。用整数存储逻辑位置，在构造角度时转换为 FP32，能避免把这个信息提前丢掉。容量方面，位置插值保留全部 token；32 层、8 个 KV 头、每头 128 维、BF16 的普通 GQA，每个位置仍需 128 KiB，长度 32768 对应每条序列 4 GiB。

扩窗的质量评估可以沿着两个坐标做：总长度和目标所在位置。固定同一条待检索事实，把它分别放在开头、中间、结尾，再增加无关文本长度。接着改用需要跨段推理或重复实体消歧的任务。这些任务能同时检查模型的距离分辨能力与扩展后的信息利用率。

推理性能也随长度变化。生成的第一步要为全部 prompt 计算 Q/K/V；后续每轮还要读取可见历史。频率扩展只决定位置表示，容量与带宽需要用实际 token 数重新计算。若窗口从 8K 扩到 32K，固定 batch 的普通 GQA KV 容量增长四倍，长历史 decode 的读取量也随之增长。服务端可以结合分页缓存、请求准入和上下文预算控制峰值。

计算与排错练习

1. 共同平移之后的点积

q=k=[1,0]，ω=π/6，query 在 3、key 在 1。两者同时加 7 后，未缩放点积是多少？

展开解答

位置差保持 −2，点积为 cos(−π/3)=0.5。若完整头维度为 2，再除以 √2，分数约为 0.353553。

2. 插值与缓存容量

训练窗口 4096，线性插值扩展到 16384。位置 12000 映射到哪里？若每 token 的 KV 为 128 KiB，新窗口占多少？

展开解答

缩放因子 s=4，映射位置为 3000。实际 token 数仍为 16384，缓存为 16384×128 KiB=2 GiB。

3. 第二块的位置

前一 chunk 长度为 5，后一 chunk 长度为 3。写出后一块的 RoPE 位置及三行 causal mask 的最后可见位置。

展开解答

RoPE 位置为 [5,6,7]，三行分别可读到 key 5、6、7。mask 形状为 3×8，判断条件是 key_pos≤query_pos。

4. 切换频率后怎样复用历史

一个多层 decoder 生成途中从 ω 切换到 ω/4，只把旧 K 重新旋转能得到新配置的完整前向结果吗？

展开解答

完整一致性要求重建受影响的历史 hidden state 与各层 K/V。前层 attention 的变化已经进入后层输入。固定单层投影 Q/K/V 的实验可以隔离旋转误差；多层模型的参考应使用新配置重新执行历史前向。

把错误位置变成可复现的实验

下载 NumPy 实验，在保存文件的目录运行：

python3 -m pip install numpy
python3 lab.py --tokens 13 --dim 8 --chunk 3 --scale 4

输出会检查二维矩阵参考、旋转范数、相对位置不变性、完整与分块 KV 一致性，并主动检测位置归零和旧频率残留两类错误。把 chunk 改为 1、5，正确路径仍应通过。再把 scale 改为 1、8，观察错误路径的差值。实验使用单层固定投影和 FP64，便于把索引错误与低精度误差分开定位。
