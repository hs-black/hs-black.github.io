旋转发生在 Q、K 投影之后

X[T,D] → Q[T,Hq,d]，K[T,Hkv,d]，V[T,Hkv,d]
Q̂ₘ = R(m)Qₘ；K̂ₙ = R(n)Kₙ；score = Q̂ₘᵀK̂ₙ / √d

T 是 token 数，H 是头数，d 是每头维度；m、n 是逻辑位置。常见解码器旋转 Q 和 K，V 保留原来的表示。

GQA 可以有不同的 query / KV 头数；每个对应头使用兼容的位置旋转。

LLM 工程 · 原理与实现

两维一组：改变方向，保留长度

R(φ) = [[cos φ, −sin φ], [sin φ, cos φ]]
[x′, y′] = [x cos φ − y sin φ, x sin φ + y cos φ]

φ = mω：位置每前进一步，就转过 ω 弧度。旋转矩阵满足 RᵀR = I，所以 x′² + y′² = x² + y²。

弧度是角度单位；π/2 弧度就是 90°。

LLM 工程 · 原理与实现

点积里留下的是位置差

(R(mω)q)ᵀ(R(nω)k) = qᵀR(mω)ᵀR(nω)k
R(mω)ᵀR(nω) = R((n−m)ω)

先逆转 mω，再旋转 nω，净旋转就是 (n−m)ω。因此这一组通道的分数只通过位置差依赖 m、n。

这里固定 q、k 的内容向量；整层 hidden state 仍然会受到上下文与 causal mask 影响。

先保住位置精度，再谈低精度旋转

float16(2048) = float16(2049) = 2048

若先把大 position id 转成 FP16，相邻位置可能变成同一个数。随后乘频率、再升回 FP32，也找不回丢失的差别。

positions: integer → float32/float64
phase = positions * inv_freq    # 至少用合适的高精度计算
cos_phase, sin_phase = cos(phase), sin(phase)
# 根据 kernel 的精度契约，在合适的位置转换 dtype

实验用 float64 做数值参考；实际误差阈值应按 BF16/FP16 kernel 与模型质量验证。

练习 1 · 计算与排错

转两次，还是只看位置差

q = k = [1,0]，ω = π/4。key 在 n = 1，query 在 m = 3。求未缩放点积；若共同加 10 呢？
展开参考解答

相对角度为 (1−3)π/4 = −π/2，点积 cos(−π/2) = 0。共同加 10 后位置差仍为 −2，所以还是 0。浮点计算可能出现约 10⁻¹⁶ 的舍入误差。

练习 2 · 计算与排错

插值与显存要分别计算

训练窗口 4096，目标 16384，使用线性插值。新位置 12000 映射到哪里？32 层、8 KV 头、d=128、BF16 的一个请求，16384 token 需要多少 KV？
展开参考解答

s = 16384/4096 = 4，旋转位置为 12000/4 = 3000。KV = 2×32×16384×8×128×2 = 2,147,483,648 bytes = 2 GiB；旋转位置压缩不会减少存储的 token 数。

练习 3 · 计算与排错

两个 chunk，各自从 0 开始，错在哪里？

已有位置 [0,1,2]；新 chunk 本应是 [3,4]，却用 [0,1] 旋转，mask 仍然正确。比较新位置 3 与旧位置 2 的净旋转角。
展开参考解答

正确角度为 (2−3)ω = −ω；错误角度为 (2−0)ω = 2ω，差了 3ω。mask 只能限制可见性，无法修复错误分数。修复后用 chunk=1、2、3 与完整前向逐项比较。

练习 4 · 计算与排错

更换频率后，重转 K 就足够吗？

一个两层 decoder 把频率从 ω 改成 ω/4。只把两层的旧 K 重新旋转，就一定等价于用新频率重跑完整前缀吗？
展开参考解答

不一定。第一层旧 attention 输出可能改变，第二层的历史输入、Q/K/V 因而也应改变。重转已有 K 只修正旋转，不重算这些 hidden state。若要求与固定新频率的完整前向一致，应重建相关前缀计算，或始终固定请求的频率规则。
