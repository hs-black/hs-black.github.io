集合通信与分片矩阵乘法

交互2026-10-19更新于 2026-10-22

四张 GPU 各自算出一份张量之后，下一步可能是把不同通道拼起来，也可能是把同一输出的四份贡献相加。两种操作的 shape 有时看起来很像，数学含义却直接决定结果是否正确，以及网络需要搬多少数据。

理解集合通信，可以从“每个 rank 持有什么、操作后需要什么”开始。再把张量分片方式写进矩阵乘法，就能推导通信发生在哪里，并为一个并行方案估算时间和显存。

1. 用输入和输出定义一次 collective

一个 process group 包含 \(\htmlData{symbol=ranks}{N}\) 个 rank。每个 rank 按同一组约定参加集合操作。Broadcast 由一个 root 提供数据，结束后各 rank 持有相同副本；reduce 把各 rank 的对应元素组合起来，将结果交给 root；all-reduce 则让所有 rank 得到归约结果。

Gather 收集不同位置的数据，按 rank 顺序组合；all-gather 让每个 rank 都拿到完整组合。Reduce-scatter 先对完整逻辑张量归约，再把结果分片交给各 rank。因此它能直接产出下一层需要的分片布局，省去先复制完整结果、再本地切开的步骤。

操作rank r 的输入rank r 的输出
AllReduce SUM\(x_r\)，同形状的部分和\(\sum_j x_j\)
AllGather完整张量的第 r 个分片按 rank 顺序排列的所有分片
ReduceScatter SUM完整形状的部分和总和的第 r 个分片
AllToAll按目的 rank 分成 N 份所有来源发给 r 的那一份

All-to-all 相当于交换“数据在哪个设备上”的轴。例如 MoE 中按专家目的地打包 token，接收侧按来源接收后运行专家。变长版本中，每对发送和接收的 split size 要相互匹配。Barrier 表示这个 group 的参与者都到达同步点，适合明确阶段边界；频繁插入会切断本来可以重叠的计算和通信。

2. Ring all-reduce 的字节数从哪里来

设每个 rank 都持有 \(\htmlData{symbol=volume}{V}\) 字节输入，需要对相同位置做求和。Ring 把输入划成 \(N\) 块，每块 \(V/N\) 字节。第一个阶段沿环转发并累加：每一轮，各 rank 发送一块、接收邻居的一块，并加入自己的贡献。经过 \(N-1\) 轮，每个 rank 拥有一个块的完整和。

第二阶段从这些完整块出发，再走 \(N-1\) 轮，把它们散布到全部 rank。这个阶段只传播已经完成的结果。因此每卡总发送量为

$$V_{send}=2(N-1)\frac{V}{N}.$$

四卡、每卡 8 MiB 输入时，每轮发送 2 MiB，共六轮，每卡发送 12 MiB。所有 rank 同时工作；沿同一有向链路的连续轮次才会相互等待。

若所有 rank 先把完整输入送到 root，再由 root 广播总和，root 分别要接收和发送 \( (N-1)V \) 字节。Ring 把这些搬运分散到参与设备，让所有链路在每轮同时工作。

All-gather 与 reduce-scatter 各自只做一半过程，发送量为 \((N-1)V/N\)。这里对 all-gather 的 \(V\) 使用最终完整输出大小，对 reduce-scatter 使用每卡完整输入大小；这与输入/输出分片大小相差一个 \(N\)，调用 API 时要逐项核对。

3. 小消息看启动，大消息看可用带宽

把一轮通信的启动成本记作 \(\htmlData{symbol=latency}{\alpha}\) 秒，有效单向带宽记作 \(\htmlData{symbol=bandwidth}{\beta}\) B/s。Ring all-reduce 的模型为

$$T_{AR}\approx2(N-1)\alpha+\frac{2(N-1)V}{N\beta}.$$

前一项随轮次数增加；后一项由发送字节数除以带宽得到。取 8 个 rank、\(V=16\) MiB、\(\alpha=2\) μs、\(\beta=50\) GB/s，得到启动 28 μs，传输约 587.2 μs，总计约 615.2 μs。如果输入缩到 16 KiB，启动仍是 28 μs，传输只剩约 0.57 μs。

令两项相等，得到交叉消息大小 \(V_*=N\alpha\beta\)。增加 rank 会把交叉点推高，小张量更容易受启动延迟限制。Tree 等算法通过改变轮次和数据路径改善某些消息范围；实际库会根据拓扑、消息规模和协议选择算法。测量时覆盖应用真正使用的尺寸，才能知道模型每层的通信处在曲线哪里。

双向环可以同时使用两个方向，交换网络则允许多个设备对并发交换。可用吞吐最终受每卡注入带宽、共享节点出口和路径争用约束。常见的“节点内 TP、节点间 PP 或 DP”正是在把频繁小通信留在低延迟互联域。对一组 PCIe GPU，应先测目标 collective 的尺寸曲线，再决定 TP 增加的计算收益是否足够。

4. 读懂 algbw、busbw 和真实链路

nccl-tests 的 algbw 按逻辑数据大小除以时间计算。All-reduce 的 busbw 进一步乘以 \(2(N-1)/N\)，对应归一化后的通信带宽。8 卡情况下系数是 1.75；若 algbw=100 GB/s，busbw=175 GB/s。

比较硬件规格时，把方向和范围统一：GB/s 与 Gb/s 相差八倍，双向汇总与单向发送也有区别，节点所有 NIC 的总带宽还要由参与 GPU 共享。使用同样的 rank 到 GPU/NIC 映射运行尺寸扫描，既保存小消息耗时，也保存大消息带宽和正确性结果。

./build/all_reduce_perf -b 8K -e 64M -f 2 -g 4

对延迟敏感的 TP decode，重点查看每层激活大小附近的结果。若只测试最大的消息，峰值带宽可能很好，而 8 KiB 的归约仍占据明显的逐 token 关键路径。对带宽敏感的训练梯度或长 prefill，则要看多个并发 communicator 共享链路后的表现。

5. 用 mesh 下标记录分片归属

Device mesh 给设备排列逻辑坐标。2×2 mesh 有 X、Y 两条轴；沿 X 做集合通信时，Y 坐标保持固定。记 \(A[I_X,J]\) 为 A 的行维 I 沿 X 切分，列维 J 完整；\(A[I_X,J_Y]\) 则让两维分别沿两条轴切分。

若 A 的全局 shape 为 \([8192,4096]\)，mesh 是 X=2、Y=2，采用 \(A[I_X,J_Y]\)，每卡 shape 就是 \([4096,2048]\)。采用 \(A[I_X,J]\) 时，每卡是 \([4096,4096]\)，Y 轴上形成两个相同分片的副本。这个记号同时告诉我们存储量、重复度和可用的通信组。

在这里的矩形分片模型中，一张数组内一个 mesh 轴只承担一个维度的切分。如果同时把 I、J 都沿同一个轴标为分片，只有对角块落到设备上，会缺少其余块；可用独立 mesh 轴，或先恢复某一维的完整数据。

6. 沿求和维切分，就产生部分和

矩阵乘法 \(C_{ik}=\sum_j A_{ij}B_{jk}\) 中，J 是收缩维；I、K 是输出维。分片后的每卡计算是否已经完整，取决于它是否拥有当前输出位置所需的全部 J 项。

若 \(A[I_X,J]\) 与 \(B[J,K_Y]\) 相乘，各卡拥有完整 J，于是直接算出 \(C[I_X,K_Y]\)。若只有 A 的 J 被切、B 的 J 完整，可以先 all-gather A，或在本地把 B 切成匹配的 J 片段，计算部分和后归约输出。两条路线要比较输入与输出字节数。

若两个输入的 J 都沿 X 切分，\(A[I,J_X]B[J_X,K]\) 在每卡计算的是 \(C^{(r)}_{ik}=\sum_{j\in J_r}A_{ij}B_{jk}\)。所有 X rank 的结果相加才覆盖完整 J。这时下一层需要复制输出就用 all-reduce，需要沿某个输出维分片就用 reduce-scatter。

还有一种容易遗漏的布局：\(A[I_X,J]\) 和 \(B[J,K_X]\)。同一个 rank 只算到 \((I_r,K_r)\) 对角区域，完整输出还需要 \((I_r,K_s)\) 的交叉块。Gather 一侧输入后，再按剩下的一侧分片计算，就能覆盖这些输出位置。

这个探索器沿选定路线累加通信，再与每卡计算进行比较。“若完全重叠”是二者最大值；实际依赖可能要求先 gather 再乘，最终延迟需要按执行图相加。选择布局时还应计入接下来的层：一次较贵的输出重排，可能让多个后续算子持续保持高效分片。

7. 反向传播和重叠也是布局问题

All-gather 的输出在多个 rank 上被使用，反向时这些使用者对同一输入分片的梯度要相加，并交回原拥有者，所以其线性伴随是 reduce-scatter SUM。反过来，reduce-scatter 的伴随是 all-gather。具体训练框架还会按 loss 和梯度归一化约定做缩放；先保持求和语义，再核对平均发生在哪里。

通信与计算能够重叠的前提是数据分块和依赖允许。把一次很大的 gather 分为多块后，可以边接收后续块，边计算已就绪块；更多块也意味着更多启动和调度成本。一个实际问题是寻找足够大的块，让矩阵乘仍然高效，同时能把慢链路传输藏到计算后面。

Collective 的顺序也是执行契约：同一个 group 上，各 rank 对应的操作类型、元素数和 dtype 必须匹配。模型分支、可变专家交换或梯度累积改变顺序时，按操作序号对齐记录即可检查契约。发现一边是 broadcast、另一边是 all-reduce，就沿控制流找到第一次分歧；提高超时不会改变这些数学输入。

8. 从字节账本到布局选择

练习 1：四卡通信量

四卡 all-reduce，每卡输入 8 MiB。求每轮发送量、轮数和每卡总发送量。若下一层只需要和的一个四分片，改用什么操作？

展开解答

每轮 2 MiB，六轮，共 12 MiB/卡。Reduce-scatter 只需三轮、6 MiB/卡，得到完整和的一个分片。

练习 2：临界消息大小

N=8，启动延迟 2 μs/轮，带宽 50 GB/s。启动项与字节项何时相等？

展开解答

\(V_*=N\alpha\beta=8\times2\times10^{-6}\times50\times10^9=800000\) B，约 781.25 KiB。此时两项各为 28 μs。

练习 3：本地结果需要求和吗

计算 \(A[I_X,J_Y]B[J_Y,K]\)，X=2、Y=4。写出本地输出含义、归约组，以及输出保持 I 分片时的最终布局。

展开解答

本地结果包含 I 的一个二分片、全部 K，但只求和了 J 的一个四分片。因此沿 Y 组 all-reduce，得到 \(C[I_X,K]\)，并在 Y 上复制。若后续允许 K 再沿 Y 切，可改用 reduce-scatter，得到 \(C[I_X,K_Y]\)。

练习 4：Gather 权重还是归约输出

X 完整 shape 为 [32,4096]，权重 W 为 [4096,16384]，沿输入维分到四卡，BF16。比较“all-gather 完整 W”与“本地乘后 all-reduce Y”的每卡发送字节，忽略启动时间。

展开解答

完整 W 为 128 MiB，all-gather 每卡发送 \(3/4\times128=96\) MiB。Y 为 \(32\times16384\times2=1\) MiB，all-reduce 每卡发送 1.5 MiB。这个小 token 行数下，本地切 X、乘出部分和再归约的字节量更小，计算也分到四卡。
