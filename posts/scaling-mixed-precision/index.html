混合精度训练：从 BF16 到 FP8 与 NVFP4

交互2026-10-19更新于 2026-10-22

一次训练里，同一份权重会先参与前向矩阵乘，再以转置形式参与反向；反向得到的梯度还要经过跨卡归约、Adam 状态更新，最后写回下一步的权重。把矩阵乘输入从 BF16 换成 FP8 或 FP4，会同时改变这些位置的数值误差和数据流。

混合精度的设计由几个具体选择组成：每种张量用什么格式，哪些元素共享 scale，点积在哪里累加，转置如何获得一致的数值，以及哪些状态必须跨训练步保留下来。浮点格式给出可表示的刻度，训练算法决定这些刻度该放在什么位置。

1. 为什么要降精度

PyTorch 张量默认是 FP32，每个数 4 字节。降到 16 位或 8 位有三重好处：

  • 算力：硬件为低精度矩阵乘提供更高峰值。例如 H100 SXM 的稠密 BF16/FP16 与 FP8 Tensor Core 峰值约为 989、1979 TFLOPs/s；实际 GEMM 速度还受矩阵形状、对齐、数据搬运和 kernel 影响。Blackwell 进一步提供微缩放 FP4 的硬件路径。
  • 带宽：被压缩的数据载荷随位宽减少。耗时还包括 scale、转换、同步、通信延迟与融合开销；当主要成本确实来自这份载荷时，节省的字节才接近等比例转化为时间收益。
  • 显存：激活、权重副本、优化器状态都可以更小。

混合精度让计算量大的矩阵乘使用较短的输入格式，让长归约与更新保留所需精度，再用明确的缩放和转换连接它们。第一步是了解数值在哪里溢出、下溢或被舍入。

2. 浮点数怎么编码

2.1 三个字段

浮点数就是二进制的科学计数法。一个数被拆成三部分：

  • 符号位 \(s\)：1 位，0 正 1 负。
  • 指数 \(E\)：\(e\) 位无符号整数，存的是加了偏置（bias）的指数。偏置通常是 \(2^{e-1}-1\)，这样实际指数可正可负。例如 FP16 有 5 位指数，偏置是 15，字段值 1 到 30 对应实际指数 \(-14\) 到 \(15\)。
  • 尾数 \(M\)：\(m\) 位，存小数点后的部分（IEEE 754 叫 trailing significand）。

对普通（规格化，normal）数，值是

$$x = (-1)^s\cdot 2^{E-\text{bias}}\cdot\Big(1+\frac{M}{2^m}\Big),\qquad 1\le E\le E_{\max}.$$

开头的 1 是隐含的，不占存储——规格化的二进制数小数点前总是 1。指数字段全 0 时是次正规数（subnormal），隐含位变成 0，指数固定为最小值：

$$x = (-1)^s\cdot 2^{1-\text{bias}}\cdot\frac{M}{2^m},\qquad E=0.$$

次正规数让数值能「逐渐下溢」到 0，而不是在最小规格化数以下突然变成 0。指数字段全 1 在 IEEE 格式里留给 \(\pm\infty\)（尾数为 0）和 NaN（尾数非 0）。

BF16 的「B」来自 Google Brain。它保留与 FP32 相同的 8 位指数和高 7 位尾数，转换时按所选舍入模式处理被移出的尾数位。指数范围因此接近 FP32；FP16 则用 10 位尾数和 5 位指数，在相同数量级上刻度更细、覆盖范围更窄。

FP8 有两种格式（2022 年由 NVIDIA、Arm、Intel 联合提出，后来成为 OCP 标准），取舍也是范围和精度：

  • E5M2 完全遵循 IEEE 惯例（有 \(\pm\infty\)，多种 NaN），可以看作尾数更少的 FP16，规格化指数范围相同，最大有限值为 57344。

通常的建议是权重和激活用 E4M3、梯度用 E5M2（梯度的动态范围更大）。DeepSeek-V3 则在细粒度缩放的帮助下，对纳入 FP8 路径的张量统一使用 E4M3。

2.4 TF32：矩阵乘内部的精度选择

从 A100 开始，Tensor Core 支持 TF32：矩阵乘输入在计算路径中保留 FP32 的 8 位指数与 10 位尾数，并采用 FP32 累加；显存张量仍以 FP32 存储。PyTorch 的 torch.set_float32_matmul_precision 及对应后端设置控制可用的内部实现。核对 FP32 基线时，需要同时记录这些设置，明确矩阵乘实际使用的精度。

3. 范围、精度与 ULP

浮点数的可表示值不是均匀分布的。在每个区间 \([2^k, 2^{k+1})\)（一个 binade）里，规格化数恰好有 \(2^m\) 个，等间距排列，间距是

$$\mathrm{ulp}(x) = 2^{k-m},\qquad 2^k\le |x|\lt 2^{k+1}.$$

ULP（unit in the last place）是「最后一位变 1 对应的数值」。所以绝对精度随数值变大而变粗，相对精度大致不变：在规格化范围且没有溢出时，就近舍入的相对误差不超过 \(2^{-(m+1)}\)。举个数：BF16 在 1 附近的间距是 \(2^{-7}\approx0.008\)，在 1000 附近（\([512,1024)\)）的间距是 \(2^{9-7}=4\)——1000 和 1001 在 BF16 里是同一个数，但相对来说误差都不到 0.4%。这就是为什么常说 FP32 有约 7 位十进制有效数字（\(2^{-24}\approx6\times10^{-8}\)），FP16 约 3 位，BF16 约 2 到 3 位，E4M3 约 1 位。

可以做个直观的实验：在 \([1,2]\) 之间撒 10000 个点，舍入到各格式，E4M3 只能落到其中 7 个内部值上（1.125, 1.25, …, 1.875），E5M2 只有 3 个。分辨率常用 ε（1 之后的下一个可表示数与 1 的差）来衡量：FP32 是 \(2^{-23}\approx1.19\times10^{-7}\)，FP16 约 \(10^{-3}\)，BF16 再大 8 倍。

动态范围则由指数位数决定。用「最大值 / 最小次正规数」的以 2 为底的对数衡量：FP32 约 277 个 binade，BF16 约 261，FP16 约 40，E5M2 约 32，E4M3 约 18。

4. 舍入：就近偶数与随机舍入

4.1 就近偶数

IEEE 默认的舍入方式是就近舍入、平局取偶（round to nearest, ties to even，RNE）：取离 \(x\) 最近的可表示数；如果恰好在两个数中间，取尾数最后一位是 0 的那个。平局取偶是为了让平局时向上和向下的次数大致相等，避免系统性偏差。

RNE 选择单次转换绝对误差最小的数。若一次更新仍落在当前可表示数两侧的中点之间，舍入结果就保持不变。对同一 binade 内的正向更新，条件是 \(\Delta\lt\mathrm{ulp}(w)/2\)。在 BF16 中从 0 反复加 1，到 256 时，间距变为 2；257 恰好处于 256 与 258 中间，ties-to-even 选回 256，后续累加停在这里。FP16 对应的停滞点是 2048。这是小更新被部分和吞没的具体例子。

4.2 随机舍入

设 \(x\) 落在相邻可表示数 \(a\lt x\lt b\) 之间。随机舍入（stochastic rounding，SR）以与距离成反比的概率选择：

$$\mathrm{SR}(x) = \begin{cases} b & \text{概率 } p=\dfrac{x-a}{b-a}\\[4pt] a & \text{概率 } 1-p\end{cases}$$

固定相邻刻度且数值处于可表示区间时，随机舍入的条件期望是：

$$\mathbb E[\mathrm{SR}(x)] = a(1-p) + bp = a + (b-a)\cdot\frac{x-a}{b-a} = x.$$

方差是 \((b-a)^2p(1-p)=(x-a)(b-x)\le(b-a)^2/4\)。饱和转换先把越界值裁到端点，无偏性对应的是裁剪之后的数值。于是即使每次更新都小于半个 ULP，平均下来也能正确累积：在上面「加 1」的例子里，SR 下每次有 1/2 的概率加 2，期望正好加 1。Gupta 等人 2015 年就发现，用 16 位定点数训练神经网络时舍入方式起决定性作用，配合随机舍入可以几乎无损地训练。NVFP4 预训练也对梯度使用随机舍入（第 13 节）。代价是要生成随机数，以及单次结果有噪声。

两种情形：一个权重被反复加上很小的更新；一串乘积在不同精度的累加器里求和。

5. FP16 混合精度的三个技巧

知道了 FP16 会在哪里出错，就可以对症下药。让 FP16 训练达到 FP32 精度的经典做法由三个技巧组成：FP32 主权重（防止更新被吞没）、损失缩放（防止梯度下溢）、FP32 累加（防止长求和出错）。一步训练的流程如下：

5.1 FP32 主权重

权重在优化器里保存一份 FP32 的「主副本」（master weights），每步把它转成 FP16 用于前向和反向；优化器用梯度更新的是 FP32 主副本。原因有两个：

  • 更新本身下溢：FP16 能表示的最小正数是 \(2^{-24}\approx6\times10^{-8}\)，更小的值变成 0。学习率乘梯度后常常落在这个范围以下。在一个普通话语音识别模型上统计，约 5% 的权重梯度指数小于 \(-24\)，放进 FP16 就直接变成 0。
  • 更新被吞没：即使更新本身可表示，加到权重上时也可能被舍掉，也就是吞没。设 \(w\in[2^k,2^{k+1})\)，ULP 是 \(2^{k-m}\)，更新 \(|\Delta|\lt\frac12\mathrm{ulp}=2^{k-m-1}\) 时 \(w+\Delta\) 舍入回 \(w\)。所以当 $$\frac{|w|}{|\Delta|}\gtrsim 2^{m+1}$$ 时更新会丢失。FP16（\(m=10\)）是 2048，BF16（\(m=7\)）只有 256。这个比值给出数量级判断；精确边界由当前权重附近、更新方向上的相邻刻度决定。

BF16 在相同数量级上的刻度比 FP16 更粗。以当前权重约 0.02 为例，它位于 \([2^{-6},2^{-5})\)，BF16 的 ULP 为 \(2^{-13}\approx1.22\times10^{-4}\)。若实际更新是 \(3\times10^{-5}\)，它小于半个 ULP，直接写回 BF16 会保持原值。实际 Adam 更新由学习率、矩估计、epsilon 与 weight decay 共同决定，记录真实更新量才能判断是否发生吞没。FP32 主副本、随机舍入和补偿状态为小更新提供不同的保存方式。

单独保存 FP32 主权重和 FP16/BF16 计算副本，需要每参数 4+2 字节；相较只存一份 FP32 权重，参数载荷增加 50%。训练总显存还包括激活、梯度和优化器状态，收益由各项占比决定。主副本与优化器状态可以在数据并行 rank 之间分片，见数据并行与 ZeRO。

5.2 损失缩放

第二个问题出在反向传播里的激活梯度。它们通常远小于 1。FP16 规格化数的指数范围是 \([-14,15]\)，但如果画出一个网络（比如 SSD 检测网络）的激活梯度直方图，会发现大部分 FP16 的可表示范围（尤其是靠上的部分）根本没被用到，很多值却落在最小可表示值以下变成了 0。范围是够的，只是用错了位置。

办法是把梯度整体「往上挪」。由链式法则，如果把损失乘以常数 \(S\)，反向传播得到的每个梯度都会乘以 \(S\)：

$$\frac{\partial (S\cdot L)}{\partial \theta} = S\cdot\frac{\partial L}{\partial\theta}.$$

这不需要在反向里加任何额外运算。更新前把权重梯度除以 \(S\) 还原。还原要在梯度裁剪、权重衰减等任何梯度处理之前做，这样这些超参数不用跟着改。

\(S\) 怎么选？不同网络需要的常数从 8 到 32K 不等（SSD 用 8 就够了，很多网络不需要缩放）。只要不溢出，\(S\) 越大越好；可以选使 \(S\cdot\max|g|\lt65504\) 的值。溢出会产生 inf/NaN，一旦进入权重就不可逆，所以要检测：动态损失缩放在反缩放梯度时检查 inf/NaN，发现就跳过这一步并把 \(S\) 减小；连续若干步没有溢出就把 \(S\) 增大。PyTorch 的 GradScaler 默认初始 \(S=2^{16}\)，溢出时乘 0.5，连续 2000 步无溢出时乘 2。

scaler = torch.amp.GradScaler("cuda")       # init_scale=2**16, backoff 0.5, growth 2.0 / 2000 步
for x, y in loader:
    with torch.autocast("cuda", dtype=torch.float16):
        loss = loss_fn(model(x), y)
    scaler.scale(loss).backward()            # 反向得到 S 倍的梯度
    scaler.unscale_(opt)                     # 先除以 S，再裁剪
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    scaler.step(opt)                         # 有 inf/NaN 就跳过这一步
    scaler.update()                          # 调整 S
    opt.zero_grad(set_to_none=True)

5.2.1 一个数值例子

设某层的激活梯度典型量级是 \(10^{-6}\)、小的到 \(10^{-9}\)。FP16 最小次正规数是 \(5.96\times10^{-8}\)，所以 \(10^{-9}\) 量级的值直接变成 0；\(10^{-6}\) 也在次正规区（小于 \(6.1\times10^{-5}\)），只剩 \(10^{-6}/5.96\times10^{-8}\approx17\) 个刻度，相对误差高达几个百分点。取 \(S=2^{16}=65536\)：\(10^{-6}\) 变成 \(0.066\)，回到规格化区，相对精度恢复到 \(2^{-11}\)；\(10^{-9}\) 变成 \(6.6\times10^{-5}\)，刚好进入规格化区。只要最大的梯度乘以 \(S\) 后不超过 65504（原始值小于约 1），就没有溢出。这也说明了为什么动态缩放从很大的 \(2^{16}\) 开始：先尽量往上推，溢出了再退。

5.3 累加精度

第三个技巧是让低精度乘积在较高精度里累加。矩阵乘每个输出要汇总 \(K\) 个乘积，隐藏维度或 token 数越大，求和链越长。输入格式、内部累加方式与最终输出格式是三个独立配置。逐元素融合内核也常以 BF16 读写、在寄存器内用 FP32 计算；它的速度取决于访存、指令和融合方式。

5.4 主权重的替代：补偿求和

如果连 FP32 主权重的 4 字节都想省掉，可以用 Kahan 补偿求和：除了 BF16 权重 \(w\)，再存一个 BF16 的补偿量 \(c\)，记录上次加法被舍掉的部分：

$$y = \Delta - c,\qquad t = \mathrm{bf16}(w + y),\qquad c = \mathrm{bf16}\big((t - w) - y\big),\qquad w = t.$$

\((t-w)\) 是这次实际加上的量，减去本想加的 \(y\) 就是误差；下一步先把它补回来。这样被吞没的小更新不会丢，只是延迟到累积够大时才体现在 \(w\) 上。它和随机舍入一样，都是在「不存高精度副本」的前提下保住小更新，代价是额外的 2 字节状态和几次运算。

6. 哪些运算要留在 FP32

Transformer 中尤其需要检查长归约和小分母，常见的高精度计算位置包括：

  • softmax：\(e^x\) 增长极快，FP16 下 \(x\gt\ln65504\approx11.1\) 就溢出；先减最大值可以避免上溢，但分母是一长串正数的求和，正是吞没的典型场景。FlashAttention 内部的行最大值、行和、输出累加器都是 FP32。
  • 归一化（LayerNorm、RMSNorm）：要算 \(\frac1d\sum x_i^2\)。激活里有几百量级的值时，平方后在 FP16 里会溢出（\(300^2=9\times10^4\gt65504\)）；对 \(d\) 个元素求和又有吞没问题。
  • 损失：交叉熵要对整个词表算 logsumexp，词表十几万。
  • 各种大规模归约：求和、均值、范数（包括梯度裁剪用的全局范数）。
  • 优化器：更新计算与矩估计的除法、平方根。状态存储可以另选压缩格式，但要检查它对后续每一步的影响。

PyTorch 的 autocast 就是按这个思路列的表：在 CUDA 上，matmul、linear、bmm、卷积等会被转成 FP16/BF16；softmax、log_softmax、layer_norm、group_norm、cross_entropy、sum、cumsum、exp、log、pow、norm 等会被转成 FP32；没列出的算子按输入类型运行。注意「转成 FP32 计算」不一定意味着「FP32 存储」：融合内核常常读写 BF16、在寄存器里用 FP32 算，这样既不损失精度也不多花带宽。

7. BF16：范围与更新精度

损失缩放解决反向中间量的范围问题。BF16 采用与 FP32 相同的 8 位指数，最小规格化数约 \(1.18\times10^{-38}\)，通常足以容纳训练梯度，因此常用 BF16 训练无需动态 loss scaling。数值稳定性还取决于归约、分母、优化器和数据；非有限值检测依旧是训练记录的一部分。

BF16 用 7 位尾数换取较宽范围，在规格化范围的最大相对舍入误差约为 \(2^{-8}\approx0.4\%\)。选择 FP32 主权重、梯度累积与优化器状态时，要区分持久存储和临时缓冲。一个常见账本是 BF16 参数 2 B、FP32 梯度累积 4 B、FP32 主权重 4 B、Adam 两个 FP32 状态 8 B，共 18 B／参数；额外的 BF16 梯度暂存若同时存在，再计 2 B。

7.1 梯度累加为什么要 FP32

多个 microbatch 的梯度汇总到同一个参数，部分和会逐渐变大。BF16 缓冲在连续舍入中可能丢失后续小贡献；误差方向取决于数据和舍入模式。FP32 梯度累积保留更细刻度，但通信 buffer 可以另选 BF16 或其他格式。记录累积 dtype、通信 dtype、归约算法及两种缓冲是否同时驻留，才能同时核对数值和显存。

7.2 怎么判断是精度出了问题

实际训练里，损失发散的原因很多，精度只是其中之一。几个比较直接的检查：

  • 记录每层激活、梯度的 amax 和下溢（变成 0）的比例。FP16 下大量梯度为 0、或者 FP8 下大量值饱和，都是明确的信号。
  • 做一次小规模的对照：同样的种子和数据，把可疑的部分（某一类 GEMM、某个算子、优化器状态）切回高精度，看损失曲线是否分开。DeepSeek-V3 对 Dgrad 块量化的结论就是用这种消融得到的。
  • 看权重更新量与权重的比值（\(|\Delta w|/|w|\)）。如果它接近或低于 \(2^{-(m+1)}\)，而权重又以低精度存储、没有主副本或随机舍入，更新就会被吞没——表现往往不是发散，而是学习「悄悄变慢」。

8. FP8：格式与缩放

8.1 为什么 FP8 必须缩放

E4M3 的正规范围只有 \([2^{-6}, 448]\)，加上次正规也只到 \(2^{-9}\)，约 18 个 binade；而且在每个 binade 里只有 8 个点。一个张量的数值如果分布在 \(10^{-3}\) 附近，直接转成 E4M3 大部分会落进次正规区、精度极差；分布在 \(10^3\) 附近又会溢出。所以 FP8 张量几乎总是带着一个缩放因子：

$$\htmlData{symbol=quant-scale}{S}=\frac{\text{FP8}_{\max}}{\mathrm{amax}(x)},\qquad q=\mathrm{FP8}(x\cdot S),\qquad \hat x = q/S.$$

\(\mathrm{amax}\) 是张量（或某个分组）的绝对值最大值。这样最大的元素恰好映射到格式的最大值附近，充分利用顶部的几个 binade。

看一个具体的数。设某个张量的 amax 是 0.02，其中有一个值 0.001。不缩放直接转 E4M3：0.001 小于最小规格化数 \(2^{-6}\approx0.0156\)，落在次正规区，那里的间距是 \(2^{-9}\approx0.00195\)，0.001 约是半个间距，舍入成 0.00195，误差 95%。缩放后：\(S=448/0.02=22400\)，\(0.001\times S=22.4\)，在 \([16,32)\) 里间距是 2，舍入成 22，反量化得 \(22/22400\approx0.000982\)，误差 1.8%。同样 8 位，差别全在于数被放到了格式的哪一段。这和 FP16 的损失缩放是同一个思路，只是 FP8 的范围太窄，一个全局的 \(S\) 不够，需要每个张量（甚至每个分组）各一个。

矩阵乘时缩放因子可以提出去：若 \(X\) 和 \(W\) 各有一个标量缩放 \(S_X,S_W\)，则

$$\widehat Y = \frac{1}{S_XS_W}\,(q_X\,q_W)\approx XW,$$

这里 \(\widehat Y\) 是量化输入的矩阵乘结果，\(q_X,q_W\) 为 FP8 数值，\(S_X,S_W\) 是乘在原数值上的缩放。计算还包括累加器和输出转换的误差。FP8 饱和转换把越界值钳到最大有限值；持续记录饱和比例与 amax，能判断 scale 是否覆盖了当前分布。

8.2 延迟缩放与即时缩放

计算 \(\mathrm{amax}(x)\) 要先完整扫一遍 \(x\)，这意味着「先写出高精度张量 → 读一遍求 amax → 再读一遍做转换」，对带宽受限的部分很不划算。两种策略：

  • 延迟缩放（delayed scaling）：用过去若干步记录的 amax 来估计这一步的缩放因子，转换和 amax 统计可以融合在产生这个张量的内核里一次完成。NVIDIA Transformer Engine 的 DelayedScaling 默认保留 1024 步的 amax 历史，取其中最大值，缩放因子是 \((\text{FP8}_{\max}/\mathrm{amax})/2^{\text{margin}}\)（margin 默认 0）。缺点是缩放因子是「过时」的：如果这一步突然出现比历史更大的值，就会饱和。
  • 即时缩放（current scaling，DeepSeek-V3 称为 online quantization）：用当前张量（或当前分组）的 amax。更准确，代价是多一次归约。分组越小，这次归约越容易融合进内核（一个 1×128 的分组在一个线程块里就能求完）。

Transformer Engine 的 DelayedScaling 配方常用格式组合 HYBRID：前向（权重、激活）用 E4M3，反向（梯度）用 E5M2。

8.2.1 延迟缩放会在哪里出问题

设某个激活在前 1000 步的 amax 一直在 20 左右，E4M3 下缩放因子 \(S=448/20=22.4\)。某一步出现一个 50 的值（比如一次 loss spike 的前兆）：\(50\times22.4=1120\gt448\)，被饱和成 448，反量化后是 20——这个最需要被准确表示的大值被截掉了 60%。下一步 amax 历史更新为 50，\(S\) 降到 8.96，但已经晚了一步。反过来，如果历史里曾经出现过一个很大的 amax，取窗口最大值的策略会让后面很多步的 \(S\) 偏小，普通值被压向次正规区，直到那个值滑出 1024 步的窗口。即时缩放没有这两个问题。DeepSeek-V3 选择它的理由正是这两点：缩放因子更准确，框架也更简单（不用维护 amax 历史）。

8.3 一个线性层里的三个 FP8 矩阵乘

线性层 \(Y=XW\)，\(X\in\mathbb R^{T\times d_{\text{in}}}\)，\(W\in\mathbb R^{d_{\text{in}}\times d_{\text{out}}}\)。训练时有三个矩阵乘：

  • Fprop：\(Y = XW\)，归约维度是 \(d_{\text{in}}\)。
  • Dgrad：\(dX = dY\,W^\top\)，归约维度是 \(d_{\text{out}}\)。
  • Wgrad：\(dW = X^\top dY\)，归约维度是 token 数 \(T\)。

这三个名字在 FP8 的讨论里会反复出现：Fprop 是前向（forward propagation），Dgrad 算的是传给上一层的激活梯度（data gradient），Wgrad 算的是权重梯度。将三个 GEMM 都纳入 FP8 后，可使用对应硬件更高的矩阵乘峰值；例如 H100 的 FP8 稠密峰值约为 BF16 的两倍。保存给 Wgrad 的 FP8 激活 payload 是 BF16 的一半，scale、另一读向的量化副本与保留的高精度张量另计，完整状态安排见第 14 节。注意同一个 \(X\) 在 Fprop 里沿行（\(d_{\text{in}}\)）归约，在 Wgrad 里沿列（\(T\)）归约，这在下面讲分组缩放时会成为麻烦。

8.4 FP8 能省多少时间

FP8 的主要计算收益来自纳入低精度路径的矩阵乘。按 DeepSeek-V3 的方案，注意力、归一化、embedding、输出头、MoE 门控都留在高精度；逐元素算子的时间按字节算，激活从 BF16 变 FP8 只在那些被量化的张量上省带宽；量化本身（求 amax、缩放、转换、转置后重新量化）还要额外的内核或融合工作。所以即使线性层 GEMM 占了一步的 70%，理想加速也只是 \(1/(0.3+0.7/2)\approx1.54\) 倍，实际更少。这也是为什么第 12 节里各家方案都花了很多心思在显存和通信上——FP8 的收益是算力、显存、通信三处加起来的。

9. 离群值与缩放粒度

大模型的激活有一个众所周知的特点：少数通道的数值比其他通道大一两个数量级（离群值，outlier），而且这些通道在不同 token 上比较固定。按张量缩放时，\(\mathrm{amax}\) 由离群值决定，其他所有值都被压到格式的底部：如果离群值是普通值的 1000 倍，普通值缩放后约为 \(448/1000\approx0.45\)，仍处在 E4M3 的规格化范围；更小的分量会先进入次正规区，其相对误差开始快速增加。

所以「按张量把 amax 缩放到 FP8 最大值」的标准做法，会让低精度训练对激活离群值高度敏感。解决思路是缩小共享缩放因子的分组，让一个离群值只影响它所在的那一小组。

拖动滑块能看到几件事：

  • 浮点格式比整数格式耐离群值。FP8 在每个 binade 里的相对精度相同，按张量缩放时离群值只是把普通值整体往下挪几个 binade，精度不变；直到普通值被挪进次正规区（E4M3 只有约 18 个 binade 可挪），误差才明显上升、开始大量变成 0。切到 INT8 对照：均匀刻度下，离群值一大，普通值只剩几个量化级，按张量缩放的误差立刻变大。这是 FP8 能比 INT8 更直接地用于训练的原因之一。
  • 分组只保护不含离群值的组。演示里两个离群通道都在前 128 列。通道离群时，所有包含这两列的分组（每一行的第一个 1×128 分组、左边的 128×128 块）都被拉大了缩放因子，右半边则完全不受影响；分组越小（1×32、1×16），受牵连的普通元素越少。真实模型的隐藏维度是几千，一个离群通道只污染它所在的那 1/几十 的分组。
  • token 离群时 1×128 明显优于 128×128。离群值沿行分布，按 token 分组时离群 token 自成一组，其他 token 不受影响；128×128 的块却把块内所有 token 都拖下水。DeepSeek-V3 的训练中发现，激活梯度有明显的 token 相关离群值，对它们用 128×128 块量化会导致发散。
  • E4M3 最依赖细粒度缩放。E5M2 范围大，按张量缩放时很少把小值压成 0，但每个值的精度更低；E4M3 精度高、范围窄。分组缩放补上了范围，于是可以把位数留给尾数——这就是 DeepSeek-V3「有了细粒度缩放就可以全部用 E4M3」的道理。FP4 只有约 3.6 个 binade、8 个非负值，任何粗粒度缩放都不够用。

另一类办法是在量化前把离群值「摊开」。FlashAttention-3 和 NVFP4 训练都用了随机 Hadamard 变换：对 \(x\) 乘一个正交矩阵 \(H\)（Hadamard 矩阵乘随机 \(\pm1\) 对角阵），每个输出是输入的随机 \(\pm\) 组合，一个大值被均摊到所有位置上，\(\mathrm{amax}\) 和其余值的比例大幅下降。矩阵乘的另一边乘同一个 \(H\)，由 \(HH^\top=I\) 结果不变。

一个四维的小例子：\(x=(10,1,1,1)\)，最大值是其余值的 10 倍。乘以归一化的 4 阶 Hadamard 矩阵（元素是 \(\pm\tfrac12\)）后得到 \((6.5,4.5,4.5,4.5)\)：向量的长度不变，但最大值只是其余值的约 1.4 倍，按 amax 缩放时其余元素不再被压到格式底部。

10. DeepSeek-V3 的 FP8 框架

DeepSeek-V3 在 671B 总参数的 MoE 上报告了 FP8 混合精度预训练，它把上面这些零件拼成了一个完整的系统，可以分成四块。

10.1 什么用 FP8，什么不用

  • 线性层的三个 GEMM（Fprop、Dgrad、Wgrad）全部用 FP8，输入 FP8，输出 BF16 或 FP32。
  • 保持原精度（BF16 或 FP32）的组件：embedding、输出头、MoE 门控、归一化算子、注意力算子。理由是这些算子对低精度敏感，或者计算量小、用高精度几乎不增加成本。
  • 主权重、权重梯度、优化器状态用更高精度存储；它们的显存开销靠在数据并行 rank 之间分片来摊薄。

10.2 细粒度量化

分组方式正是第 9 节演示里的两种：

  • 激活按 1×128 分组（每个 token 的每 128 个通道一个缩放因子）。
  • 权重按 128×128 分块（每 128 个输入通道 × 128 个输出通道一个缩放因子）。

为什么两者不一样？激活每个 token 一行，离群值常集中在个别 token 或通道上，1×128 能把它们隔离得最细。权重则要在两个 GEMM 里用：Fprop 沿 \(d_{\text{in}}\) 归约，Dgrad 用 \(W^\top\)、沿 \(d_{\text{out}}\) 归约。128×128 的块在两个方向上都按 128 对齐，转置之后仍然是合法的分组，同一份 FP8 权重两边都能直接用，不用重新量化。

关键的一点是：这些分组是沿着 GEMM 的归约维度 K 划分的。以 Fprop 为例，\(Y_{ij} = \sum_k X_{ik}W_{kj}\)。把 \(k\) 按 128 分成若干组 \(b\)，每组的激活缩放 \(s^X_{i,b}\) 和权重缩放 \(s^W_{b,j'}\)（\(j'\) 是 \(j\) 所在的 128 块）各不相同：

$$Y_{ij} = \sum_b s^X_{i,b}\, s^W_{b,j'}\sum_{k\in b} q^X_{ik}\,q^W_{kj}.$$

缩放因子随 \(b\) 变化，不能像按张量缩放那样提到整个求和外面，只能在每组的部分和算完之后乘上去。Hopper 上常规的按张量 scale 路径需要为这种沿 K 分组的缩放另作安排。DeepSeek 的实现把它和下面的「提升到 CUDA core 累加」结合在一起：每 128 个元素的部分和从 Tensor Core 拷到 FP32 寄存器时，顺便乘上这一组的两个缩放因子。

这种分组和微缩放格式的思路一致，最好由 Tensor Core 直接接收分组缩放因子，而不是在软件里补——Blackwell 的 MX 格式正是这样做的（第 13 节）。

10.3 全部用 E4M3、在线量化

此前的工作（Transformer Engine、FP8-LM 等）前向用 E4M3、反向用 E5M2。DeepSeek-V3 纳入 FP8 计算的张量使用 E4M3，理由是细粒度分组相当于让一组元素共享指数位，弥补了 E4M3 范围小的缺点，于是可以把位数花在尾数上。缩放因子用在线（即时）量化：每个 1×128 分组或 128×128 块现算 amax，而不是用历史估计。

10.4 低精度存储与通信

  • 优化器状态：AdamW 的一阶、二阶矩用 BF16 存，没有观察到性能下降；主权重和用于梯度累加的梯度仍是 FP32。
  • 激活缓存：给 Wgrad 用的激活以 FP8 缓存。两个例外：注意力之后那个线性层的输入对精度更敏感（它在注意力的反向里也要用），用一种自定义的 E5M6 格式；并且它在反向里要从 1×128 分组转成 128×1 分组，为避免额外的量化误差，缩放因子都取 2 的整数次幂。MoE 里 SwiGLU 的输入以 FP8 缓存，输出在反向时重算。
  • 通信：MoE 上投影之前的激活先量化成 FP8 再做 dispatch（缩放因子同样是 2 的幂），下投影之前的激活梯度也类似；combine 阶段保持 BF16。

10.5 转置的麻烦和一个失败的尝试

同一个激活在 Fprop 里沿行归约、在 Wgrad 里沿列归约。若只缓存按 1×128 分组的 FP8 结果，构造另一种读向时就需要反量化、调整分组后重新量化。保留高精度源张量时，也可以从源张量分别构造两种布局。一个省事的替代是对激活梯度也像权重一样用 128×128 块量化，这样转置只需交换块的下标。DeepSeek 试过这条路：对 Dgrad 相关的张量都用块量化，在约 16B 参数的 MoE 上训练约 300B token 后发散了。原因是激活梯度在 token 之间极不均衡，存在 token 相关的离群值，块量化管不住。

10.6 效果

DeepSeek 在两个规模上和 BF16 做了对比：约 16B 总参数的 MoE 训练 1.33T token，约 230B 总参数的 MoE 训练约 0.9T token。FP8 相对 BF16 的损失相对误差始终低于 0.25%，在训练随机性的范围内。

11. 累加精度

低精度乘积要在高精度里累加。DeepSeek-V3 针对 H800 报告的 FP8 GEMM 路径中，内部部分和约保留 14 位有效位，远低于 FP32 的 24 位有效位。机制是这样的：对齐 32 个尾数乘积时按最大指数右移，只用每个乘积最高的 14 位相加，超出的位截断；加到寄存器里的累加也是 14 位精度。实测 \(K=4096\) 的两个随机矩阵相乘，最大相对误差接近 2%。\(K\) 越大问题越严重，而大模型训练中 \(K\)（隐藏维度，或者 Wgrad 里的 token 数）恰恰很大。

为什么 14 位不够？原因还是吞没：累加器里的部分和越来越大，而每次加进来的只是一个乘积。14 位有效位意味着部分和比新加的项大 \(2^{14}\approx1.6\times10^4\) 倍以上时，新项就被整个截掉；没到这个倍数时也会被截掉低位。\(K=4096\) 个同号的项相加，后面的项和部分和之比轻易就降到几千分之一，截断误差一路单向积累。如果只在 Tensor Core 里累加 128 项就把结果交出去，块内部分和的增长范围更小，截断损失就小得多；真正的长求和交给 FP32 做。

这就是 DeepSeek 的办法，叫提升到 CUDA core（promotion）：Tensor Core 里只累加 \(N_C\) 个元素，然后把部分和拷到 FP32 寄存器，在 CUDA core 上做全精度累加（同时乘上分组缩放因子）。\(N_C=128\)，对应 4 次 WGMMA 指令，是他们实验中能明显提升精度、又不带来太大开销的最小间隔。这会降低单个 warpgroup 发射 WGMMA 的速率，但 H800 上通常有两个 warpgroup 的 WGMMA 并存：一个在做提升时另一个可以继续做 MMA，Tensor Core 的利用率仍然很高。

这是对硬件限制的妥协，DeepSeek 也因此建议未来的芯片提高 Tensor Core 内的累加精度、原生支持分组缩放、把 FP8 转换和 TMA 融合以支持在线量化、支持转置读取。Transformer Engine 后来的 FP8 块缩放方案也注明它需要「分段累加」（split accumulation）来保证精度。

上面「舍入与累加」演示的第二个模式用一个简化模型复现了这种现象：累加器每次加法后截断到 14 位有效位；可以对比 FP32 累加、每 128 个元素提升一次到 FP32、以及 BF16 累加。

13. 微缩放：MXFP8 与 NVFP4

13.1 MX 格式

DeepSeek-V3 的分组缩放在 Hopper 上要靠软件（CUDA core 上的乘法）实现。开放计算项目（OCP）的微缩放（Microscaling，MX）规范把这件事标准化、交给硬件：一个 MX 块由 \(k\) 个低精度元素和一个共享缩放因子组成。所有具体的 MX 格式都用 \(k=32\)，缩放因子格式是 E8M0（8 位指数、0 位尾数，只能表示 2 的幂，范围覆盖 FP32 的全部指数）：

格式块大小缩放因子元素平均位宽
MXFP832E8M0FP8（E4M3 或 E5M2）8.25
MXFP632E8M0FP6（E2M3 或 E3M2）6.25
MXFP432E8M0FP4（E2M1）4.25
MXINT832E8M0INT88.25

转换算法是这样的：先求块内 \(\mathrm{amax}\)，共享指数 \(\lfloor\log_2\mathrm{amax}\rfloor - e_{\max}\)，其中 \(e_{\max}\) 是元素格式最大规格化数的指数（E4M3 是 8，E2M1 是 2）；每个元素除以 \(2^{\text{共享指数}}\) 后量化，超出范围的饱和。因为缩放因子是 2 的幂，乘缩放因子只是改指数，硬件代价很小；但 amax 被向下取到 2 的幂后，块内最大值未必能用满元素格式的顶部。

举个例子：一个块的 amax 是 5.3，元素格式 E4M3。\(\lfloor\log_2 5.3\rfloor=2\)，共享指数 \(2-8=-6\)，缩放因子 \(2^{-6}\)，即每个元素乘 64。最大元素变成 \(5.3\times64\approx339\)，没有越过 448，但也没用满。如果元素格式是 E2M1（\(e_{\max}=2\)），共享指数是 0、缩放因子是 1，5.3 只能舍入到 6，误差 13%。这正是下面 NVFP4 要改进的地方。

分组是沿某一个轴的（通常是矩阵乘的归约维度），所以 MX 量化和转置不可交换：转置后分组的方向变了。Transformer Engine 的 MXFP8BlockScaling 方案的处理方法是：需要一个张量和它的转置时（前向和反向各用一个），两份都直接从高精度输入量化，避免二次量化误差。它的默认格式是全 E4M3。

13.2 NVFP4

NVIDIA Blackwell 支持 FP4、MXFP4 和自家的 NVFP4。元素都是 E2M1（可表示 0、0.5、1、1.5、2、3、4、6 及其相反数）。NVFP4 和 MXFP4 的区别：

  • 块更小：每 16 个元素一个缩放因子（MXFP4 是 32 个）。
  • 缩放因子用 E4M3 而不是 E8M0，可以是非 2 的幂的小数，能把块内最大值更准确地对到 6 上。
  • E4M3 缩放因子的范围不够，再加一个 FP32 的张量级缩放因子，构成两级缩放。

对于每 16 元素一组的载荷，平均是 4.5 bit／元素，外加张量级 FP32 scale。用反量化尺度表示，NVFP4 的两级计算为：

$$\htmlData{symbol=global-scale}{s_g}=\frac{a_{\rm global}}{448\times6},\quad \htmlData{symbol=block-scale}{s_b}=\mathrm{E4M3}\!\left(\frac{a_b}{6s_g}\right),\quad q_i=\mathrm{E2M1}\!\left(\frac{x_i}{s_gs_b}\right),\quad \widehat x_i=q_i s_b s_g.$$

\(a_{\rm global}\) 是整张量最大绝对值，\(a_b\) 是当前块最大绝对值；全零张量采用约定的非零 scale，并保存全零元素。例如固定 \(s_g=1\)、某块 \(a_b=5.3\)，块 scale 的理想值为 0.8833，E4M3 存为 0.875；最大元素恢复为 \(6\times0.875=5.25\)。实际张量的 \(s_g\) 由上式决定，局部 scale 的舍入也属于量化误差。

13.3 用 NVFP4 预训练

NVIDIA 在 2025 年用 NVFP4 训练了一个 12B 参数的 Mamba-Transformer 混合模型，10T token，损失曲线和下游精度都接近 FP8 基线。配方几乎就是上面这些手段的组合：

  • 敏感层保留高精度：12B 模型保守地把前 2 个和最后 8 个块的线性层留在 BF16，约占线性层的 16%。
  • 随机 Hadamard 变换：对 Wgrad 的输入做 16×16 的随机 Hadamard 变换（RHT），压制块内离群值。Fprop 和 Dgrad 不做：在它们上面做变换没有带来收益，小模型上反而略差。
  • 二维缩放：权重按 16×16 的块缩放，这样前向和反向（转置后）看到的是同一个量化结果；激活和梯度按 1×16 缩放。
  • 随机舍入：梯度用随机舍入，权重和激活用就近偶数。Blackwell 的 FP4 转换指令原生支持这两种舍入。

TE 2.20.2 的 NVFP4 配方默认对权重采用 16×16 二维 scale，对激活和梯度采用 1×16 scale；梯度使用随机舍入，Wgrad 的输入与梯度在列向量化前做 16 维 RHT。高精度参数、可复现的随机数状态与所需的反向缓存共同构成训练状态。

14. 把误差追踪到完整训练步

在一个线性层中，记 \(T\) 为本批 token 数、\(K\) 为输入宽度、\(N\) 为输出宽度。令 \(X\in\mathbb R^{T\times K}\) 是本批激活，\(W\in\mathbb R^{K\times N}\) 是权重，\(G=\partial\mathcal L/\partial Y\in\mathbb R^{T\times N}\) 是上游梯度。三个 GEMM 分别为：

$$\htmlData{symbol=fprop}{Y=XW},\qquad\htmlData{symbol=dgrad}{dX=GW^\top},\qquad\htmlData{symbol=wgrad}{dW=X^\top G}.$$

它们沿 \(K\)、\(N\)、\(T\) 三个不同维度求和。Fprop 的误差先改变激活和本步 loss；Dgrad 的误差影响更早的所有层；Wgrad 的误差写进优化器，并通过下一步权重继续影响前向。为了定位来源，可以先固定高精度 \(X,W,G\)，分别只替换一个 GEMM，再执行完整训练闭环。

写 \(\widehat X=X+E_X\)、\(\widehat W=W+E_W\)，输入量化引起的前向差为：

$$\widehat X\widehat W-XW=E_XW+XE_W+E_XE_W.$$

这里 \(E_X,E_W\) 是反量化后的输入误差。结果还要加上内部累加和输出转换的误差。观察张量相对 L2 误差、最大绝对误差与梯度方向，能够区分平均误差很小但少数通道异常的情况。输出范数接近零时，同时保留绝对误差，避免一个很小的分母主导指标。

14.1 转置的是字节，还是同一个近似矩阵？

用 \(Q_r\) 表示按行分组量化、再按各组 scale 反量化得到的近似矩阵，用 \(Q_{2D}\) 表示二维方块的对应操作。按行量化的 \(Q_r(W)\) 与先转置再按行量化的 \(Q_r(W^\top)\) 使用不同分组，因此一般有 \(Q_r(W)^\top\ne Q_r(W^\top)\)。若前向和反向使用了两套不同的近似权重，Dgrad 中的矩阵就会偏离本次前向实际使用的权重转置。

二维方块给出一种一致性约定。只要同一个方块使用同一 scale、同一确定性舍入规则，转置仅交换方块位置，\(Q_{2D}(W)^\top=Q_{2D}(W^\top)\)。NVFP4 的 16×16 权重 scale 利用这一性质；每个 1×16 物理块可以携带相应的复制 scale。激活和梯度保持更细的 1×16 分组，因此它们的两种方向需要各自计算。

需要两种一维布局时，从保留的高精度输入分别构造两份，可以避免“先舍入一次，再换分组舍入一次”的误差叠加。代价是额外的输入读取、量化和缓存。选择保存高精度输入、保存两份低精度布局还是反向时重计算，应当与 activation checkpointing 一起算显存和时间。

Wgrad 还可以沿 token 归约维使用正交变换。取分块正交矩阵 \(R\)，每块为归一化的 16 维随机 Hadamard 变换，则：

$$X^\top G=(X^\top R)(R^\top G),\qquad RR^\top=I.$$

两边使用同一旋转，精确算术下的乘积保持不变；量化看到的是旋转后更分散的数值。TE 的 NVFP4 路径在 Wgrad 的列向输入和梯度量化前实施这一步，并从旋转后的张量计算 scale。反向重计算还需要复现对应的随机数与变换状态。

14.2 一次 all-gather 需要一个共同的数值解释

Sequence parallelism 会让不同 rank 持有不同 token 片段。若这些片段要以 NVFP4 格式 all-gather 成一个张量，接收端需要用同一个张量级 \(s_g\) 解释所有块。各 rank 的局部 amax 可以不同，因此 TE 的顺序是：计算局部 amax，以 max all-reduce 得到全局 amax，然后算共同 \(s_g\)、本地量化，最后 all-gather 数据与块 scale。

$$a_{\rm global}=\max_r a_r,\qquad s_g=\frac{a_{\rm global}}{448\times6}.$$

这里 \(a_r\) 是 rank \(r\) 的本地绝对值最大值，\(s_g\) 是反量化时的共同乘数。块 scale \(s_b\) 依旧属于本地块，不需要对它们逐项 all-reduce。量化 payload、块 scale、张量级 scale 与布局共同描述一个数值张量；通信实现必须保持这份对应关系。

小 amax 归约仍有通信启动与依赖开销。对小 GEMM 或短序列，额外同步可能占据明显比例；对大矩阵，压缩后的 all-gather 与 GEMM 收益可能覆盖它。测量时把 amax reduction、scale/cast、all-gather、GEMM 与等待时间分开记录，再看哪些能与独立工作重叠。

14.3 无偏舍入的噪声怎样进入 Adam？

固定本步真实梯度 \(g\)，把量化梯度写成 \(\widetilde g=g+e\)。若条件均值 \(\mathbb E[e\mid g]=0\)，它的平方期望仍然是：

$$\mathbb E[\widetilde g^2\mid g]=g^2+\htmlData{symbol=qvariance}{\operatorname{Var}(e\mid g)}.$$

Adam 用 \(v_t=\beta_2v_{t-1}+(1-\beta_2)\widetilde g_t^2\) 累积二阶矩，因此舍入方差也会进入分母 \(\sqrt{\widehat v_t}+\epsilon_{\rm Adam}\)。这条关系逐分量成立。它描述的是梯度量化的影响；若再量化 \(m_t,v_t\) 的存储，还会叠加状态压缩误差。更新本身涉及随机分子与随机分母的比值，应当通过实际更新分布检查。

FP4 All the Way 将这个问题进一步放到下降与曲率的平衡中。对一个固定梯度 \(g=\nabla L(\theta)\)、Hessian \(H\) 和零均值量化噪声协方差 \(\Sigma\)，二阶展开给出：

$$\mathbb E[\Delta L]\approx-\eta\|g\|_2^2+\frac{\eta^2}{2}\left(g^\top Hg+\operatorname{tr}(H\Sigma)\right).$$

其中 \(\eta\) 是梯度下降步长。在局部正曲率区域，噪声增加了二阶代价；梯度随着训练变小时，同样大小的噪声会占更大比例。实用的判断是同时测量信号范数、量化误差范数与真实验证损失，并对训练后期保留更高精度的梯度做对照。论文中的特定阈值依赖其噪声与曲率假设，实际 Adam 训练可以用这些量建立自己的受控探针。

长训练还会改变输入分布。Scaling FP8 Training to Trillion-token LLMs 观察到 SwiGLU 两个投影逐渐对齐，乘法门控放大离群值，短训练中稳定的量化方案在更长周期出现问题。Smooth-SwiGLU 在量化前按通道缩放，并在后续计算中补回尺度，保持高精度函数的对应关系。它提示我们把 amax、饱和率和块内动态范围作为时间序列保存，尤其关注训练后期。

14.4 把高精度留给哪些层？

Megatron-Bridge 的公开实验提供了两种可复用的对照设计。第一组在 B200 上训练 Research-8B，保持同样数量的 BF16 block，比较 F0L2 与 F1L1：前者保留最后两层，后者保留首尾各一层。这个命名中的 F、L 分别指前端、末端。实验中末端保留两层的验证损失更低，说明高精度预算放在哪里本身影响结果。其数据是内部研究语料。

第二组用 Llama3-8B 与 DCLM 比较 optimizer recipe。Recipe1 和 Recipe2 保持相同学习率范围、global batch 与 NVFP4 F0L4 配置，仅将 AdamW epsilon 从 \(10^{-8}\) 改为 \(10^{-5}\)，较大的 epsilon 改变了小二阶矩区域的更新。诊断时记录 \(\epsilon_{\rm Adam}/\sqrt{\widehat v}\) 的分布：该比值很大时，更新主要由 epsilon 决定，逐坐标二阶矩调节作用减弱。原记录中的 Recipe0 同时改变了学习率和 batch，适合比较整套配方；单项机制由前两组的受控对照来判断。

可以沿用这种实验结构：固定训练数据和初始 checkpoint，只把一种 GEMM、指定层或 optimizer state 切回高精度；记录层间误差、参数更新方向、验证曲线与 step time，再决定精度分配。保存权重、矩状态、scale 历史、随机数状态与数据位置，才能在同一训练状态上重放。更一般的梯度监测可看深层 Transformer 的训练稳定性。

15. 计算与诊断习题

练习一：18 B 与 20 B 分别怎么算出来？

模型有 1B 参数，BF16 参数副本、FP32 主权重、FP32 梯度累积和两个 FP32 Adam 状态全部常驻。另有一个覆盖 100M 参数的 BF16 临时梯度 bucket。求参数相关小计和该 bucket 存活时的显存，使用十进制 GB。

推导与答案

持久量为 \(1B\times(2+4+4+8)=18\) GB。临时 bucket 为 \(100M\times2=0.2\) GB，同时存活时为 18.2 GB。只有额外 BF16 梯度副本覆盖全部 1B 参数时才增加 2 GB、形成 20 GB。量化权重缓存、scale、激活与通信 workspace 分别追加；如果状态已分片，则按实际分片范围计算。

练习二：按行量化与转置是否交换？

取 \(W=\begin{bmatrix}6&1.2\\2.3&4\end{bmatrix}\)，每行 scale 为该行最大绝对值除以 6，元素用 E2M1 RNE。求 \(Q_r(W)^\top\) 与 \(Q_r(W^\top)\)。再用整张 2×2 方块共享 scale 比较。

推导与答案

第一行 scale 为 1，1.2 舍入到 1；第二行 scale 为 \(2/3\)，2.3 归一化为 3.45、舍入到 3，恢复为 2。因此 \(Q_r(W)^\top=\begin{bmatrix}6&2\\1&4\end{bmatrix}\)。先转置后第二行变成 [1.2,4]，scale 仍为 \(2/3\)，1.2 归一化为 1.8、舍入到 2，恢复为 \(4/3\)。两条路径在一个元素处差 \(1/3\)。整块 scale 为 1，固定分组在转置后保持相同成员，两种路径完全一致。

练习三：all-gather 后为何放大了八倍？

两个 rank 的块最大值为 6 与 48，各自先用本地 amax 计算 NVFP4 全局 scale。接收端采用第二个 rank 的 scale 解释整个拼接张量。第一个 rank 的最大元素会被恢复成多少？正确同步后它的块 scale 又是多少？

推导与答案

本地量化时，第一个 rank 有 \(s_g=6/(448\times6)=1/448\)，块 scale 为 448，元素 q 为 6。接收端使用 \(48/(448\times6)=1/56\)，恢复出 \(6\times448/56=48\)，放大八倍。先同步 amax 后，两边共同使用 \(1/56\)，第一块的 scale 为 \((6/6)/(1/56)=56\)，恢复值为 \(6\times56/56=6\)。

练习四：无偏梯度的二阶矩

真实梯度为 0.01，可用相邻刻度是 0 与 0.02。使用随机舍入，求概率、均值、方差与平方期望。若旧 Adam 二阶矩为 0、\(\beta_2=0.9\)，更新后的二阶矩期望是多少？

推导与答案

两端概率都是 1/2，均值为 0.01，方差为 \(0.01^2=10^{-4}\)。平方期望为 \(0.5\times0.02^2=2\times10^{-4}\)，恰好是均值平方加方差。未做偏差校正的 \(v_1\) 期望为 \(0.1\times2\times10^{-4}=2\times10^{-5}\)；精确梯度对应 \(10^{-5}\)。要判断最终 Adam 更新，再同时跟踪一阶矩及其与二阶矩的相关性。

16. CPU 实验：从量化矩阵走完一次训练

下载 lab.py，在有 NumPy 的环境中运行 python lab.py --seed 7。实验使用 FP32 scale 和 E4M3／E2M1 的可表示值，固定块划分，先验证转置一致性、随机舍入的期望与方差，再检查三次 GEMM 的误差分解和解析梯度。

小训练闭环是两个线性层加 tanh 的回归网络，输入为 64×8，隐藏层宽度为 8，输出宽度为 4。主权重与 Adam 状态始终以 FP32 保存；只切换 GEMM 输入格式和梯度的舍入方式，激活与权重维持 RNE。每个实验使用同一初始化和数据；最终损失统一由当前 FP32 主权重计算，比较训练轨迹留下的差异。脚本同时报告三类 GEMM 误差与舍入噪声的二阶矩。全部计算由 NumPy 在 CPU 上执行，块 scale 的 FP32 约定用于隔离元素量化误差。
