流水线并行：从 GPipe 到 DualPipe

交互2026-10-19更新于 2026-10-22

把一个 Transformer 的层依次放到四张 GPU 上，可以降低每张卡的权重和优化器状态占用。但一批数据仍要按顺序经过四段：第一张卡算完，第二张才拿到输入；反向传播又从末段逐级返回。只放入一批数据时，许多设备会一直等待。

流水线并行用多个 micro-batch 填补这些等待。真正需要设计的是一张带依赖的时间表：哪个 stage 先处理哪批数据、何时发送激活、何时算梯度、哪些中间结果必须继续留在显存。调度改变的是时间、通信和显存之间的取舍。

1. 一批训练数据怎样穿过流水线

将模型切为 \(\htmlData{symbol=stages}{p}\) 个 stage，每个 stage 放到一个设备或一个 TP 设备组。把一次优化器更新的数据划分为 \(\htmlData{symbol=microbatches}{m}\) 个 micro-batch，每批含 \(b\) 条样本，数据并行副本数为 \(d\)，则全局 batch size 为 \(B_{global}=bmd\)。序列长度可变时，还需单独记录参与 loss 的有效 token 数。

第 j 批在 stage r 的前向 F 依赖 stage r−1 的输出；其反向依赖下游返回的输入梯度。每个 stage 保存前向产生的激活，供本批反向使用。等所有 micro-batch 的梯度累积完成，再执行一次优化器更新，这样同一轮中的各批使用相同版本的参数。

前向沿边界发送激活，反向沿相反方向发送激活梯度。若边界张量形状为 [b,S,H]、每元素占 \(b_e\) 字节，一次发送大小为 \(bSHb_e\)。例如 b=2、S=2048、H=4096、BF16，单向消息为 32 MiB；每批在这个边界的往返 payload 为 64 MiB。

2. 空泡如何进入一步训练的耗时

先看等时 stage：每个 micro-batch 的前向用时 \(t_F\)，完整反向用时 \(t_{BW}\)，忽略通信。AFAB（all forward, all backward）先让全部批次完成前向，再反向。第一批的前向需要 p 拍穿过流水线，后续每批多一拍，所以前向需要 \((m+p-1)t_F\)。反向同理：

$$T_{iter}=(m+p-1)(t_F+t_{BW}).$$

每张卡完成的有效工作为 \(m(t_F+t_{BW})\)。将设备总忙碌时间除以设备数和迭代时长，得到平均利用率

$$U=\frac{m}{m+p-1},\qquad f_{idle}=\frac{p-1}{m+p-1}.$$

这里 p 是流水级数，m 是本次更新的 micro-batch 数。4 级、8 批、每段前向 1 ms、反向 2 ms，一步需要 33 ms，每卡工作 24 ms，平均空闲 9 ms，利用率 72.7%。增加到 24 批，利用率达到 88.9%，但训练 batch、激活保存量和单批矩阵效率也随之影响整体选择。

当每段耗时不同时，最慢 stage 决定稳态出批速度。以四段 [1,1,2,1] ms 的纯前向为例，首批需要 5 ms，之后每批至少间隔 2 ms；8 批总计 19 ms。相同总计算量均衡为每段 1.25 ms 时，总计 13.75 ms。因此切层时应考虑 embedding、词表投影、MoE 和不同序列长度下的算子耗时。

3. 1F1B 主要改变激活的生命周期

AFAB 中，靠前 stage 会先为 m 批保存激活，之后才开始释放。1F1B 先做短暂预热，然后交替执行一批前向与一批反向，最后排空剩余反向。下游梯度到达后尽早使用并释放对应激活，缩短保留时间。

在等时、零通信的同步模型中，AFAB 与 1F1B 的理想空泡相同。它们的显存表现差异很大：AFAB 每个 stage 的保存量可达 m 批；标准 1F1B 中，编号 r 从 0 开始的 stage 峰值约为 \(\min(m,p-r)\) 批。上图默认 4 级、8 批，第一张卡从保存 8 批降到 4 批。

若每个 stage 为一批保存 200 MiB 激活，AFAB 峰值约 1600 MiB，1F1B 的首段约 800 MiB。更深的流水线虽减少每段层数，也可能增加首段同时保留的批数。估算时应将“单批本段激活大小”与“同时存活批数”相乘，再加入通信缓冲和重计算工作区。

固定全局 batch 时，增加 m 会减小单批 b。矩阵乘的行数随之下降，GPU 计算效率可能降低；通信总字节量大致相同，但消息数量增加，启动成本变大。实际扫描 m 时，应同时记录步时、峰值显存、GEMM 效率与边界通信，从总步时判断净收益。

4. 交错调度用更多边界换更短空泡

交错流水线让每卡持有 \(v\) 个分开的模型片段。例如 p=4、v=2，八个逻辑 stage 依次位于 GPU 0、1、2、3、0、1、2、3。每张卡的总层数保持不变，单片段约为原来的 1/v。调度器在多个片段之间安排就绪批次，使填充和排空的时间更短。

在片段均衡、足够多 micro-batch、通信可以隐藏的近似下，空泡时间由 \((p-1)(t_F+t_{BW})\) 降到约 \((p-1)(t_F+t_{BW})/v\)。代价是一个批次需要经过更多设备边界，调度也更细。上面的 4 卡配置从 3 个逻辑边界增到 7 个，每批跨卡次数随之增加。

深度优先调度倾向尽快推进已在途的批次；广度优先调度会把同一片段上的多批工作集中起来，更容易复用已 gather 的权重。使用 FSDP 与 PP 组合时，片段切换可能触发权重 gather，因此选择顺序还应把权重生命周期加入账本。图中的组大小 N 控制一组批次在片段之间的推进顺序。

5. 拆开反向，找到可以延后的计算

对线性层 \(Y=XW\)，收到输出梯度 \(G=\partial\mathcal L/\partial Y\) 后，反向包含两个矩阵乘：

$$\underbrace{\frac{\partial\mathcal L}{\partial X}=GW^\top}_{B\text{：输入梯度}},\qquad \underbrace{\frac{\partial\mathcal L}{\partial W}=X^\top G}_{W\text{：权重梯度}}.$$

输入梯度 B 决定上游能否继续反向，位于跨 stage 的依赖链。权重梯度 W 只需在优化器更新前完成，可以延后执行。Zero Bubble 调度把 B 优先放到关键路径，将 W 填到本来等待数据的空隙。

记三个操作用时为 \(t_F,t_B,t_W\)，完整反向为 \(t_B+t_W\)。对均衡的等时模型，ZB-H1 的空泡近似为 \((p-1)(t_F+t_B-t_W)\)。若三者均为 1，4 级的空泡从 9 降到 3。ZB-H2 允许更多批次在途，进一步为 W 寻找空隙；在足够多批次、F/B/W 时间匹配的条件下，可以覆盖稳态空泡。首批填充和末批排空仍占据端到端时间，因此图中的迭代总长和稳态空泡分开统计。

延后 W 会延长 X 和 G 的保存时间。图中分别统计“待输入梯度”和“待权重梯度”，峰值保留激活按两类的同时存活量合计。调度优化需要在显存预算下进行；显存紧张时，重计算部分激活或提早完成 W，可能比继续增加在途批次更有效。

将通信 c 从 0 调到 0.5，再比较普通与交错 1F1B，可以看到额外边界怎样侵蚀收益。随后延长 W，观察延迟计算累积了多少待完成工作。时间表中的“平均空闲”由迭代总长减去每卡平均忙碌时间得到；近似公式采用均衡、零通信的条件，当前排程则使用滑块所给的各项耗时。

6. DualPipe 把双向批次与通信重叠结合起来

DualPipe 在流水线两端分别放入批次，让一组沿 GPU 0→p−1 推进，另一组反向推进。每张卡持有两个方向对应的模型片段，来自相反方向的工作形成更多可调度组合。上图中带撇号的编号属于反向流；F 与 BW 拼在一格时，表示一个组合执行单元。

其关键优化还包括细化一个 Transformer block：将 attention、MLP、输入梯度、权重梯度与 MoE dispatch/combine 按依赖交错，使一批的计算覆盖另一批的通信。能覆盖多少取决于可并行的计算长度、网络持续时间，以及两者同时执行时的 GPU 资源争用。上图组合单元按 \(t_F+t_B+t_W\) 计时，展示批次顺序和依赖；重叠收益应由实际 block 的联合执行用时替换这个值。

选择这类调度时，先测独立计算与通信，再测它们并行时的速度。如果同时运行造成 GEMM 和传输都明显变慢，理想的 max(计算,通信) 时间就无法达到。DualPipe 的双向布局还增加参数片段与缓冲管理需求，相关变体通过 V 形层放置调整这部分开销。

7. 实际训练需要保持的三个约定

通信 shape 与分片约定。 前一段发送的 shape、dtype、micro-batch 编号必须与下一段接收相匹配。采用预分配静态通信缓冲时，末批大小变化或变长序列需要 padding、分桶，或切换到支持相应动态形状的路径。使用 TP+PP 时还要写清边界张量是复制还是按序列/通道分片，避免多卡重复发送一份完整激活。

梯度的归一化约定。 如果每个 micro-batch 的 loss 已按本批样本取平均，将 m 个平均梯度直接累加会放大 m 倍；等大小批次应再除以 m。语言模型中批次有效 token 数不同时，应累计各批 token loss 的和，再除以全局有效 token 总数，同时核对 DP 的 SUM/AVG 语义。这样改变流水线批次数仍能保持同一个训练目标。

模型切分与测量约定。 先固定序列分布和全局 batch，再扫描 stage 边界、micro-batch 大小与调度。若时间线上某一 rank 总是繁忙、其他 rank 反复等待，调整层划分；若增加 m 后空泡更少却步时更长，检查小 GEMM 效率和消息启动；若延后 W 导致峰值显存超过预算，限制在途激活或把 W 提前。每个选择都对应时间表上可定位的一段工作。

8. 练习：从排程推回部署选择

练习 1：利用率达到 90%

4 个等时 stage，前向 1 ms、完整反向 2 ms。至少需要多少 micro-batch 才能达到 90% 利用率？此时一步耗时多少？

展开解答

\(m/(m+3)\ge0.9\) 得 m≥27。总时间为 \((27+3)\times3=90\) ms，每卡工作 81 ms，平均空闲 9 ms。若全局 batch 固定，应继续检查减小单批后是否仍能保持给定计算时间。

练习 2：为 1F1B 做显存预算

p=4、m=16，每个 stage 每批保存 200 MiB 激活。比较 AFAB 与标准 1F1B 第一段的峰值，并求减少的容量。

展开解答

AFAB 约为 16×200=3200 MiB；1F1B 约为 min(16,4)×200=800 MiB，减少 2400 MiB。通信缓冲、算子工作区和优化器状态另行计入。

练习 3：交错调度的通信门槛

4 卡流水线，v 从 1 增到 2。每批边界消息为 32 MiB，有效单向带宽 16 GiB/s，忽略启动。每个批次前向增加多少跨卡边界和串行传输时间？

展开解答

逻辑边界从 3 增到 7，多 4 次。每次传输为 \(32/16384\) s=1.953125 ms，串行字节时间增加 7.8125 ms/批。实际暴露延迟取决于其中多少传输能够与其他批次计算重叠；反向还需发送对应梯度。

练习 4：不同长度批次如何平均 loss

两批分别有 100 和 300 个有效 token，平均 token loss 分别为 2 和 1。直接对两个平均 loss 再平均会得到什么？正确的整体 token 平均是多少？

展开解答

直接平均得到 1.5。按有效 token 加权，\((100\times2+300\times1)/(100+300)=1.25\)。反向传播的缩放也应与这个全局 token 平均一致。

用上面的排程器做一次小实验：固定 p=4、m=8、F=B=W=1、c=0，记录 AFAB、1F1B、ZB-H1 的迭代时长与峰值保留激活；再分别增加通信 c、micro-batch 数 m 和权重梯度时间 W。每次只改一个参数，并用依赖、字节量或保留时间解释变化。
