SimpleHC：把多路残差的读写合并起来

交互2026-11-11

把一个 Transformer 的单路残差扩展为四条，额外 FLOPs 可以很少，训练时间却明显增加。原因藏在每个 attention 和 FFN 之间：读出几条宽向量，计算门控，把它们合成子层输入，再把新输出写回。计算单元很快做完了乘加，下一步却要等数据搬过来。

SimpleHC 把这个问题拆成两件事：保留对模型有用的读写选择，再把相邻子层对同一份宽状态的访问合并起来。它采用恒等残差通路，保留动态、逐层独立的读写门控；连续四个子层从共同的入口状态生成门控，子层之间用标量系数传递新输出，最后统一写回四条残差流。这里最值得理解的是：哪些信息需要马上交给下一层，哪些大张量可以晚一点再落回显存。

1. 先分清读取、计算、混合与写入

普通残差子层计算 \(x_{l+1}=x_l+F_l(x_l)\)。这里 \(l\) 每增加 1，经过一个 attention 或 FFN；一个完整 Transformer block 包含两个这样的子层。\(F_l\) 包含子层需要的归一化及 attention/FFN 运算。

Hyper-Connections 同时保存多条状态。对一个 token，令 \(\htmlData{symbol=state}{X_l}\in\mathbb R^{n\times C}\)：\(n\) 行分别是残差流，每行有 \(C\) 个通道。默认 \(n=4\)。完整 batch 的张量还带有 batch、序列位置两个前导维度；以下公式描述一个位置，attention 在计算 \(F_l\) 时仍会访问序列中的其他位置。

读取门控 \(p_l\in\mathbb R^n\) 决定当前子层从每条流读取多少；写入门控 \(q_l\in\mathbb R^n\) 决定把计算结果向每条流写入多少。残差混合矩阵 \(M_l\in\mathbb R^{n\times n}\) 的第 \(i\) 行、第 \(j\) 列表示旧流 \(j\) 对新流 \(i\) 的贡献。三个步骤是：

\[ u_l=X_l^\top\htmlData{symbol=read}{p_l},\qquad o_l=F_l(u_l),\qquad X_{l+1}=\htmlData{symbol=mixing}{M_l}X_l+\htmlData{symbol=write}{q_l}o_l^\top. \]

\(u_l,o_l\) 都是 \(C\) 维列向量。\(X_l^\top p_l\) 把 \(n\) 条流汇总成一个子层输入；\(q_lo_l^\top\) 是一个 \(n\times C\) 外积，把同一个输出按不同比例分配回各流。例如 \(q_l=(1,0.5,0.2,0.8)^\top\)，四条流分别加上 \(o_l,0.5o_l,0.2o_l,0.8o_l\)。

HC 允许学习自由的混合矩阵；mHC 用 Sinkhorn 归一化，使混合矩阵近似满足非负、每行每列和为 1。SimpleHC 取 \(M_l=I\)，于是每条旧流直接留下，再加上本层写入：

\[ X_{l+1}=X_l+q_lo_l^\top. \]

这个改动保留了跨流的信息交流：子层从多条流读取，经过 \(F_l\) 计算，再把结果写入多条流。它把交流集中在“读入子层—计算—写回”的通路上，旧状态本身沿恒等路径向前传播。

2. 保留什么：两种有效的交互机制

先看质量，再决定哪些操作值得保留。在 15B 总参数、每个 token 激活约 1B 参数的 MoE 对照中，把门控和混合逐一拆开，会看到两个有效组合：一组是共同学习的读取与写入；另一组是不受双随机约束的混合。下表摘取相同实验中的关键配置；平均分由 MMLU、HellaSwag、MATH、MBPP、C3 五项组成，分数越高越好，验证 loss 越低越好。

残差设计读取 / 写入混合Loss五项平均分
Vanilla单路残差恒等1.67852.4
mHC共同学习Sinkhorn1.65955.0
identityHC共同学习恒等1.66055.4

固定写入读取学习，写入固定恒等1.67852.8

固定读取使用 \(p=\mathbf1/n\)，即平均读取各流；固定写入使用 \(q=\mathbf1\)，即向各流写入同样的输出。只固定其中一侧，就会削弱恒等残差版本的收益。一个自然的理解是：不同子层需要选择合适的信息，也需要把新信息放到合适的流中；读取与写入共同建立这种分工。

SimpleHC 选择了共同学习的读写门控和恒等残差。这个配置在上述对照中保留了接近 mHC 的质量，同时为后续的加法展开提供了简单结构。自由混合的额外收益和跨深度的传播行为，留到稳定性部分一起看。

动态门控怎样生成

将 \(n\times C\) 状态按行展平成 \(nC\) 维向量，进行无仿射参数的 RMSNorm，得到 \(z_l\)。对于读取和写入，各有一套独立参数：

\[ z_l=\operatorname{RMSNorm}(\operatorname{vec}X_l),\qquad \ell_l^s=\alpha_l^s(W_l^s)^\top z_l+b_l^s, \quad s\in\{\mathrm{pre},\mathrm{post}\}, \] \[ p_l=\sigma(\ell_l^{\mathrm{pre}}),\qquad q_l=2\sigma(\ell_l^{\mathrm{post}}). \]

这里 \(W_l^s\in\mathbb R^{nC\times n}\)，\(b_l^s\in\mathbb R^n\)，\(\alpha_l^s\) 是可学习标量。\(\sigma\) 为 sigmoid，因此每个读取系数位于 \((0,1)\)，写入系数位于 \((0,2)\)。这些系数随 token 状态变化，读取系数的总和也可以变化。下一步要减少的，是生成它们时反复访问宽状态的次数。

3. 四个子层怎样只写回一次

设一组从子层 \(L\) 开始，共有 \(\htmlData{symbol=group}{K}\) 个子层。默认 \(K=4\)，顺序是 attention、FFN、attention、FFN，正好两个 Transformer block。组入口 \(X_L\) 保存四条宽残差流。

恒等残差使中间状态成为逐项相加：

\[ X_j=X_L+\sum_{k=L}^{j-1}q_ko_k^\top. \]

\(o_k\) 是前面第 \(k\) 个子层的 \(C\) 维输出，\(q_k\) 是当时向各流写入的 \(n\) 维系数。当前子层 \(j\) 用 \(p_j\) 读取状态，把上式代入 \(u_j=X_j^\top p_j\)：

\[ u_j=\underbrace{X_L^\top p_j}_{\text{入口基础读取}} +\sum_{k=L}^{j-1}\underbrace{(p_j^\top q_k)}_{\text{一个标量}}o_k. \]

一次“写入各流，再从各流读取”，合起来就是一个内积。假设之前的输出向两条流分别写入 \(1\) 倍与 \(0.5\) 倍，后面读取两条流的权重是 \(0.25\) 与 \(0.75\)，那么这个输出对后面输入的总贡献就是 \(0.25\times1+0.75\times0.5=0.625\) 倍。

先把门控准备好

上面的展开需要当前的 \(p_j,q_j\) 已经可用。逐子层门控原本依赖更新后的 \(X_j\)。SimpleHC 改为让组内各子层从入口 \(X_L\) 生成自己的门控：

\[ \bar p_j=g_j^{\mathrm{pre}}(X_L),\qquad \bar q_j=g_j^{\mathrm{post}}(X_L),\qquad L\le j<L+K. \]

横线表示“根据组入口计算”。每个 \(g_j\) 仍有自己的投影、缩放和偏置。因此四个子层看到同一份输入状态，也可以作出四种不同的读写选择。

共享入口改变了门控的条件输入；给定这组门控以后，后面的计算重排是代数等价的。两件事分别由消融实验和数值等价检查来验证。训练时，梯度会通过每个门控函数回到组入口。

把跨子层的贡献写成一个小矩阵

把组内的门控按子层顺序排成列，得到 \(P=[\bar p_L,\ldots,\bar p_{L+K-1}]\) 和 \(Q=[\bar q_L,\ldots,\bar q_{L+K-1}]\)，二者均为 \(n\times K\)。预先计算：

\[ V=X_L^\top P\in\mathbb R^{C\times K},\qquad \htmlData{symbol=correction}{D}=\operatorname{tril}(P^\top Q,-1)\in\mathbb R^{K\times K}. \]

\(V\) 的第 \(a\) 列是第 \(a\) 个子层从入口取得的基础输入。\(D\) 的行对应后面读取的子层，列对应前面写入的子层；\(D_{ab}=\bar p_{L+a}^\top\bar q_{L+b}\)。只保留严格下三角，因为第 \(a\) 个子层能接收的输出来自 \(b<a\)。当 \(K=4\) 时，\(D\) 有六个这样的系数。

\[ u_{L+a}=V_{:,a}+\sum_{b<a}D_{ab}o_{L+b},\qquad o_{L+a}=F_{L+a}(u_{L+a}). \]

四个子层仍按顺序计算。后一个子层用到了前一个子层刚产生的输出，只是这份信息通过 \(C\) 维向量直接传递。组末再把全部输出排成 \(O=[o_L,\ldots,o_{L+K-1}]\in\mathbb R^{C\times K}\)，统一写回：

\[ X_{L+K}=X_L+QO^\top. \]

可以把执行顺序记成：入口读一次以生成各层门控，入口再读一次以生成各层基础输入；依次计算子层并补入历史输出；组末统一写回。中途保留的是每个子层的窄输出，宽残差状态只在组边界更新。

对应的伪代码
# X: [tokens, n, C]；每个 token 独立生成门控
# P, Q: [tokens, n, K]；各子层参数独立
P, Q = grouped_gates(X)
V = einsum("tnc,tnk->tck", X, P)
D = tril(einsum("tna,tnb->tab", P, Q), diagonal=-1)
outputs = []
for a in range(K):
    u = V[:, :, a]
    for b in range(a):
        u = u + D[:, a, b, None] * outputs[b]
    outputs.append(sublayers[a](u))
X_next = X + einsum("tnk,tck->tnc", Q, stack(outputs, dim=-1))

这段写法直接表达计算关系。高效实现会把内层乘加、输出读取和最终写回融合，减少临时张量。

4. 共享入口，为什么仍要逐层独立的门控

共享输入是否损失质量，取决于入口包含多少后续门控所需的信息，以及组内新输出能否及时进入后续子层。15B-A1B 对照把这两个问题分开验证：

共享 2 个子层各层独立保留1.66054.8
SimpleHC，共享 4 个子层各层独立保留1.66055.0
共享 8 个子层各层独立保留1.66254.3

共享 4 个子层，省去修正各层独立省去，组末仍写回1.70547.9

最明显的下降发生在省去修正时。虽然组末仍把四个输出写回了残差流，后面的子层在计算当下却只拿到入口信息。这切断了组内的顺序加工。相比之下，四层门控共同看入口，同时保留各自参数和输出修正，维持了接近参考模型的质量。

门控预测实验进一步检查了入口的信息量：冻结训练好的 identityHC，让独立的小预测器从组入口预测后面子层的门控。误差在冻结教师模型的轨迹上评估，写入门控先除以 2，使读写两种门控都按 \(0\) 到 \(1\) 的尺度统计。测试集上，直接使用对应教师门控参数时，写入门控的平均绝对误差为 0.05044；只训练预测器后，降到 0.01034。读取门控也从 0.05817 降到 0.01653。这解释了为什么“相同输入、不同映射”有机会保留逐层的路由选择。

这个比较给出的设计结论很具体：可以尝试减少决定门控时的状态刷新频率，同时保留逐层决策和最新子层输出。把组继续扩大，需要同时考察门控预测误差、最终质量和修正成本。

5. 18C 到 9C：逐项计算显存访问

GPU 的 HBM 保存大张量，线程在寄存器和片上存储中计算。一次 kernel 可以把数据读进来，完成多步运算再写回；跨 kernel 留下的大型中间张量通常增加显存流量。SimpleHC 的收益主要来自减少对 \(nC\) 个元素的宽残差状态的重复访问。

先固定计数范围：每个 token、每个子层的残差连接前向激活读写，以元素数计。读取参数、小型门控系数和 attention/FFN 内部访问分别核算。一次读或写一条完整的宽残差状态，计 \(nC\) 个元素；一条子层输入或输出只有 \(C\) 个元素。

融合后的 mHC 与 identityHC

操作读写内容每 token、每子层
投影与 RMS 统计读取宽状态\(nC\)
汇总子层输入读取宽状态，写出窄输入\(nC+C\)
写回残差读取旧宽状态和窄输出，写出新宽状态\(2nC+C\)
合计\(4nC+2C\)

取 \(n=4\)，结果为 \(18C\)。融合后的 mHC 在同一 kernel 中完成混合、输出分配与残差写回，所以 identityHC 去掉混合后，仍需要这三次操作中的相同大张量访问。减少算术和减少数据搬运，是两笔可以分别检查的账。

SimpleHC 的组边界访问与组内修正

一组 \(K\) 个子层只做一次门控状态读取、一次基础输入状态读取，以及一次宽状态读出与写回，共 \(4nC\) 个元素。摊到每子层为 \(4nC/K\)。各层的基础输入写出、最终写回时的窄输出读取，平均还需要 \(2C\)。

组内第 \(a\) 个子层从 0 开始编号。对于 \(a>0\)，修正 kernel 读取一个基础输入和 \(a\) 个之前的输出，再写出一个修正后的输入，共 \((a+2)C\) 个元素。第 0 个子层直接使用基础输入。平均修正流量为：

\[ Q_{\mathrm{corr}}(K)=\frac{C}{K}\sum_{a=1}^{K-1}(a+2) =\frac{C(K-1)(K+4)}{2K}. \]

因此，SimpleHC 每个 token、每个子层的逻辑前向访问量为

\[ \htmlData{symbol=traffic}{Q_{\mathrm{act}}}(K) =\underbrace{\frac{4nC}{K}}_{\text{宽状态访问}} +\underbrace{2C}_{\text{基础输入写出与输出读取}} +\underbrace{\frac{C(K-1)(K+4)}{2K}}_{\text{组内修正}}. \]

当 \(n=K=4\) 时，三项分别为 \(4C,2C,3C\)，合计 \(9C\)。取 \(C=6144\)、8192 个 token、BF16 每元素 2 字节，这部分前向读写从每子层 \(1728\) MiB 降到 \(864\) MiB。这里统计的是所有 token 累计搬运的字节数；设备实际 HBM 事务还受缓存复用和 kernel 布局影响。

组越大，第一项越小，但每个输出需要送往更多后续子层，第三项随之增长。对 \(n=4\)，上式可整理为

\[ \frac{Q_{\mathrm{act}}(K)}C=\frac K2+\frac72+\frac{14}{K}. \]

连续近似的最低点在 \(K=\sqrt{28}\approx5.29\)，整数 \(K=5\) 给出 \(8.8C\)。\(K=4\) 的 \(9C\) 是所比较的 \(2,4,8,16\) 四种组长中最低的，而且恰好覆盖两个完整 block。实际选组长还要加入质量、尾组、流水线边界和 kernel 效率。四个子层是有实验支撑、结构对齐的折中点。

FLOPs 怎么变

采用一次乘加计 2 FLOPs 的近似，mHC 每子层的门控投影将 \(nC\) 维输入映射到 \(n^2+2n\) 个系数，成本约 \(2nC(n^2+2n)\)。去掉混合投影后，读写门控只需 \(2n\) 个系数，成本约 \(4n^2C\)。在 \(n=4\) 时，两者为 \(192C\) 与 \(64C\)。

分组仍保留各子层的独立门控，投影的乘加总量保持对应的规模，但可以更充分地复用同一次载入的输入。标量修正每组包含 \(K(K-1)/2\) 个“向量乘系数再相加”，平均增加约 \(C(K-1)\) FLOPs/子层；若只计算所需的严格下三角系数，还约需 \(n(K-1)\) FLOPs/子层；伪代码和 CPU 实验为表达简洁，先计算完整 \(P^\top Q\) 再取下三角，这一步约为 \(2nK\) FLOPs/子层。它用少量窄向量算术换取宽状态访问的减少。attention、FFN、归一化和反向传播的成本需要接着加入整步账本。

6. 把公式变成快的前向与反向

代数重排提供的是优化空间，kernel 决定这个空间能用掉多少。在宽度 \(C=6144\) 的效率配置下，SimpleHC 的 PyTorch 实现额外训练时间为 22.5%，专用实现降到 2.4%。这里有三个可迁移的工程方法。

先复用加载，再融合小算子

组入口展平为 \(x\in\mathbb R^{nC}\)。将 \(K\) 个子层的读写投影拼成 \(W\in\mathbb R^{nC\times2Kn}\)，可以一次得到所有未归一化投影。同时累积平方和：

\[ t=W^\top x,\quad s=x^\top x,\quad r=\left(\frac{s}{nC}+\epsilon\right)^{-1/2}. \]

\(r\) 是 RMS 的倒数。由于门控采用无仿射 RMSNorm，线性投影满足 \(W^\top(rx)=r(W^\top x)\)。因此 kernel 可以一起计算 \(t,s\)，随后在小张量上完成 \(\alpha rt+b\) 和 sigmoid，省下一个 \(nC\) 大小的归一化中间缓冲。

在 \(n=K=4\) 时，合并投影的形状是 \(4C\times32\)：32 列对应四层、读写两种操作、每种四个系数。接着，基础读取 kernel 从宽状态的一个 tile 生成四个不同的基础输入。修正 kernel 直接接收之前输出的指针，融合乘系数、相加与写出；组末 kernel 一次性完成四份输出分配及残差相加。

反向传播也可以一起处理宽梯度

重新记住这三个形状：\(P,Q\) 为 \(n\times K\) 门控矩阵，\(V,O\) 为 \(C\times K\) 基础输入与子层输出，\(X_L\) 为 \(n\times C\) 入口。令 \(E=\partial\mathcal L/\partial X_{L+K}\) 为组出口的宽梯度，\(G=\partial\mathcal L/\partial V\) 为各基础输入的梯度。基础读取与最终写回贡献：

\[ \nabla_{X_L}\mathcal L\mathrel{+}=E+PG^\top,\qquad \nabla_O\mathcal L\mathrel{+}=E^\top Q. \]

符号 \(\mathrel{+}=\) 表示把这条计算路径的梯度累加进去。前式把四层输入返回的梯度和恒等路径的 \(E\) 合在一次宽写出中；后式读取同一份 \(E\)，给四个子层输出生成各自梯度。组内修正和动态门控投影还会贡献梯度，它们沿各自路径继续累加。

标量修正的反向传播

在组内把子层 \(L+a\) 简写为 \(a\)：\(v_a=V_{:,a}\)，\(p_a=\bar p_{L+a}\)，\(q_a=\bar q_{L+a}\)，\(u_a,o_a\) 分别表示该子层的输入、输出。对于 \(u_a=v_a+\sum_{b<a}D_{ab}o_b\)，令 \(g_a=\partial\mathcal L/\partial u_a\in\mathbb R^C\)。一对 \((a,b)\) 给出

\[ \nabla_{o_b}\mathcal L\mathrel{+}=D_{ab}g_a,\qquad \nabla_{D_{ab}}\mathcal L=g_a^\top o_b. \]

再由 \(D_{ab}=p_a^\top q_b\) 得到 \(\nabla_{p_a}\mathcal L\mathrel{+}=q_b\nabla_{D_{ab}}\mathcal L\)、\(\nabla_{q_b}\mathcal L\mathrel{+}=p_a\nabla_{D_{ab}}\mathcal L\)。因此反向按子层逆序处理，每个早期输出接收来自后面多个子层的梯度。

小门控梯度怎样利用 Tensor Core

一个常见的 GPU 工程问题是：输出矩阵很小，归约维度却很长。读写门控的两条梯度贡献为

\[ \nabla_P\mathcal L\mathrel{+}=X_LG,\qquad \nabla_Q\mathcal L\mathrel{+}=EO. \]

取 \(n=K=4\)，\(X_LG\) 是 \((4\times C)(C\times4)\)，每个 token 只产出 16 个数。把通道分块后，各块的局部结果还需要归约；如果写出许多局部结果再启动一个 kernel 求和，临时缓冲与启动开销会侵蚀收益。

一种办法是一起处理四个 token。将各 token 的 \(X\) 沿行拼成 \(16\times C\) 矩阵，将各自的 \(G\) 沿列拼成 \(C\times16\) 矩阵，得到适合成块矩阵乘法的 \(16\times16\) 输出：

\[ \begin{bmatrix}X^{(0)}\\X^{(1)}\\X^{(2)}\\X^{(3)}\end{bmatrix} \begin{bmatrix}G^{(0)}&G^{(1)}&G^{(2)}&G^{(3)}\end{bmatrix}. \]

结果的块 \((i,j)\) 是 \(X^{(i)}G^{(j)}\)。需要保存的是四个对角块 \(X^{(i)}G^{(i)}\)，各自对应同一个 token 的门控梯度。通道归约在片上累积，最后只写出这四块。

这个设计体现了一条实用原则：先找出反复读取、零碎归约和中间缓冲，再考虑用适合硬件的矩阵块来承载它们。判断优化是否有效，可以同时测 kernel 时长、显存事务、临时缓冲大小与整步训练时间；Tensor Core 指令形状和精度选择则随目标 GPU 调整。

7. 激活显存究竟省在哪里

显存流量是运行中累计搬运了多少数据；激活存储是反向传播开始时，还需要留下哪些数据。一个张量可以只存一份、被读取多次，所以这两笔账需要分开。

先看最简单的残差入口存储。若没有重算，逐子层执行要保存 \(K\) 份 \(n\times C\) 入口，分组执行主要保存一份组入口。仅对这部分状态，理想减少比例为 \(1-1/K\)，\(K=4\) 时为 75%。完整实现还要保存子层输入、输出、基础读取、门控和一些拷贝。

取八个 Transformer block，即 16 个子层，宽度 \(C=2048\)，一个 8192-token 序列，BF16。令 \(T=8192\) 为本地 microbatch 的 token 数，

\[ U=2TC\ \text{bytes}=32\ \text{MiB}. \]

\(U\) 表示一份形状为 \(T\times C\) 的窄激活。按源码级存储分配估算，留下的边界与 HC 激活如下：

一个容易漏算的实践细节：切片让整块存储继续存活

四个基础输入一起分配为一个包含 \(4U\) 数据的缓冲，第一个子层取其中一片作为输入。只要这个输入 view 还被 autograd 保存，整块底层存储就仍然存活。因此输入这一行已经计入了 \(U\) 后，每组还需计入剩余 \(3U\)，四组就是表中的 \(12U\)。这能解释“张量看起来只剩一小片，显存却没有释放”的常见现象。

排查时，先看张量是否共享底层 storage，再看 autograd 保存了哪些引用。显存统计应对每块存储计数一次，同时覆盖仍被 view 保留的完整分配。主动复制小切片可以缩短大缓冲的生命周期，但会增加复制成本；是否值得，取决于大缓冲何时能释放、其他切片是否还被需要。

主要收益是减少逐层保留的宽状态；新增的基础读取和辅助张量会抵消一部分节省。用完整生命周期计算，才能从“理论上少存几份状态”走到真实训练显存。

8. 稳定性：恒等路径保住了什么

一个早期 FFN 算出的特征，可能要到很多层之后才派上用场。多路残差提供了两种调节办法：写入时决定把它存到哪些 stream，读取时决定从哪些 stream 取回；还可以让中间的混合矩阵不断重新分配它。

固定一个 token，设第 \(k\) 个子层的输出是 \(o_k\)，第 \(j\) 个子层读取的输入是 \(u_j\)，且 \(j>k\)。用 \(p_j\in\mathbb R^n\) 表示后层的读门、\(q_k\in\mathbb R^n\) 表示前层的写门，\(M_t\in\mathbb R^{n\times n}\) 表示中间第 \(t\) 层的 stream 混合。这里 \(p,q\) 统一表示实际使用的门值；SimpleHC 中就是前文带横线、从各自组入口生成的门控，前后两层可以跨组。沿残差支路展开，\(o_k\) 在 \(u_j\) 中的系数是：

\[ c_{j,k}=p_j^\top \underbrace{M_{j-1}M_{j-2}\cdots M_{k+1}}_{\text{写入之后、读取之前的重新分配}} q_k. \]

相邻两个子层之间没有中间混合，括号中的乘积取单位矩阵。这个式子把三件事串起来了：\(q_k\) 分配输出，中间矩阵改变分配，\(p_j\) 收集结果。

读写门可以直接学历史权重

identityHC 和 SimpleHC 都令中间混合为单位矩阵，于是上式缩成 \(c_{j,k}=p_j^\top q_k\)。例如，前层把输出按 \((1,0.5)\) 写到两条 stream，后层按 \((0.6,0.4)\) 读取，就得到 \(0.6\times1+0.4\times0.5=0.8\) 倍的历史输出。写门与读门合作，便能为不同的前后层组合形成不同权重。

信息仍会经过计算分支在 stream 之间交流：读门先把多条 stream 汇成一个 \(C\) 维输入，attention 或 FFN 加工它，写门再把结果送回多条 stream。恒等映射保留了旧状态的直通路径，跨 stream 的新信息由这个非线性分支产生。

SimpleHC 的读门用 sigmoid，写门用两倍 sigmoid。对 \(n\) 条 stream，每个读系数在 \((0,1)\)，写系数在 \((0,2)\)，因此每一对前后层满足：

\[ 0<c_{j,k}=\sum_{s=1}^{n}p_{j,s}q_{k,s}<2n. \]

四条 stream 对应上界 8。这个上界控制单个历史输出的直接残差路径系数；整个网络的尺度与梯度还取决于许多历史项的累加、计算分支以及门对输入的敏感程度。

混合矩阵提供的自由度在哪里？

换一种设计：读门固定为 \(p_j=\mathbf1/n\)，即平均读取；写门固定为 \(q_k=\mathbf1\)，即把输出同样写入所有 stream。此时可学习的历史权重来自中间混合：

\[ c_{j,k}=\frac1n\mathbf1^\top \bigl(M_{j-1}\cdots M_{k+1}\bigr)\mathbf1. \]

无约束矩阵可以产生带正负号、幅度各异的系数，也会沿深度反复放大某些方向。例如，每次把同一方向放大 1.01 倍，连续 100 次就成为 \(1.01^{100}\approx2.70\) 倍。

完全双随机的矩阵元素非负，行和、列和都是 1。它保持全一向量，也保持对 stream 求和，因此上面固定读写门的系数恰好是 \(c_{j,k}=1\)。这解释了两类交互的分工：可学习读写门直接选择历史权重；无约束混合通过途中变换学习权重。双随机约束收紧途中变换的自由度，同时保留可学习读写门提供的选择能力。

稳定性要同时检查数值和导数

对完全双随机矩阵 \(M\)，有 \(\|M\|_2\leq1\)：把矩阵固定以后，这条线性路径的欧氏范数受到控制。训练中的混合矩阵还会随输入 \(X\) 改变。若 \(Y=M(X)X\)，输入发生一个小扰动 \(\mathrm dX\)，输出的变化为：

\[ \mathrm dY= \underbrace{M\,\mathrm dX}_{\text{沿当前矩阵传播}} +\underbrace{(\mathrm dM)X}_{\text{输入改变了混合方式}}. \]

工程诊断因此有两个层面。前向记录 FFN 输出尺度、混合前后 RMS，以及有限轮 Sinkhorn 的实际行列和，能定位异常值从哪里进入、在哪一步继续增大。反向分别记录固定矩阵路径和动态门路径的梯度，能检查混合方式对输入的敏感性。完整网络的稳定性需要把这两类观测连接起来。

压力实验里，异常从哪里开始

在230B-A6B、10倍参考学习率的压力实验中，峰值学习率为 \(6.2\times10^{-3}\)，warmup为4000步，三种配置都运行28,000步。mHC出现约 \(1.9\times10^6\) 的梯度峰值，SimpleHC和identityHC保持有界。一次捕获的早层MoE事件中，输入RMS为0.294，写入门控之前的FFN输出RMS已达到 \(2.31\times10^4\)。这一步把异常的起点定位到了计算分支。

另一次记录中，20轮Sinkhorn后的行和仍为 \((2,1,0.5,0.5)\)，混合把同一token的RMS从 \(5.42\times10^4\) 进一步放大到 \(7.50\times10^4\)。一次反向尖峰的动态混合门输入梯度约为固定矩阵路径的9.4倍。它提示诊断时既要检查分支输出，也要检查归一化误差与动态导数；动态路径的异常究竟来自数学敏感性还是反向数值效应，还需要进一步定位。

这项简化的取舍很清楚：保留动态读写门来选择历史信息，以单位矩阵传递旧 stream，消除反复混合及其额外的动态梯度路径。它提供了更简单的传播结构；最终训练质量和稳定范围，则由相应规模、学习率与数值实现下的实验来确定。

额外开销下降，换算成整步速度是多少

在宽度 6144 的八层效率测试里，把 Vanilla 的单步时间记为 \(t_0\)。高效 mHC 约为 \(1.070t_0\)，SimpleHC 为 \(1.024t_0\)。所以相对 mHC，整步用时减少

\[ 1-\frac{1.024}{1.070}\approx4.30\%, \qquad \frac{1.070}{1.024}\approx1.045. \]

右边是相同工作量下的吞吐倍率，约提升 4.5%。若某个匹配配置的 mHC 训练要 1000 GPU 小时，按这个比值估算，SimpleHC 约需 957 GPU 小时。这是由报告比例换算的预算示例，实际部署应在目标深度、并行方式和重算配置上测量。

宽度 1024 时，mHC、identityHC、SimpleHC 的额外开销分别为 26.8%、10.1%、6.3%。随着宽度增加，主要专家矩阵乘法的成本上升，多流连接的相对占比下降。仅删混合与进一步共享访问，分别改善了不同部分的成本。

截至 2026-11-11，官方项目公开了报告和图表，训练代码与高效 kernel 尚待发布；报告也未列出效率测试的 GPU 型号、卡数和具体并行配置。当前可复现的起点是验证计算等价性，再在自己的 GPU 上实现读写融合、测整步收益。下方 CPU 实验覆盖第一步。

SimpleHC 的核心价值，是让残差结构与执行计划一起变简单。读写门控保留选择信息的能力，恒等路径使历史贡献可以直接展开，共享入口把多次宽状态访问合并。最终效果来自这三者的配合，以及把公式落实为低中间存储的 kernel。

10. 计算题与可运行实验

练习一：一次写入经过两条流，后面读到多少

入口 \(X=(2,6)^\top\)，第0个子层读取 \(p_0=(0.75,0.25)^\top\)，计算 \(F_0(u)=u/2\)，写入 \(q_0=(1,0.5)^\top\)。第1个子层读取 \(p_1=(0.25,0.75)^\top\)。分别通过完整状态和标量修正计算第1个子层的输入。

展开解答

先有 \(u_0=3,o_0=1.5\)。完整状态更新为 \((3.5,6.75)^\top\)，随后读取 \(0.25\times3.5+0.75\times6.75=5.9375\)。分组方法的基础输入为5，修正系数为 \(p_1^\top q_0=0.625\)，因此 \(5+0.625\times1.5=5.9375\)。两种执行对同一组门控得到相同结果。

练习二：增加组长，为什么流量会回升

四条流下，计算 \(K=4,8,16\) 时每 token、每子层的前向连接流量。若只保存组入口，三种配置的残差入口存储分别减少多少？

展开解答

代入 \(Q_{\mathrm{act}}(K)/C=K/2+3.5+14/K\)，得到 \(9,9.25,12.375\)。对应残差入口状态的理想减少比例为 \(1-1/K\)，即75%、87.5%、93.75%。组长增大持续减少入口存储，修正产生的流量却逐渐增加。选择组长要分别查看流量、存储、质量三项。

练习三：去掉修正还剩多少顺序依赖

保持组入口门控和最终写回，但令组内所有 \(D_{ab}=0\)。四个子层的输入如何变化？哪一项训练机制被改变？

展开解答

各层输入变成 \(u_{L+a}=V_{:,a}=X_L^\top\bar p_{L+a}\)。它们都仅由入口生成，后一个子层的输入失去了前一个子层的新输出。组末依然汇总了所有输出，但组内四步顺序的非线性加工被改成对入口分别加工。这与消融中 loss 从1.660升至1.705对应。

练习四：把额外开销换算成训练预算

同一工作量下，mHC 用时为基线的1.07倍，SimpleHC为1.024倍。mHC任务需要400张卡运行10天，其他条件保持一致，按这个比例估计节省多少 GPU 天？

展开解答

原预算4000 GPU天。新预算为 \(4000\times1.024/1.07\approx3828.04\) GPU天，节省约171.96 GPU天。保持400张卡时约节省0.430天，即10.32小时。预算预测成立的前提是目标配置获得相同的整步时间比例；应先用真实 batch、并行与重算做短程测量。
