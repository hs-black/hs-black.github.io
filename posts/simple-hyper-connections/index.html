SimpleHC：把多路残差的读写合并起来

交互2026-11-11

把 Transformer 的单路残差扩成四条，多出来的 FLOPs 并不多，训练却明显变慢。卡脖子的地方在每个 attention 和 FFN 之间：每层都要从显存里读出几条宽向量、算门控、拼出子层输入，算完再写回去。算力单元一眨眼就干完活了，大半时间都在等数据搬运。

SimpleHC 的解法分两步走：先把没必要的残差混合删掉，只留动态、逐层独立的读写门控和恒等残差；再把连续四个子层打包成一组——门控统一从组入口算出来，子层之间只用标量系数传递刚算出的新输出，等整组跑完再一次性写回四条残差流。背后其实是笔很直白的账：哪些窄向量必须立刻交给下一层，哪些宽状态可以攒到组末再落回显存。

1. 先分清读取、计算、混合与写入

标准残差子层写起来就一行：\(x_{l+1}=x_l+F_l(x_l)\)。这里每走一步 \(l\)，就是过一个 attention 或 FFN（含前面的归一化），所以一个完整的 Transformer block 占两个子层。

Hyper-Connections 把单路状态扩成了多路。盯住单个 token 来看（下文公式省去 batch 和序列维度，attention 算 \(F_l\) 时照常看全序列），残差状态变成一个矩阵 \(\htmlData{symbol=state}{X_l}\in\mathbb R^{n\times C}\)：共 \(n\) 行，每行是一条 \(C\) 维残差流，默认 \(n=4\)。

多路残差在子层前后加了三样东西：读取门控 \(p_l\in\mathbb R^n\) 决定从各条流里各取多少，写入门控 \(q_l\in\mathbb R^n\) 决定把子层输出按什么比例分回去，残差混合矩阵 \(M_l\in\mathbb R^{n\times n}\) 则负责在旧流之间重新洗牌（第 \(i\) 行第 \(j\) 列是旧流 \(j\) 对新流 \(i\) 的权重）。合起来就是三步：

\[ u_l=X_l^\top\htmlData{symbol=read}{p_l},\qquad o_l=F_l(u_l),\qquad X_{l+1}=\htmlData{symbol=mixing}{M_l}X_l+\htmlData{symbol=write}{q_l}o_l^\top. \]

其中子层的输入 \(u_l\) 和输出 \(o_l\) 都还是 \(C\) 维列向量，没有变宽。\(X_l^\top p_l\) 把 \(n\) 条流加权压成一条输入；外积 \(q_lo_l^\top\) 则是把同一个输出按不同倍数分发回各条流——比如 \(q_l=(1,0.5,0.2,0.8)^\top\)，四条流就分别加上 \(o_l,0.5o_l,0.2o_l,0.8o_l\)。

原版 HC 直接学一个自由的 \(M_l\)，mHC 为了稳住数值，用 Sinkhorn 迭代把它压成近似双随机矩阵（非负，且每行每列之和为 1）。SimpleHC 更干脆：直接令 \(M_l=I\)，旧流原封不动往下传，只叠加上本层的写入：

\[ X_{l+1}=X_l+q_lo_l^\top. \]

别以为删了 \(M_l\) 就断了跨流交流。子层依然会从多条流里读信息，经过 \(F_l\) 加工后再写回多条流——跨流交互只是全都收束到了这条非线性计算支路上，主干道则退回到干净的恒等映射。

2. 保留什么：两种有效的交互机制

敢不敢直接把 \(M_l\) 砍掉，得先拿消融实验说话。在 15B 总参数、每 token 激活约 1B 参数的 MoE 模型上，把读写门控和残差混合拆开排列组合，结果很清楚：真正撑起收益的机制其实只有两套——要么读写门控一起学，要么放开自由混合。下面摘了这组对照的关键配置（五项平均分涵盖 MMLU、HellaSwag、MATH、MBPP 和 C3）：

残差设计读取 / 写入混合Loss五项平均分
Vanilla单路残差恒等1.67852.4
mHC共同学习Sinkhorn1.65955.0
identityHC共同学习恒等1.66055.4
固定读取读取固定，写入学习恒等1.67653.6
固定写入读取学习，写入固定恒等1.67852.8
固定读写均固定无约束1.66056.0

表里的「固定读取」是直接取均值 \(p=\mathbf1/n\)，「固定写入」是等量广播 \(q=\mathbf1\)。注意看中间两行：在恒等残差下，读写门控只要锁死任何一边，收益立马缩水大半。道理不难想——光能从特定流里挑东西却不能定向存回去，或者只管定向存却只能糊成一团读，四条流的分工根本立不住，读写必须配合着学。

对比下来，学习读写门控 + 恒等残差（表里的 identityHC）几乎拿到了 mHC 的全部质量，还把残差主干变成了纯加法——这正是后面能做分组展开的前提。至于最下面两行「无约束混合」多出来的那点分数，代价是什么、深层会不会炸，留到第 8 节一起算账。

动态门控怎样生成

读写门控都随 token 动态生成：先把 \(n\times C\) 的状态按行拉直成 \(nC\) 维向量，做一次不带仿射参数的 RMSNorm 得到 \(z_l\)，再用两套各自独立的线性映射算出读取和写入的 logit：

\[ z_l=\operatorname{RMSNorm}(\operatorname{vec}X_l),\qquad \ell_l^s=\alpha_l^s(W_l^s)^\top z_l+b_l^s, \quad s\in\{\mathrm{pre},\mathrm{post}\}, \] \[ p_l=\sigma(\ell_l^{\mathrm{pre}}),\qquad q_l=2\sigma(\ell_l^{\mathrm{post}}). \]

其中 \(W_l^s\in\mathbb R^{nC\times n}\)，\(b_l^s\in\mathbb R^n\)，\(\alpha_l^s\) 是可学习标量，\(\sigma\) 是 sigmoid。这样读系数落在 \((0,1)\)，写系数落在 \((0,2)\)，不强求之和为 1。门控本身算起来很轻，真正拖慢速度的，是每算一层门控就要把整份 \(n\times C\) 的宽状态从显存搬一遍。

3. 四个子层怎样只写回一次

把从子层 \(L\) 开始的连续 \(\htmlData{symbol=group}{K}\) 个子层划成一组。默认 \(K=4\)，依次是 attention、FFN、attention、FFN，正好盖住两个完整的 Transformer block。

因为残差主干退化成了恒等映射，组内任何一步的状态 \(X_j\) 都只是入口 \(X_L\) 加上前面各层的写入：

\[ X_j=X_L+\sum_{k=L}^{j-1}q_ko_k^\top. \]

现在看第 \(j\) 个子层怎么取输入：把上式直接代进 \(u_j=X_j^\top p_j\)，就能把中间宽状态彻底拆开：

\[ u_j=\underbrace{X_L^\top p_j}_{\text{从入口读的基础输入}} +\sum_{k=L}^{j-1}\underbrace{(p_j^\top q_k)}_{\text{标量系数}}o_k. \]

这一步很漂亮：先按 \(q_k\) 写进 \(n\) 条宽流，再按 \(p_j\) 读出来，兜这么大一圈，效果其实就等于把 \(C\) 维窄向量 \(o_k\) 乘上一个标量内积 \(p_j^\top q_k\)。举个数：前一层按 \((1,0.5)\) 写进两条流，后一层按 \((0.25,0.75)\) 读取，前一层输出对后一层输入的净贡献就是 \(0.25\times1+0.75\times0.5=0.625\) 倍，根本不必先把宽状态更新一遍再读出来。

卡壳的地方：门控还等着 \(X_j\)

上面的展开有个前提——算到第 \(j\) 层时，\(p_j,q_j\) 得先到位。可按原来的写法，门控要等最新的宽状态 \(X_j\) 落地才能算；不把 \(X_j\) 写出来，门控就出不来。

SimpleHC 的办法很干脆：让组内这 \(K\) 个子层统一看组入口 \(X_L\) 来生成各自的门控：

\[ \bar p_j=g_j^{\mathrm{pre}}(X_L),\qquad \bar q_j=g_j^{\mathrm{post}}(X_L),\qquad L\le j<L+K. \]

头上加横线，表示它是从组入口算出来的。注意，共享的只有输入 \(X_L\)，每个 \(g_j\) 依然拿着自己独立的投影矩阵、缩放因子和偏置，所以四个子层对着同一份入口状态，照样能做出四套不同的读写决策。

这里要把两件事分开看：改用共享入口是一次结构近似（改变了门控的条件输入），好不好使靠第 4 节的消融实验说话；而一旦这组门控算定，后面的延迟写回就是精确的代数等价，半点误差都没有。反向传播时，梯度也会顺着每个门控函数一路传回组入口。

把跨子层修正收进一个小矩阵

把组内各层的门控按列拼成两个 \(n\times K\) 小矩阵 \(P=[\bar p_L,\ldots,\bar p_{L+K-1}]\) 和 \(Q=[\bar q_L,\ldots,\bar q_{L+K-1}]\)，就能在进组时一口气算好两样东西：

\[ V=X_L^\top P\in\mathbb R^{C\times K},\qquad \htmlData{symbol=correction}{D}=\operatorname{tril}(P^\top Q,-1)\in\mathbb R^{K\times K}. \]

\(V\) 的第 \(a\) 列就是第 \(a\) 个子层从入口拿到的基础输入。\(D\) 是一个 \(K\times K\) 严格下三角矩阵，行对应后面读取的子层，列对应前面写入的子层，元素 \(D_{ab}=\bar p_{L+a}^\top\bar q_{L+b}\)（只有 \(b<a\) 的历史输出能进当前层，\(K=4\) 时总共就 6 个非零系数）。

接下来四个子层照旧按顺序跑，每层把基础输入加上前面各层的标量修正：

\[ u_{L+a}=V_{:,a}+\sum_{b<a}D_{ab}o_{L+b},\qquad o_{L+a}=F_{L+a}(u_{L+a}). \]

后一层依然吃得到前一层刚算出来的新输出，只是传递载体从 \(n\times C\) 的宽状态换成了 \(C\) 维窄向量。等整组四个子层全算完，把输出按列拼成 \(O=[o_L,\ldots,o_{L+K-1}]\in\mathbb R^{C\times K}\)，在组出口一次性写回宽状态：

\[ X_{L+K}=X_L+QO^\top. \]

整组跑下来，对宽状态的访问缩成了三下：进组读一次算门控，再读一次算各层基础输入，出组统一写回一次。组内四个子层来回倒腾的，全是窄向量。

对应的伪代码
# X: [tokens, n, C]；每个 token 独立生成门控
# P, Q: [tokens, n, K]；各子层参数独立
P, Q = grouped_gates(X)
V = einsum("tnc,tnk->tck", X, P)
D = tril(einsum("tna,tnb->tab", P, Q), diagonal=-1)
outputs = []
for a in range(K):
    u = V[:, :, a]
    for b in range(a):
        u = u + D[:, a, b, None] * outputs[b]
    outputs.append(sublayers[a](u))
X_next = X + einsum("tnk,tck->tnc", Q, stack(outputs, dim=-1))

上面是最直观的等价写法；真要跑快，还得把内层加权、读取和最终写回融合进 kernel，避免频繁落地临时张量。

4. 共享入口，为什么仍要逐层独立的门控

把四个子层的门控都改到组入口上算，模型会不会变傻？在 15B-A1B 上拆开一测，就能看清哪一步真不能省、哪一步可以放心省：

配置组内门控新输出的标量修正Loss五项平均分
identityHC，逐子层入口各层独立通过完整状态传递1.66055.4
共享 2 个子层各层独立保留1.66054.8
SimpleHC，共享 4 个子层各层独立保留1.66055.0
共享 8 个子层各层独立保留1.66254.3
共享 4 个子层，复用一对门控各层共用同一对保留1.66753.5
共享 4 个子层，省去修正各层独立省去，组末仍写回1.70547.9

表里有三处落差非常刺眼。第一，最不能省的是标量修正——把 \(D\) 删掉后，loss 从 1.660 飙到 1.705，平均分直接掉 7 分。原因很直白：组末虽然还是把四个输出写回了残差流，但组内后三个子层算的时候全看不到前面刚算出来的结果，相当于把串联的四层硬拆成了对着入口各自干活的并联支路，组内有效深度直接拍扁。

第二，门控参数必须逐层独立。同样是共享入口、保留修正，如果偷懒让四层共用同一对门控，loss 涨到 1.667，平均分掉到 53.5——毕竟 attention 和 FFN、前一层和后一层想读想写的流本来就不一样。反过来，只要留住独立参数和标量修正，\(K=4\) 的共享入口几乎没有伤到质量（loss 维持 1.660，平均分 55.0 对 55.4），直到拉大到 \(K=8\) 才开始出现退化。

为什么单靠组入口 \(X_L\) 就能替后面三层做好门控决策？论文做了一个探针实验：把训好的 identityHC 冻住，用独立的小线性预测器直接从 \(X_L\) 去猜后面子层真实的读写门控（写门控先除以 2，统一折算到 \([0,1]\) 尺度）。在测试集轨迹上，如果直接拿原模型对应层的门控权重套在 \(X_L\) 上，写门控和读门控的平均绝对误差分别是 0.05044 和 0.05817；稍微训练一下预测器，误差立刻降到 0.01034 和 0.01653。换句话说，入口状态本身就藏着足够多的路由信号，只要给每层留出独立的映射参数，就能复现逐层决策；真正不能滞后的，是送进计算分支的那条数据流。

5. 18C 到 9C：逐项计算显存访问

算完质量账，来算显存带宽账。对残差连接这种逐元素小操作来说，算力从来不是瓶颈，真正拖时间的是在 HBM 和片上存储之间来回搬运 \(n\times C\) 的宽状态。

先把统计口径定死：只算每个 token、每个子层在残差连接前向中读写的激活元素数（不计权重、极小的门控标量，也不算 attention/FFN 内部）。搬一次完整的宽残差状态计 \(nC\) 个元素，搬一条子层输入或输出只有 \(C\) 个元素。

融合后的 mHC 与 identityHC：都要搬 \(18C\)

操作读写内容每 token、每子层
投影与 RMS 统计读取宽状态\(nC\)
汇总子层输入读取宽状态，写出窄输入\(nC+C\)
写回残差读取旧宽状态和窄输出，写出新宽状态\(2nC+C\)
合计\(4nC+2C\)

代入 \(n=4\)，每层一共要搬 \(18C\) 个元素。注意一个反直觉的事实：哪怕把混合矩阵删了变成 identityHC，只要还是逐子层执行，前向访存量依然是 \(18C\)——因为融合后的 mHC 本来就把混合、输出分配和写回塞在同一个 kernel 里，少算了那点混合乘加，该读该写的宽张量一个没少。

SimpleHC：把宽状态访问摊薄到组边界

分组之后，连续 \(K\) 个子层只在组边界动宽状态：进组读一次算门控（\(nC\)）、再读一次算基础输入（\(nC\)）、出组读旧写新（\(2nC\)），整组合计 \(4nC\)，摊到每个子层就是 \(4nC/K\)。再加上每层各写出一次基础输入、组末读回一次窄输出，固定占 \(2C\)。

省下来的带宽不是白拿的，代价是组内的标量修正。从 0 开始给组内子层编号：第 0 层直接用基础输入，没有额外修正；第 \(a\) 层（\(a>0\)）的修正 kernel 要读 1 份基础输入、\(a\) 份前面子层的窄输出，再写出 1 份修正后的输入，一共搬 \((a+2)C\) 个元素。整组平均到每层，修正流量为：

\[ Q_{\mathrm{corr}}(K)=\frac{C}{K}\sum_{a=1}^{K-1}(a+2) =\frac{C(K-1)(K+4)}{2K}. \]

三项合起来，SimpleHC 每个 token、每个子层的逻辑前向访问量就是：

\[ \htmlData{symbol=traffic}{Q_{\mathrm{act}}}(K) =\underbrace{\frac{4nC}{K}}_{\text{宽状态访问}} +\underbrace{2C}_{\text{基础输入写出与输出读取}} +\underbrace{\frac{C(K-1)(K+4)}{2K}}_{\text{组内修正}}. \]

取 \(n=K=4\)，三项正好是 \(4C+2C+3C=9C\)，相比 \(18C\) 直接砍半。换成具体字节数更有体感：宽度 \(C=6144\)、8192 个 token、BF16（2 字节），单看这部分前向激活读写，每子层就从 1728 MiB 降到 864 MiB。

从公式一眼就能看出组长 \(K\) 的拉扯：\(K\) 越大，宽状态摊得越薄，但后面子层要翻查的历史输出越来越多，修正流量反倒往上爬。代入 \(n=4\) 整理一下：

\[ \frac{Q_{\mathrm{act}}(K)}C=\frac K2+\frac72+\frac{14}{K}. \]

连续函数在 \(K=\sqrt{28}\approx5.29\) 处取极小，整数里 \(K=5\) 最低（\(8.8C\)）。不过 5 个子层会把 Transformer block 劈成两半，不利于架构对齐和流水线切分；而 \(K=4\) 的 \(9C\) 已经离极值差不了多少，刚好盖住两个完整 block，质量也没掉，自然成了默认选择。

顺手看一眼 FLOPs

按一次乘加计 2 FLOPs 算：mHC 每层要把 \(nC\) 维输入投影成 \(n^2+2n\) 个系数（混合矩阵加读写门控），开销约 \(2nC(n^2+2n)\)；去掉混合矩阵后，只剩 \(2n\) 个读写门控系数，降到 \(4n^2C\)。在 \(n=4\) 时，就是从 \(192C\) 降到 \(64C\)。

分组后各层依然保留独立门控，投影总 FLOPs 还是 \(64C\)/子层，但同一份载入的输入现在被四层一起复用。新增的算术主要是标量修正：整组共 \(K(K-1)/2\) 次窄向量乘加，摊到每层约 \(C(K-1)\) FLOPs；算下三角系数矩阵 \(D\) 本身只花约 \(n(K-1)\) FLOPs/子层（前面伪代码和 lab.py 为写着省事，先算了完整 \(P^\top Q\) 再取下三角，约 \(2nK\) FLOPs/子层，相比 \(C\) 都是零头）。本质上就是拿一点点廉价的窄向量算术，去换宝贵的宽状态显存带宽。

6. 把公式变成快的前向与反向

纸面上的访存减半不会自动变成速度。在宽度 \(C=6144\) 的实测里，直接用 PyTorch 写 SimpleHC，额外训练开销高达 22.5%；换成专用融合 kernel 后，直接压到 2.4%。把这部分性能榨干，靠的是三个很实在的 GPU 优化技巧。

先复用加载，再把小算子焊在一起

把组入口展平成 \(x\in\mathbb R^{nC}\)，再把 \(K\) 个子层的读写投影矩阵横着拼成一个 \(W\in\mathbb R^{nC\times2Kn}\)，就能在扫描一遍 \(x\) 的同时把所有未归一化投影和平方和一并算出来：

\[ t=W^\top x,\quad s=x^\top x,\quad r=\left(\frac{s}{nC}+\epsilon\right)^{-1/2}. \]

这里的巧妙之处在于：门控用的 RMSNorm 没有仿射缩放参数，\(r\) 只是个标量，所以线性投影满足 \(W^\top(rx)=r(W^\top x)\)。也就是说，根本不需要先落地一份 \(nC\) 大的归一化中间张量再做矩阵乘——kernel 可以边读 \(x\) 边同时攒 \(t\) 和 \(s\)，最后在极小的 \(t\) 上补乘 \(\alpha r\)、加偏置 \(b\) 再过 sigmoid 就完事了。

以 \(n=K=4\) 为例，拼完的投影权重只有 \(4C\times32\)（32 列对应 4 层 × 读写 2 种 × 4 条流）。紧接着，基础读取 kernel 每从显存载入宽状态的一块 tile，就顺手把四个子层的基础输入一块算出来；组内修正 kernel 直接拿着前面几个窄输出的指针，把乘系数、累加和写出焊在一起；出组时再用一个融合 kernel 一次性分配四份输出并加回宽残差。

反向传播照样合并宽梯度

核对一下前向的几个矩阵形状：门控 \(P,Q\) 是 \(n\times K\)，基础输入 \(V\) 和子层输出 \(O\) 是 \(C\times K\)，组入口 \(X_L\) 是 \(n\times C\)。反向时，设组出口传回来的宽梯度是 \(E=\partial\mathcal L/\partial X_{L+K}\)，各基础输入的梯度是 \(G=\partial\mathcal L/\partial V\)，那么基础读取和组末写回这两条路径贡献的梯度就是：

\[ \nabla_{X_L}\mathcal L\mathrel{+}=E+PG^\top,\qquad \nabla_O\mathcal L\mathrel{+}=E^\top Q. \]

这里 \(\mathrel{+}=\) 表示往对应张量的梯度里累加（组内修正和门控投影的梯度后续也会汇进来）。好处和前向一模一样：左边把恒等路径的 \(E\) 和四层输入的梯度合进一次宽张量写出；右边复用同一份 \(E\)，一口气给四个子层输出算出各自的梯度。

标量修正的反向传播

把组内子层 \(L+a\) 简记为 \(a\)：基础输入 \(v_a=V_{:,a}\)，门控 \(p_a=\bar p_{L+a},q_a=\bar q_{L+a}\)，子层输入输出为 \(u_a,o_a\)。对 \(u_a=v_a+\sum_{b<a}D_{ab}o_b\)，设 \(g_a=\partial\mathcal L/\partial u_a\in\mathbb R^C\)，每条跨层修正边 \((a,b)\) 贡献：

\[ \nabla_{o_b}\mathcal L\mathrel{+}=D_{ab}g_a,\qquad \nabla_{D_{ab}}\mathcal L=g_a^\top o_b. \]

再顺着 \(D_{ab}=p_a^\top q_b\) 往回传，得到 \(\nabla_{p_a}\mathcal L\mathrel{+}=q_b\nabla_{D_{ab}}\mathcal L\) 和 \(\nabla_{q_b}\mathcal L\mathrel{+}=p_a\nabla_{D_{ab}}\mathcal L\)。反向按子层倒序走一遍，早期输出就能收齐来自后面所有子层的梯度。

小门控梯度怎么喂给 Tensor Core

反向还有一个 GPU 上很经典的别扭形状——输出极小、归约维度极长。看读写门控的两项梯度：

\[ \nabla_P\mathcal L\mathrel{+}=X_LG,\qquad \nabla_Q\mathcal L\mathrel{+}=EO. \]

在 \(n=K=4\) 时，\(X_LG\) 是 \((4\times C)\) 乘 \((C\times4)\)，每个 token 归约完 \(C\) 维只产出 16 个数。如果硬把通道拆块并行算，各块还得把局部和写回显存、再起一个 kernel 归约，光临时缓冲和启动开销就能把省下的时间吃光。

解法很聪明：一次打包四个 token。把四个 token 的 \(X\) 竖着叠成 \(16\times C\)，把对应的 \(G\) 横着拼成 \(C\times16\)，直接喂进 Tensor Core 做一次规整的 \(16\times16\) 块状矩阵乘：

\[ \begin{bmatrix}X^{(0)}\\X^{(1)}\\X^{(2)}\\X^{(3)}\end{bmatrix} \begin{bmatrix}G^{(0)}&G^{(1)}&G^{(2)}&G^{(3)}\end{bmatrix}. \]

算出来的是一个 \(4\times4\) 的分块矩阵，其中 \((i,j)\) 块是 \(X^{(i)}G^{(j)}\)。我们只留下对角线上那四个同 token 块 \(X^{(i)}G^{(i)}\)，其余交叉块直接扔掉。

7. 激活显存究竟省在哪里

显存带宽算的是「跑一趟搬了多少数据」，激活显存算的是「留到反向传播时还占着多大坑」。同一个张量可以只存一份、反复读十次，所以这两笔账得分开算。

如果只盯着残差入口状态，不开激活重算时，逐子层执行每组要留 \(K\) 份 \(n\times C\) 状态，分组后只留 1 份组入口——单看这一项确实省了 \(1-1/K\)，\(K=4\) 时就是 75%。但真实训练里，子层输入、输出、基础读取缓冲和门控张量全都在显存里，拉通算下来就没这么夸张。

拿一个具体尺寸来盘账：8 个 Transformer block（16 个子层）、宽度 \(C=2048\)、单条 8192-token 序列、BF16。设本地 microbatch 的 token 数为 \(T=8192\)，定义一份形状 \(T\times C\) 的窄激活为单位：

\[ U=2TC\ \text{bytes}=32\ \text{MiB}. \]

按实际存储分配核算，不算 attention/FFN 内部激活，残差连接和子层边界留下的显存如下：

一个很容易踩的坑：切片会把整块大缓冲保活

表里那行「额外基础读取存储 \(12U\)」是怎么冒出来的？按理说，子层 1 到 3 用的是修正后的输入，反向时并不需要把所有基础读取都留着。问题出在内存布局上：前向时四个子层的基础输入是一起分配在一块 \(4U\) 连续大缓冲里的，第 0 个子层直接切片取了第一份（一个 view）当自己的输入。只要 autograd 还攥着这 1 份 view，PyTorch 就没法释放底下的整块 \(4U\) storage——除了输入行里已经算过的那 \(1U\)，剩下 \(3U\) 就跟着一起活到了反向结束，四组正好白占 \(12U\)。

平时调显存遇到「明明只留了一小片，显存却死活不掉」，八成就是撞上了这个。如果大缓冲本来很快就能释放，把那片小切片 .clone() 出来切掉对原 storage 的引用，就能把大块显存提前腾出来；反过来如果本来就会拖到反向，复制反而白花带宽，得按具体生命周期决定。

8. 稳定性：恒等路径保住了什么

早期某个 FFN 算出来的特征，往往要隔几十层才被后面的层用上。顺着残差通路展开，看看第 \(k\) 个子层的输出 \(o_k\)，到了后面的第 \(j\) 个子层（\(j>k\)）输入 \(u_j\) 里时，前面挂着多大的系数。统一用 \(p_j,q_k\) 表示实际生效的读写门（在 SimpleHC 里就是从各自组入口算出的 \(\bar p_j,\bar q_k\)，两层完全可以跨组），把中间经过的混合矩阵一路乘起来：

\[ c_{j,k}=p_j^\top \underbrace{M_{j-1}M_{j-2}\cdots M_{k+1}}_{\text{写入之后、读取之前的连乘}} q_k. \]

相邻两层中间没有混合，括号里就是单位矩阵。这个式子把三步串到了一起：\(q_k\) 负责把 \(o_k\) 存进各条流，中间的 \(M\) 沿深度不断洗牌，最后 \(p_j\) 按需把它们捞出来。

恒等路径：系数天然有界，不随深度膨胀

在 identityHC 和 SimpleHC 里，所有 \(M_t=I\)，连乘直接消失，只剩一个内积 \(c_{j,k}=p_j^\top q_k\)。比如前层按 \((1,0.5)\) 写入两条流，后层按 \((0.6,0.4)\) 读出，净权重就是 \(0.6\times1+0.4\times0.5=0.8\)——不同层对之间靠读写门配合，照样能学出各自的跨层权重。

更关键的是尺度被锁死了。SimpleHC 的读门过 sigmoid、落在 \((0,1)\)，写门是两倍 sigmoid、落在 \((0,2)\)，因此任意两层之间的直接残差系数满足：

\[ 0<c_{j,k}=\sum_{s=1}^{n}p_{j,s}q_{k,s}<2n. \]

四条流时上界就是 8。注意这个界跟层距 \(j-k\) 无关——隔 2 层还是隔 100 层，直接残差路径都不会出现连乘放大。

混合矩阵的自由度从哪来，又为什么会失控？

反过来看第 2 节表里的另一路：把读门锁死成均值 \(p_j=\mathbf1/n\)，写门锁死成广播 \(q_k=\mathbf1\)，这时跨层权重全指望中间的混合矩阵：

\[ c_{j,k}=\frac1n\mathbf1^\top \bigl(M_{j-1}\cdots M_{k+1}\bigr)\mathbf1. \]

如果对 \(M_t\) 不加约束，连乘可以凑出带正负号、幅度任意的权重——所以第 2 节里「固定读写 + 无约束混合」能跑出不错的分数。但代价是深层连乘没有护栏：哪怕每层只把某个方向放大 1.01 倍，叠 100 层就是 \(1.01^{100}\approx2.70\) 倍，随时可能失控。

加上双随机约束呢？真正的双随机矩阵元素非负、行和与列和都是 1，意味着 \(M\mathbf1=\mathbf1\)、\(\mathbf1^\top M=\mathbf1^\top\)。代进上式一看，无论连乘多少层，\(c_{j,k}\) 恒等于 1。这也正好解释了 mHC 的本质：双随机约束把混合矩阵沿深度的缩放自由度收紧了，模型真正用来挑选历史信息的，还是那套可学习的读写门控。

双随机约束为什么在高压下还是会炸？

理论上，严格双随机矩阵满足谱范数 \(\|M\|_2\leq1\)，看上去已经把线性路径摁住了。问题在于，mHC 的混合矩阵 \(M(X)\) 是随输入动态算出来的。对 \(Y=M(X)X\) 求微分，输入扰动 \(\mathrm dX\) 会走两条路：

\[ \mathrm dY= \underbrace{M\,\mathrm dX}_{\text{固定矩阵路径}} +\underbrace{(\mathrm dM)X}_{\text{动态门路径}}. \]

第一项受 \(\|M\|_2\leq1\) 约束，第二项却不然——输入一旦出现异常大值，不仅 \(X\) 本身很大，还会剧烈扯动 \(M(X)\) 的输出，把扰动和梯度一起放大。

压力实验里，尖峰是怎么一步步滚大的

论文在 230B-A6B 模型上做了一轮极端压力测试：把学习率拉到参考值的 10 倍（峰值 \(6.2\times10^{-3}\)，warmup 4000 步），三种结构都跑 28,000 步。结果 SimpleHC 和 identityHC 全程梯度有界，mHC 却撞出了约 \(1.9\times10^6\) 的梯度尖峰。

抓现场日志能看到异常滚雪球的过程：一次早层 MoE 里，输入 RMS 还是正常的 0.294，经过 FFN 之后、还没进写入门控，输出 RMS 就已经飙到 \(2.31\times10^4\)——火苗是从计算分支点起来的。但真正把它烧成灾难的，是后面的动态混合：在另一次记录中，20 轮 Sinkhorn 迭代没来得及收敛到双随机，行和还歪在 \((2,1,0.5,0.5)\)，直接把同一个 token 的 RMS 从 \(5.42\times10^4\) 继续放大到 \(7.50\times10^4\)；而在一次反向尖峰里，动态混合门路径 \((\mathrm dM)X\) 传回来的输入梯度，达到了固定矩阵路径 \(M\,\mathrm dX\) 的 9.4 倍。

换句话说，有限步 Sinkhorn 碰到离群大激活会失守，动态混合门本身又多开了一条放大梯度的侧门。SimpleHC 直接令 \(M_l=I\)，相当于把这两处隐患连根拔掉，只留下有界、直通的读写门控。

省掉的残差开销，折成整步速度是多少？

在宽度 6144 的 8 层效率测试中，以 Vanilla 单步时间 \(t_0\) 为基准，高效 mHC 是 \(1.070t_0\)，SimpleHC 降到了 \(1.024t_0\)。换算成相对 mHC 的整步提速：

\[ 1-\frac{1.024}{1.070}\approx4.30\%, \qquad \frac{1.070}{1.024}\approx1.045. \]

也就是端到端快了约 4.5%——按这个比例，原本要烧 1000 GPU 小时的 mHC 训练，换成 SimpleHC 大约 957 GPU 小时就能跑完。

模型越窄，多路残差的占比越显眼。在宽度 1024 时，mHC、identityHC 和 SimpleHC 的额外开销分别是 26.8%、10.1% 和 6.3%。这组递减刚好拆出了两步改动的各自功劳：删掉 Sinkhorn 混合先把额外耗时从 26.8% 压到 10.1%，分组共享读写再从 10.1% 压到 6.3%。等宽度拉到 6144，主干矩阵乘占了大头，相对开销进一步收敛到 2.4%。

补一句复现现状：截至 2026-11-11，官方仓库只放出了报告和图表，训练代码与融合 kernel 还没开源；报告也没披露训练总 token 数以及效率测试所用的 GPU 型号、卡数和并行策略。眼下能立刻动手的，是先写段脚本把前反向的代数等价性验实，再按第 6 节的思路在自己的卡上焊 kernel 测真实吞吐。

10. 计算题与可运行实验

练习一：一次写入经过两条流，后面读到多少

入口 \(X=(2,6)^\top\)，第 0 个子层按 \(p_0=(0.75,0.25)^\top\) 读取、计算 \(F_0(u)=u/2\)、再按 \(q_0=(1,0.5)^\top\) 写回。第 1 个子层按 \(p_1=(0.25,0.75)^\top\) 读取。分别用「更新完整状态」和「标量修正」算出第 1 个子层的输入。

展开解答

第 0 层先算出 \(u_0=3\)、\(o_0=1.5\)。如果逐层更新完整状态，新状态变成 \((2+1\times1.5,\ 6+0.5\times1.5)^\top=(3.5,6.75)^\top\)，第 1 层读出 \(0.25\times3.5+0.75\times6.75=5.9375\)。改用分组展开，第 1 层的基础输入是 \(0.25\times2+0.75\times6=5\)，修正系数 \(p_1^\top q_0=0.625\)，合起来同样是 \(5+0.625\times1.5=5.9375\)。

练习二：组拉得太长，为什么流量反而回升

四条流下，分别算出 \(K=4,8,16\) 时每 token、每子层的前向连接流量。如果只留组入口，这三种组长把残差入口存储各省了多少？

展开解答

代入 \(Q_{\mathrm{act}}(K)/C=K/2+3.5+14/K\)，三者依次为 \(9C\)、\(9.25C\) 和 \(12.375C\)。残差入口状态的理想省存比例是 \(1-1/K\)，对应 75%、87.5% 和 93.75%。组越长，入口确实越省，但后面子层翻查历史输出的修正流量会反超宽状态摊薄的收益。

练习三：把标量修正清零，网络变成了什么

保留组入口门控和组末写回，但把组内所有 \(D_{ab}\) 设成 0。四个子层的输入会怎样变化？为什么消融实验里掉点那么狠？

展开解答

此时每个子层的输入都退化成 \(u_{L+a}=V_{:,a}=X_L^\top\bar p_{L+a}\)，全都只看组入口，彼此看不到前一层刚算出的新输出。组末虽然照样把四份输出加回了残差流，但原本串行的四步非线性加工被拍扁成了四条并行支路，组内有效深度从 4 掉到 1——这正是消融表里 loss 从 1.660 猛涨到 1.705 的原因。

练习四：把额外开销换算成训练预算

同一任务下，mHC 单步耗时是基线的 1.07 倍，SimpleHC 是 1.024 倍。如果 mHC 方案需要 400 张卡跑 10 天，换 SimpleHC 大约能省多少 GPU 天？

展开解答

原预算 4000 GPU 天，换算后变为 \(4000\times1.024/1.07\approx3828.04\) GPU 天，省下约 171.96 GPU 天；同样用 400 张卡，墙钟时间缩短约 0.43 天（10.32 小时）。

脚本顺带还会打印出「去掉修正」「复用同一对门控」「改回逐层更新门控」三种改动带来的输出差异，以及不同组长 \(K\) 下的访存账本，全部通过后输出 all checks passed。你可以自己改改组长和子层权重尺度，直观看看流量和函数偏移是怎么跟着变的。
