张量布局、stride 与 GPU 访存

交互2026-10-20更新于 2026-10-22

Attention 常把一个张量从 [batch, heads, tokens, dim] 转成 [batch, tokens, heads, dim]，再把最后两维合并。几行代码里，transpose 可以只改变元数据，后面的 reshape 却可能触发一次完整复制。要知道这次复制是否必要，先跟着一个元素找到它在存储里的位置。

一个索引怎样变成地址

张量由存储、起始偏移、shape 和 stride 共同描述。Shape 给每个轴的长度；stride 给沿这个轴前进一步要跨过多少个元素。PyTorch 的 stride 以元素计，NumPy 的 strides 以字节计。设元素占 \(\htmlData{symbol=bytes}{b}\) 字节，存储基址为 \(p\)，张量起点相对存储的偏移为 \(o\)，第 \(k\) 维索引和 stride 分别为 \(i_k,s_k\)，地址就是

$$\operatorname{addr}(i_0,\ldots,i_{n-1})=p+b\left(o+\sum_{k=0}^{n-1}i_ks_k\right).$$

连续的 [2,3,4] 张量从最后一维往前累计，stride 为 [12,4,1]。索引 [1,2,3] 对应元素偏移 \(12+8+3=23\)。若元素是 FP32，它相对基址的字节偏移为 92。写 kernel 时，传入指针通常已经指向张量的第一个元素，外部代码应把 storage offset 加入一次，然后由 kernel 使用各维 stride。

转置、切片与共享存储

对一个 [3,4] 连续矩阵转置，shape 变成 [4,3]，stride 从 [4,1] 变成 [1,4]。新坐标 y[2,1] 仍指向元素偏移 \(2+4=6\)。数据沿着原来的物理顺序保留，新索引负责解释它。

切片还会改变起点。对 x[:,1:,::2]，原来的 [2,3,4] 变为 [2,2,2]，起始偏移为 4，stride 为 [12,4,2]。其中 [1,1,1] 的元素偏移是 \(4+12+4+2=22\)。让输入值直接等于存储偏移，能很快暴露漏加 offset 或使用错误 stride 的实现。

这些视图共享底层数据。修改 y[2,1] 也会改变原矩阵的对应位置。广播的 expand 用 stride 0 让多个逻辑位置指向同一元素，因此对展开结果做独立写入时，需要先建立独立存储。基本切片常形成视图，高级索引通常产生新张量；检查别名关系时应跟踪数据存储，而不只比较 shape。

什么时候需要一次复制

把相邻维度 \(d\) 到 \(d+k\) 合成一维，需要这些维度能按一个固定步长顺序遍历。典型的合并条件为 \(s_i=s_{i+1}\,\operatorname{size}_{i+1}\)。转置后的 [4,3] 使用 [1,4]，沿逻辑行走完三个元素后，下一行的起点会跳回存储的前部，单一线性 stride 无法表示整个遍历。

view 要求新形状能由现有存储直接表示；reshape 在满足条件时返回视图，否则复制出符合目标逻辑顺序的存储。出现 view size is not compatible 时，可以先打印 shape、stride() 和 storage_offset()，找到无法合并的维度。选择 reshape 可以得到正确值，随后还要在 profiler 中检查复制是否进入热点路径。

Attention 的输出若是 [B,H,T,D] 连续布局，转为 [B,T,H,D] 后，H 与 D 常常无法直接合并。transpose(...).contiguous().view(...) 把这次重排写得很明确。另一条路线是让上游 kernel 直接按下游需要的布局写出结果，或者让下游 GEMM 接受真实 stride，从整个算子链消除中间复制。

把布局契约写到算子边界

一个二维 kernel 的地址应由 base + row*stride_row + col*stride_col 给出。若快速路径要求 stride_col=1，调用端先验证这个条件，再选择实现。对于 batch 张量，还要把 batch stride 显式传入；形状相同的两份 tensor 可以有不同的 batch 间距。让接口说明接受的布局，比在 kernel 中默默假定连续更容易维护。

大小为 1 的维度只有一个有效索引，它的 stride 通常不影响实际访问；空张量也有自己的边界行为。因此通用的 view 合法性应交给框架判断，工程分析中的 stride 连续关系用来解释需要合并的实际遍历。测试 shape 时加入 singleton 轴，可以发现把维度顺序与内存顺序混在一起的代码。

判断两个 tensor 是否会互相影响，可以先确认是否来自同一底层 storage，再结合 offset、shape 和 stride 计算访问区间。两个视图的 data_ptr() 不同，也可能指向同一存储的重叠区域；它们的 storage 相同，也可能访问互不重叠的部分。需要写入的 kernel 应对允许的重叠方式给出清楚约束，尤其是在原地操作和输出复用时。

GPU 同时看到一组地址

一个 warp 的 32 个 lane 执行同一条访存指令时，硬件会把它们访问的地址合并成内存事务。用 32 B sector 观察 FP32 读取：32 个 lane 连续读取 32 个数，共需 128 B；当首地址按 32 B 对齐时，恰好覆盖 4 个 sector。起点后移一个 FP32 后，区间跨越五个 sector。

stride 为 2 时，32 个地址覆盖 8 个 sector；stride 为 8 时覆盖 32 个。线程请求的有效数据仍为 128 B，sector 覆盖量却增长到 1024 B。stride 为 0 的广播读取集中在同一个地址。分析一个 kernel 时，应逐条访存指令观察同一 warp 的地址分布，并结合 L1/L2 命中解释最终 HBM 流量。

Shared memory 的列读取

Shared memory 按 bank 服务访问。对于 32 个 bank、每个 32-bit 字映射一个 bank 的常见情况，字地址 \(a\) 对应 \(a\bmod32\)。一个 tile[32][32] 的列读取让 lane \(i\) 访问 \(32i+j\)，所有 lane 落在 bank \(j\)，需要分批服务。

给 tile 加一列，改为 tile[32][33]，同一列的地址变成 \(33i+j\)，bank 编号随 lane 变化，覆盖全部 32 个 bank。全局内存的合并读取与 shared memory 的 bank 分布分别约束数据搬运的两段路径；转置 kernel 通常用共享 tile 把两段都安排成顺畅的访问。

线程布局和数据布局一起选择

设矩阵每行连续，一种直接的映射是 block 固定 row，lane 负责相邻 col。这样同一条 load 指令覆盖连续地址。若把 lane 映射到相邻 row，它们相差一个行 stride，矩阵越宽，访问就越分散。调整线程映射可以在不复制张量的情况下改善访存，代价可能转移到输出或下一阶段的读取。

向量化加载改变每条线程指令搬运的字节数；合并访存关注同一 warp 的地址如何组成 sector。连续标量访问已经可以合并，宽加载进一步减少指令数量。反过来，单线程读一个连续向量，跨 lane 的向量起点若很分散，仍可能产生较多事务。调优时分别查看每线程访问宽度和跨 lane 地址分布。

广播也影响反向计算。若一个长度为 D 的参数 expand 到 R×D，前向多行共享同一份值，反向需要把这 R 行的贡献加回原参数。这种归约来自共享关系本身。把 expand 误当成独立可写副本，可能同时破坏前向数值和反向累加，应使用拥有独立存储的输出承接需要逐行改写的结果。

把隐藏复制算进整个调用链

设 BF16 激活形状为 [4,2048,32,128]，元素数乘 2 B 得到 64 MiB。复制需要读旧位置、写新位置，最低流量为 128 MiB。若复制耗时为 \(T_c\)，一次有 stride 的下游调用耗时为 \(T_s\)，连续布局调用耗时为 \(T_d\)，在 \(n\) 次复用之后，复制方案划算的条件是

$$T_c+nT_d\lt nT_s\quad\Longleftrightarrow\quad n>\frac{T_c}{T_s-T_d}.$$

例如一次复制 80 μs，下游从 140 μs 降到 100 μs，复用两次持平，第三次才净省 40 μs。测量时把复制包含在端到端计时范围内，并检查每次调用是否重复执行了同一份重排。通过缓存连续副本提高复用次数时，还要在原始张量更新后刷新副本。

自定义 kernel 对转置输入给出错误结果时，先用 arange 构造可辨认的数据，再逐元素对照地址公式。只在 shape 尾部失败，通常指向边界 mask；只在切片失败，重点检查 offset 和 stride；数值正确但骤然变慢，则比较复制事件、sector 数、寄存器与 L2 命中。这些观测能把“布局有问题”变成可验证的具体判断。

练习与实验

1. 带 offset 的寻址

FP32 张量 shape 为 [2,2,2]，stride 为 [12,4,2]，storage offset 为 4。求 [1,1,1] 相对存储基址的字节偏移。

展开解答

元素偏移为 \(4+12+4+2=22\)，字节偏移为 \(22\times4=88\) B。若传入 kernel 的指针已指向张量起点，kernel 内再加的偏移为 \(18\times4=72\) B。

2. 一次 warp 读取

32 个 lane 读 FP32，元素偏移为 \(1+2i\)。它们覆盖多少个 32 B sector？

展开解答

首个字节地址为 4，最后一个元素覆盖 252–255 B。其地址覆盖 sector 0 到 7，共 8 个，sector 总量为 256 B，有效数据为 128 B。

3. 共享数据还是独立排列

连续矩阵 x 的形状是 [3,4]。令 y=x.T，z=y.contiguous()，然后改写 y[2,1]。哪一份数据会跟着改变？

展开解答

x[1,2] 与 y[2,1] 指向同一存储位置，所以 x 跟着改变。z 保存的是创建时按 y 的逻辑顺序复制的值，随后保持独立。z 的 shape 为 [4,3]，连续 stride 为 [3,1]。

4. 复制的回本次数

复制花 120 μs，下游调用从 90 μs 降为 70 μs。至少复用多少次才更快？

展开解答

净节省为 \(20n-120\) μs，要求 \(n>6\)，因此第 7 次复用开始有收益；仅一次调用会额外增加 100 μs。
