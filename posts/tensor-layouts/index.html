每一维贡献一段偏移

element_offset = storage_offset + Σ indexᵢ × strideᵢ
byte_address = storage_base + element_offset × itemsize

若用张量自己的 data_ptr()，它已经指向该 view 的首元素，不要再重复加 storage_offset。

连续布局从最后一维往前推

stride[last] = 1；stride[i] = size[i+1] × stride[i+1]
shape元素 stride解释
[3, 4][4, 1]列加 1，行加 4

这是默认 row-major 连续格式的推导。大小为 1 的维度不移动地址，其 stride 可有多个等价取值。

view 能合并哪些维度？

若要把相邻维度合成一维，它们的地址跳跃必须能组成同一个等差序列。

stride[i] = stride[i+1] × size[i+1]

可以合并

[2, 3]，stride [6, 2]：6 = 2×3。展平为 6 个元素，stride 2，仍可共享 storage。

不能直接合并

[3, 2]，stride [1, 3]：1 ≠ 3×2。按逻辑顺序走的偏移是 0,3,1,4,2,5。

这是非退化相邻维度的合并判据；view 不要求输入一律连续。

reshape 保持逻辑顺序，不负责换轴

x = [[0, 1, 2], [3, 4, 5]]
x.reshape(3, 2)  -> [[0, 1], [2, 3], [4, 5]]
x.transpose(0, 1) -> [[0, 3], [1, 4], [2, 5]]

想交换“行”和“列”的含义，用 transpose / permute。reshape 只是重新分组当前逻辑遍历顺序。

PyTorch reshape 在 stride 兼容时返回 view，否则复制；代码不能依赖它一定共享存储。

attention 合并 head 时为什么常见 contiguous？

连续 attention 输出是 [B, H, T, d]。交换中间轴后是 [B, T, H, d]，但元素 stride 成为 [HTd, d, Td, 1]。

要合并 H 与 d，需要 stride[H] = d × stride[d]

一般 T > 1 时，Td ≠ d，不能直接 view 成 [B, T, Hd]。先按新顺序排紧，再合并。

y = y.transpose(1, 2).contiguous().view(B, T, H*d)

也可以让前一个 kernel 直接写目标布局，或让下一个 kernel 接受原 stride。

一次隐藏复制可能搬 128 MiB

BF16 张量 [B,T,H,d] = [4,2048,32,128]，每元素 2 byte。

payload = 4 × 2048 × 32 × 128 × 2 = 64 MiB
完整复制的逻辑读写量 = 64 + 64 = 128 MiB

新输出还要占 64 MiB 显存。峰值时旧输入未释放，两份 storage 同时存在。

128 MiB 是读写字节账本；实际 HBM 流量受 cache、合并访存和实现影响。1 MiB = 2²⁰ byte。

expand 用 stride 0 表示广播

x: shape [1, 4], stride [4, 1] → expand(3,4): stride [0,1]

第 0 维换行不移动地址：y[0,2]、y[1,2]、y[2,2] 都读取同一个元素。

读：可以复用

12 个逻辑位置只需要 4 个底层数，广播本身不复制数据。

写：存在别名

不同逻辑位置指向同一物理位置，不能当作独立输出。需要独立可写副本时先 clone。

正确的 kernel 先接受真实 stride

row = ...; col = ...
valid = (row < M) & (col < N)
ptr = X + row * stride_row + col * stride_col
x = load(ptr, mask=valid, other=0)

X 已指向当前 view 的首元素。边界由逻辑 shape 决定；地址由 stride 决定。

连续快路径可以单独优化，但要通过 stride 检查进入。先用转置、切片和广播输入验证通用路径。

线程、warp、block、SM 各是谁？

层级含义与访存的关系
thread / lane线程；lane 是 warp 内的编号每个线程发出自己的地址
warpNVIDIA 上 32 个线程的执行组同一条指令的地址一起合并
block一组能协作与同步的线程共享一块 shared memory
SMGPU 中执行线程组的处理单元分配寄存器、shared memory 等资源

一个 SM 可驻留多个 block / warp；一个 kernel 通常启动许多 block。具体驻留数量取决于资源使用。

GPU 关心同一条指令的 32 个地址

一个 warp 的活跃 lane 同时执行 load。硬件把落在同一 32-byte sector 的请求合并。

sector_id = floor(byte_address / 32)

假设 32 个 lane 各读一个对齐 FP32，lane ℓ 访问 base + 4ℓ：128 byte 连续覆盖 4 个 sector。

以下采用现代 NVIDIA GPU 的 32-byte sector 计数模型；它是访问效率模型，不等同于每个请求都穿透 cache 到 HBM。

只偏移一个 FP32，也会多一个 sector

lane 0…31 读取 byte [4,131]，覆盖 sector 0…4
有效唯一字节 / sector 字节 = 128 / (5×32) = 80%

广播读同一个值，不是 32 次 HBM 读取

所有 lane 都读取同一个 FP32 地址，只覆盖 1 个 sector；结果可以分发给多个 lane。

唯一有效字节 = 4；lane 请求字节之和 = 32×4 = 128

评估覆盖率时要区分唯一地址与重复请求。用 128 / 32 得到 400% 不能当作物理带宽利用率。

同一地址的读取可合并；多个线程并发写同一个地址则必须分析写入规则和同步。

shared memory 还有另一套地址分组

对常见 NVIDIA 32-bank、32-bit word 模型，连续 FP32 依次落入不同 bank。

bank = word_index mod 32

同一 warp 的不同地址若争用同一 bank，访问需要拆分；所有 lane 读同一 word 是广播，不能按 32 路冲突计算。

global memory 的 sector 与 shared memory 的 bank 是两个问题，分别检查。

转置 tile 加一列，为的是打散 bank

读取第 c 列lane ℓ 的 word 地址bank
tile[32][32]ℓ × 32 + cc：32 个不同 word 同 bank
tile[32][33]ℓ × 33 + c(ℓ+c) mod 32：各不相同
额外容量 = 32 × 1 × 4 = 128 byte

这是 FP32 方形转置的经典例子。向量化指令、数据类型和 Tensor Core 布局改变后，应重新推导，而非处处加一列。

复制一次，后面要省回多少？

教学测量输入：布局转换 80 μs；原布局 kernel 每次 140 μs；连续布局每次 100 μs。同一份数据会被复用 R 次。

T直接 = 140R；T转换 = 80 + 100R（μs）
转换获利条件：R > 80 / (140−100) = 2

R=1 会变慢；R=2 持平；R=3 节省 40 μs。还要确认 64 MiB 临时显存是否值得。

练习 1

带 offset 的地址怎么算？

FP32 张量 shape=[2,2,2]、stride=[12,4,2]、storage_offset=4。求 y[1,1,1] 相对 storage 起点的 byte 偏移。若 data_ptr 已指向 y 首元素，应该加多少 byte？
展开参考解答

元素偏移 = 4 + 12 + 4 + 2 = 22；相对 storage 起点为 22×4 = 88 byte。

data_ptr 已含 offset 4，因此只再加 (12+4+2)×4 = 72 byte。两种起点不可混用。

练习 2

跨一格读一次，覆盖多少 sector？

32 个 lane 各读 FP32，地址为 4×(1+2ℓ)，ℓ=0…31。起始 storage 32-byte 对齐。计算 sector 数与唯一有效字节覆盖率。
展开参考解答

首地址 4，末元素覆盖 byte 252…255；sector 为 0…7，共 8 个。可逐项检查，每个 sector 恰好有 4 个 FP32。

有效字节 32×4=128；sector 字节 8×32=256；覆盖率 50%。这是地址模型，不是实际 HBM 带宽测量。

练习 3

共享存储，还是重新排列？

x 为连续 [2,3]，y=x.T。y 展平成一维的逻辑值次序是什么？能用一维常数 stride 直接 view 吗？复制成本 80 μs、每次省 40 μs，消费 4 次是否划算？
展开参考解答

若 x 的 storage 是 0…5，则 y 的遍历次序是 [0,3,1,4,2,5]；相邻差不是常数，不能直接用一维 stride 表达。

需要复制或改消费方式。4 次的节省为 4×40−80=80 μs；还应计入新 storage 的峰值显存。
