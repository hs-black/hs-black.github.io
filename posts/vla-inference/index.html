VLA：从视觉 token 到机器人动作

把动作表征、时间预算与反馈连成一条执行链

从模型到系统

输出从一句话，变成一段带单位的动作

VLA 把视觉、语言与机器人状态映射为动作。动作不仅要数值正确，还要在正确的坐标系、时间点和控制接口里解释。

策略输入：图像 + 指令 + 状态
策略输出：A ∈ ℝ[B, H, Da]

B 是 batch，H 是预测动作步数，Da 是每步动作维数。离散 action token 也要解码回同样明确的动作语义。

先修：多模态推理账本、KV cache。

逐步演算

同一个 chunk，预测与执行不是同时发生

视觉与状态在采集时刻描述世界；模型返回动作时，时钟已经向前走了。

这里用二维教学动作画流程。实际接口还可能包含关节、姿态、夹爪及各自的 mask。

工程细节

先写动作契约，再写推理代码

字段需要明确的含义错误示例
平移位置 / 增量 / 速度；m 或 mm把 0.02 m 当成 0.02 mm
姿态轴角 / Euler / quaternion；坐标系把工具轴旋转当成基座轴旋转
夹爪开度 / 二值指令；开闭方向训练中 1 为开，接口中 1 为闭
时间控制周期、动作时间戳与有效区间把 50 Hz 轨迹逐点发给 10 Hz 接口

形状相同只能证明维度对上，不能证明动作语义对上。

工程细节

归一化把物理量搬到模型的数值区间

以单轴位移为例，训练范围 low = −0.04 m，high = 0.04 m。用区间映射到 [−1, 1]。

z = 2(a − low)/(high − low) − 1
a = low + (z + 1)(high − low)/2

a = 0.013 m → z = 0.325。推理输出 z 后必须用同一套统计量反归一化。

有些模型按分位数或均值/标准差处理，不同维度还有 mask；检查 checkpoint 配套的 action transforms。

逐步演算

离散 action token 究竟损失了什么？

教学量化器：把 [−1,1] 分成 8 个等宽区间，以每个区间中心重建。

这里的 8 个区间只是手算模型；真实 tokenizer 要核对边界数量、中心数量和 token 映射。

工程细节

动作头有不同的生成路径

Autoregressive action token

将每个动作标量或压缩动作序列编码成 token，逐个预测，再解码回连续动作。

连续 action chunk

直接预测 [H, Da] 数组；可以用回归、diffusion 或 flow matching 生成。

OpenVLA 展示了离散动作 token 路径；Octo 使用 diffusion action head；π₀ 使用 flow matching action expert。

chunk 不等于一次网络调用：迭代去噪或 flow 采样可能需要多次 action head 前向。

工程细节

Flow matching：把噪声逐步移到动作分布

用 σ 表示生成进度：σ = 0 是噪声，σ = 1 是动作。网络根据观察 o、当前动作数组 Aσ 和 σ 预测速度场 vθ。

dAσ / dσ = vθ(Aσ, σ, o)
Aσ+Δσ ≈ Aσ + Δσ × vθ(Aσ, σ, o)

一次 Euler 步更新整个 H × Da 动作数组；采样步数 K 与动作步数 H 是不同的轴。

时间参数方向依实现而定。openpi 的当前 pi0.py 用 t = 1 表示噪声、t = 0 表示动作，更新步长为负。

工程细节

训练时，速度场的答案从哪里来？

训练数据给出真实动作数组 A*；再采样噪声 ε 与进度 σ，构造一条连接两者的路径。

Aσ = (1 − σ)ε + σA*
vtarget = A* − ε；loss = mean((vθ − vtarget)²)

单个分量例：ε = −0.7，A* = 0.3，σ = 0.5，所以 Aσ = −0.2，目标速度为 1.0。若预测 0.8，这个分量的平方误差是 0.04。

推理时没有 A*。网络只能依据观察、当前候选动作与 σ，给出学到的速度；各轮更新逐渐形成条件动作样本。

逐步演算

一次动作 chunk，经过多轮细化

把一个两维动作画成平面上的点；每一小步根据速度场改变当前候选动作。

演示采用常量速度场，直线轨迹只为解释 Euler 更新；真实网络的速度场依当前点与观察改变。

工程细节

固定观察的 KV 可以跨采样步复用

这次推理固定的条件

图像与文字先编码为 prefix；只要条件和 mask 不变，它们的每层 KV 可以复用。

每轮改变的动作

噪声动作、生成时间 σ 与 action hidden state 会改变；相应后缀仍要重新计算。

openpi 的 π₀ 采样先构建观察 prefix KV，再在多次 action expert 更新中读取同一份条件。

新摄像头帧或新状态到来后，要重新检查哪些 prefix 已改变；不能把不同观察直接当成同一缓存。

工程细节

动作 horizon 与生成步数，别乘错位置

量含义教学例
H预测未来多少个控制时刻16 步
Da每个时刻多少个动作分量7 维
Kflow / diffusion 的网络更新次数10 轮
E每次重规划前实际执行几步4 步

动作数组只有 16 × 7 = 112 个数。K = 10 代表反复计算这份数组，不代表最终输出 1,120 个动作数。

工程细节

预测 16 步，不必全部执行

控制周期 Δt = 20 ms，预测 H = 16 步覆盖 320 ms。若只执行 E = 4 步就重新观察，重规划间隔是 80 ms。

预测时域 = H × Δt
重规划间隔 = E × Δt，1 ≤ E ≤ H

较小 E

更频繁利用新观察，推理请求更多。

较大 E

摊薄每次推理成本，但后半段动作依据更旧的观察。

Octo 的推理接口也允许执行整个 chunk 或仅执行前部，形成 receding horizon。

每次只执行前两步，余下计划会被替换

图中 H = 8、E = 2。每次得到新观察后，重新预测未来，而不是永久排队旧计划。

为看清重规划关系，这张图暂取推理延迟为 0；下一页加入真实时间预算。

工程细节

模型每秒算几次，和机器人每秒动几次不同

控制器以 50 Hz 取动作，即 Δt = 20 ms。策略若每 4 步更新一次，只需持续提供 12.5 个 chunk/s。

策略请求率 = 1/(E × Δt) = 12.5 次/s
单串行推理器可持续条件：Lcompute ≤ E × Δt

教学例：推理 60 ms，E = 4 时 60 ≤ 80 ms；E = 2 时 60 > 40 ms，积压会持续增长。

这个条件只判断计算供给。传输、抖动、初始等待与观察陈旧度还需要单独预算。

逐步演算

60 ms 后返回的计划，前 3 步已经过去

动作周期 20 ms。计划针对采集时刻 t = 0 开始的动作时序，直到 60 ms 才返回。

此处规定每个动作带绝对执行时刻；另一种“到达后重新起算”接口需要重新定义训练与执行对齐。

工程细节

时延要从观察曝光时刻量起

时间代表什么能发现什么
tobs传感器采集时间相机缓冲中的陈旧帧
tsubmit / tready提交模型 / 结果就绪排队、传输与模型执行
texec动作真正生效时间控制队列与发送延迟
观察年龄 age = texec − tobs

模型耗时 30 ms，不代表动作只依据 30 ms 前的世界。旧帧排队 80 ms，就已经把年龄推到 110 ms 以上。

工程细节

用时间戳丢掉已过期的动作

result = future.result()
for i, action in enumerate(result.actions):
    execute_at = result.observation_time + i * dt
    if execute_at < now:
        continue
    queue[execute_at] = action
# 更晚观察产生的新计划替换同一时刻的旧计划

这个规则要求训练目标与接口采用“从观察时刻起”的动作时间轴。只有动作顺序、没有时间戳，无法判断它是否已经过期。

没有可用动作时的行为属于控制器契约；本课实验把速度指令置为 0，模拟漂移仍持续。

工程细节

工具坐标里的“向前”，不等于基座 X 轴

二维例子：工具相对基座逆时针旋转 90°，工具系位移 Δptool = [0.02, 0] m。

Δpbase = Rbase←tool × Δptool
R90° = [[0, −1], [1, 0]]
Δpbase = [0, 0.02] m

位移向量只乘旋转。变换一个点坐标才加入平移：pbase = R ptool + t。把两者混用会凭空多出一段移动。

同一个位移，换个坐标系重新表达

箭头长度保持 0.02 m，方向随工具系相对基座的旋转变化。

这里只演示平移向量的二维旋转；三维姿态需遵守所用旋转参数的组合约定。

工程细节

为什么动作误差需要反馈来修正？

用一维模型看清原因：x 是位置，u 是速度指令，d 是未建模的持续漂移。

xk+1 = xk + Δt(uk + d)
uk = k(g − x̂k)

g 是目标，k 为反馈增益；x̂k 是策略依据的状态。观察越旧，x̂k 越可能偏离真实 xk。

真实机器人还有动力学、接触与延迟；这个简化模型只隔离“旧状态 + 重规划”的作用。

工程细节

即使无延迟，比例反馈也会留下稳态误差

若每步都拿到当前状态，u = k(g − x)。达到平衡时，速度指令与漂移相互抵消。

0 = k(g − x*) + d
x* = g + d/k

取 k = 2 s⁻¹、d = 0.10 距离单位/s：稳态位置比目标多 0.05。增加重规划频率不能消除这项模型偏差。

先区分时延问题、动作解码问题与控制模型误差；看到偏差就盲目提高 FPS，可能没有效果。

工程细节

动作系统需要两组指标同时成立

模型与服务

视觉编码、prefix prefill、action head、采样轮数；p50 / p99 时延、观察年龄、请求积压。

执行与任务

动作解码误差、跟踪误差、过期或缺失动作；任务成功率、完成时间与场景分层。

action token accuracy 高，不保证轨迹误差小。相邻 bin 与反向夹爪的工程后果不同，必须回到连续量和任务结果看。

先按任务与环境条件分桶，再比较同一批起始状态；平均数会掩盖特定场景失败。

离线回放，先守住输入与时间的一致性

验证层比较方式定位的问题

工程细节

动作输出很小，模型推理未必便宜

H = 16、Da = 7、FP32：动作输出只有 16 × 7 × 4 = 448 字节。大头通常在图像/语言 backbone、缓存与多轮 action head 计算。

Trequest ≈ Tvision + Tprefix + K × Taction-step + Tother

教学例：20 + 30 + 10 × 4 + 10 = 100 ms。把 K 从 10 改为 5，算术上变为 80 ms；采样质量还需重新评估。

只有条件 prefix 可正确复用时，Tprefix 才能只算一次；跨请求换观察后不能自动省略。

练习 · 先算，再展开

量化后，0.013 m 会变成多少？

动作范围 [−0.04, 0.04] m，映射到 [−1,1] 后分成 8 个等宽区间，用中心重建。求归一化值、0-based bin、还原动作和区间内最大误差。
展开参考解答

z = 2 × (0.013 + 0.04) / 0.08 − 1 = 0.325。bin = floor((z + 1) × 8 / 2) = 5，中心 ẑ = 0.375。还原 â = 0.015 m，误差 0.002 m。物理区间宽 0.08 / 8 = 0.01 m，未截断值的最大误差为 0.005 m。

练习 · 先算，再展开

50 Hz 控制，需要多快的模型？

Δt = 20 ms，H = 16，E = 4。单串行模型耗时 60 ms。求预测时域、策略请求率和能否持续供给。若 E 改为 2 呢？
展开参考解答

预测时域 16 × 20 = 320 ms。E = 4 时每 80 ms 请求一次，即 12.5 次/s；模型容量约 16.67 次/s，可以持续供给。E = 2 时每 40 ms 一次，即 25 次/s，超过串行模型容量，将积压。H 不变不代表请求率不变。

练习 · 先算，再展开

变换一个点，还是一个位移？

工具系相对基座旋转 90°，平移 t = [1, 2] m。工具系点 p = [0.02, 0] m，与位移 Δp = [0.02, 0] m，变到基座系各是什么？
展开参考解答

旋转后都是 [0, 0.02]。点坐标还需加 t，得到 pbase = [1, 2.02] m；位移只旋转，Δpbase = [0, 0.02] m。若给位移也加 t，会把坐标原点偏移错误地变成额外运动。

练习 · 先算，再展开

结果到达时，该跳过哪些动作？

chunk 的动作时刻是 tobs + i × 20 ms，i = 0…7；tobs = 1,000 ms，结果在 1,065 ms 到达。只保留执行时刻 ≥ now 的动作。哪些索引已经过期？还剩多少？
展开参考解答

i = 0、1、2、3 对应 1,000、1,020、1,040、1,060 ms，均已过期。最早剩下 i = 4，执行时刻 1,080 ms，共剩 4 个动作。到 1,080 ms 时观察年龄为 80 ms；不能把刚收到结果当作刚观察到世界。
